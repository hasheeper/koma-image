# P3：NovelAI 官方连接

2026-10-19。NovelAI 官方 API 是公开官方协议，按 [Gateway Profile](architecture.md#gateway-profile) 的规则作为独立 Profile 适配：用户自己添加连接和 Key，地址固定为官方地址；私有渠道与中转仍只走标准 Profile。

P3.0／P3.1 不新增 NovelAI 可见功能，标准 Profile 行为不变。P3.2 起可以先用模拟接口实现，但官方请求体、返回格式和扣费条件无法核实，因此在拿到 Key 前暂停。

## 设计要点（P3.2 起）

- **Profile。** ID 暂定 `nai-official-v1`。不支持报价、不声明费用上限，走无报价执行：不报价、不带上限字段、不预占。静态目录声明 V5 与 V4.5 的 Full、Curated。地址固定，设置里不可改。
- **请求。** 生图、图生图、重绘发往 `/ai/generate-image`，放大发往 `/ai/upscale`；不带标准 Profile 的原生附加请求头。错误体转为中文提示：401 为「Key 无效」，402 为「Anlas 不足」。不自动重试，不加付费确认。
- **额度。** 读 `/user/subscription`，显示 Anlas、V5 用量和回充；不套用标准 Profile 的日额度和 300 阈值。
- **额度标签。** 按官方条件在本地判断「不限量」「占 V5 用量」「扣 Anlas」「可能扣 Anlas」，只显示，不拦截。官方没有费用上限，花费只靠显示，所以判断不确定时写「可能扣 Anlas」。实际消耗按执行前后的余额差记录，仅供参考。
- **来源。** 同一模型由多个连接提供时，仍按连接顺序取第一个。
- **本地模式。** 本地代理只服务标准 Profile，第一期不在本地模式中添加 NovelAI 连接。
- **调度。** 保持全应用 N=1。

## 留给 P3.2

- 额度查询固定读 `quota`、`stats` 两条路径，缺失时整个查询报错；NovelAI 需要自己的额度分支。
- 绘图历史把 `quote: null` 原样存为 null；记录与备份对空报价的处理要补测试。
- 编辑结果的报价暂写为 `output.quote ?? undefined`。
- 首次进入且没有连接时，「生成」按钮禁用，看不到去设置的入口；入口方案未定。

## 待核验（需要 Key）

用一个 Opus 账号做最少量的请求，执行前取得授权，结果单独记录：

1. `GET /user/subscription` 的实际字段和上限。
2. 一张 V5 Full 832×1216、23 步生图：返回格式、余额变化，以及占用量还是扣 Anlas。
3. 图生图和重绘各一次：重绘模型 ID、蒙版格式，有底图时是否扣 Anlas。
4. 放大一次：请求体、返回格式、倍数和价格。
5. Medium 档位及其重绘模型是否可用。
6. V5 Curated 重绘使用的模型。
7. `Accept: application/json` 是否适用于全部操作。

核验前，NovelAI 连接在设置里标「未实测」，编辑操作的额度标签一律为「可能扣 Anlas」。
