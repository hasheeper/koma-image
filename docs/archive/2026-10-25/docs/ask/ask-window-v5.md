# ASK 对话窗口 v5：界面、对话管理与附件实施规范

日期：2026-10-23。状态：用户已确认；W1–W6 已完成本地开发与模拟验收，见 §9 的 W6 收口记录。代码基线：`535c3a8`（R1–R4）。界面基线：用户逐轮确认的 B v5 交互预览，位于 `.local/ask/ui-proposal/preview/`，不提交。

本文把 B v5 预览落到业务逻辑：多对话、编辑重答、分支、草稿逐级回退和附件。文档 4 [§2.9](ask-implementation-plan.md#29-对话窗口-v5) 采纳本文作为本专题的目标契约；本专题内与文档 1–3、A2 记录及 UI 规范冲突处以本文为准，其余工程优先级与 `AGENTS.md` 红线不变。

## 1. 范围

本次做：

- 窗口界面定稿：草稿卡 v5、消息操作、编辑框、检查点行、附件栏、对话菜单、空对话页。
- 多对话：新对话、切换、删除、从某条回答分支；未收藏只在本页内存，用户收藏的会话刷新后保留。
- 编辑提问：删除这条回答及之后的对话，回退其中写入的草稿，再重新回答。
- 草稿撤销栈：保留「只撤销最近一份」，回退后才能继续回退上一份。
- 附件：图片和文本随提问发送，图片过大时压缩；粘贴、拖入、选择三种入口；与工作区之间按窗口归属分配粘贴和拖放。

不做：

- 全量自动保存、会话导出与跨对话检索。收藏持久化与重命名已由用户后续批准。
- PDF、Office、EPUB、SVG、压缩包、音视频的解析。
- 附件作为 `restore_partial` 来源；首版附件参数只作只读参考（§5.6）。
- 编辑器内 ASK（D9 不变）。
- 超长附件由模型分段读取：首版只按 §5.6 的上限直接拦截，分段读取留作以后的设想。

不变的红线：不调用生图、编辑、放大、报价或扣费接口；不发送 CHAT 消息；不参与生成锁；ASK 同一时间只运行一轮；不自动重试；用模拟服务验证；不新增依赖；严格 TS；大对象不进深层 reactive；监听器与 Observer 有清理。

## 2. 已确认的决策

| 主题 | 决定 |
| --- | --- |
| 对话存储 | 收藏保存在本机；未收藏按页面保留，刷新清空 |
| 草稿配色 | 删除行用深红透明底，新增行用深绿透明底；文字保持中性色，只有 ± 号用纯红绿；不用灰框 |
| 字段图标 | 每个字段标题前都有图标，与折叠箭头、± 号同列 |
| 不支持的文件 | 直接用站内错误提示弹出拦截，如「不支持 PDF」；输入区不留文字，不给建议 |
| 消息操作 | 提问右下：复制 · 编辑；回答左下：复制 · 分支；小图标、悬停出现 |
| 编辑提问 | 等于「删除之后的对话 + 回退草稿 + 重新回答」；不保留旧版本，没有 ‹ 1/2 › 翻页 |
| 分支 | 把到这条回答为止的对话复制成一个新对话，原对话不动 |
| 附件发送 | txt、md 等文本随提问发送；图片也随提问发送，过大时压缩 |
| 草稿回退 | 保留「只撤销最近一份」；回退这一级之后才能继续回退上一级；数据对不上显示「回退失败」 |
| 粘贴与拖放 | 按简单的多窗口规则：粘贴归焦点所在窗口，拖放归指针下方的窗口 |
| 空对话页 | 用预览中的三条起手问题，见 §5.8 |
| 上限 | 对话数与附件上限首版即生效，超出直接拦截提示 |
| 删除对话 | 必须二次确认（行内「删除」） |
| 草稿卡全文 | 沿用预览当前的全文视图（逗号词组 LCS，删除划线） |

其中「图片随提问发送」修订文档 1 D3 与 F7 对用户附件的约定：用户亲手附上的图片视为本轮提问的一部分，「发送图片给模型」开启时随提问外发；ASK 自己去看历史图仍走 `view_image` 与原视觉预算。

## 4. 数据模型

所有会话消息、Blob、编码后的图片和撤销记录都是普通对象，由 `service.ts` 持有；Vue 只拿低频视图（shallowRef 与修订号）。

### 4.1 对话

```ts
interface AskConversation {
  readonly id: string;                 // 本页唯一，不复用
  title: string;                       // 首条提问的首行；未发送前为「新对话」
  readonly origin: { conversationId: string; turnId: number } | null; // 分支来源，仅用于图标
  readonly session: Session;           // 已提交轮次，事务语义不变
  entries: AskEntry[];                 // 视图轮次
  draft: DraftRecord | null;           // 该对话末轮的未决草稿
  input: string;
  anchor: string | null;
  tray: AttachmentId[];                // 尚未发送的附件
  readonly createdAt: number;
}
```

- 切换对话时，把当前对话的 `entries`、`input`、`anchor`、托盘与未决草稿换进现有的 shallowRef，组件接口尽量不变。
- 用量改为页面级累计：所有对话的上游计费 tokens 相加，删除对话不减少。
- 调用日志（`debug.ts`）记录对话 ID；「调用上下文」显示当前对话的调用，导出包含全部。

### 4.2 轮次与会话

`AskTurnView` 增加：

- `attachments`：本轮附件的只读视图（ID、类型、名称、尺寸／字数、缩略图）。
- `committed`：成功提交时为该轮在会话中的序号；失败和停止的轮次没有序号。
- `checkpoint`：本轮写入的轻量只读视图（记录 ID、标题、状态、+N／−M），没有则为空。完整草稿只由未决槽位、撤销栈或 redo 持有；超过栈上限的历史检查点保留展示，不保留可回退的完整快照。

`session.ts` 增加：

- `commit(meta)`：同时保存本轮成功查看的图片 ID，供 `crop` 前置条件使用；`viewed()` 返回剩余已提交轮次的并集。
- `truncate(count)`：只保留前 `count` 个已提交轮次；运行中调用直接抛错。
- `fork(count)`：新建会话，共享前 `count` 个已提交轮次（消息数组不可变，可以共享），用量从零开始。
- 事务、预算和图片脱水规则不变。截断和分支只切掉尾部，保留轮次按已脱水的形态原样留下，所以下一次请求的历史与最近一次实际发出的请求前缀逐字节一致，供应商的前缀缓存仍可命中（已脱水的旧图不会恢复）。

### 4.3 草稿记录与撤销栈

```ts
interface DraftRecord {
  readonly id: number;
  readonly conversationId: string;
  readonly turnId: number;
  readonly draft: Draft;
  off: ReadonlySet<string>;                    // 用户撤回的步骤
  status: "pending" | "applied" | "reverted";
  plan: DraftPlan | null;              // 应用时冻结
  beforeReceipt: string | null;        // 最近一次应用前的 CHAT 键
  receipt: string | null;              // 最近一次成功写入／回退后的 CHAT 键
}
```

- `undoStack` 是页面级数组，按应用顺序存放 `applied` 记录；表单与 CHAT 输入框只有一份，所以撤销栈跨对话共享。上限 50 条，超出时丢弃最早的。
- `redo` 只记最近一次回退的记录；之后再应用任何草稿就清空。
- `createDraftWriter` 不再自持 receipt：`apply(plan, receipt?)` 和 `undo(plan, receipt)` 返回本次完成后的键（IMAGE 为 null），`canUndo(plan, receipt)` 检查记录持有的键。恢复时把上次回退所得的键交给 `apply`；首次应用使用计划中的原键。写入仍只由用户操作触发，`draft/apply.ts` 仍是唯一写入模块。
- CHAT 分支回退会递增 `selectionRevision`。栈保存应用前后的精确键；成功回退后，仅在完整状态除该修订号外都一致时，更新持有相同原边界键的较早记录。手动改动、附件／上下文变化和会话切换不会被这个衔接过程放过。

### 4.4 附件

```ts
interface Attachment {
  readonly id: string;                 // 图片 #a1、#a2…，本页递增不复用；文本用内部 ID
  readonly kind: "image" | "text";
  readonly name: string;               // 粘贴的长文本为「粘贴的文本」
  readonly bytes: number;
  // 图片
  readonly blob?: Blob;                // 原文件，供 view_image 与裁切
  readonly size?: { width: number; height: number };
  readonly sent?: AskImage;            // 发送用编码（原样或压缩后），添加时生成
  readonly params?: Record<string, unknown>; // PNG／JPEG 内的 NAI／WebUI 参数
  // 文本
  readonly text?: string;
}
```

- 页面级登记表按引用计数管理：托盘、轮次（含分支复制出的轮次）各算一次引用。移除、截断、删除对话后引用归零，立即释放 Blob、编码数据和缩略图 Object URL。
- 附件不写入绘图历史、IndexedDB、备份、CHAT 或任何设置，刷新即消失。

## 5. 交互与业务规则

### 5.1 对话菜单：新建、切换、删除

顶栏为：ASK 标识、对话标题下拉、放大／还原、更多（…）、收起。分支对话的标题前有分支图标。

下拉菜单：

- 顶部依次为「新对话」「重命名」「收藏会话／取消收藏」。下面是对话列表，收藏置前，同组按创建时间新的在上；当前对话打勾，收藏用星标，其他分支对话用分支图标。底部说明：「收藏保留，其余刷新后清空」。
- 每项悬停显示 ×（触屏常显）。点 × 后该项变成红色「删除」按钮，再点一次才删除；移开指针、按 Esc 或关闭菜单即取消。

规则：

- **新对话**：复用已有的未收藏空对话，否则新建并切换；已收藏的空对话不被复用。
- **切换**：运行中或正在写入草稿时，菜单里的切换、新建、删除不可用。每个对话各自保留输入、锚点、托盘和未决草稿；未决草稿只在所属对话显示，Tab／Esc 只作用于当前对话。
- **2026-10-23 上下文修正**：新建或复用空对话时清除图片锚点；普通打开与 Ctrl/⌘J 唤起不自动绑定画布当前图。显式 Ask／对比／点选与手输 ID 保留定位能力。未引用图片的 v4 摘要不预载旧 Prompt／Diff 或表单正文，详见文档 4 §2.10；起手问题显示的当前图 ID 仅在用户点击后成为明确提问。
- **删除**：运行中的对话不能删除。删除当前对话后切到列表中最新的一个；没有剩余对话时新建一个空对话。删除会释放附件，并把该对话的记录移出撤销栈，已写入的内容保持原样，不回退。
- **上限**：本页最多 20 个对话；达到上限时新建或分支弹出「最多 20 个对话」。
- **标题**：首次发送时取提问首行（压缩空白，最多存 60 字，显示时 CSS 截断）；提问为空时用第一个附件名。分支沿用来源标题。
- **其他入口**：画框「Ask」「Ask Diff」「Ask Why」与 ⌘K 行内模式都进入当前对话，不自动新建。
- **紧凑形态**：结果卡、运行胶囊、已写入胶囊只反映当前对话；运行中不能切换，所以不会显示别的对话的状态。

「更多」菜单：发送图片给模型（与设置页同一开关，写入 `koma.ask.v1`）、使用个人偏好（沿用本次临时停用）、调用上下文（显示本对话用量）、ASK 设置。个人偏好停用时，输入区上方显示「偏好已停用」，点击即恢复。

### 5.2 消息操作

| 位置 | 操作 | 显示 |
| --- | --- | --- |
| 提问气泡右下 | 复制、编辑 | 桌面悬停气泡或键盘聚焦时显示；触屏点气泡切换显示 |
| 回答左下 | 复制、分支 | 桌面悬停该轮时显示，最后一轮常显；触屏常显 |

- 图标 28px（触屏 36px），`--fg-3`，悬停 `--ask-hover` 底。操作行上方留 4px、下方留 10px，不能压住下一段文字。
- 运行中的轮次不显示操作。失败或停止的轮次：提问可以复制、编辑；回答有文字时可以复制，没有分支（未提交）。
- **复制**：提问复制原始文本；回答复制各段正文，以空行分隔，不含工具行和候选图。使用 `navigator.clipboard.writeText`；成功时图标变成对勾 1.5 秒，失败时弹出「复制失败」。

### 5.3 编辑提问

界面：

- 气泡原地变成输入框：铺满宽度，`--ask-hover` 底、`--line-2` 描边、18px 圆角，去掉全站 textarea 的焦点光圈；本轮附件仍显示在上方，只读。
- 底部是「取消」文字按钮和 28px 圆形主色发送键（触屏 36px），发送键提示「删除这条之后的对话，撤回其中的草稿，重新回答」。
- Enter 发送，Shift+Enter 换行，Esc 取消；输入法组合中不响应。编辑框作为 Esc 浮层登记，先于草稿和窗口关闭。同一时间只开一个编辑框。

可用条件：没有运行中的轮次、没有正在写入；新文本非空，或本轮有附件；连接就绪（未就绪时提示与普通发送相同）。

流程（回退前先检查连接、模型与 Key 是否就绪；保存期间配置若变化，截断前再次检查）：

1. 收集本轮及之后各轮的 `applied` 记录。
2. **整体预检**：这些记录必须正好是撤销栈最上面的几条（中间没有夹着别的对话较新的记录）；再从栈顶起依次模拟回退，校验每条的字段值、CHAT 会话和分支键（§5.5）。任何一步不满足，就弹出「回退失败：…」并停止：不删除轮次、不发送，编辑框保留。目标检查点若已超出最近 50 条完整记录的保留范围，提示「回退失败：草稿已超出撤销保留范围」，不能跳过它直接截断。
3. 从栈顶起逐条真实回退。中途写入失败就停下，弹出「回退失败：…」；已回退的记录如实标为已回退，不发送，编辑框保留。
4. 删除本轮及之后的视图轮次，`session.truncate()` 到本轮之前，丢弃该对话的未决草稿，释放只被删除轮次引用的附件，重算已看图片。
5. 用新文本、本轮原附件和原锚点，走普通发送路径生成新的一轮；保留本轮的仅元数据状态，不清空底部尚未发送的输入。
6. 回退了草稿时弹出成功提示「已撤回 N 份草稿」。

现有「重试」（plain／metadata／codec）保持原样：失败或停止的轮次没有提交，重试只移除该轮视图并重新发送，不删除之后的轮次，也不回退草稿。

### 5.4 分支

- 只对已完成并提交的回答显示「分支」。运行中或正在写入时不可用；对话数已达上限时弹出「最多 20 个对话」。
- 新对话包含：来源到这一轮为止的视图轮次（去掉检查点行和 `.note`）、`session.fork(n)`、附件引用、重算后的已看图片、分支点这一轮的原锚点。输入、托盘和未决草稿为空。
- 草稿记录不复制：写入属于来源对话，回退也只在来源对话进行。
- 创建后切换过去，滚到底部并聚焦输入框；菜单与标题显示分支图标。
- 代码里用 `fork` 命名，避免与 CHAT 的 `chat_distill_branch`（对话页分支）混淆。

### 5.5 撤销栈与检查点行

界面：

- 草稿应用后，输入框上方的草稿卡收起，所在轮次的回复正文下方、复制／分支图标上方出现检查点：「✓ 已写入 标题 +N −M」。按用户 2026-10-23 的排版调整，正文与横幅间距为 8px，横幅与图标行间距为 4px。
- 只有撤销栈栈顶，并且属于当前对话时，该行最右侧常显 28px「回退」图标按钮（`i-undo`，读屏名「回退」，触屏 36px）；其他检查点不显示回退，统计直接贴右。按用户 2026-10-24 选定的方案 A，不再用悬停才显现、平时透明占位的文字按钮。
- 回退后该行变为「已回退 标题」，统计数字划掉、文字降为 `--fg-3`。最近一次回退的记录显示「恢复」图标按钮（`i-redo`，读屏名「恢复」），条件是之后没有再应用过草稿。执行中按钮禁用并降为 `--fg-4`。
- 回退和恢复都是单击执行，不弹确认：只动这一份，与 ⌘Z 一致。预览里「之后的…一起撤回」的确认面板随逐级规则取消。

规则：

- **回退**：只对栈顶。用 `canUndo(plan, receipt)` 校验：目标字段仍等于写入后的值；CHAT 草稿仍在原会话；分支草稿的分支键仍等于 receipt。通过后写回原值，记录出栈，下一份成为栈顶；不通过就弹出「回退失败：Prompt 已变化」，表单和记录都不动。
- **失败原因**：列出字段名：Prompt、Negative、参数名（模型、尺寸、Seed…）、对话输入框、对话分支，如「回退失败：Prompt、Seed 已变化」。会话切换时为「回退失败：对话已切换」；编辑预检遇到夹层时为「回退失败：先回退较新的草稿」。
- **恢复**：只对 `redo` 记录。校验目标字段仍等于写入前的值，通过后重新写入并压回栈顶；失败时弹出「恢复失败：…」。
- **入口一致**：⌘Z／Ctrl+Z 与检查点「回退」都只作用于属于当前对话的栈顶，焦点护栏沿用 A2。2026-10-23 起已写入胶囊和结果卡不再放「撤销」，见文末小岛记录。
- **流记录**：不再写「已应用草稿」「已撤销草稿」两种 `.note`；读屏播报保留。「提示词已在外部修改」的 `.note` 保留。
- **未决草稿**：草稿待确认时不能继续提问（D2 不变）。回退不会让旧草稿卡重新出现，状态都在检查点行上。

### 5.6 附件

入口：

- 焦点在 ASK 窗口内时按 ⌘V／Ctrl+V。
- 把文件拖进展开的 ASK 窗口。
- 点输入栏左侧的 ＋（28px，触屏 36px）选择文件，可多选。

| 类型 | 接受 | 单个上限 | 每条上限 | 发送方式 |
| --- | --- | --- | --- | --- |
| 图片 | PNG、JPEG、WebP、GIF（取首帧）、AVIF、BMP；HEIC 仅在浏览器能解码时 | 20 MB，4000 万像素 | 4 张 | 随提问发送，过大时压缩 |
| 文本文件 | `.txt` `.md` `.markdown` `.json` `.csv` `.tsv` `.yaml` `.yml` `.log`，UTF-8 | 默认 5 万字符，可在 ASK 设置中调整 | 4 个，默认合计 10 万字符，可调整 | 随提问发送，包在 `<data>` 中 |
| 长粘贴 | 纯文本超过 2000 字 | 同文本文件设置 | 计入文本合计 | 自动变成「粘贴的文本」附件 |

本页附件原文件合计不超过 200 MB。文本上限在「设置 → ASK → 上下文与附件」即改即存，可恢复默认，并随 ASK 设置备份；合计不能小于单个上限。调整作用于后续添加，已附加／已发送的正文保持原样。

**判定与提示**：

- 图片以 `createImageBitmap` 能解码为准，文本以扩展名或 `text/*` 加上 `TextDecoder("utf-8", { fatal: true })` 解码成功、且不含 NUL 为准。
- SVG 一律拒绝。
- 其他文件弹出站内错误提示，同一批合并为一条：「不支持 PDF」「不支持 DOCX、SVG」。
- 其他错误：「无法读取 文件名」「文件名 超过 N 字符」「每条文本附件合计最多 N 字符」（N 使用当前设置）、「每条最多 4 张图片」「文件名 超过 20 MB」「文件名 压缩后仍超过 1 MB」「本页附件已超过 200 MB」。
- 不在输入区留文字，不给建议。

**图片压缩**：

- 添加时就生成发送编码，托盘可以直接显示最终状态；编码完成前发送键不可用。
- PNG／JPEG／WebP 长边不超过 1568px 且不超过 1 MB 时原样发送。
- 其他情况用 OffscreenCanvas 缩到长边 1568px，编码为 WebP（质量 .85）。仍超过 1 MB 时以质量 .7 重试，再不行就拒绝。
- 原文件保留在内存，供 `view_image` 查看全图或裁切。

**消息组装**（当前用户消息）：

1. 工作区状态块（不变）。
2. 每张图片：一行说明「附件 #a1 · 文件名 · 原尺寸 → 发送尺寸」，后接图片块；带 NAI／WebUI 参数时，把 `readImageParams()` 读出的字段放进 `dataBlock()`，作为文件元数据。
3. 每个文本附件：一行说明「附件 · 文件名 · N 字」，正文放进 `dataBlock()`；`dataText()` 已把 `<` 转义，正文不能闭合标签。
4. 用户提问。

**仅发送元数据时**（发送图片关闭，或用户选择仅元数据重试）：图片块不发送，只发说明行和参数；托盘图片显示虚线与灰度。文本附件照常发送。

**与工具的关系**：

- 随提问发出的图片计为本轮已看全图，可直接 `crop`；附件图片不计入 `view_image` 的 4 次／1.5MP／400KB 视觉预算。
- 历史轮次的附件图片按现有规则脱水：保留最近 3 轮，更早的换成占位文字，模型需要时再用 `view_image #a1`（计入预算）。
- `get_meta #a1` 返回文件名、类型、原尺寸、发送尺寸与字节数、参数（无参数为 null）；`diff_meta` 可比较 `#a` 与 `#h`；`view_image`／`view_sheet` 接受 `#a`。
- `search_history` 不检索附件。`restore_partial` 拒绝 `#a` 来源，并返回「附件参数仅供参考」。
- 词表混淆仍只在 `provider.ts` 收发边界作用于全部出站文本，附件文本同样经过它。

**估算**：附件图片按发送尺寸 `ceil(宽×高/750)` 估 tokens，文本照常估，仍标「约」。文本附件留在历史中，以后每轮都会重发，估算如实计入。

**界面**：

- 托盘在输入框上方。图片 52px 方块，左下角显示 `#aN`；文本为图标、名称加「MD · 480 字」的小卡。悬停右上角出现 ×（触屏常显），托盘上方与右侧留出空间，× 不被裁切。
- 已发送的提问上方右对齐显示 64px 缩略图和文件小胶囊。
- 点文本附件打开只读查看浮层（Esc 关闭）；点图片或正文中的 `#aN`，沿用 `AskReference` 的预览（附件没有画布位置，不做定位）。
- 只有附件、没有文字也可以发送。

### 5.7 粘贴与拖放的窗口归属

规则只有两条：粘贴交给焦点所在的窗口，拖放交给指针下方的窗口。

- **粘贴**：ASK 窗口根元素在冒泡阶段监听 `paste`。焦点在 ASK 内时，文件进附件，超过 2000 字的纯文本进「粘贴的文本」，然后 `preventDefault()` 并 `stopPropagation()`，CHAT 的 `document` 监听收不到。较短的文本照常粘进输入框，也阻止冒泡。焦点在 ASK 外时，ASK 不处理，工作区行为不变。
- **拖放**：ASK 根元素监听 `dragenter`／`dragover`／`dragleave`／`drop`。数据含 `Files` 或历史拖拽类型（`names.historyDragType`）时阻止冒泡，并显示 ASK 自己的投放层；指针移出窗口后，由工作区原有计数接管。
- **历史图拖入**：把绘图历史里的图拖进 ASK，会在输入框插入它的 `#hN` 引用，不复制像素、不作为附件。
- **不接收的形态**：静默圆形、运行胶囊、结果卡、已写入胶囊不接收粘贴和拖放，拖到上面按原工作区处理。
- **模态与编辑器**：模态 dialog 打开时 ASK 不处理，与 CHAT 一致；编辑器打开时 ASK 已隐藏。
- **不改工作区**：CHAT 与绘图代码不改。浏览器测试须证明：投放层不会残留，绘图导入面板不会被 ASK 内的投放触发。若阻止冒泡仍出现残留，才在对应工作区加一行「事件来自 ASK 根元素则跳过」的判断，并在实施记录里说明。

- 编辑重答：后续轮次删除、草稿回退、成功提示；人为改动 Prompt 后显示「回退失败」，不删除也不发送。
- 分支：新对话出现在菜单，原对话不变，分支首个请求的历史前缀与来源一致。
- 撤销栈：只有栈顶可回退，回退后上一份可回退，恢复可用条件，⌘Z 只作用于栈顶。
- 附件：CHAT 激活时在 ASK 内粘贴图片，ASK 托盘加一、CHAT 附件数不变；在 CHAT 输入框粘贴归 CHAT；绘图页拖进 ASK 不打开导入面板；拖出后投放层不残留；不支持的格式弹出提示；请求体内图片不超过 1 MB、文本在 `<data>` 中；发送图片关闭时没有图片块。
- 资源：删除对话后 `URL.revokeObjectURL` 被调用，登记表清空；反复开关菜单／文本预览／编辑后监听器回到基线，卸载后窗口与消息观察器断开；真实拖动不触发窗口或消息组件重渲染。
- 所有新流程中生图、编辑、放大、报价、扣费和 CHAT 发送请求为零。
- 320／390／768／1440px 截图：长草稿、多轮加检查点、编辑中、对话菜单、附件、空对话页，存入 `.local/ask/`，不提交。

不以模拟回复评价看图或改写质量；真实供应商的图片大小限制、CORS 与费用仍属实测待办。

## 9. 风险与默认值

| 项目 | 默认值或处理 |
| --- | --- |
| 请求体大小 | 每条最多 4 张、每张不超过 1 MB；中转若限制请求体，显示上游原文，不自动重试，由用户移除图片或关闭发送图片 |
| 非视觉模型 | 「发送图片给模型」仍是用户对模型能力的声明；关闭后只发参数 |
| 文本重复计费 | 文本附件每轮随历史重发；估算如实显示，不做隐式脱水 |
| HEIC | 仅在浏览器能解码时接受（主要是 Safari） |
| 内存 | 对话 20 个与附件原文件合计 200 MB：超出直接拦截提示；撤销栈按 §4.3 保留最近 50 条，超出只释放最早的完整撤销记录，保留检查点展示 |
| 剪贴板 | 回环地址与 HTTPS 可用；失败时提示「复制失败」 |

以上数值都集中定义为常量，调整时同步本文。
