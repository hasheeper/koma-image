## 1. 已批准的入口

用户看过桌面与手机截图方案后确认「按此方案接入」：

- 图片信息栏右侧「Ask」打开抽屉并绑定当前图；参数行在 Seed 前显示稳定 ID，可复制。
- 历史／收藏缩略图显示 ID。底部「对比」进入显式选择模式，勾选两张后「Ask Diff」可用；勾选不切换正在查看的图片。
- 错误卡「Ask Why」预填问题。上述入口都不自动发送。
- 回复中的 ID 支持悬停／键盘焦点预览和点击定位；手机定位后收起抽屉以露出画布。删除的图片引用停用。
- `search_history` 多命中时显示最多 3 张候选缩略图，用户点选后绑定锚点并预填下一问，仍由用户发送。

2026-10-23 用户批准入口样式调整：「Ask」去掉底框，作为操作栏首组（舞台宽度 ≤640px 时回到标题行右侧）；缩略图 ID 改用收藏星标同款底色，移到左下角，当前图为强调色；「对比」改为图标开关，与清空历史同列于图片栏底部右侧，按下时显示强调底色，再次点击退出。行为不变。

UI 沿用当前侧栏与抽屉，不重编号、不移动抽屉位置。手机历史栏内原有按钮宽度与隐藏规则会覆盖新增对比操作，已在 `ImageLibrary.vue` 内收窄样式，覆盖 320／390／768px 菜单内部边界；桌面折叠图片栏保留原有短条形态。

## 2. 只读工具与摘要

| 工具 | 实现 |
| --- | --- |
| `get_state` | 读取最新状态，作为工具结果追加在队尾，不改本轮初始快照 |
| `search_history` | 按关键词、变化字段、Prompt 相似度检索本轮历史／收藏快照 |
| `get_meta` | 当前绘图与编辑记录的参数，包括批次、随机种子、缓存、优化、强度／噪声等；保留实际发送 Prompt 与请求尺寸差异，不带路由或二进制输入 |
| `diff_meta` | 参数变化及 Prompt 增删差异 |
| `view_image` | `glance`／`look`／`crop`，只读取已有 Blob |
| `view_sheet` | 复用 `native/comparison.ts` 的网格与 contain 绘制，2–6 张、带稳定 ID |
| `search_tags` | 查询本页词典已经加载的内存缓存，不触发网络请求，最多 20 条 |

工具只接收只读端口，不持有生成、写表单、CHAT 发送或报价接口。工具外部文本包在 `<data>` 中并转义 `<`。每轮复制参数并保留 Blob 引用，历史删除和新增不会改变该轮工具输入；新增图下一轮才可查询。会话、Blob、图片缓存和控制器均不进入深层 reactive。

L0 升为 v2，包含固定 `history_cursor`：

- **模式 A**：指定锚点时提供锚点全量参数；同 Prompt 为 T1 参数差异；词级 Jaccard 相似度 ≥90% 为 T2，包含 Prompt 差异；其余进入冷区。
- **模式 B**：无锚点时最近 3 张提供全量参数及 Prompt 差异，第 4–15 张提供相对前一张旧图的差异，其余进入冷区。
- **简化冷区聚类**：按连续记录的 Prompt、Negative、模型和尺寸分组，保留 ID、数量、120 字 Prompt 摘要和变化范围。阈值与摘要效果需真实会话数据评估。

词典目前只有远程查询，没有随应用分发的完整离线词库。因此本阶段以已有查询结果建立最多 4000 条的本页内存索引；无命中会明确提示缓存未命中，不把它当成无效标签。分类 1 同时供 Prompt 分区识别画师。刷新后重建，未新增持久化。

## 3. 视觉、预算与隐私

- `glance` 长边不超过 384px，`look` 与 `crop` 不超过 768px，小图不放大；优先 WebP 质量 0.82，浏览器不支持 WebP 编码时保留实际 PNG 类型。
- 裁切使用 `[x,y,w,h]` 的 0–100 百分比，四边各扩原区域的 25%，裁到图像边界；同图先成功调用过 `glance`／`look` 才允许裁切。失败／停止轮次不提交已看图状态。
- 每轮严格限制 4 次、1,500,000 像素、400,000 个压缩图片字节；缓存命中照样计入预算，超限返回工具错误，不自动降画质。字节数指图片编码字节，不含 Base64 与请求 JSON 开销。
- 缓存最多 16 个派生结果，按图片 ID、Blob 身份、规格和区域区分，淘汰最久未用项；取消／异常路径关闭 ImageBitmap，应用销毁清缓存。预览借用绘图服务缩略图 URL，不重复创建 Blob URL。
- 只保留最近 3 轮的图片块。发送新轮前，较早图片替换为含 ID、规格、字节量的文字占位；工具调用 ID 与界面轨迹保持。
- 关闭「发送图片给模型」或点击「仅发元数据重试」时，当前视觉工具拒绝执行，历史消息中的图片也全部替换为文字占位。
- OpenAI 工具图片经 user `image_url` 发送；Anthropic 在 `tool_result` 内放 base64 图片。图片来源标记只留本地，不进入协议载荷。

ASK 不调用生图、编辑、放大、报价、余额或扣费接口，不发送 CHAT 消息，不参与生成锁。现有工作区增加入口与 ID；草稿写入仍留到 A2。

## 6. 工具失败原因补齐

用户截图出现「未能查看 #h2」，后面同一图片又成功 `look`。旧实现只把错误内容回传给模型，`tool-end` 与界面轨迹只保留失败状态，导致用户无法判断原因。截图没有错误原文，不能据此断言当次一定是裁切前置条件、坐标还是预算问题。

用合成图片复现相同调用顺序：先在已提交轮次 `look #h1`，再 `view_sheet #h1/#h2`、参数对比、`crop #h2`、`crop #h1`、`look #h2`。只有缺少单图全览的 `crop #h2` 失败，拼图不满足该前置条件。工具说明与系统提示已明确「同一 ID 先成功单图全览，再裁切」，不把拼图当成单图全览，不自动补发图片，也不放宽预算。

`tool-end` 现在携带实际失败原因，经服务保留到对应轨迹并在下一行显示；与模型收到的错误文字一致。抛出异常、工具显式报错、未知工具均有单元覆盖；浏览器覆盖上述调用顺序、错误坐标、失败不附带像素、后续读取成功及四宽原因换行。验证仅使用模拟推理和合成图片，原截图中的真实图片未发送。
