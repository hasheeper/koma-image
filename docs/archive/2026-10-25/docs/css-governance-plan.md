# 字体与 CSS 治理计划

2026-10-20。状态：G0–G4 已实施并完成本地验收，见[字体记录](font-style-governance.md)、[样式归属记录](style-ownership.md)与[检查收口记录](style-checks.md)。用户后续已授权本轮提交与 Git 推送；本轮不包含 Pages 部署。

## 目标与边界

让字体配置有唯一来源、样式有明确归属、修改能定位到负责的文件，同时保持当前界面的字体、尺寸、间距、色彩、布局、动效和业务行为。

治理继续使用原生 CSS、CSS 自定义属性和 Vue 已有的样式能力。不引入 UI 库、Tailwind、CSS-in-JS 或 Sass；不以文件数、代码行数、GitHub 语言占比作为完成指标。不同时重做主题、统一断点或改名全部 DOM 类。

报价、分流、`max_cost`、额度护栏、取消、并发和存储不在本轮改动范围。Vue 与原生高频驱动的所有权约定继续有效，见[架构规范](architecture.md)。

## 当前基线

以下为 G0 固定的治理前工作区统计，包含当时尚未发布的调整，不代表线上版本。字节数为未压缩文件大小；下列问题与阶段内容保留为治理依据，已实施情况见记录。

| 范围 | 文件数 | 字节数 | 现状 |
| --- | ---: | ---: | --- |
| 字体声明 | 3 | 300,171 | `public/fonts/*/index.css` |
| 应用样式 | 8 | 228,970 | 7 份 `public/styles/*.css` 与 `src/app/shell.css` |
| 合计 | 11 | 529,141 | 字体声明约占 57% |
| 公共 `ui.css` | 1 | 94,593 | 混合变量、基础规则、控件、工作区和全局反馈 |

G0 基线的 33 个 Vue 组件均无 `<style>` 块。当时界面样式主要依赖外部全局 CSS，并不是每个组件都在重复声明字体。

具体问题：

- 字体已有 `--sans`、`--mono`、`--brand` 三个角色，但字体资源配置、生成脚本、HTML 预加载和角色定义分散。
- 资源圆体有 101 个 Unicode 分片、三个静态字重，共 303 条 `@font-face`。大量声明是浏览器按需加载的必要数据；303 个 WOFF2 不会因声明存在就全部下载。`unicode-range` 也不能靠一个普通 CSS 变量消除三份字重描述。
- `build-rounded-font.py` 从 CSS 注释和 `unicode-range` 反读分片配置，甚至以自己的输出作为输入，缺少独立源配置。
- `styles.css` 首行再次导入已经由 HTML 加载的 `ui.css`。即便浏览器复用下载缓存，级联中仍存在重复的公共规则。
- Tag 自动补全、Tag 选择器等公共界面的规则位于绘图样式。需核实其他工作区是否靠重复规则补齐，不能直接移动或删除。
- 工作区依靠 `presentation.ts` 切换 `#style-image`、`#style-chat`、`#style-tags` 的 `media`；编辑、设置和备份样式持续加载。
- `shell.css` 修正词典背景下编辑器继承的 `--hist`。这是跨边界依赖的实例，不能当作无用补丁删除。

## 责任划分

| 类别 | 唯一负责处 | 规则 |
| --- | --- | --- |
| 字体资源及字重、分片、预加载清单 | `config/fonts.json` 与分片数据 | 配置维护，CSS 自动生成 |
| 字体用途 | 同一字体配置中的角色映射 | 生成 `--sans`、`--mono`、`--brand`，组件只消费角色 |
| 色彩、字号、字重、间距、圆角、层级、动效变量 | `public/styles/tokens.css` | 保留现有变量名和值，工作区只覆盖自己的上下文变量 |
| reset、默认排版、表单继承、基础可访问性 | `public/styles/base.css` | 少量明确的全局规则 |
| 按钮、输入框、图标、勾选、分段、滑杆 | `public/styles/controls.css` | 跨组件复用的控件规则 |
| 提示词、高亮、公共弹层、Toast 等共享组合 | `public/styles/ui.css` 与对应共享组件 | 按功能归属；逐段整理，不再加入页面专属布局 |
| 绘图／对话／词典布局 | 各自工作区 CSS | 保留现有独立加载与 `media` 开关 |
| 编辑／设置／备份 | 覆盖层 CSS、对应组件 | 不依赖当前工作区启用了哪份 CSS |
| 组件私有细节 | 对应 `.vue` 的 `<style scoped>` | 先迁移归属清晰的叶子组件，不全面强制 scoped |
| 拖拽坐标、画布尺寸、进度与其他实时数值 | 现有原生驱动／模板绑定 | 可继续写受委托的样式属性，不转入 Vue 高频响应链 |

目录位置本身不是治理目标。此轮保留稳定的静态样式入口，避免为整理目录再建设一套 CSS 打包系统。

## G1：字体配置集中管理（优先实施）

目标：开发者维护清单，浏览器继续消费生成后的字体 CSS；减少人工维护，不以删除分片换取表面上的代码减少。

G1 已按以下结构实施：

```text
config/fonts.json                    字体族、资源、字重、角色、预加载与许可路径
config/font-ranges/koma-rounded.json  101 份范围，每份仅维护一次
scripts/build-font-css.mjs            从配置生成声明；仅依赖 Node
scripts/build-rounded-font.py         离线生成字体二进制，读取同一清单／范围
public/fonts/index.css               统一生成入口，含三族声明及三个字体角色
public/fonts/<family>/files/          沿用现有 WOFF2 文件与路径
public/fonts/<family>/LICENSE        沿用现有许可
```

实施内容：

- 从现有声明提取配置，保留所有字体族的覆盖、样式、`font-display` 和字重描述符。资源圆体继续为 400／500／700，600 继续使用 Bold；不改成可变字体。
- 生成一个字体 CSS 入口，替换 HTML 中三个字体 CSS 引用；生成时正确重写相对 URL。旧声明文件在验证通过后删除，避免两份来源。
- HTML 保留三个显式预加载项，由检查命令核对其与清单一致，不为几行预加载另造 HTML 模板生成器。
- 三个字体角色从同一清单生成；字号、字重等设计变量仍由手写 `tokens.css` 管理。
- 普通构建只生成声明，不重新切字体。Python／TTF／fontTools 只在主动更新字体二进制时需要，现有 WOFF2 保持原字节。
- 离线字体脚本取消从生成 CSS 反读配置；生成失败不能先清空现有字体目录，先在临时目录完成再替换。
- 保留圆点 `·`、乘号 `×` 的比例字形修改、字体内部命名和第三方许可。修正现有“所有字重来自可变字体”等过时注释。
- 生成文件标注来源与重建命令；可在 `.gitattributes` 标记生成 CSS，便于评审。统计显示变化不计作治理成果。

验收：声明语义、角色映射、预加载及现有字体哈希一致；根路径／子路径无字体 404，中文、英文、数字及 `· ×` 正常。构建不要求本机存在原始 TTF，不新增外部字体请求。

## G2：拆分基础层，保留级联顺序

已完成，实际入口与验证见[样式归属记录](style-ownership.md)。以下保留实施要求。

从 `ui.css` 按现有连续顺序提取 `tokens.css`、`base.css`、`controls.css`，其余仍由 `ui.css` 加载。先只移动，不顺便重写值、选择器或格式化全部文件。

HTML 的显式顺序调整为：

```text
字体声明与字体角色
→ tokens → base → controls → ui
→ image／chat／tags（仍按 media 启停）
→ editor → settings → transfer
→ 现有 shell／组件构建样式
```

- 基础层直接使用顺序明确的 `<link>`，不增加多层运行时 `@import` 链，也不增加新的 CSS 编译工具。
- 确认无独立入口依赖后，移除 `styles.css` 对 `ui.css` 的重复导入；每个公共入口只参与一次级联。
- `#style-*` 的 ID、开关语义和工作区组合不变，词典目前同时启用绘图样式的行为此时也不改变。
- `body > .topbar` 等结构选择器原样保留。不能加包装容器来方便组织 CSS。
- 不引入 `@layer`：已有未分层规则会影响优先级，不能与文件拆分同时处理。

验收：提取后的规则顺序与声明保持一致；四视口布局、切页保活和工作区隔离通过。构建产物仍保留可用的 `#style-*` 开关，不因工具合并入口而失效。

## G3：收回组件归属，消除隐式依赖

已完成本轮归属整理，保留的全局结构与词典布局依赖已明确记录，见[样式归属记录](style-ownership.md)。以下保留实施要求。

这一阶段按功能小批推进，每批只调整一个区域：

1. 先核对公共消费者，将 Tag 自动补全／选择器规则归到公共宿主，保证从绘图、对话、词典和编辑打开时一致。移动与删除旧副本在同一批完成。
2. 再整理 Toast、确认弹窗等归属清晰的组件私有规则；适合的叶子组件采用 `<style scoped>`。通用按钮、输入框与图标基础规则继续共享。
3. 最后处理提示词高亮、结果图片、图片栏、编辑画布及工作区布局等高风险区域；明确共享部分与工作区覆盖，减少互相借样式。
4. 追踪 `--hist` 等继承依赖；先记录实际消费者，再在独立改动中处理外壳补丁。不能在整个项目全局替换变量名。

迁移规则：

- scoped 会增加选择器约束，并改变样式进入构建产物的位置。迁移前查清外部覆盖，迁移后检查最终计算样式；不假定搬入 SFC 就能保持原效果。
- Teleport 的宿主规则不能只依赖原父级祖先链；原生 dialog／popover 顶层行为与焦点、滚动语义保持。层级不能只看 `z-index` 数字。
- 高亮镜像的 `v-html` 后代不自动带 scoped 属性，必要时使用局部且明确的 `:deep()`；镜像与 textarea 的字号、行高、字距、内边距和滚动必须一致。
- 动态类、伪元素、媒体／容器查询、JS 引用的类名和变量均纳入使用判断，不能按“模板搜不到”删除 CSS。
- 不统一禁用内联样式。原生蒙版、分栏拖拽、波浪、光标和实时几何值继续由已有驱动负责，静态外观才归入 CSS。
- 不再新增“文件末尾覆盖同一选择器”的补丁。新变更落回负责规则；重复声明只有在所有相关状态验证后才合并。

验收：一个功能在所有使用位置表现一致，规则只有明确的一处来源；共享改动不影响隐藏工作区或从其他工作区打开的覆盖层。

## G4：建立轻量约束与收尾

已完成，检查入口、必要例外与依赖限制见[检查收口记录](style-checks.md)。以下保留实施要求。

- 引入精确锁定版本的 Stylelint 与 Vue 样式解析支持，检查手写 CSS／SFC；字体生成输出不套人工排版规则，单独校验生成一致性与资源引用。
- 首批规则只约束语法错误、无效属性／值、意外重复声明等实际问题。全局上下文中的合法重复选择器不一刀切判错。
- 字体族只允许在字体配置中维护；业务样式消费三个角色。共享色彩和字号优先使用现有变量，不重复发明同义变量。
- 不把每个尺寸都变成 token。图片几何、光学修正、类别颜色和组件局部数值可保留；只有跨组件复用且语义相同的值才集中。
- 新增 `!important` 必须有具体原因；已有 `[hidden]` 与减少动效等行为性规则逐条保留或核实，不能为了清零改变行为。
- 在现有 `npm run check`／CI 中接入样式检查与字体清单检查，不建设额外测试平台。现有可接受的写法先由配置兼容；新增规则随对应范围治理再收紧，避免全仓自动修复。
- 更新字体生成说明、样式入口与组件归属文档。最终报告列出剩余的全局依赖和必要例外，未完成项不标成完成。

验收：普通构建、CI 和本地开发都能使用同一配置；新增错误可被阻止，开发者能从组件或入口找到负责样式，无需全文追加覆盖规则。

## 验证与回退

G1–G4 每批执行 `npm run check`，配合受影响的现有浏览器用例；只有字体／样式入口、跨工作区依赖或生命周期发生变化时，增加对应的必要断言。文档计划本身不需要运行应用测试。

视口仍只有 **320／390／768／1440px**；这是验证视口，不是把实际 CSS 断点改成这四个值。复用现有 shell 四视口用例与有限的代表性截图，不恢复多断点像素矩阵。

重点检查：

- 字体加载完成后的换行、按钮尺寸、等宽数字及高亮镜像对齐；保留 `font-synthesis: none`。
- 绘图、对话、词典切换，手机侧栏／菜单与 Teleport 前后样式；无意外整页横向滚动。
- 设置、Key 弹窗、备份、编辑从三个工作区分别打开；验证图标填充、输入、弹层层级与滚动。
- 空白、加载、成功、错误、禁用、选中、焦点及减少动效等相关状态，用合成数据／模拟请求驱动。
- 触及高频宿主时复用“指针事件不触发 Vue 重渲染、反复开关无资源泄漏”的检查，不增加帧率跑分。
- 入口或资源路径变化后检查生产构建的根路径／子路径；发布包的许可和资源引用继续完整，不包含私有信息。

每阶段单独形成可回退的提交，不将其与已有功能混在一起；出现偏差先回退该批样式改动，不通过叠加全局补丁掩盖。不涉及用户数据或 schema 回退。推送与 Pages 发布仍按项目约定另行取得用户授权。
