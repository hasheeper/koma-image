# 全局图片 ID 与资产标识重构规划

日期：2026-10-28。状态：**已授权实施的 ID1–ID4 设计归档**。本文保留审阅时的目标、边界和验收矩阵；现行实现见[图片身份与引用](../../engineering/image-identity.md)，本地验证记录另列，不构成推送或部署授权。

现行行为仍由[架构](../../architecture.md)、[业务契约](../../business-contracts.md)、[ASK 维护入口](../../ask/README.md)及各工作区专题维护。用户已授权按 ID1 → ID2 → ID3 → ID4 实施；当时的勘探和目标表保留作设计背景，实际行为以现行专题为准。

## 1. 目标与现状

统一 IMAGE、HOME 定稿、CHAT、EDIT 和 ASK 附件的图片身份，解决跨工作区流转、收藏编号跨刷新、局部短码串台和视觉状态割裂，同时保留现有存储、生成记录与资源所有权。

| 范围 | 勘探所得现状 | 重构目标 |
| --- | --- | --- |
| 历史 `#h` | ASK 注册表已经递增分配，同一作用域内删图不重排；编号随 ASK 作用域保存／恢复 | 统一使用应用本页注册表，不因切换 ASK 会话重建当前图片编号 |
| 收藏 `#f` | 同一注册表内不重排；收藏记录未保存固定序号，刷新后会重新登记 | 收藏库保存固定 `favSeq`、计数器与库身份 |
| 图片归并 | IMAGE 历史与收藏共用记录 ID，图片库已合并别名；CHAT 原图资产已有 SHA-256 身份，但 ASK、收藏的包装记录使用不同 ID | 已知流转继承同一实体，独立导入的相同原图字节可关联到同一实体 |
| EDIT | 已有独立画板、稳定内部画板／版本 ID、原始出处及版本父子关系 | 完整码 `#e板号.版本`、本板简写 `#e版本`、同组字母尾缀；结果归 EDIT |
| HOME／Slate | 封面和交付已有稳定记录／资产指针，未使用显示序号作为主键 | 保留原指针及独立持久资产，补充实体关联与可读血统 |
| ASK 视觉 | 派生编码缓存使用图片 ID 与 Blob 对象身份；全图查看资格使用图片 ID | 按实体共享派生编码和已看资格，按实际发送保留视觉预算 |

上一轮尚未收口的本地 EDIT 编号试作不是本稿基线规范：`eb2:#e3.1` 及“最后一个数字点号表示去背景变体”的临时语法由本稿替代，不作为长期兼容格式。已有透明背景和 HOME 样式改动保持独立，不因本次身份重构顺带调整。

## 2. 范围与不变项

本稿包含统一身份、收藏序号、五类短码、冻结解析、旧 Koma 字段兼容、视觉共享、状态／协议、备份及相应 UI 角标和输入提示。

- 保留现有数据库与 Blob 所有权，不将五个区域搬进一个新的全局图片仓库，不复制原图建立“实体库”。
- 现有 `record.id`、CHAT `assetId`、编辑画板／版本 ID、Slate `assetId` 继续有效；`entity_key` 是新增关联身份，不替换这些主键。
- 不改变报价、扣费、付费确认、生成分流、任务锁、取消、重试、图像参数和 Photopea 分层／蒙版行为。
- ASK 仍是只读感知与草稿提议，不获得编辑／生图／放大执行权；本稿不打开 EDIT 内 ASK 窗口，不增加 EDIT 参数草稿。
- EDIT 结果留在编辑画板，不能为了取得编号、收藏或 Slate 交付而自动插入 IMAGE 历史。
- `#h`、编辑画板及版本仍只在本页存活；收藏／CHAT／已收藏 ASK／Slate 沿原路径持久化。编号升级不提供 EDIT 跨刷新恢复或 PSD 持久化。
- 本次兼容仅针对现有 Koma 字段与 Koma v2 备份，不恢复已取消的旧应用迁移、旧库探测、转换器或迁移 UI。

## 3. 身份、记录和别名

对外仍采用“实体身份 + 展示短码”两层。内部复用现有记录承载操作参数，避免图片内容归并后丢失生成事件。

### 3.1 图片实体

本稿建议 `entity_key` 使用原图 Blob 文件字节的 SHA-256，规范为 `sha256:<64 位小写十六进制>`。CHAT 已有相同算法的资产 ID 可直接适配；明确未改字节的跨区传递直接继承已验证的键。

- 指纹仅针对实际保存的原图，不针对缩略图、768px 预览、拼图或视觉编码。
- 相同原图字节共享实体；重新编码、改元数据或方向归一化后文件字节不同，属于不同实体，必要时保留已知来源关系。
- 不解码所有图片做像素级去重，不按感知哈希、外观、文件名或 Prompt 猜测同图。
- Photopea 原有像素未变检测继续用于避免制造无效手动版本，不因导出 PNG 字节变化就强行新增版本。
- 新增原图在发布到业务状态前取得身份；已有 Koma 记录受控补齐、缓存计算结果，不在每次渲染或摘要更新时重复哈希。相应图片身份未就绪时，使用它的操作等待就绪，不声明已经完成同图归并。
- 异步哈希遵守任务取消、来源冻结和数据租约；不在已开启的 IndexedDB 事务里等待图片哈希。导入外部文件时验证字节，不信任其自报的实体键。

```ts
// 规划结构，实施时按现有类型归属落位。
interface ImageEntity {
  entity_key: string;
  width: number;
  height: number;
}
```

实体索引只关联原存储中的可用图片，不拥有一份额外 Blob。相同实体的多个 Blob 实例可以共享派生编码，仍由各自服务释放原图及 Object URL。

### 3.2 操作记录与血统

生成参数、Seed、时间、来源工作区、工具及父子关系归具体记录所有。同一份图片字节被两个独立操作产出时，可以共享实体，但两条操作记录及其参数不合并覆盖。

```ts
interface ImageLineage {
  parent_record_id?: string;
  parent_entity_key?: string;
  parent_ref?: ImageTagBinding;
  via: "image" | "chat" | "edit:img2img" | "edit:inpaint"
    | "edit:enhance" | "edit:upscale" | "edit:director"
    | "edit:photopea" | "upload";
  tool_detail?: string; // 如 bg-removal:masked、focused-inpaint
}
```

- 原图从 `#h1` 进入 EDIT 成为 `#e1.1`，仅增加画板内版本位置与别名；已知源记录继续指向原记录，不制造新的生成事件或实体自环。
- 新衍生版本保存父记录／父实体，原始 IMAGE 画板或 CHAT 会话／轮次／资产身份继续保留。
- 多条记录碰巧共享实体时，血统关系仍按记录解释；不能从“相同字节”推断生成来源。
- `parent_tag`、`origin` 等文字是来源展示快照，附作用域；解析和交付不依赖它们重新查找父图。
- 父图已经移除时，保留已知出处和工具信息，不伪造父图仍可打开。`get_meta` 读取所引用记录的参数，不能换用同实体另一条记录的配方。

### 3.3 展示引用

```ts
interface ImageTagBinding {
  tag: string;
  entity_key: string;
  record_id: string;
  scope: {
    kind: "page" | "favorites" | "chat" | "ask";
    id: string;
    board_id?: string;
    turn_id?: string;
    version_id?: string;
    asset_id?: string;
  };
}

interface ImageEntityRef {
  entity_key: string;
  tags: string[];
  primary_tag: string;
}
```

`ImageEntityRef` 是当前可访问范围的投影，不在实体上永久保存跨作用域的全局 `tags` 数组。同一实体可能有多个参数不同的记录，每个标签必须有自己的 `ImageTagBinding`。

`primary_tag` 按位置决定：IMAGE 历史优先 `#h`，HOME 定稿优先 `#f`，EDIT 版本栏优先本板简写。限定来源的检索使用该来源标签；不能因为同实体有一个收藏就把所有 UI 都改成 `#f`。

## 4. 五类短码与分配

所有新展示短码最多一个数字点号；只有既有 CHAT 三段式作为输入兼容保留。编号空洞合法，删除、淘汰、排序与重命名均不补洞。

| 类别 | 展示／完整码 | 简写或兼容 | 分配与寿命 |
| --- | --- | --- | --- |
| IMAGE 历史 | `#h12` | 相同 | 本页递增；当前保留成员才是有效历史标签；刷新重置 |
| HOME／收藏 | `#f3` | 相同 | 当前收藏库持久递增；删除不重用；刷新保持 |
| EDIT | `#e1.3`、`#e1.3a` | 当前板 `#e3`、`#e3a` | 板号本页递增，板内逻辑版本递增；关闭不重用 |
| CHAT | `#c2.1`、`#c2.1a` | 兼容 `#c2.1.1` | 会话及具体轮次／版本／资产作用域；当前分支提供展示位置 |
| ASK 附件 | `#a1` | 相同 | ASK 会话作用域内递增；收藏会话恢复计数器，不复用已释放号码 |

### 4.1 EDIT 版本与多图

- 画板保存稳定 `id` 与数字 `boardSeq`；空板也分配板号，关闭后不回收。对外导出 `board_seq`，不把 UUID 印进角标。
- 每板原图为逻辑版本 1；后续实际生成／回传图片按到达顺序取得 `versionSeq`。删除版本不回退计数器，后台结果使用发起板的计数器。
- 去背景三图共享一次逻辑版本：`a=masked`、`b=generated`、`c=blend`。其他单图工具结果不加尾缀。
- `#e1.3`／本板 `#e3` 指向该组当前激活的变体，默认 `a`；整轮冻结后不跟随用户切换。
- 完整码中点号前永远是板号，后面永远是逻辑版本号。`#e3.1` 只能解释为画板 3 的原图，不能解释为本板版本 3 的第一张变体。
- 本次建议保持现有每板最多 30 张原图资源的内存边界，三图组占三张，不扩大为 30 组三图；逻辑编号与容量计数分开。原始底图、当前底图及查看组受保护，淘汰／移除按组释放，号码不回收。
- 初始底图受保护，后续设为底图不改变谁是 `#e1`。只改蒙版、切查看图或改变参数不产生新版本。

### 4.2 CHAT 多图与分支

- 新显示使用 `#c轮次.版本a/b/c…`；单图保持无尾缀。
- 旧 `.1/.2/.3` 与新 `a/b/c` 指向同一张资产，不制造新记录。无尾缀沿用当前行为，指该版本第一张图片，不额外引入变体选择状态。
- 字母映射与实际输出顺序一致；解析器只接受快照中真实存在的成员，不能仅凭正则推测图存在。单字母范围之外的现有输出仍保留旧数字别名，不因格式升级丢图；不扩张供应商输出数量能力。
- 保持当前分支的轮次显示习惯；每次引用绑定 `conversationId/turnId/versionId/assetId`。同一会话切分支后，旧回复和旧草稿不得按新祖先链重新解释 `#c2.1`。

## 5. 作用域与冻结解析

| 作用域 | 覆盖内容 | 改变时机 |
| --- | --- | --- |
| `picture_scope_id` | 本页 `#h`、完整 `#e` 与编辑板号空间 | 应用页面重新初始化；切板、切工作区、切 ASK 会话不改变 |
| `favorites_scope_id` | 持久 `#f` 编号空间 | 新建收藏库或显式重建库；普通刷新、删收藏、正常合并导入不改变 |
| CHAT 引用上下文 | 会话稳定 ID、分支及轮次／版本／资产映射 | 新一轮开始读取当前上下文；已冻结引用不变 |
| ASK 附件作用域 | 当前 ASK 会话的附件号码 | 新会话创建；收藏恢复沿用该会话作用域 |

解析顺序：校验完整语法与引用版本 → 校验作用域 → 以本轮冻结的活动板补全 EDIT 简写 → 在冻结别名表查找 → 得到具体记录及实体。

- 工具、草稿、回复预览、候选卡、定位、账本、压缩和归档使用同一引用管线。正则、Markdown 行内码、普通文本识别共享语法定义。
- 不把合法前缀从非法编号中截出来；句末标点不属于编号。覆盖 `#e1.3a`、旧 `#c2.1.1`、句末 `#c2.1.` 及非法多段编号等情况。
- 工具整轮使用冻结图片库。`get_state(scope="latest")` 可读新状态，但不重绑本轮标签、不将新图纳入本轮库、不替换草稿基底。
- 不在冻结库中的当前输入返回不可用；不跨会话猜测同名 `#c/#a`，也不回退到另一板同名 `#e2`。
- 保存的回复引用额外携带具体绑定。刷新后旧页标签已失效时，不重解为新图；若同一实体仍在收藏等允许来源可读，可以显示准确旧图并标明原标签已失效。缺失的原记录参数不能用其他同图记录补造。
- 只保存标签文字、缺乏稳定记录映射的旧记忆不具有定位权；可作文字上下文，不能据此执行绑图或恢复参数。

## 6. 收藏编号与 Koma 字段兼容

### 6.1 持久结构和原子分配

在现有收藏库中增加小型元数据与编号登记；不增加第二份收藏图片库。

```ts
interface FavoriteIdentityState {
  libraryId: string;
  nextFavSeq: number; // 下一个可分配值；新库从 1 开始
}
// FavoriteRecord 增加 favSeq、entity_key 及相应记录血统字段。
// 最小登记保留 seq → recordId/entity_key 的关系及 active/retired 状态，不保存 Blob。
```

分配固定为“取 `nextFavSeq`，成功提交时计数器加 1”。编号登记、收藏记录和计数器在同库同一 readwrite 事务内提交，写入走 `data.write`；不能先更新 UI 或靠 localStorage 自增。

- 失败／中断不点亮收藏，不留下部分记录；多标签页由 IndexedDB 事务串行化分配，BroadcastChannel 只通知重读。
- 取消收藏删除图片收藏载荷、停用标签，但保留最小号码登记。剩余 `#fN` 不变，删除全部收藏也不重置计数器。
- 现有即时撤销恢复原记录和原 `favSeq`。撤销窗口结束后重新收藏分配新号；旧号保持停用，不转给别的图。
- 已知同一源记录从历史进入 EDIT 原图后再收藏，复用已有收藏关系，不因工作区包装制造重复定稿。不同生成记录即使字节相同，仍保留各自参数；不顺带按实体去删除用户已有的重复收藏。
- 数据库版本只为必要存储／索引递增；计数器、登记和实际有效 `favSeq` 的一致性作为启动及导入校验的一部分。

### 6.2 现有 Koma 收藏与 ASK 引用

缺失 `favSeq` 的现有 Koma 收藏一次性补齐。优先使用可唯一确认的当前编号快照；其余按原注册顺序的稳定依据 `favoritedAt/createdAt/id` 分配，不按当前 UI 反向排序临时计算。已存在合法固定编号的记录不重排，计数器超过全部已登记号码。

收藏 ASK 的旧 `IdSnapshot` 继续作为该历史上下文的映射，不把其中的旧 `#f3` 自动改认成新全局 `#f3`。对话、消息、工具结果、记忆和归档正文不全局替换编号字符串；新写入的引用保存结构化绑定与格式版本。

旧 Koma 缺少 `entity_key` 的记录通过原图取得身份；没有字节、只有历史元数据时保持不可看图。普通备份不因此携带原本不导出的 ASK、编辑现场或页内历史。

### 6.3 备份合并与空库恢复

现有备份执行合并导入，继续保留该模式，不增加覆盖库流程或新的恢复弹窗。

- 本稿建议保留 Koma v2 备份封装，增加受校验的可选图片身份版本、收藏库元数据、固定序号／最小登记、实体及血统字段。缺失这些字段时走本节的 Koma 字段补齐；不支持的显式身份版本拒绝导入，不能静默忽略。
- 导入先验证文件字节与实体键，再按既有记录冲突规则保留／复制记录；原图库现有编号始终不变。
- 同一收藏库来源且编号登记完全一致时，可以恢复原号；冲突不能覆盖本地登记，冲突副本取得新的本地编号。
- 不同收藏库合并时，新加入记录分配本地新号；外部 `#fN` 只作为带来源库身份的出处，不成为本地新别名。重复导入仍幂等。
- 目标为从未使用过的新空库时，可以继承合法备份的库身份、固定编号及计数器，保证完整恢复后的号码延续。已经用过、只是删空的库不视为新库。
- 备份中的 CHAT／收藏记录、实体和来源关联同步校验及调整；ASK 收藏不在普通备份里，不能声称已一起恢复旧对话引用。

## 7. ASK 图片库与视觉共享

图片库保留两种索引：实体索引用于像素与派生编码；引用索引用于来源成员、具体参数和操作记录。`#h1/#f1/#e1.1` 若来自同一原记录，合并为别名；不同参数记录即使同实体，也不能丢失版本、Diff 或检索结果。

- `get_meta/diff_meta/restore_partial` 使用标签绑定的记录参数；`view_image/view_sheet` 使用该实体的原图。
- `search_history` 增加 EDIT 来源；按实际成员判断 scope，不能将被移除的 `#h` 仅因同实体仍被收藏就继续列为历史。参数不同的操作记录不按实体盲目合并。
- 全图查看资格按 `entity_key` 保存到当前 ASK 会话的有效视觉记录，附件实际随请求发送时也登记原图实体。另一个 ASK 会话不能继承模型已经看过的状态。
- 编码缓存键包括实体、规格和裁切范围；同一实体重新从 IndexedDB 读取成不同 Blob 对象时，可以复用派生编码。别名变化不导致像素重编，图中文字标注仍使用本次请求标签。
- 同轮相同实体、相同规格／区域、已经成功发送的重复工具请求可返回紧凑已查看结果，避免再发送和再扣本地视觉预算；缓存像素存在但本轮尚未发送，不视为已发送。
- `glance → look`、新的 crop 或用户明确重新查看仍按实际发送计预算。跨轮不能仅凭缓存或已看资格省略重新发送；压缩／图像退化成文字占位后也不声称模型仍拥有原图像素。
- crop 的“已看全图”前置条件按实体共享，crop 本身继续消耗预算；拼图不登记单图全图资格。
- 现有图片开关、仅元数据模式、次数／像素／字节上限不放宽；失败、取消、未真正发送的视觉请求不制造成功已看记录。
- 原图、实体索引和编码缓存独立清理。实体无可用原图时，历史别名或记忆不能恢复它；删除一个别名不应误清仍被其他来源使用的实体。

## 8. 状态、外部协议与交付

### 8.1 `<workspace_state>` 与 Bridge 状态

新增身份／引用格式标记与作用域字段；EDIT 摘要包含活动板稳定 ID、`board_seq`、各板目录和轻量版本索引。版本索引展示完整码、本板简写、实体、父记录／出处、尺寸和工具／变体；不在初始状态展开所有编辑配方或自动发送全部图片。

```json
{
  "picture_ref_version": 2,
  "picture_scope_id": "page-scope",
  "favorites_scope_id": "favorite-library",
  "edit": {
    "active_board_id": "stable-board-id",
    "board_seq": 1,
    "read_only": true,
    "versions": [
      { "id": "#e1.1", "local_id": "#e1", "origin": "#h4" },
      { "id": "#e1.3a", "local_id": "#e3a", "variant": "masked" }
    ]
  }
}
```

示例只说明摘要命名，省略实体与绑定字段；所有来源文字仍需稳定引用支撑。身份与可读目录不替换 IMAGE 表单的 `base_hash`，外部草稿写入目标仍为 IMAGE。

- 新版投递引用 `#h/#e` 时验证页面作用域，引用 `#f` 时验证收藏库作用域。混合引用分别验证；完整 `#e板号.版本` 跨板有效，本板简写使用接收时冻结且显式匹配的活动板。
- 原有 `koma.bridge.live.v1`／草稿外层增加可识别的引用格式标记。旧格式投递继续执行原有保守作用域校验，不能无标记猜测新旧 `#f` 含义。
- 目录生成的 `PROTOCOL.md`、手动 JSON、公开外部 `SKILL.md` 与内部工具同步更新。外部不能仅凭一个实体键访问不在允许快照中的本机图片。
- EDIT 只读索引不触发 EDIT 草稿、自动生成或额外原图导出；原有选中图／最近历史预览边界保持。

### 8.2 Slate、HOME 与跨区流转

- Slate 的交付资产仍是独立持久副本，保留 `assetId/sourceId`，补充来源实体和记录绑定；原记录移除、刷新 EDIT 后，已交付成果仍可读。
- 支持 EDIT 原图／生成／Photopea 手动结果直接交付，无需先注册 `#h` 或强制收藏。应用草稿时检查实体、具体记录、元数据和来源有效性，不能用同实体的另一份参数替换。
- 不因统一身份扩大现有其他交付来源权限；CHAT 可以沿已有收藏 `#f` 路径交付，ASK 附件不顺带成为可绑图成果。
- HOME 封面保持创作线和收藏记录指针；实体只帮助识别图像，不让另一创作线的同图替换已选封面。展示副本不获得原图标签或视觉查看资格。
- 图片拖拽、进入 EDIT、CHAT 参考、ASK 原图附件与收藏在明确未改字节时传递实体；接收方仍建立原有工作区位置和来源记录。不能把实体字段传入供应商生成请求。

## 9. UI 范围

- IMAGE 历史角标仍为 `#h12`；已收藏时以紧凑星标／`#f3` 关联，不增加常驻来源段落。
- HOME 定稿使用固定 `#f`；来源链在已有提示／详情中查看，含页内来源时保留作用域快照，不能把旧页的 `#h12` 当成当前页链接。
- EDIT 版本栏显示本板 `#e1/#e2/#e3a`，三图切换可见明确变体；详情及复制引用使用完整码。不展示 `entity_key`、UUID 或底层登记状态。
- ASK 输入 `#` 时复用输入框附近的紧凑候选，按当前任务上下文优先排列；EDIT 上下文优先当前板版本，随后其他可访问来源。当前 EDIT 内 ASK 仍隐藏，不为补全新增入口。
- 候选显示标签、缩略图和必要来源；方向键选择、Enter／Tab 插入引用，Esc 关闭，中文输入法组合期间不抢键。插入不发送请求，不清空用户文字，也不改变原有补全关闭时的发送／草稿确认行为。
- 所有 UI 使用现有 tokens、角标、工具状态与预览，不新增任务面板、资料弹窗或解释协议的长文案。
