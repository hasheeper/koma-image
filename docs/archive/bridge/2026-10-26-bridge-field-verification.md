## 方法与范围

使用 macOS 上实际运行的 Microsoft Edge、独立本地来源 `127.0.0.1:3219` 和仓库忽略目录 `.local/bridge/field-test/.koma-bridge/`。原生选择器选择专用目录，并通过浏览器实际读写授权。没有为这轮实战注入目录句柄、伪造权限、访问 Vue 私有对象、调用应用内部服务或写入 IndexedDB。

外部 Agent 读取生成的 `PROTOCOL.md`、`state.live.json`、`refs/` 和任务文件，使用文件工具原子替换 `draft.inbox.json`／任务 JSON。界面操作承担用户角色：挂载、确认草稿、加入任务同步、生成、撤销／恢复、导出及刷新。这些是协议内明确的用户步骤；外部 Agent 没有自动应用草稿或自动生图端口。Koma 此处提供文件协同桥，并非直接的 MCP Server。

图像测试使用用户配置的标准图像供应商，正常界面报价为「免费 ×1」后执行一次 NAI V5 Full 生成。界面免费张数由 250 变为 249，媒体积分保持 5,000；未执行显示收费的生成。独立账号账单未另行核验。没有调用站内 ASK 文本推理，不能据此声称真实文本模型的任务拆解或 `read_ref` 已验收。预先准备的合成备份未导入，也未用于最终结果。

## 发现与处理

1. **已修复同步误报**：审阅外部任务文件时，本机提交先于 ASK 发布 applied 回执；同步驱动曾把仍待确认的同一文件当作冲突，旧错误又被复制到下一份草稿。现在普通交付对内容未变且仍 pending 的已知提议等待回执，再由扫描确认同步；新外部修改及要求立即交付的失败仍阻断。实际重新投递并确认后不再残留错误，增加了对应回归断言。
2. **已补齐协议说明**：明确 `rewrite`／`append` 与必须带唯一 anchor 的局部编辑区别；明确新任务的目录映射步骤，避免仅凭 `active_slate` 误认为完整任务文件已导出。
3. **当时发现的操作不顺**：先挂目录再创建任务，需要额外点击一次加入同步；任务 Diff 展示完整配方和任务前后文本，长配方下审阅较冗长。没有为验收绕开审阅步骤；用户随后确认优化范围，两点均已按下节收口。

结论：本次范围内的外部文件闭环可用，不依赖未公开写入接口。原生刷新权限恢复仅证明本机当前 Edge 环境；浏览器重启、撤销权限后重新授权、其他浏览器及同时竞争文件仍不能据此判定通过。直接文件编辑、交付和恢复已验证；不是所有断电／跨进程竞争情况的保证。
