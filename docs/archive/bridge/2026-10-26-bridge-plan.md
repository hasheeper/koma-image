## 1. 产品边界与命名

Koma 导出 IMAGE 状态与轻量预览，外部 Agent 整理资料并提交草稿；草稿进入当前 ASK 会话，用户审阅后应用，再自行决定是否生成。共享资料目录与 Slate 已连接多图工程。

**Todo／Slate 是 Koma 默认具备的本地任务能力，由 B3 实现；目录挂载只增加外部同步。** 用户无需挂载文件夹即可创建、修改、推进并保存任务；内置 ASK 可通过同一草稿链路协助拆解和推进。这里的“默认”指入口与本地能力可用，不表示自动创建清单、自动确认草稿或自动生成图片。手动管理任务不需要 ASK Key，内置 ASK 推理仍使用用户配置的文本连接。

| 对象 | 约定 |
| --- | --- |
| 实现模块 | `src/bridge/` 负责外部同步与收件；B3 本地 Slate 领域与服务独立于目录驱动 |
| 默认交换目录 | `.koma-bridge/`；以用户选中的目录句柄为边界，不要求文件夹实际名称一致 |
| 文件协议标识 | `koma.bridge.live.v1`、`koma.bridge.draft.v1`；B3 使用 `koma.bridge.slate.v1` |
| 实施阶段 | B1 外部草稿闭环与直接设参 → B2 共享资料按需读取与沉淀 → B3 默认本地任务清单与目录同步 |
| 现有交接 | `src/services/handoff.ts`、`koma-handoff` 数据库和 CHAT 交接 H0–H4 保持原职责；不作为外部协同实现或阶段编号 |

用户可选择名为 `.koma-handoff/` 的目录，但仍使用本协议，不增加旧协议检测或迁移。协议靠文件中的 `schema` 识别，不靠文件夹名字猜测。

对用户的文案统一为：

- **无需配置 ASK 文本推理 Key**。外部 Agent 提供推理，Koma 的草稿审阅、应用和撤销不依赖 ASK 上游连接；图像生成仍使用已配置的图像供应商。
- **前台近实时同步**。不承诺后台持续监听、零延迟或零性能开销。
- **未经用户选择，不向外部工程目录写出原图**。B1 写出状态与预览；B3 仅导出用户选中并绑入已映射 Slate 的图片。挂载不导出整库历史或收藏。应用内部既有的收藏、CHAT 素材和参考资产持久化继续遵守各自契约。

文件接收、排队、审阅、应用、撤销、状态导出和目录恢复均不触发生图、参考编码、报价、额度刷新或文本推理请求。协同桥不取得生成执行端口、不占生图任务槽，也不自动发送 CHAT 消息。生成仍由用户显式操作，经现有 `runTask` 执行。

本方案面向能访问同一本地目录的外部 Agent；云端或远程运行不自动获得本机文件。B1 使用浏览器 File System Access API 和手动文件入口，不扩展 `server.mjs` 为任意文件读写服务器，不要求安装 MCP 或新增外部依赖。

### 六项补充的必要性

六项均纳入实施范围，分别补齐可操作性、上下文和持久化闭环：

| 补充 | 判断与阶段 |
| --- | --- |
| 直接提议表单参数 | 必要；仅能恢复旧图参数无法表达新画幅或微调。B1 增加内外共用 `params_patch`，不开放任意配置写入 |
| 历史／收藏轻量索引 | 必要；仅 3 张预览不足以发现可恢复来源。B1 导出当前编号目录，不额外编码图片 |
| ASK 按需直读 `refs/` | 必要；避免每次手动添加附件。B2 先给文件目录，再由只读工具按需取内容 |
| ASK／外部 Agent 推进 Todo | 必要；任务清单应能参与创作过程。B3 通过 `slate_edit` 与提示词草稿联合审阅 |
| Slate 单机模式 | 核心要求；默认本地可用并持久化。B3 将任务状态与目录同步状态分开 |
| 配方／备忘录沉淀 | 必要；资料应能从创作结果回流。B2 实现显式导出到 `refs/`，B3 补充任务和共用配方上下文 |

## 3. 交换文件与状态导出

### 3.1 文件职责

以下路径均相对于用户选中的协同目录。

| 路径 | 写入方 | 阶段与用途 |
| --- | --- | --- |
| `PROTOCOL.md` | Koma | B1：自动生成的外部操作说明、步骤示例及限制 |
| `state.live.json` | Koma | B1：IMAGE 画板／表单、实际图片参数、预览与历史／收藏文本索引、最后一份收件回执 |
| `draft.inbox.json` | 外部 Agent／用户 | B1：单文件投递槽；Koma 只读，不用覆盖或删除它表示已处理 |
| `live/*.webp` | Koma | B1：当前选中图与最近 3 张历史图的去重预览 |
| `refs/` | 外部 Agent／用户；Koma 经显式导出写入 | B2：由 ASK 按需读取的文本／图片，以及经共享文件草稿沉淀的配方、备忘录与任务资料 |
| `slates/*.slate.json` | 双方按职责更新 | B3：多图任务、共用基底、变更记录与实际交付回执 |
| `assets/` | Koma 在用户绑图或同步已绑成果时写入 | B3：原图与可选打标文件的默认位置 |

B1 维护状态／预览与收件；B2 受限扫描 `refs/`，显式导出时才创建资料文件。B3 受限读取 `slates/` 并将变化交给草稿审阅。

### 3.2 `state.live.json`

状态导出从应用服务读取，不从 DOM 抓取。手动导出与目录同步调用同一序列化函数，当前外层字段如下；TS 类型从实现导出，不维护手写配对声明。

| 字段 | 含义 |
| --- | --- |
| `schema` | 固定为 `koma.bridge.live.v1` |
| `updated_at`、`revision` | 文件更新时间与本挂载会话内递增版本；不参与画板 `base_hash` |
| `scope_id` | 本页协同上下文标识，用于区分刷新前后的快照及展示编号 |
| `picture_scope_id` | 当前 ASK 图片编号作用域；与本次冻结的 `#h`／`#f` 索引一同导出 |
| `active_workspace` | 真实工作区标识；在 CHAT／TAGS 中仍可导出 IMAGE 状态，不伪装为当前正在绘图 |
| `active_board_id` | IMAGE 的活动画板 ID |
| `base_hash` | 对应冻结 `DraftState` 的哈希，由现有实现计算；外部原样带回即可，不另实现哈希算法 |
| `boards` | 当前 `DrawingBoard[]` 的完整 JSON 数据，保留 `form`、稳定角色 ID 等结构 |
| `form` | 活动画板对应的 `DrawingForm`，与本次 `boards` 来自同一冻结快照 |
| `selected_image` | 当前选择的实际图片 ID、可选展示编号／来源板 ID、尺寸、生成参数与预览相对路径；没有图片时为空 |
| `recent_history` | 最近 3 张历史图的实际 ID、展示编号、尺寸、真实参数与预览相对路径 |
| `history_index`、`favorites_index` | 当前 ASK 编号作用域内可用历史／收藏的轻量文本目录；每项仅 `label`（`#hN`／`#fN`）、`width`、`height`、可用的 `seed` 与 `prompt_excerpt` |
| `last_inbox_receipt` | 尚无可关联收件时为空，否则使用第 5 节的单份回执 |
| `refs_index` | B2 元数据清单：available、files 的相对路径和字节数、total、omitted 与 limited；不带正文或像素 |

参数结构必须保留现有完整字段：`model`、`width`／`height`、`steps`、`scale`、`sampler`、`seed`、`batchCount`、`cfgRescale`、`naiMode`、`complexity`、`qualityPreset`、`negativePreset`、`transparentBg`、`characters`、`placement`、`naiReferences` 及其他现有表单字段。

这里的 Guidance Rescale 在代码中名为 **`cfgRescale`**，协议沿用该字段，不另建 `guidanceRescale` 别名；遗留 `cfg` 仅兼容历史记录，默认空、不发送上游。`characters` 保留 `id`、`on`、`prompt`、`negative`、`centers`，不退化成数组序号和一个位置字符串。Effort 沿用当前模型 ID 的表达。表单 Seed 沿用当前字符串结构，空串表示随机，实际生成快照的 Seed 为数值，合法的 `0` 不丢失。

图片参数取自该图的实际记录：保留 `basePrompt`／`baseNegative` 与实际 `prompt`／`negative_prompt` 的区别、实际角色及本地角色快照等字段。不能拿当前表单补写旧图的缺失参数；没有的数据保持缺失，不声称可完整复现。

历史／收藏索引与本次状态来自同一冻结图片库，列出可用条目，不限于 `recent_history` 的 3 张。Prompt 摘录沿用现有基础提示词取值，最多 160 个字符；缺失 Seed 保持缺失，`0` 保留。索引不含全文、完整参数或新预览，不因生成目录而解码任何图片。用户可据编号点选，外部可据编号提出 `restore_partial`，恢复值仍从受信的冻结记录读取，不能从摘录推造。

编号沿用当前 ASK 注册表，不按列表位置重排或回收。内部保存 `picture_scope_id`、展示编号与实际记录 ID 的对应关系；导出基底缓存和待审草稿共同冻结该关系。不同作用域、过期快照或歧义不能仅凭相同 `base_hash` 命中另一份图片索引；应拒绝并要求重新导出，不能将旧 `#h1` 解析为新图。轻量目录本身不构成图片持久化。

只序列化明确的数据对象，不整体导出服务、连接配置或存储。Key、地址中的凭据、解锁材料、目录句柄、Object URL、原图 Blob 和参考编码缓存不进入 JSON。`naiReferences` 保留现有配置与资产标识，不内嵌参考原图或 Vibe 编码；这些本机标识也不意味着外部工程已经拥有对应资产。

### 3.3 预览与写入顺序

- 表单变更采用约 300ms 防抖更新 JSON；回执变化也应尽快写入，不依赖用户再次改表单。
- 预览最长边 768px。稳态仅保留当前选中图与最近 3 张历史图，按实际图片 ID 去重，最多 4 张；不承诺每张固定 40–60KB。
- 使用实际记录 ID 与图片内容／编码配置作为缓存依据。图片未变时仅更新 JSON，不重复解码、编码或覆写 WebP。
- 预览采用稳定图片文件名，由 JSON 明确指向，避免复用 `current.webp` 时状态已换而图片仍旧。先写完本次需要的预览，再提交新状态文件，成功后回收不再引用的旧预览；归属由本机存储登记，不依据外部改写的 JSON 删除文件。中途失败不发布指向缺失图片的新状态。
- 文件同步串行合并最新状态，旧异步编码结果不能覆盖较新的选择。序列化、预览和接收都不修改当前画板或选图。

## 4. 草稿协议与基底校验

### 4.1 `draft.inbox.json` 复用内部语法

外部文件只增加投递元数据 `schema`、`draft_id`、可选 `source_label` 及图片引用所需的 `picture_scope_id`。草稿正文直接沿用 `propose_draft` 的 `draft_title`、`steps`、可选 `new_board_name` 和 `base_hash`。引用 `#h`／`#f` 时必须原样带回导出的 `picture_scope_id`；纯文字／设参草稿可省略。作用域不可识别时拒绝引用，不重新绑定到当前同名编号。

接收时先校验投递元数据及编号作用域，再剥离这些外层字段；补齐允许省略的 `base_hash` 后，将正文交给共享 Schema 和现有解析器。内部 ASK 工具的 `base_hash` 必填规则不变，其图片作用域由本轮快照提供。文件不得提供内部 `Draft.base`、恢复步骤中的可信 `values` 或可执行操作对象。

示例刻意省略 `base_hash`，用于展示收件时补齐的规则：

```json
{
  "schema": "koma.bridge.draft.v1",
  "draft_id": "example-001",
  "source_label": "外部助手",
  "draft_title": "补充傍晚光线",
  "steps": [
    {
      "kind": "prompt_patch",
      "target": "image.prompt",
      "mode": "after",
      "anchor": "blue sky",
      "text": ", warm evening light"
    }
  ]
}
```

该例仍要求目标中存在唯一可匹配的 `blue sky`；接收到文件并不表示已应用。

B1 仅接受共享 Schema 中作用于 IMAGE 的步骤：

| 步骤 | 范围 |
| --- | --- |
| `prompt_patch` | `image.prompt`、`image.negative`、`image.char.c1.prompt`／`.negative` 等稳定角色目标；使用现有 `replace`／`before`／`after`／`append`／`rewrite` |
| `character_edit` | 现有增删、重排、启停、位置和定位模式操作，继续按模型能力校验 |
| `restore_partial` | 从本次冻结图片库读取现有字段，不能由外部直接填入数值；仅接受该快照确实包含且作用域明确的图片编号 |
| `params_patch` | B1 新增共享步骤，直接提议第 4.2 节白名单中的表单值，复用现有参数 Diff |

共享 Schema 保留原有 CHAT 能力，Bridge B1 在接收边界明确拒绝 CHAT 写入、`chat_handoff` 和 `chat_distill_branch`。站内 ASK 同步获得 `params_patch`，不改变其现有 CHAT 边界。

不新增 `ops`、`insert_after`、`image.char.1.prompt`、任意 `image.params` 目标或 `target_board`。默认目标为冻结的来源画板；提议新画板使用 `new_board_name`，用户也可沿用现有卡片菜单选择新板。直接设参只通过共用的 `params_patch` 白名单，不接受自由路径写入。

### 4.2 B1 直接设参：`params_patch`

共享 `propose_draft.steps` 已支持 `params_patch`，内置 ASK 与外部草稿均可直接提议值；`restore_partial` 继续用于从图片恢复。步骤形状如下：

```json
{
  "kind": "params_patch",
  "params": { "width": 1216, "height": 832, "scale": 5, "cfgRescale": 0.2, "seed": "0" }
}
```

- **字段白名单**：`width`、`height`、`steps`、`scale`、`cfgRescale`、`seed`、`complexity`、`model`、`sampler`、`naiMode`、`qualityPreset`、`negativePreset`、`transparentBg`、`batchCount`；不再接受遗留 `cfg` 的直接设参。参数必须非空，未知字段拒绝；类型直接复用 `DrawingForm` 的对应字段。Prompt 与角色继续使用原步骤。
- **能力与值校验**：复用并补齐现有表单校验，检查型号／采样器可用性、尺寸对齐与面积、数值范围、枚举以及 NAI 固定参数约束。Seed 使用表单字符串，空串随机、`"0"` 合法，非空须为 uint32。不支持的透明底、Complexity 或 Rescale 等须显示原因，不静默忽略或替换为默认值。
- **组合约束**：按勾选后的最终表单校验模型、尺寸、采样器及关联参数；改模型不能留下不兼容值，取消关联步骤也须重算。直接设参与 `restore_partial`、`prompt_patch` 可同稿使用，按步骤顺序计算，Diff 清楚显示最终值；非法组合不能部分写入。
- **原有审阅链路**：在现有“参数”分组展示逐字段前后值，复用冲突检查、来源板／新板、`data.write` 和撤销。冻结原值后，用户又改过该参数时按现行规则呈现冲突；不由外部强制覆盖。
- **权限边界**：不开放连接／Key、供应商路由、报价／额度策略、并发、缓存开关、全局偏好或参考资产导入。草稿的接收、预览和应用不触发报价、生成、编码或扣费；后续显式生成仍经过现有全部护栏。

B1 同步更新工具说明、共享 Schema、解析与校验、参数 Diff 和协议说明，不在 Bridge 另造一套校验逻辑。`restore_partial` 的可信 `values` 仍只由本机图片记录产生，不能借直接设参改为信任外部恢复值。

### 4.3 `base_hash` 与冻结时机

1. **未提供 `base_hash`**：在成功读出完整 JSON 并进入接收管线时，读取当前 IMAGE 活动画板的实时 `DraftState`，填入其 `base_hash`，冻结画板、角色和可用图片索引，然后进行现有锚点与字段校验。不能拿 300ms 防抖尚未落盘的旧状态代替实时状态。
2. **已提供 `base_hash`**：使用本页可识别的对应导出基底；图片步骤同时匹配其 `picture_scope_id`。当前状态相同可直接匹配，已保留的旧导出快照仍须经过现有冲突检查。找不到对应基底或快照已过期时返回 `invalid`，不把显式旧哈希替换为当前哈希。导出基底缓存应有界，正在排队／审阅的草稿独立持有其冻结基底。
3. `base_hash` 缺失与空串、错误类型不同；仅真正缺失时补齐。哈希沿用现有计算函数，包含其现行依赖，不在 Bridge 中重定义一套“等价”算法。
4. 进入等待队列时就固定来源板和基底，不在队列释放时重新解释为届时活动画板。用户切板、改词、删角色后，仍按原基底检查，不自动重定向或强制覆盖。
5. `replace`／`before`／`after` 沿用精确匹配后唯一宽容匹配；`rewrite`／`append` 按现有语义展示。无哈希导入只能以接收时状态为基底，不能证明外部编写期间没有发生修改；所有内容仍须由用户审阅。
6. 收件完成结构与初始目标校验，审阅及点击应用前继续调用现有校验与 fingerprint 检查。后续变化通过现有冲突行呈现，不因为导入时通过就跳过应用检查。

## 5. 会话归属、等待与单文件回执

### 5.1 进入当前 ASK 会话

有效外部草稿接收时绑定当时的 ASK 会话，并在该会话流中追加一条轻量的「外部草稿」记录，展示来源与标题。记录使用本地稳定 ID，与现有检查点、DraftCard 和撤销栈关联。

这是一种会话记录来源，不是一次伪造的模型回答：不调用 provider，不制造 tool-call 往返、token 用量或成功推理轮次，不启动 AI 命名或自动压缩。外部内容按资料展示，不提升为系统指令。下一次用户主动发起 ASK 时，由既有最新工作台状态反映已应用的修改。

现有会话记录、检查点更新和收藏序列化已经支持该来源；不直接向 `DraftCard` 塞一份脱离 `ask/service.ts` 管理的对象，不创建第二套校验器、写入器或撤销栈。

- ASK 空闲且没有未决草稿：使这份草稿进入现有审阅槽，沿用 Diff、勾选、来源板／新板和应用交互。
- ASK 正在运行或已有未决草稿：保留原内容，新草稿按接收顺序挂起，提示「有外部草稿待处理」。压缩、写入、会话恢复等事务也不能被异步收件打断。
- 释放等待项只让其进入审阅，不等于自动应用。等待项保留接收时的会话归属；切换会话不搬移记录、不抢切会话，回到所属会话且审阅槽空闲后再处理。
- 应用继续走 `draft/apply.ts` 与 `data.write`，保存成功后才算应用完成；失败保留待处理草稿及错误反馈。Tab／Esc／⌘Z 沿用现有焦点、输入法和浮层层级，不全局劫持输入。
- 内外草稿共用页面 50 条撤销栈，遵守全局栈顶和会话所有权。外部记录能够呈现应用／回退检查点，删除会话不撤销已经写入的画板。

记录、排队项和待确认草稿遵循所属会话生命周期：未收藏只在本页，收藏时随会话通过既有保存路径持久化；恢复后不自动应用。撤销执行栈仍不持久化。删除会话时终止其等待项，按忽略处理。普通 Koma ZIP 不收录 ASK 会话、挂载句柄或外部队列。

### 5.2 回执定义

回执只放在 `state.live.json`，不另建回执文件：

```ts
interface InboxReceipt {
  draft_id: string;
  status: "pending" | "applied" | "dismissed" | "invalid";
  error?: string;
}
```

| 状态 | 含义 |
| --- | --- |
| `pending` | 已接收，正在等待或审阅；尚未成功应用 |
| `applied` | 用户确认的勾选内容已通过原写入路径成功保存；不代表已经生成 |
| `dismissed` | 用户忽略、取消等待，或所属会话被删除 |
| `invalid` | 能识别 `draft_id`，但版本、正文结构、基底或接收目标不符合契约，未接入审阅槽 |

等待期间出现可审阅冲突，或应用时保存失败，仍为 `pending`，可在 `error` 给出简短原因；恢复后清除过时错误，不谎报为已应用。

`last_inbox_receipt` 表示最近一份已识别投递的处理结果，不是所有草稿的事件日志。内部保留每个已接收 ID 的状态；较早草稿完成时，不用它覆盖较新的 `last_inbox_receipt`。外部单个发送方应等待自己 ID 的终态，再覆写投递下一份；多个来源的已接收草稿可内部排队，但单文件不提供多生产者消息队列保证。

`applied` 是收件处理结果。用户随后通过 ⌘Z 回退时，更新会话检查点、画板状态与 `base_hash`，回执不杜撰第五种状态；它不作为“当前表单仍与草稿一致”的证据。回退后再恢复也复用既有撤销链路。

### 5.3 重复投递与半写入

- 同一协同上下文内，`draft_id` 是幂等键；挂载时手动导入也共享该上下文，未挂载时使用本页上下文。重复扫描、聚焦和手动导入同一份草稿，不追加重复记录、不重复应用；修改正文须使用新 ID。同 ID 不同正文视为投递冲突，保留原记录和原回执，提示使用新 ID，不覆盖已接收内容。
- 读到 JSON 解析失败时，静默等待短暂间隔后完整重读一次。再次失败后，不继续对同一文件版本高频重试；等待后续修改或用户重新导入，必要时只显示一次简短错误。
- 只有完整解析并通过接收流程后，才记为已接收。解析失败不能抢占当前草稿，也不能消耗该 ID 的正常后续修正版。
- 无法可靠读出 `draft_id` 的坏 JSON，不伪造 ID，也不把错误写到上一份草稿的回执上；保留上次可关联回执并给出读取错误。能读出合法 ID 的结构错误使用 `invalid`。
- 目录恢复时核对已有回执、已保存的会话记录及去重信息，避免刷新重放已应用／已忽略草稿。未收藏的 `pending` 内容刷新后不再具有原基底；应报告上下文失效并要求以新状态重新投递，不能把旧投递自动绑定到新画板。

半写重读不是文件系统事务，也不能恢复从未被 Koma 读到、就被外部覆写的草稿。`PROTOCOL.md` 应明确单文件交付节奏，并指导外部先完成整份 JSON 再替换投递文件。

## 6. 目录挂载、手动兜底与生命周期

### 6.1 挂载与恢复

- 目录选择由用户手势发起，获取必要的读写权限。句柄通过受数据租约管理的 IndexedDB 路径保存，Koma 命名集中登记；不放入深层 reactive、不混入普通备份。
- 恢复句柄后先查询权限；已授权才恢复同步，需要重新授权时提供显式入口。拒绝、失效或目录不可访问时暂停该挂载，不静默改写其他目录、不自动循环弹权限提示。
- 挂载后生成 `PROTOCOL.md`，写出当前状态；已有草稿文件按正常收件流程处理，初始化不得清空它，也不得覆盖用户资料。
- 前台按约 1.5s 的节拍检查投递文件，窗口聚焦／可见时立即检查并合并重复事件。比较修改时间、大小与必要的内容指纹，不能只靠时间戳承担幂等判断。
- 隐藏页面暂停心跳，恢复时同步；未挂载不启动目录轮询或预览编码。卸载／切换目录／服务销毁清理计时器、事件监听、编码资源与临时 URL，旧异步结果不写回新目录。
- 应用级服务统一持有驱动；同一应用同一目录只允许一个同步写入者，其他标签页显示占用并等待显式接管，不与生成锁混用。跨源页面或不同应用同时挂载同一目录的互斥不作自动保证，操作说明明确单写入者约定。

所有 Bridge 自动写入限定在用户授权目录内部，拒绝绝对路径、父级跳转及非法路径片段。读写失败只影响协同状态；不得破坏既有工作区或静默扩大授权范围。同步数据和外部文本不作为脚本、HTML 或命令执行。

### 6.2 手动 JSON 入口

手动导入调用同一个 `receiveInbox` 管线；手动导出调用同一个状态快照与序列化管线，不另做简化版协议。是否挂载目录只决定传输方式，不改变缺失哈希、队列、校验、审阅和回执语义。

不支持目录 API 或未授权时仍可导入草稿 JSON、导出状态 JSON。手动状态导出必须诚实描述预览可用性：没有写出对应预览文件时不声称该相对路径可读，也不把原图或 base64 塞进 JSON。B1 不以 ZIP 打包为前置条件；B2／B3 的非目录出入料能力在各阶段单独落实。

`PROTOCOL.md` 由同一协议定义生成，包含目录职责、实际字段名、IMAGE 支持步骤、缺失／显式哈希规则、回执与投递节奏、预览限制和“用户确认应用后自行生成”。模型提示词资料引用已有维护入口，不在说明书里复制一套会漂移的 NAI 参数或硬规则。

## 7. B2：共享资料按需读取与沉淀

### 7.1 目录感知与两种读取入口

挂载目录后，`<workspace_state>` 附带 `refs/` 的轻量清单，每项只含相对于 `refs/` 的文件名／路径和字节大小，不自动附带正文或图片。`state.live.json` 在 B2 同步增加该清单 `refs_index`。目录变化只刷新清单；大量条目按现有上下文预算分页或截取并标明未列出的数量，不能把不完整清单伪装成全部文件。

用户手动传文件走现有「＋」系统原生选择器、粘贴或拖入；不新增资料搜索勾选弹窗。也可以直接向 ASK 提及某份目录资料。后者由 B2 新增的只读工具 `read_ref`按清单中的相对文件名读取文本或图片，无需先手动挂为附件。不增加每次读文件的重复确认；有同名文件或目标含糊时使用完整相对路径消歧。

只读工具只能访问当前挂载的 `refs/`，不接受任意工程路径、绝对路径或父级跳转，不读取 `assets/`、凭据文件或整个工程。文件不存在、权限失效、类型不支持或超限时返回明确结果，不偷偷读取别处同名文件。不因目录挂载或刷新自动发起 ASK；读取发生在用户发起的本轮请求中，模型按问题需要调用。

### 7.2 内容、预算与生命周期

手动选择与工具读取复用现有附件校验、文本字符数、每轮文件数、图片字节／像素／编码限制，以及工具输出和视觉预算。按需读取的图片进入既有视觉通道，文本进入只读工具结果；不能用文件工具绕开单轮限制。ASK 图片能力不可用时保留目录可见性，并反馈无法读取图像内容。

读取时冻结文件内容与来源版本；之后的目录变更不回改已发送消息、工具结果或现有附件，下一轮显式读取才取得新版本；同轮分页与重复读取固定首次成功读取的内容。发送给模型的是资料数据，不把文件正文提升为系统指令。临时图片、编码和 Object URL 沿用资源释放规则；收藏后的实际引用内容按 ASK 持久化边界保存，不保存整份目录副本，也不只存一条会失效的路径。

B2 不扫描整个外部工程，不自动把全部资料塞入上下文，不引入 RAG／Embedding，也不触发生图或编码参考资产。未挂载或没有目录能力时，用户仍可使用现有手动附件入口；目录只读工具报告当前不可用。

### 7.3 配方与《创作交接备忘录》一键沉淀

文件沉淀统一使用 DraftCard 的紧凑文件行与共享 `save_ref` 步骤，内外 Agent 均可提议，用户确认后写入。没有独立代码预览弹窗或格式下拉。

| 内容 | 导出约定 |
| --- | --- |
| 当前画板配方 | 固定 `.json`，保留提议时的完整表单／角色、来源与时间，不冒充生成回执 |
| ASK《创作交接备忘录》 | 固定 `.md`，逐字保存所选回答或草稿正文，不包含整段会话或隐藏上下文 |
| 活动任务交接资料 | 固定 `.json`，冻结提议时任务、配方、进度与更改记录，不附原图 |

普通 IMAGE 草稿的应用下拉可追加文件，已完成回答的保存按钮创建备忘录草稿；不覆盖当前待审内容。可读摘要、来源、真实路径与去向在文件行中按需展开。提议时冻结内容与目录身份；既有目录失联、变化或无权限时阻断整稿，不静默改为下载。未挂载时固定走浏览器下载。

文件名自动生成安全名称及唯一后缀，不允许任意路径、格式或覆盖既有资料。应用与 Tab 统一确认，失败保留草稿并补偿本次文件；撤销只删除本次未被外部修改的文件，不能收回已发起下载。成功后刷新 `refs/` 清单，不额外调用推理。底层与复合写入的具体限制见[现行文件契约](../../integrations/bridge.md#文件保存草稿)。

## 8. B3：默认本地 Slate、ASK 推进与绑图持久化

### 8.1 Todo 是默认能力，挂载只负责同步

**B3 交付的 Todo／Slate 必须默认在站内可用，不能以挂载文件夹、安装外部工具或启用协同模式为前提。** 用户可在暗房内从空白新建清单、编辑任务与状态、绑定成果；配置文本连接后，内置 ASK 也能主动提议这些操作。目录不支持、未授权或中途断开，都不禁用本地任务能力。

Slate 保存稳定 ID、标题、版本、`golden_recipe`、Todo 的 ID／标题／描述／要求／状态／`mutation` 及绑图回执。通过应用级任务服务和现有 `data.write` 路径持久化到本机 IndexedDB，刷新后恢复；不依赖某个 ASK 会话是否收藏，也不随未收藏会话销毁而丢失。待审草稿仍遵守所属 ASK 会话的生命周期，任务的持久化与草稿的持久化分开。

共享配方复用现有画板／表单结构，结果复用真实生成快照，不省略模式、Rescale、预设、角色或参考配置。B3 按实际类型定义完整 Slate Schema；B1 不预建任务板 UI 或暴露尚未实现的步骤。任务与绑图的资源所有权独立于 Bridge：卸载目录只停止同步，不删除本地 Slate 或成果。

### 8.2 状态感知、`slate_edit` 与复合推进

Slate 同时由用户、站内 Koma ASK 与外部 Agent 协作推进。B3 必须实现 ASK 主动创建、修改和推进 Todo，不能仅提供手动任务列表。

- **状态感知**：存在活动 Slate 时，`<workspace_state>` 附带本轮冻结的轻量摘要：Slate ID／标题／版本、`golden_recipe` 概况与锁定状态，以及各 Todo 的 ID、标题、状态和要求。`state.live.json` 在 B3 增加同源 `active_slate` 摘要供外部使用；没有活动 Slate 时明确为空。完整配方、任务详情与关联资料由共享只读入口按需读取，摘要不携带原图。
- **共享步骤 `slate_edit`**：在 B3 扩展同一份 `propose_draft.steps` Schema，内外 Agent 使用相同结构、校验与审阅。支持新建 Slate 并从零拆解 Todo、向现有清单追加 Todo／Bonus、修改标题／描述／要求与 `mutation` 更改记录、更新进行中／完成／放弃等状态、绑定所选 `#hN`／`#fN` 成果，以及更新和锁定 `golden_recipe`。
- **身份与配方锁定**：已有目标使用稳定 Slate／Todo ID，新建对象的最终 ID 由本机分配，同稿依赖按共享解析规则关联。图片编号在冻结作用域中解析为实际记录。锁定后的配方不能被隐式改写；需要调整时，在草稿中明确呈现解锁与修改，或建立新版本，经用户确认后才生效。配方锁定不改变生成锁或供应商规则。
- **复合推进**：允许同一份草稿组合 `slate_edit`、IMAGE `prompt_patch` 及 B1 的 `params_patch`。例如“记录 Todo 1 的更改、绑图并标记完成，同时把 Todo 2 的提示词和画幅写入画板”。在同一张 DraftCard 按目标分组呈现；任务默认显示紧凑摘要，完整任务及配方前后文本按需展开，解锁与要求目录交付保持可见。用户按 Tab 或点击应用后一并生效；内外来源都不能绕过确认，提议本身不创建任务、不写文件、不生成。
- **联合校验**：同时冻结 Slate 版本、Todo、图片和画板基底，应用前对全部已勾选步骤联合预检；依赖项成组处理。图像交付型任务不能只完成状态步骤而漏掉绑图。外部版本变化、图片失效或画板冲突时阻断该组合，不先应用另一半，也不自动覆盖用户修改。纯任务草稿同样校验 Slate；不能以未变的画板 `base_hash` 代替任务版本检查。
- **写入与撤销**：复用会话归属、检查点和页面撤销栈。任务与画板跨存储写入须有提交记录、失败补偿／可恢复状态，组合成功才展示应用完成。若还包含目录交付，须同时满足第 8.3 节的文件条件；跨 IndexedDB 与文件系统不宣称天然原子。撤销校验目标和文件版本，不删除后续被用户或外部 Agent 修改的成果；失败必须明确呈现，不能伪造完整回退。

在未挂载目录时，以上内置 ASK 能力全部可用；外部草稿也可通过同一手动 JSON 入口提交。默认能力不等于自动代办：ASK 可根据用户任务提出下一步草稿，确认、生成与交付副作用仍由用户控制。

### 8.3 绑图立即持久化，区分本机成果与目录交付

用户将图片绑入 Todo 时，立即冻结实际记录、原字节和已有生成参数，不能只保存易失的 `#hN`，等待以后再取图。按当前模式完成相应动作：

| 模式 | 绑图行为与完成依据 |
| --- | --- |
| 未挂载目录 | 关联已有收藏的持久资产，或将原图与真实参数保存为 Slate 持有的本机资产；成功后完成本地绑定。可同时显式下载图片／参数或交付包，但下载不是创建和推进任务的前提 |
| 已挂载且 Slate 已映射 | 在本机持久绑定的同时，将原图立即写到授权目录内的 `target_path`（默认 `assets/`），核对后更新 `.slate.json` 与交付回执；不能先标记“已同步交付”再延后取图 |

本机绑图回执保存持久资产 ID、SHA-256、尺寸／类型、绑定时间与该图已有的完整生成参数；目录交付另外保存实际相对路径、文件校验和、交付时间及同步版本。不能用当前画板替代旧图参数，缺失字段不补造默认值。`#hN`／`#fN` 只保留为显示信息，长期引用使用实际资产 ID 或文件回执。

- 本机资产由 Slate 明确持有；取消收藏、清空普通历史或删除 ASK 会话不得让已绑成果悬空。删除／解绑时按引用责任清理，不误删仍被收藏或其他任务持有的图片。
- 保留原图字节与真实格式，扩展名与内容一致。路径冲突和重绑覆盖明确反馈；失败不能标记目录交付成功。
- 先完成并核对图片及可选标签文件，再更新目录回执。多文件写入记录部分成功，恢复时核验已有文件并续办，不重新生成、不删除无关文件。
- 通过浏览器下载时记录“已发起下载／导出”，不能把浏览器无法验证的最终保存路径或落盘成功写进目录回执。可恢复的本机绑定独立保留；以后挂载时仍能同步原图。

**Todo 进度、本机绑定状态、目录同步状态分开保存与展示。** 未挂载可以完成本地任务；同步失败保留本机成果并显示待同步／错误，不把失败伪装成已交付，也不让全部任务退回不可操作状态。显式要求目录交付的复合草稿，只有对应文件和回执全部成功才报告该次复合应用完成。

### 8.4 挂载后的自动映射与同步

挂载时将当前本地 Slate 按稳定 ID 映射到 `slates/*.slate.json`，将其中用户已选中绑入的成果映射到 `assets/`；挂载期间手动新建或确认草稿创建的活动 Slate 默认自动加入当前目录，外部任务文件创建沿用原文件映射，避免重复导出。映射范围在挂载入口明确显示。映射后自动同步任务状态与这些成果，无需重建清单或逐条重新绑定；其他已有 Slate 按用户选择加入映射。不因挂载导出全部历史、收藏或未绑参考原图。自动映射沿用版本／内容冲突检查及本机保存与目录交付分离的失败语义。

已有同 ID／同名文件时先比较版本和内容，不盲目覆盖。外部 `.slate.json` 的新清单或修改经解析成为待审差异，用户确认后经同一任务写入路径接入；Agent 也可直接提交 `slate_edit`。外部文件不得绕过草稿审阅直接改画板、标记交付或触发生成。

任务内容版本与目录同步版本分开。同步前重读检查外部版本；同一 Todo／配方的冲突留待审阅，不静默采用最后写入者。目录断开后保留本地修改与同步记录；重新授权或恢复后对比版本再续办。卸载不删除文件；切换目录建立新映射，不把旧目录的成功回执当作新目录已交付。

B3 将本地 Slate／资产的持久化、导入导出和清理责任纳入数据维护约定；不默认混入现有普通 ZIP，也不能仅靠会话收藏或目录句柄实现“保存”。无需目录的任务 JSON 导出与成果下载应与本机能力一并验收。

### 8.5 确定性打标与配方沉淀

取消 `clean_no_artists`，仅提供：

| 模式 | 行为 |
| --- | --- |
| `full` | 输出选定来源的原文，保持字符与顺序 |
| `strip_syntax` | 仅剥离已定义的权重语法包装与 XML 块标签，保留块内正文、提示词内容及顺序，不移除画师名 |

B3 在实现与测试中明确支持的权重语法、嵌套、字面符号和畸形输入行为；不使用会吞掉正文的宽泛替换。这里的 XML 块处理仅移除标签包装，不删除块内文字。无法确定是语法的内容保持原文。

打标来源须明确为所选图片的哪份原文，`full` 与 `strip_syntax` 对同一来源工作；不把基础 Prompt、实际追加预设后的 Prompt 与角色文本静默混为一份。清洗不查询词库、不调用模型、不按名称或词义猜画师。

复用第 7.3 节的一键沉淀入口，将用户选中的 `golden_recipe`、任务要求／更改记录与交接备忘录分别按固定 JSON／Markdown 类型输出。挂载时写入 `refs/`，未挂载时下载同格式资料，不把可读摘要冒充实际出图回执。

### 9.2 阶段门槛

| 阶段 | 交付与进入下一阶段的条件 |
| --- | --- |
| **B1 · 已实现** | 目录挂载与权限恢复；手动 JSON 兜底；协议说明生成；状态、预览及历史／收藏轻量索引；内外共用直接设参；IMAGE 草稿接收、排队、审阅、应用、撤销与单文件回执闭环 |

### 9.3 B1 必验行为

1. 无 ASK 文本连接／Key 时，合法 IMAGE 草稿仍可接收、审阅、应用到来源板／新板和撤销；全过程没有新增上游请求。
2. 内外共用步骤 Schema；有效角色 ID、`after`、`new_board_name` 正常工作。`params_patch` 可直接修改画幅、Seed 0、Rescale 等白名单字段，并展示 Diff／冲突、应用到来源板／新板与撤销；未知字段、非法范围／组合、模型不支持项、旧 `ops`、越界 CHAT 写入和任意 `image.params` 被拒绝。
3. 缺失哈希取收件时实时状态；显式旧／未知哈希按对应基底规则处理。队列期间切板、改词、删角色或图片消失不会误写其他目标；应用前仍校验。
4. ASK 运行中、已有未决草稿、切换／删除会话、保存失败及恢复收藏等情况下不覆盖审阅内容，归属与等待顺序正确；外部记录不制造模型用量或轮次。
5. 四种回执、重复投递、较早草稿晚完成、半写后重读、不可解析 ID 和刷新去重均符合第 5 节；无虚假 `applied`。
6. 导出覆盖现有 NAI 控件、完整角色及参考配置，区分表单与生成快照；历史／收藏索引只含约定的轻量元数据，编号与 ASK 一致且不跨作用域错配，能供 `restore_partial` 解析。Seed 0 保留，凭据和二进制资产不进入 JSON。
7. 仅改文字不重新编码图片；当前图与最近历史去重；快速切图与失败时 JSON 不指向缺失／错误预览，过期资源得到释放。
8. 目录权限拒绝／恢复、单写入者、隐藏暂停、卸载／重挂及服务销毁正常；未挂载无目录定时器或目录自动写入，不影响手动下载和后续本地 Slate 保存。
9. 手动与目录入口得到相同校验、排队和回执结果；路径越界不能写出，目录同步不改写 `draft.inbox.json` 或用户资料。
10. 320／390／768／1440px 下外部记录、等待提示与原 DraftCard 无溢出；键盘和减少动态设置沿用现有规则。

### 9.4 B2／B3 闭环验收

- **B2 读取**：仅清单进入初始状态；用户提及资料后 ASK 能按名称读取，正文／图片符合预算。文件消失、同名消歧、目录越界、超限、权限失效与内容冻结都有明确结果；手动附件入口继续可用。
- **B2 沉淀**：画板配方与已选备忘录可写入 `refs/` 并刷新清单，未挂载可下载；文件冲突、取消和写入失败反馈准确，无凭据或未选会话内容外泄。
- **B3 默认任务**：完全未挂载、没有目录 API 或目录断开时，手动与内置 ASK 均能创建／修改／推进任务；刷新后恢复，删除未收藏 ASK 会话不删除本地任务；手动任务不要求 Key。
- **B3 草稿**：内外 `slate_edit` 可创建清单／Bonus、修改描述和 `mutation`、更新状态、锁定配方、绑定成果；能与 `prompt_patch`／`params_patch` 复合确认和撤销。并发版本变化、锁定配方改写与部分写入失败不产生虚假完成。
- **B3 成果**：清空普通历史后仍能读取已绑图原字节与参数；本地任务完成和目录交付状态独立。稍后挂载能自动映射已选成果，断开／重挂／换目录不丢任务、不重放或覆盖冲突文件。
- **B3 导出**：实际文件字节、格式、参数和校验和一致；`full`／`strip_syntax` 保持确定性；Slate 配方／备忘录可沉淀到 `refs/`，下载不冒充已验证落盘。

实施时运行 `npm run check` 及变更涉及的 ASK／绘图／外壳／存储浏览器检查。目录测试使用临时授权目录、合成图片与模拟服务；真实浏览器权限恢复和文件轮询须另记实际浏览器及结果，不能用模拟句柄宣称全部兼容。
