# ComfyUI 极简直通适配器 MVP 方案

日期：2026-11-01。状态：本方案已实施并完成相应本地模拟及一次 SDXL 应用内真实闭环，未推送或发布。本文保留实施前约定；现行行为由 [ComfyUI 接入](../../integrations/comfyui.md)维护，证据见[接入验收](2026-11-01-mvp-verification.md)。不代表 MOSS、Krea 或 LoRA 已实测。

## 1. 目标与范围

**将 ComfyUI 作为 IMAGE 工作区的纯文生图执行后端：用户在 ComfyUI 原生界面调通管线，导出 API JSON；Koma 只绑定和注入 Prompt、可选 Negative 与 Seed，提交任务并拉回原图。** 一个连接配置一份工作流，以连接名称作为 IMAGE 中的生成条目显示名。

云端供应商继续使用现有协议；自管 GPU 首期采用 `Koma → ComfyUI HTTP API`，不同时建设 OpenAI 包装路径。接入单位是工作流，无需按 Qwen、Anima、MOSS、Krea、SDXL 或 FLUX 分别适配模型架构；模型、精度、显存、自定义节点及 LoRA 的可用性由目标 ComfyUI 环境决定。

只做三件事：

- **本地规则扫描与手动绑定**：列出字面量字符串、整数和支持的输出节点，用户确认目标，不请求文本模型或节点说明。
- **有限字段注入**：深拷贝工作流，只替换绑定位置，其余尺寸、步数、采样器、模型、LoRA、二次采样和连线保持原样。
- **轮询收图与复用本地结果路径**：容忍短时网络抖动，下载原图进入本页历史，用户按现有方式收藏、下载或交接。

首期不做 AI 节点识别、动态参数表单、LoRA 管理／提示词 LoRA 标记解析、工作流拓扑编辑。也不增加内置工作流库、逐模型测试矩阵、图生图、蒙版上传、视频、WebSocket 预览、断点续传或跨刷新任务恢复。

## 2. 连接配置与绑定

复用现有「配置供应商」弹窗，新增协议 `comfyui-workflow`，不新增独立工作台或通用节点面板。

| 字段 | 交互与校验 |
| --- | --- |
| 名称与地址 | 用户自定义名称；远程地址使用 HTTPS，本机回环可用 `http://127.0.0.1:8188`，沿用现有 URL 归一化规则 |
| API Key | 新建时可留空，明确表示无鉴权；启用 Bearer 时发送 `Authorization: Bearer <Key>`。编辑已有 Bearer 连接时，空输入沿用现有“保留 Key”规则，切换无鉴权需明确操作；其他协议仍按原规则要求 Key |
| 工作流 JSON | 粘贴 `Export (API Format)` 导出的 API 图，要求节点 ID 对应 `{ class_type, inputs, _meta? }`；普通画布格式如 `{ nodes: [...] }` 提示“请导出 API 格式 JSON”，不自动转换 |
| 正向 Prompt | 必选，字符串候选中多选 1～N 个位置，同一本次 Prompt 写入全部位置 |
| Negative | 可选，默认不绑定；最多选择 1 个字符串位置 |
| Seed | 必选，整数候选中多选 1～N 个位置；字段名为 `seed`／`noise_seed` 的项作为预选，仍需用户确认 |
| 图片输出 | 必选 1 个 `SaveImage` 或 `PreviewImage` 节点；优先预选唯一的 SaveImage，存在歧义时由用户选择，不猜最终成品 |

正向和 Seed 使用多选控件，Negative 与图片输出使用单选。候选显示节点 ID、类型、字段和可用的自定义标题，例如 `#6 CLIPTextEncode · inputs.text`。条目使用由连接 ID 派生的稳定身份，改名不改变身份，不把工作流伪装成 NAI／GPT 型号，也不要求 ComfyUI 提供模型目录接口。

扫描只遍历各节点的 `inputs`：

1. 值为 `string` 时列入 Prompt／Negative 候选，包含空字符串 `""`。
2. 值满足 `Number.isSafeInteger(value)` 时列入 Seed 候选；候选不等于已确定的随机种子。
3. 数组、对象、布尔值、浮点数等不作为可绑定输入；数组连线原样保留。
4. 输出候选仅为 `class_type` 等于 `SaveImage`／`PreviewImage` 的节点。
5. 标题优先取有效的 `_meta.title`，否则使用 `class_type`；字段身份始终为节点 ID＋输入字段名。

规则可以很短，完整校验单独实现：API 图非空、各节点结构正确、绑定节点和字段存在、类型匹配、无重复或正负向冲突、不覆盖连线、输出受支持。保存和提交前均校验，不能通过配置导入绕过。

自定义提示词节点只要暴露字面量字符串，就可手动绑定，字段名不必是 `text`。若输入来自拼接或翻译节点，应选择真正可替换的上游字符串。结构规则不能判断主 Prompt，也不自动展开表达式、脚本或特殊容器。

更新工作流采用重新导出、粘贴和保存。节点 ID、类型、字段及字面值类型均未改变的绑定可保留；失效项提示重新绑定，不能只凭 ID 未变静默沿用。保存产生新配置版本，一个串行批次使用启动时冻结的工作流、绑定和来源身份，期间更新不影响该批次；地址或凭据失效时按原任务规则停止，不切到新地址继续请求。

只有配置有效并明确保存后才可调用服务；保存、恢复配置或切换条目不自动生图。非秘密配置、JSON 和绑定走现有配置校验及保存路径，Key 由凭据服务管理。

## 3. IMAGE、LoRA 与 ASK 行为

| 区域 | 选中 ComfyUI 条目时的行为 |
| --- | --- |
| 可编辑 | 画板、Prompt、Seed、串行批次数；已绑定时的 Negative |
| Negative 未绑定 | 显示“由工作流固定”，不可编辑，画板原值保留，不能记为本次已采用负向 |
| 尺寸、步数等参数 | 显示“由工作流决定”，不使用画板旧值约束执行；输出宽高以实际解码结果为准 |
| NAI 专属控件 | 隐藏 Anime／Furry、Effort、Complexity、质量／负向预设、角色、Vibe／Precise 等；保留原画板值供切回原型号使用 |
| 结果操作 | 沿用历史、收藏、下载及显式送入 EDIT／CHAT 的路径；ComfyUI 连接本身仅声明文生图能力 |

注入当前画板 Prompt 原文及已绑定的 Negative，不经过 NAI 专属词文编译或追加隐藏的质量／角色内容。空 Prompt 沿用现有 `best quality` 兜底并记录实际发送文本；绑定 Negative 允许发送空字符串。Seed 沿用空值随机、0 合法、显式 Seed 串行递增及 uint32 回绕规则；本次同一 Seed 写入所有绑定位置，其他随机输入不变。

串行批次数表示 `/prompt` 提交次数，每次只接收所选节点的第一张图片，建议工作流固定为单张输出。已下载结果归发起画板，切板不抢画面；未解析管线尺寸时，占位只显示等待状态，不把画板旧尺寸当作实际参数。

LoRA 由工作流中的加载节点执行；换 LoRA 或改权重后重新导出 JSON 即可。本期不解释 `<lora:名称:权重>`，不下载、切换或检查权重兼容性，不增删任何 LoRA 节点。

ASK 复用 `prompt_patch`（`image.prompt`／`image.negative`）与 `params_patch`（Seed／批次数），不增加工具或草稿类型，但需补齐能力感知和写入校验：

- 状态摘要告知当前为 ComfyUI 工作流、可写字段及固定参数；Negative 未绑定时不可写。
- 草稿确认和部分参数恢复均拒绝修改当前工作流固定的尺寸、步数、采样器、角色等字段，不能只在 UI 隐藏控件。
- 模型选择沿用现有条目选择规则；草稿切换条目时，按最终目标重新验证字段能力与配置版本冲突。
- ASK 不获得工作流、连接、Key 或 LoRA 配置写入权限，不调用 ComfyUI API；确认草稿只改画板，不提交生成。

## 4. 执行、容错与取消

全批次进入现有 `runTask`，保持全应用 N=1。无报价保持费用未知，标准网关的报价、余额、`max_cost` 和既有费用行为保持。

```text
冻结来源画板、工作流、绑定与本次 Prompt／Negative／Seed
  → 深拷贝 JSON，只替换绑定输入
  → POST /prompt，body = { prompt: workflowCopy }
  → 取得并记录 prompt_id
  → GET /history/{prompt_id} 轮询该任务
  → 读取 outputs[outputNodeId].images[0]
  → GET /view?filename=...&subfolder=...&type=...
  → 下载原始字节，解码实际格式与宽高
  → 写入本页历史，完成结果处理后释放任务槽
```

HTTP 地址始终来自本次连接，`/view` 的 `filename`／`subfolder`／`type` 经 URL 参数编码构造，不把文件名拼成另一地址。保留原图字节，不假定 PNG，也不重编码为统一格式；JSON／HTML 错误页或无法解码的内容不能作为图片成功结果。

| 阶段 | MVP 行为 |
| --- | --- |
| 提交 | 每次仅一次 POST。4xx／5xx、超时或响应丢失均停止后续批次；可能已受理但没有取得 ID 时显示“提交结果未知，上游可能仍在处理”，禁止自动重发或换源 |
| 历史轮询 | 上一次请求结束后间隔 1000ms 发下一次，不重叠。缺少该 ID 的记录视为尚未完成；检查 `status.status_str === "error"` 等明确失败状态并提取可读节点错误 |
| 短时抖动 | 网络错误、单次读取超时或 502／503／504 允许继续 GET；连续第 3 次失败即停止，成功读取一次清零。鉴权失败、其他明确 HTTP 错误和响应结构错误直接停止 |
| 图片下载 | 只读 GET 同样容忍上述短时抖动，每张最多 3 次尝试；取得完整字节后不重复下载，解码失败不重新生成 |
| 完成但无图 | 服务已报告完成，却没有所选节点的有效第一张图片，作为输出缺失失败，不无限轮询或改收其他节点 |
| 时间上限 | 单次只读请求超时 10s；首期总执行上限沿用现有 240s，包含提交、等待、下载和结果处理。读取容错不重置总期限；真实目标管线若超出上限，需另行明确 ComfyUI 调整，不改其他协议超时 |

以上重试仅针对读取同一任务结果，不是重试生成。失败、超时和取消停止剩余串行任务，保留已完成图片。浏览器后台计时可能延后，不承诺实时一秒调度。

取消先中止本地等待与下载。已取得 `prompt_id` 时，用独立短超时信号尝试一次 `POST /queue`，body 为 `{ delete: [prompt_id] }`，移除自身未运行项；不能复用已中止的信号。不调用无条件全局 `/interrupt`，本期不依赖版本特定的运行中定向中断。队列删除失败不重发、不阻止本地取消；已运行任务可能继续，界面据实说明，不声称 GPU 已停止。

## 5. 历史、收藏与配方

**原图下载完成后，该图在当前页内不再依赖 GPU；点击收藏并写入成功后，才在当前浏览器和站点来源下持久保存。** `#h` 历史仍刷新清空并遵守既有数量限制，`#f` 收藏由用户主动触发。不自动收藏，不把浏览器存储称为文件系统落盘，也不保证 GPU 在下载完成前关机仍能收图。

每张结果记录工作流稳定身份、名称、配置版本、本次实际注入文本与 Seed、所选输出及实际宽高／格式。配方同时保留本批次冻结的模板 API JSON 与绑定快照，结合本次输入可还原提交图，不能只存名称或哈希后称为完整配方。快照不可被后续更新覆盖；历史／收藏、交接和新版备份的参数白名单需相应保留经校验的数据，收藏仍经 `data.write`。连接 Key 和鉴权头不进入配方或普通备份，工作流自身应使用不含凭据的推理图。

配置快照不含模型文件，不能替代 GPU 环境。节点版本、未绑定随机量和运行时行为仍影响复现。配方不自动重建连接或覆盖当前工作流；ASK 只能按可写字段恢复 Prompt／Negative／Seed 等，不能恢复固定管线参数。

短时网络容错仅限本页同一任务和总期限内。首期不持久化待收任务，不在刷新、重新连接或服务重启后自动恢复，也不重提已提交任务。

## 6. 工程落点与部署

| 职责 | 必要改动 |
| --- | --- |
| 纯逻辑 | 新增 `src/domain/comfy-workflow.ts`：API 图与绑定校验、候选扫描、配置快照及深拷贝注入 |
| 传输 | 新增 `src/gateway/comfyui.ts`：提交、轮询、有限读取重试、原图下载、队列删除与结果规范化 |
| 协议与连接 | `src/gateway/profile.ts`、`src/config/connections.ts`、`src/services/connections.ts` 等：新 Profile、配置保存、可选鉴权、配置版本及本地生成条目；无需远程模型目录 |
| 配置与 IMAGE | 供应商弹窗实际位于 `src/overlays/SettingsOverlay.vue`；增加 JSON 与绑定控件，IMAGE 服务及组件按能力收敛控件和执行校验，绕过不适用的 NAI 参数构造 |
| ASK 与结果数据 | 扩充状态摘要、草稿／恢复校验和结构化配方保留，接入原历史、收藏、交接及备份路径 |
| 检查 | 针对配置、请求、任务生命周期、真实字节与持久化补充单元和浏览器模拟验证 |

核心逻辑可以很薄，但不承诺“仅三个文件、250 行”或完全不触及共享模块。目标是不改变既有协议行为，必要接线、严格类型和结果数据责任不能省略。

首期保持静态网页浏览器直连，目标服务或其 HTTPS 代理负责允许 Koma 来源的 CORS，Bearer 模式同时允许相应请求头和预检；本机网络权限按目标浏览器实测。不新增 `server.mjs` 的 ComfyUI 代理，不自动探测本机服务，不提供任意 URL 转发。远程隧道或部署代理由 GPU 环境维护。

## 7. 最小验收

目标硬件为 Linux＋RTX 4090 24GB，复用一份已跑通的单张文生图 API 工作流，只安装所需权重和节点；环境不放入 Koma 源码或 `.local/`。现有 SDXL 独立出图记录可作为后端样例，浏览器直连与 Koma 完整闭环分别验证。

1. **扫描与绑定**：空字符串、改良节点、多 Prompt／Seed、Seed 0、连线及冲突、普通画布格式拒绝；更新保留有效绑定并拒绝失效项。除绑定字段外，图的值与拓扑保持一致。
2. **配置与界面**：无鉴权／Bearer；配置完成前不请求，其他协议继续要求 Key。工作流条目身份稳定，固定字段不可编辑且不冒充实际采用参数，切回原型号保留原值。
3. **提交与读取**：一次提交，短时失败后继续读取；覆盖连续第 3 次失败、成功清零、鉴权错误、节点错误、完成无图、下载抖动、格式／解码错误及总期限，不发生自动重提交或换源。
4. **批次与取消**：全局 N=1、切板归属、冻结版本、Seed 递增、首图选择；中止本地读取且最多删除一次自身队列项，绝不全局中断，后续批次停止。
5. **历史与持久化**：原图字节不变，`#h` 刷新清空；手动 `#f` 收藏成功后刷新可读，配方快照经交接与新版备份往返仍在且无连接凭据，更新工作流不覆盖旧结果。
6. **ASK**：沿用草稿确认与撤销；允许 Prompt、已绑定 Negative、Seed／批次数，拒绝固定参数和未绑定 Negative；不新增工具、不请求 ComfyUI、不自动生成。
7. **真实闭环**：Koma 浏览器提交、下载解码、历史、收藏、下载与 EDIT／CHAT 显式交接；记录样例、环境和结果，不将模拟验收或 SDXL 成功外推为新模型已兼容。

本文不构成推送、发布或额外真实生成的授权；实施与验收遵守现行工程约定。
