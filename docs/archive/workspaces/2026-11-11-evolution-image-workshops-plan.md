# 版本演进：IMAGE 主干、事后立为阶段与工坊交付

日期：2026-11-11。更新：2026-11-13。状态：**已按 IW1–IW6 实施；当前待交付入口已收口。本地验证与限制见第 16 节，未 build／发布。**

本文将用户提供的框架落实到 Koma 当前模块、数据和交互路径，并纳入随后明确的两项决定：**「立为阶段」只提拔选中图且切换 IMAGE 游标；工坊结单后可在原板继续追加交付或另起下一步。**

本文替代[上一轮审阅稿](2026-11-11-evolution-parameters-workspaces-review.md)中“三工作区实时游标”和“用户预先新建空框”的目标方案。旧稿保留为问题证据。现行功能统一维护在[版本演进](../../workspaces/recipe-retrospect.md)。本文归档需求、实施前勘探与本次验收，后续不在此维护日常契约。

## 1. 本次落定的产品边界

| 对象 | 新规则 |
| --- | --- |
| IMAGE | 每棵树只有一路 IMAGE 主干跟踪；手动生成默认追加到当前阶段相册，逐图保留真实配方 |
| 手动升阶段 | 看到结果后「立为阶段」，只移动选中的一张图；不移动后续连抽，不弹范围选择框 |
| ASK 修改 | 确认有效的 IMAGE 创作修改后准备一次待生成目标；首张成功图兑现，微调不改变落点 |
| 并行预设 | 沿用已存在的 `stage_evolution_branch`，保存完整 IMAGE 配方，载入后手动生成、原地转实 |
| EDIT／CHAT | 工坊历史继续由原生版本／会话管理；只有显式交付或明确跨工坊接力才记入演进 |
| 工坊续交 | 首次交付后保留关联锚点；再次交付可「追加到本阶段」或「作为下一步」 |
| 跨区活动 | IMAGE 可以继续创作，同时存在多个 EDIT／CHAT 工单；工单不移动 IMAGE 游标 |
| 对照 | 演进中的词级红绿 Diff 服务于兼容的 IMAGE 配方；工坊交付显示来源图、交付图及操作原文 |
| 生命周期 | 普通收藏、查看、切工作区不结单或结束；显式定稿先收藏，再结束整树活动 |

“并发派工”指多个工单同时存在，不改变全应用默认 N=1 的生成调度。演进树、工单、续交锚点、布局仍只保留本页，不增加数据库或外部 Bridge 协议。

## 3. 参数与身份：继续保留什么

### 3.1 原始记录、比较投影与阶段分开

1. **原始记录**：保留 `ImageRecord.params`、实际 Seed、原始角色槽、模型与尺寸，以及 EDIT／CHAT 的冻结输入。
2. **比较投影**：`Recipe` 用于归纳与展示，已经省略部分运行字段和角色本地 ID；它不等于完整原始记录。
3. **阶段归属**：由当前 IMAGE 阶段、明确采纳的 ASK 方案、事后提拔和工坊交付决定，不由参数签名决定。

`effectiveSignature` 仍可用于候选折叠、配方证据整理；不得重新接回“签名不同就新增 vN”。Seed、权重、分辨率、重绘幅度、蒙版等差异继续如实保存。

停用槽及正负词均为空白的槽只在比较／候选投影中过滤；原始槽保留。当前源码字段是 `on`，不是需求举例中的 `enabled`；工具目前通过 `source_characters` 返回源记录 `localCharacters`。沿用现有字段，不为文字统一另造一套角色 Schema。

### 3.2 三种来源不可混用

| 数据 | 作用 |
| --- | --- |
| 阶段父节点 | 表示用户采纳的创作推进关系，例如 IMAGE v4 → CHAT 交付 v6 |
| 工单来源样本 | 某次派工或后续接力确切选中的图片，用稳定记录绑定保存 |
| 实际输入证据 | 每次操作真正使用的底图、参考、上下文、蒙版和参数，来自 `EvolutionInput` |

例如 EDIT 的第二次交付挂在 v6 下方，但实际仍使用早期原图作为重绘底图：连线表达精修推进，详情明确列出真实底图，不能互相覆盖。

`#h/#e/#c/#f` 是显示引用，工单应复用 `ImageTagBinding` 的 `record_id/entity_key/scope`。CHAT 使用会话／轮次／版本／资产的完整身份。图片字节相同不代表操作记录相同，不能仅以 Blob 或哈希认领工单。

## 4. 目标状态结构与责任分工

以下为内部设计建议，字段名在实施时结合类型定稿；不新增模型可写的前端记账字段。

| 状态 | 内容与责任 |
| --- | --- |
| 树 | 稳定 ID、revision、active／ended、节点／连线、批注、定稿、布局和相机 |
| `imageTrack` | 关联的 IMAGE boardId、当前阶段与具体样本、跟踪代次、可选的 ASK 待生成目标；每树至多一路 |
| IMAGE 待生成目标 | 只有已确认 ASK 修改才准备的单次落点、父样本和独立位置；没有预存完整蓝图的语义 |
| `generated` 节点 | 已入树的 IMAGE 样本或工坊交付样本；增加明确的原生来源标记，按样本读取真实配方 |
| `staged` 节点 | 沿用已有完整 IMAGE 预设配方与基底；不拿它表达工单 |
| `workshopTickets` | 待交付的工单 ID、树 ID、源样本、父节点映射、目标 EDIT 板／CHAT 会话及必要分支绑定、挂件位置 |
| 工坊续交关联 | 目标板／会话与最近交付节点、具体交付样本的关联；交付后保留，不需要任何逐张生成游标 |
| 交付记录 | 所选真实样本、成品／方向否定语义和简短说明；可与 generated 节点的逐样本资料合并存放 |

工单第一次结单后，虚线挂件转为正式节点，工坊续交关联仍有效。之后生成只改变工坊自身历史，不自动再长一个虚线挂件。只有再次明确派工、接力或用户选择“作为下一步”才产生相应关系。

目标状态由 `retrospect/store.ts` 持有；工作区服务继续持有图片和原生历史。`ask/service.ts` 负责协调读写与界面入口，不让组件自己拼工单或按当前页面推断归属。必要时将工单纯逻辑拆到 `retrospect/workshops.ts`，不另建应用级图片库。

现有 `services/handoff.ts` 的短时图片传输票据与 Workshop Ticket 是两件事：前者负责一次导入，后者负责本页主题中的派工与交付关系。二者通过成功接收回执关联，不混用过期时间或持久化规则。

## 5. IMAGE：入相册、提拔和 ASK 进阶

### 5.1 默认入相册

无活动树时沿用 IMAGE 历史；有活动树且没有待生成目标时，任何手动配方修改后的成功图均进入提交时的当前 IMAGE 阶段。各样本可有不同配方，不需要相似度阈值。

批量提交冻结目标，同批成功结果进入同一阶段。失败、取消、仅预览不增加样本；展示拼图 `isComparison` 不入树。结果事实按提交时目标归属，返回时不抢用户后来切换的游标。

### 5.2 「立为阶段」——用户已明确

入口复用 IMAGE 图片操作栏与演进相册当前样本操作区。

1. 只对树内的 IMAGE 真实样本提供操作；原阶段只有一张图时隐藏或禁用，避免留下空节点。
2. **仅将选中的一张图从原阶段移到新子节点，其余尝试留在原阶段。** 不复制计数，不按时间带走后续图片，不弹选择框。
3. 新节点挂在该图原所属阶段下方。`v(N+1)` 表示分配下一个可用版本号，不是把父节点编号机械加一；保留已有节点 ID。
4. **IMAGE 主游标切到新节点及该样本**，包括用户从其他阶段选图提拔的情况。此后新提交的生成进入新阶段；不自动恢复该样本配方，不擅自覆盖当前表单。
5. 新节点以该图为封面，标题由尺寸／词文／角色的简短变化摘要产生，可编辑；不额外调用命名模型。原节点封面若被移走，从剩余样本确定新封面。
6. 原节点位置保留，新节点仅做局部布置；已有预设、工单、交付来源若恰好引用被提拔的样本，按稳定记录重映射到新节点，保留它们自己的位置和批注。
7. 操作在一个树 revision 内提交。容量不足或映射校验失败时不移动任何样本，不造成半拆分。

提拔发生在已准备的其他 IMAGE 目标之后时，视为用户显式改变下一次归属：完整 staged 分支保留但不再选中；未兑现的普通 ASK 目标解除当前选中。已在途请求继续按原冻结目标处理，不能误记到新提拔阶段。

例如，当前最大版本号为 v3，其相册包含 `#h8、#h9、#h10`。选中 `#h9`「立为阶段」后：

| 对象 | 操作后的状态 |
| --- | --- |
| 原阶段 v3 | 保留 `#h8、#h10`；`#h10` 虽然生成得更晚，也不会被一起带走 |
| 新阶段 v4 | 仅包含 `#h9`，连线为 v3 → v4 |
| IMAGE 游标 | 指向 v4／`#h9`；随后新提交的 `#h11` 进入 v4 |

这只调整演进中的样本归属；IMAGE 原生历史、图片字节和各图配方保持原样。

### 5.3 ASK 确认与预设

- 只对**内部 ASK 的有效 IMAGE 创作修改**准备新落点；纯分析、文件、Slate、标题或无实际改动不准备。
- 用户确认后再微调、改 Seed 或分辨率，首张成功图仍兑现既定目标，后续手动生成继续入该阶段。
- 尚未生成时连续修订同一方案，复用当前待生成目标；明确换基底则重新绑定，避免遗留空框。
- 已载入完整 staged 时，继续用该 staged 接收首图；不叠加第二个普通 ASK 空框。
- 工坊内 ASK 草稿继续修改原生配置／输入，但不创建 IMAGE 阶段，也不自动交付工单。
- `stage_evolution_branch` 保持单轮最多成功新建 4 个、每树 16 个未生成预设；成功逐个保存，单次校验失败不影响前序分支。

## 6. 工坊：派工、首次交付与原板续交

### 6.1 派工发生在明确交接成功后

活动树中的具体样本被送入 EDIT／CHAT，且目标完成接收后，才创建工单。派工父节点由来源样本所在节点确定，与 IMAGE 当前游标无关。直接打开工作区、浏览旧图、改变查看版本、选择另一张参考图，都不能自行触发派工。

多个 EDIT 板、CHAT 会话可分别挂在不同父节点下；切换工坊板／会话只改变查看位置，不销毁未完成工单。未关联活动树的普通编辑和对话仍可独立使用，不自动造一棵树。

同一次接收回执重复通知必须幂等。同一源图再次“打开”已有目标不能重复挂单；明确另开新目标则可以创建并列工单。CHAT 多图交接以明确选中的底图为派工来源，其余参考图不会各挂一单。

工坊目标被新来源复用时，不能把旧工单静默覆盖。需依据明确交接记录与实际分支辨认结果；存在多个可匹配工单时，在交付处显示来源供选择，不按“最近打开的树”猜测。

### 6.2 第一次「记入演进」

只针对已完成、可精确定位的实际图片；临时合成预览、纯文本、尚未应用的 Photopea 回传、生成失败记录不作为交付图。

| 操作 | 入树结果 | IMAGE 游标 |
| --- | --- | --- |
| 阶段成品 | 在原工单位置生成一个工坊交付节点，选中图作为首个样本和封面 | 保持原位 |
| 方向否定 | 同样保留真实样本，附“方向否定”标识与可选说明，不删除原图 | 保持原位 |
| 设为最终定稿 | 交付所选图、确保已收藏，再记录准确样本和根到节点路径，结束整树活动 | 停止跟踪 |
| 取消挂靠 | 移除未完成工单和对应续交关联，不改工坊已有内容 | 保持原位 |

同一张已入树记录重复交付为幂等操作，定位现有节点，不制造重复 vN。原直出与正式回贴是不同记录，交付用户当前明确选中的那一个，原直出仍可在工坊查询。

### 6.3 结单后继续交付——用户已明确

首次交付点亮为 v6 后，**该 EDIT 板／CHAT 会话的交付锚点自动顺延到 v6 和刚交付的样本**，保留在原工坊继续工作的能力。它只控制下一次交付归属，不改 EDIT 底图、CHAT 上下文或 IMAGE 主游标。

再次选中一张新结果点击「记入演进」时，在现有轻量菜单中提供两种明确操作：

| 选择 | 行为 |
| --- | --- |
| **追加到本阶段 v6** | 新图追加进 v6 相册，不覆盖旧样本；作为更新后的代表交付图，封面切到新图；续交锚点保持 v6，但具体样本更新为本次交付图；节点与连线位置不变 |
| **作为下一步** | 建立 v6 的新子节点，选中图为其首个样本；工坊关联锚点顺延到新节点 |

两者都不退出工坊、不自动生成、不挪动 IMAGE 主游标。成品／否定语义与“追加／下一步”是不同维度；否定记录按具体样本保留，不能因后来追加成功图就抹去此前尝试。

连续交付的自动顺延只对该关联生效。如果用户从另一个旧样本明确重新派工，按新来源建立分支，不能仍接在刚才的 v6 后。

以同一 EDIT 板先修手、再修海报字、最后调整光影为例，IMAGE 主游标始终停在原来的 v5：

| 动作 | 演进结果 | 该 EDIT 板的续交锚点 |
| --- | --- | --- |
| 修手图 `#e3` 首次记为阶段成品 | 原工单原地转为 v6，包含 `#e3` | v6／`#e3` |
| 继续修字得到 `#e4`，尚未交付 | 仅 EDIT 历史增加结果；v6 不变，也不新增待交付空框 | v6／`#e3` |
| 对 `#e4` 选择「追加到本阶段 v6」 | v6 包含 `#e3、#e4`，代表图为 `#e4` | v6／`#e4` |
| 再修光影得到 `#e5`，选择「作为下一步」 | v6 → 新阶段 v7；v7 仅含 `#e5`，v6 两张旧图保留 | v7／`#e5` |

样本追加／新建节点、代表图和续交锚点必须在同一次交付中更新；失败时均保持原状态。重复交付已入树的记录仅定位已有节点，不重复追加，也不把已顺延的锚点拨回旧图。工坊锚点变化仍不等于更换原生编辑底图。

### 6.4 接力与自动结单

- **所选图已入树**：从它实际所在节点派出下一工单；不重复结单。
- **所选图属于尚未结单的工单**：目标接收成功后，将这张图作为阶段成品结单，再在新节点下挂下一工单。
- **已交付后又选了尚未入树的新图接力**：建议默认追加到当前交付阶段，再从该具体样本接力；需要独立精修阶段时，先显式选择“作为下一步”。该默认是本规划建议，避免接力替用户自动细分阶段。
- **连续 CHAT → EDIT → CHAT**：每次保留新的来源记录与目标绑定；即使返回同一 CHAT 会话，也追加关系而不复用旧节点作回边，防止成环。

接力事务需要冻结来源样本、来源工单／锚点和目标接收身份。目标接收失败或取消时，不先结单、不留下假工单；同一次回执重放不重复追加。普通演进记账失败也不能把已完成的生成标成失败，更不能重发上游请求。

## 7. 实施前交接缺口与接入范围

| 现有入口 | 当前路径 | 所需接入 |
| --- | --- | --- |
| IMAGE → EDIT | `ImageStage.resultAction → editor.open`，已有 `sourceId/settings` | 在完成源图导入后取得明确目标板与版本，创建对应工单 |
| IMAGE → CHAT | `ImageStage.resultAction → createHandoff.queue → chat.claim` | 图片传输补稳定来源关联与成功接收回执；目前只传 Blob 无法可靠识别来源 |
| CHAT → EDIT | `ChatTurn.openEdit → editor.open`，已有具体 CHAT 来源 | 接收成功后按所选版本结单／接力，不能取当前最新回复代替所选图 |
| EDIT → 新 CHAT | `EditWorkspace.sendSelection → createHandoff.queue` | 同样补来源信息；所选 EDIT 版本必须冻结到接收完成 |
| EDIT → 原 CHAT | `editor.useResult → chat.useEditorResult` | 当前只传图片／名称／尺寸，需补精确 EDIT 记录；尊重其现有“附为参考图”的行为，不擅自改底图 |
| 区域批注 → CHAT | `services/annotations.ts → chat.prepareAnnotations` | 原图作为来源，编号指示图只是辅助参考；同一次交接只挂一个工单 |
| ASK 交接 | `draft/apply.ts → writeHandoffDraft/createAskBoard/writeAskDraft` | 在用户确认、目标写入成功后提交工单；提议阶段不挂单；共享写入失败与撤销补偿 |
| HOME／收藏打开编辑 | `HomeImage.vue → editor.open` 等 | 仅已绑定活动树的明确来源才派工；普通“定位原版本”与“从此图另开处理”须区分意图 |

不能直接把所有 `onEvolutionMove` 改名为“派工”：当前事件还用于 EDIT 换底、CHAT 选择／跟随最新、恢复和导航，会造成误挂单。应以明确的交接完成事件作为入口，返回目标身份；原生查看事件不记账。

工单附加信息建议保留在本页协调层，由传输票据 ID 或 ASK 写入回执关联。跨刷新后图片仍可按原传输规则接收，但旧页演进关系失效，不以旧 `retrospectId` 激活新页树。普通图片来源元数据可沿原路径保存，工单本身不进入持久会话或备份。

### 「送回 IMAGE」需要准确界定

当前 `drawing.ts` 目录只选 `provider === 'novelai'` 的模型，IMAGE 是绘图配方表单；`ImportSheet.vue` 明确拒绝把 CHAT 文本当绘图配方，EDIT 结果也不自动进入 `#h` 历史。因此，框架中的“导回 IMAGE”尚无通用的像素编辑接收端，不能在文档中写成已经具备。

本规划建议拆成明确的原生动作：

- **返回 IMAGE 继续构图**：回到关联的 IMAGE 画板；若需要恢复某份 NAI 配方，选择真实 IMAGE 样本并走可撤销恢复。工坊图仍保持原生身份。
- **用作 IMAGE 参考**：在当前 NAI 能力支持时，经现有参考图流程导入；这与把成品当作重绘底图含义不同。
- **继续修改工坊成图像素**：进入 EDIT／CHAT。

只有实际完成了明确的内容交接才触发自动结单，单纯切回 IMAGE 页面不触发。若本轮产品还要求“工坊结果作为 IMAGE 新分支的直接底图”，需要另行定义 IMAGE 接收能力及主干回接语义；本方案不以伪造 NAI 配方来填补该缺口。

## 8. ASK 重整：IMAGE 可重划，交付关系自动保留

当前 `preserveStaged` 只处理未生成预设。新方案必须在同一次重整事务中保留以下对象：

1. 所有未生成 staged 的 ID、完整配方、精确基底及位置。
2. 已结单 EDIT／CHAT 节点及其全部已交付样本、原文、成品／否定标识和子工坊链。
3. 待定工单、工坊续交锚点、IMAGE 待生成目标及各自来源绑定。
4. IMAGE 游标、定稿样本、用户批注和仍有效的节点位置。

建议复用现有 `show_retrospect` Schema：模型提交可重整的 IMAGE 已生成节点及它们的阶段关系；工坊节点、工单与 staged 由本地合并保留，不要求模型反复抄写前端状态。若模型回传了受保护节点，只接受身份与内容一致的引用，不能以模型文本改写已交付证据。

父节点重映射始终按**来源样本的稳定记录 ID**：例如 #h4 从 v2 被重划到 v7，其 EDIT 工单与预设随该来源指向 v7，挂件位置不重置。一个旧节点被拆成两个时，不能只按旧节点 ID 或重合图数量猜工单归属。

重整不能删掉受保护对象依赖的来源样本。返回具体缺失引用，供 ASK 保留后重调；不能把工单挂到任意剩余节点。合并后统一检查容量、节点 ID 冲突、单父和无环，再一次提交。

在途生成目标也要参与映射保护。新结果、用户提拔或工坊交付使树 revision 变化后，旧 `expected_revision` 必须失效；拖动和缩放仍只更新展示状态，不让 ASK 草稿无故失效。

## 9. 恢复、定位与对照呈现

### 9.1 三类动作各走原路径

| 所选对象 | 主操作 | 应有边界 |
| --- | --- | --- |
| IMAGE 已生成样本 | 恢复到 IMAGE 画板／从这里开始 | 恢复原生配方，更新 IMAGE 游标，整体进入共享 50 步撤销栈 |
| IMAGE staged | 载入画板 | 沿用 `stagedLoadPlan`；完整配方与目标一起写入并可撤销 |
| EDIT 已交付样本 | 定位原编辑板及版本 | 优先复用 `editor.locate`，只切查看；“设为底图”另走 EDIT 原生显式操作 |
| CHAT 已交付样本 | 定位原对话及版本 | 精确定位会话／轮次／版本／资产；不能直接复用会改变分支底图的 `restoreEvolution` 来冒充纯定位 |
| 未完成工单 | 打开对应工坊 | 导航到已绑定目标；不改 IMAGE 表单和主游标 |

IMAGE 现有 `restoreRecipe` 有字段校验和失败补偿，但没有创建共享历史记录；需复用 `prepareRecipe` 的纯校验，接入 `draft/apply.ts + stack.ts`。不能继续用直接写入后“看起来成功”代替可撤销恢复。

“完整配方”需区分运行选项：当前恢复保留画板 Seed／批次数，原图实际 Seed 仍可查看；staged 只有显式覆盖才带入 Seed／张数。本轮建议沿用这一行为并明确文案，不在重整状态机时顺便改变抽卡习惯。原始角色 ID 与写入后重新分配的槽 ID 按现有映射处理。

IMAGE 原板不存在、原图仅剩缩略图、工坊板／对话被删除，应分别处理。仅缩略图但完整配方仍可恢复 IMAGE 配方；缺原件不能继续像素编辑或设为定稿。来源板不存在时给出明确状态，不因当前在 CHAT 就误走 CHAT 恢复。

### 9.2 演进对照的语义边界

| A／B | 演进面板展示 |
| --- | --- |
| IMAGE ↔ IMAGE，输入契约兼容 | 原始 Prompt／Negative／有效角色词级 Diff，另列实际参数变化 |
| IMAGE ↔ IMAGE，记录不完整或字段含义不兼容 | 展示已知原文与参数，标出缺失／不同输入契约；不补造默认值 |
| 含 EDIT／CHAT 的任一侧 | 来源图与交付图 A/B、工作区和操作类型、各自原文与输入证据；不生成整段全删全增 |
| 同一工坊两次交付 | 成品对照，各次模型／底图／参考／蒙版／处理参数和说明；不因同工作区就自动套词级替换 |

判断输入契约使用已记录的能力／操作事实，不按模型显示名猜语法。IMAGE 的签名、参数和空槽过滤继续复用；演进展示模式应在 `diff.ts/groups.ts/RecipeReview.vue` 统一表达。

本轮只收敛演进对照，不取消 ASK 草稿按步骤展示实际删增，也不删除 EDIT／CHAT 的原始输入记录或其他只读查询能力。

## 10. ASK 接口与提示词的最小调整

“一读＋两写”描述的是演进组织能力，不是删除整个 ASK 的其他工具。

| 接口 | 项目对应调整 |
| --- | --- |
| `get_recipe_clusters` | 返回关联树的 IMAGE 候选、完整源词文与原始角色槽、已交付工坊节点、staged 和必要待交付摘要；不把工坊全部中间试错塞入 IMAGE 候选序列 |
| `show_retrospect` | 首次建立 IMAGE 主干，或携带 revision 重整 IMAGE 已有历史；本地自动合并受保护对象，更新同一棵树 |
| `stage_evolution_branch` | 保持 IMAGE 专属、每次一分支、同轮非终结调用与现有预算校验；只接受树内真实 IMAGE 原始配方 |
| `propose_draft` | IMAGE 确认新改法准备待生成目标；EDIT／CHAT 草稿继续走原生配置／交接流程，不自动入树 |
| `set_retrospect_status` | 保留显式结束／继续的现有能力；这是生命周期控制，不让模型管理单个工单 |

在 EDIT／CHAT 发起 ASK 时，可经现有工坊关联读取对应主干树；没有关联时不凭当前工坊历史新建实时树。建议指引先回 IMAGE 选择主题历史；原生看图、参数分析和草稿能力仍可用。旧演进快照继续可读，不新增跨刷新迁移。

提示词只交代创作含义：IMAGE 手动尝试可事后整理；用户采纳新方案会进阶；工坊只收选定交付结果；跨区原文不可互当改写。工单 ID、接收回执、容量预留和撤销键不写进系统提示词。

`get_recipe_clusters` 可用简短 `kind/origin/status/source_image_id` 区分已生成、待生成、待交付，但不向模型开放工单写入字段。保持 `local_characters` 的原始槽位语义与现有 `source_characters` 输出映射。

### EDIT 回退草稿的连带处理

当前 `EditRollback.evolution` 是必填，`parseDraft` 的 EDIT `base_image_id` 依赖活动演进游标。移除 EDIT 游标时不能连带删掉已提供的同板回退能力。

建议把它解耦为 EDIT 本地的来源版本／配置／蒙版修订校验：同板同尺寸回退仍经确认与撤销，保留当前蒙版，不触发交付、不移动 IMAGE 游标。IMAGE 的 `base_image_id` 继续绑定主干基底；CHAT 的 `chat_distill_branch` 继续只处理原生会话分支。

## 11. 容量、撤销、在途与资源

### 11.1 容量

已经明确的上限保持：**80 个总节点、16 个未生成 IMAGE 完整预设、每轮最多新增 4 个成功预设**。工坊工单不占“16 个预设”的配额。

建议为承诺原地转实的空位预留总节点容量：

`已生成节点 + staged 节点 + 未兑现 IMAGE 目标预留 + 待定工单预留 ≤ 80`。

这是待审的容量实现口径，不新增独立的工单上限。结单／转实消费预留而不重复计数；取消挂靠释放预留。续交追加不增加节点，新一步和单图提拔需要一个新名额。满额时仍可继续原生生成和相册追加，不能删除旧分支或阻断正常创作。

### 11.2 写入与撤销

- ASK 确认修改、IMAGE 恢复和 staged 载入使用现有共享 50 步栈；表单与演进状态一起成功或补偿。
- ASK 交接确认需同时处理目标写入、工单创建及接力结单；撤销预检不能继续只以树 ID 判断所有变化，需区分 IMAGE 状态和具体工单／关联。
- 提拔、手动交付等纯树操作建议复用同一栈的演进操作类型；撤销恢复成员、封面、锚点和位置，不回滚工坊实际修图历史。
- 已有后续生成、接力或重整依赖时校验冲突，不能用旧整树快照覆盖新成果。
- staged 或 ASK 目标已生成后撤销／重做，只切换表单与选择，不删真实结果，不复活空壳。
- 显式最终定稿先完成收藏。收藏失败不关闭工单、不结束树；收藏成功后若树已变化，保留正常收藏并提示重新选择，不能错误宣称已定稿。

### 11.3 在途和生命周期

IMAGE 提交冻结树、主干 boardId、代次、阶段／目标、具体基底；工坊只冻结原生操作与其派工来源证据，不为每次生成预留节点。后台完成时不能根据当前选中页寻找归属。

切 IMAGE 具体画板沿用换题边界，解除对应 IMAGE 自动收集；**不能顺手删除已经派出的工单**。切 EDIT 板／CHAT 会话也不取消工单。整树仅在明确结束／定稿时停止新的派工与交付；建议未完成挂件保留为已停止的只读记录，继续演进后重新校验目标。

活动树已结束时，晚到图仍由原工作区保存，不改定稿和游标。取消挂靠后继续生成，不重新挂靠。目标板删除或来源不可用时，显示失效目标并允许清理关联，保留已交付节点的可读证据。

### 11.4 图片保留

继续通过 `drawing.retainHistory`、`editor.retainRecords` 和 CHAT 现有资产引用管理资源。树内样本、待派工来源、正在交付的选中图和撤销所需记录应纳入引用保护；工坊未交付的中间结果遵守原历史上限，不因有工单而无限保留全部原图。

取消／删除／撤销应释放相应引用；演进数据只持稳定绑定与小型参数，不复制大图进入 reactive。刷新后工单和布局结束，已收藏图仍按收藏契约保留。原件已释放时不把缩略图伪装成可精修原图。

## 15. 已采纳的项目口径

已明确：IMAGE 主干、手动入相册、**单图提拔且游标必跟进**、ASK 采纳进阶、工坊只交结果、**原板续交可追加或另起下一步**、跨工坊接力、原生定位、异构非红绿对照，以及 4／16／80 上限。

用户已批准本稿后，以下项目边界一并纳入实施：

1. 工单与普通 IMAGE 待生成目标预留 80 总节点名额，保障原地兑现。
2. 已交付后新结果直接接力，默认追加到当前交付阶段；明确下一步时才另建阶段。
3. “返回 IMAGE”区分导航、恢复 NAI 配方与参考图输入；通用像素底图回接尚无现成路径。
4. 纯树操作复用共享撤销；最终定稿与收藏按各自事实处理，不隐式取消收藏。
5. 保留 `set_retrospect_status` 及 EDIT 本地回退能力，移除它们对工坊实时游标的依赖。

这些边界已用于本次实现；未改变 IMAGE 对像素编辑底图的接收能力，也未扩展外部 Bridge。
