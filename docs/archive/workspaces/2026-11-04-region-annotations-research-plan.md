# 图片区域批注：上游核对与实施规划

日期：2026-11-04。状态：**调研与范围决策归档；Step 1～3 及人工审核后回贴已完成本地实现，未发布。** 现行行为统一维护在[图片区域批注](../../workspaces/annotations.md)。第 5.2 节第 3 条已按确认改为同方向、同宽高比（≤1.5% 误差），不要求同像素宽高。

勘探时的代码基线：`main` / `252552895ce7410e68566f1528499f5d280c5425`（v0.4.0 发布记录提交）。勘探阶段只读取公开上游文档、核对项目源码并整理规划；未调用带 Key 的接口、未执行收费生成，也未修改产品代码或发布。第三方供应商未提供具体接口契约，本次不能证明其兼容性。

## 1. 结论

方案方向可行：**一份绑定原图的区域批注，分别用于改图提示、EDIT 蒙版和 ASK 看图。** 归一化坐标、SVG 交互和 Canvas 派生图片均适合当前工程，不需要增加第三方依赖。

原稿有七处需要修正，否则容易出现“界面能框选，实际请求却不对”的情况：

| 原稿中的假设 | 核对结果与建议 |
| --- | --- |
| 连续数字 `id` 同时代表批注身份 | 数字只作显示序号；另用稳定 `key`，并绑定具体原图实体与版本，避免删除重排后评论错绑 |
| 归一化坐标自然保证对齐 | 还必须共用图片实际内容矩形、EXIF 方向和缩放／平移变换；不能对着整个视口或有留白的 `<img>` 外框换算 |
| 双图法可以精准限制修改范围 | 双图是视觉提示，OpenAI 的 Mask 也是引导，均不保证区域外逐像素不变；硬性保留需要客户端合成 |
| 单图渠道可以自动回退到 Mask | 单图输入和支持 Mask 是两种独立能力；Gemini 原生当前没有独立 Mask 字段，不能这样回退 |
| 黑白 Mask 可通用于各接口 | Koma／NAI 使用白色表示重绘；OpenAI 需要透明区域表示重绘，Alpha 语义相反 |
| ASK 可直接调用 `crop`、`edit_action` | 实际为 `view_image(spec:"crop")` 和 `propose_draft`；坐标单位、看图前置和草稿权限均需对接 |
| 合并评论即可成为 NAI 分区修改指令 | 一个合并蒙版配一份提示词，并没有“第 1 区执行第 1 条”的协议绑定；诊断文字也不一定适合直接写入 NAI 正向提示词 |

实施范围锁定为共享批注＋ASK、EDIT 形状转换、CHAT 双图交接，并在 GPT Image 2／Gemini 的双图改图结果上增加**人工审阅后应用的本地外扩／羽化回贴**。取消原第 4 步的 OpenAI Mask 适配，不扩展 `ModelLink` 的 Mask 能力字段，不增加 CHAT 独立 Mask 资产。

**NAI 本来已有蒙版重绘和局部回贴，继续沿用。** 批注只可作为现有蒙版／聚焦框的便捷输入，不为本次防劣化方案改写 NAI 请求、聚焦处理或回贴规则。新增本地保护流程针对 GPT Image 2／Gemini 这类全图改图结果。

**结果返回后先看模型直出，人工核对画幅、比例、构图和位置；用户点击「应用蒙版」后才正式回贴。** 程序的尺寸检查不能代替人工审阅，也不能在结果到达时自动套蒙版或自动替换下一轮底图。

## 2. 实际上游能力

以下结论依据本次打开的官方页面，链接集中在文末。文档能力、当前代码接入和真实生成效果分别描述。OpenAI Mask／markup 的资料保留为勘探依据，不属于本次实施范围。

### 2.1 OpenAI：GPT Image 2

- 官方 `gpt-image-2` 模型页明确列出 `/v1/images/generations`、`/v1/images/edits` 和 inpainting；不能把它直接作为 `/chat/completions` 的图像模型使用。[O1]
- Images 编辑接口支持多张输入，GPT Image 上限为 16 张；当前参考页既展示 JSON 图片引用，也保留 multipart `image[]` 示例。Koma 已使用 multipart，本功能可以沿用。[O2]
- Mask 应作用于第一张输入图，因此**干净底图必须处在第一位**。蒙版需与被编辑图片对齐、含 Alpha 通道，重绘部分透明；普通黑白 PNG 不等价。[O2][O3]
- 官方明确说明 GPT Image 的 Mask 是提示引导，模型可能不严格遵循其形状。双图加编号也是提示策略，不能宣称“其余区域绝对不变”。[O3]
- 若要保留区域外像素，须在拿到尺寸／位置可对齐的结果后，本地只替换蒙版内像素。Koma 已有这种合成函数，但 GPT 返回的画幅、尺寸和内容对齐仍须验证；不能把任意比例结果强行拉伸回原图。
- `gpt-image-2` 不应附加 `input_fidelity`，当前接口参考要求省略该参数。新增批注功能不应顺便注入一套固定参数。[O2]

**与官网“批注”相关的新信息：**本次查到 Images API 已有 `markup`：与第一张图尺寸、方向一致的透明 PNG 标记层，支持 **GPT Image 2.5**，不能和 `mask` 同时使用。这是明确的模型能力区别，不能套用到用户计划中的 GPT Image 2，也不能假设所有 OpenAI 兼容渠道都支持。[O2]

这里仅确认公开 API 的 `markup` 字段；没有证据证明官网具体批注界面内部采用哪条链路。首轮仍可用通用双图法，2.5 专用 `markup` 留作后续可选适配。

### 2.2 Gemini：香蕉系列

- 官方支持图片加文字进行编辑，也支持适用型号的多参考图。Gemini 2.5 Flash Image 的文档表述是“最多 3 图效果最佳”；Gemini 3 Pro Image 支持合计最多 14 图，3.1 Flash Image 也有多参考图说明。[G1]
- Koma 当前预设将上述数量设为本地上限；其中 Nano Banana 2 Lite 的 `inputImages` 为 **1**。官方总览只说 Lite 不针对多参考输入优化，本次没有找到可据此断言“所有 Lite 服务端一律硬性只收一张”的契约。代码限制和官方建议须分开写。
- 官方“**Inpainting (Semantic masking)**”示例是文字描述要修改的对象，不是上传逐像素 Mask 的示例。本次核对的 `GenerateContentRequest` 没有独立的图像蒙版字段。[G1][G2]
- 因此，Gemini 可尝试“干净原图＋编号指示图＋区域说明”；不能发送 OpenAI 的 `mask` 字段，也不能把一张黑白图片声称为协议级蒙版。
- 仅单图可用的来源，可明确选择“原图＋方位文字”这种较弱的方式；若必须有视觉指示，应提示换用支持双图的来源。不要静默把指示图当唯一底图。
- Koma 图像链路当前使用独立的 `generateContent` 请求，将选中的历史文字和图片重新组装；它不是 Gemini 原生的有状态连续编辑。ASK 的 Gemini 签名处理属于另一条推理链路，不能据此声称图像链路已经接通。

本次 Google 的旧文档地址跳转到 Google AI Studio 文档，图像总览已以 Interactions 示例为主；已另外读取仍在公开的 `generateContent` 请求规范，核对 Koma 实际使用的接口。本次不建议为批注迁移 API 或更换模型。[G1][G2]

### 2.3 NovelAI：普通与聚焦重绘

- 官方 Inpaint 界面用选区蒙版决定修改部分；Focused Inpainting 会选择局部范围、放大处理并保留周围上下文。[N1]
- Koma 已实现普通重绘、聚焦裁切／放大和返回后的局部回贴；批注转 Mask 可以复用这些能力，不需要发明新的上游“区域批注 API”。
- **聚焦框是处理范围，蒙版是修改范围。** 圆形或多边形的 `bbox` 只能转为聚焦框；把 bbox 当成蒙版会把形状外的内容也选进去。
- 官方页面提到聚焦框内不画蒙版时可重绘整个框；Koma 当前明确拦截空蒙版。首轮继续沿用 Koma 规则：从批注形状生成蒙版，再设置包含它的聚焦框。
- 当前代码只为官方、准确映射的 V4.5 Full／Curated、V5 Full High／Medium 开放聚焦重绘；V5 Curated 不开放独立重绘。保留现有固定五型号规则。
- 多区域合并为一张 Mask 后，上游收到的仍是一份正向／负向提示词，并没有逐区域 comment 参数。若各区域要求相互冲突，建议用户逐个区域处理，或先由 ASK 整理一份可审阅的提示词；不自动拆成多次收费请求。

以上属于已有能力及输入约束，不是要求重新实施 NAI。GPT／Gemini 新增的外扩／羽化回贴不插入 NAI 管线；NAI 仅复用第 5.3 节的批注转蒙版／聚焦框入口。

本次成功读取官方 Inpaint 文档；公开 `https://image.novelai.net/docs/doc.json` 返回 403，未重新取得 API Schema。因此具体 `infill` 请求字段以上游现有适配源码与仓库已有核验记录为依据，不写成本次真实接口测试通过。

### 2.4 第三方供应商

“OpenAI 兼容”“相同模型 ID”“有文字和图像入口”均不能证明支持多图、Mask 或 `markup`。

当前按来源配置的 `image_capabilities.fields` 只处理标量参数。它不能表达文件上传、多个图片角色或 Mask 编码；`mask` 还在应用保留字段中，不能通过“新增参数”绕过。

本次不再新增上述 Mask 能力配置。CHAT 使用既有多图请求和 `maxImages` 检查；支持双图的来源发送干净原图＋指示图，单图来源明确提示换源或由用户选择仅带方位文字。实际提交仍按完整图片数和参数筛选来源，不自动丢图，也不在失败后换协议重试。

本地回贴不需要上游 Mask 支持；图片输入数量、格式、返回图片和既有参数兼容仍按当前来源检查，不声称任意渠道都一定接受双图。

## 4. 数据结构与坐标约定

### 4.1 保留归一化，补齐身份

建议在原稿基础上调整为以下结构。它是拟议类型，不是已实现 API：

```ts
type AnnotationShape = "rect" | "ellipse" | "polygon";
type UnitPoint = { x: number; y: number };
type UnitRect = { x: number; y: number; w: number; h: number };

interface RegionAnnotation {
  key: string; // 稳定身份，用于选中、编辑、撤销和 Vue key
  shape: AnnotationShape;
  bbox: UnitRect;
  points?: UnitPoint[];
  comment: string;
}

interface ImageAnnotations {
  image: ImageTagBinding; // 复用原图实体、记录、作用域与具体版本
  width: number;         // EXIF 方向归一化后的原图尺寸
  height: number;
  regions: RegionAnnotation[];
}
// 展示和出站编号 = regions 中的位置 + 1，不作为稳定主键。
```

原图 Blob 和派生图放在服务普通内存／现有资产池，轻量几何才交给 Vue。指示图是原图的派生物，不能复用原图 `entity_key` 冒充同字节图片。

同尺寸的新生成版本也不自动继承批注：尺寸相同不代表眼睛、衣服或格子的位置相同。切换查看版本应按具体绑定恢复或开始新的批注；异步渲染完成时复核绑定，避免落到用户刚切换的图片上。

### 4.2 几何与校验

- `x/y/w/h` 以及顶点均为有限数；`w/h > 0`，外接框在 `[0,1]` 内；多边形至少三个不同顶点、面积非零。
- 多边形以顶点为几何来源，每次编辑后重新计算 bbox，禁止独立编辑两套坐标。首轮建议拒绝自交多边形，保持 SVG 与 Mask 填充一致。
- `ellipse` 是椭圆。若工具标“圆形”，拖拽必须按**原图像素**约束宽高相等；否则应标“椭圆”。归一化的 `w === h` 在非方形图片上并不是圆。
- 单击默认圆的像素半径为 `0.06 × min(width,height)`；归一化宽高分别是 `2r/width`、`2r/height`。靠边时移动中心使圆完整落在图内，明确这种边界处理，不把椭圆和 bbox 裁出两套形状。
- `<4px` 判定使用屏幕 CSS 像素，检查手势最大移动距离；拖出又拖回不能误判为单击。命中已有区域优先选中，不同时新建默认圆。
- 选区移动、缩放和多边形顶点修改应使用同一边界校验，取消手势恢复开始前的几何。
- UI 序号、文本清单、指示图和 Mask 均由同一次冻结的 `regions` 快照生成；不能渲染过程中一边重排、一边取旧编号。
- 区域数、顶点数和评论长度需要有界；组装后的 CHAT 文字仍受现有 24,000 字符上限约束。超限提示用户整理，不截断到编号与评论失配。

### 4.3 坐标转换

| 使用位置 | 单位与转换 |
| --- | --- |
| 批注存储 | 0～1 的原图坐标 |
| 显示／命中 | 实际图片内容矩形或共用变换矩阵；排除 object-fit 留白、容器 padding、滚动偏移 |
| SVG | 可用原图宽高作为 viewBox；每个归一化坐标乘源宽／高，描边用非缩放描边，角标保持屏幕可读尺寸 |
| 位图 Mask | 原图像素；按形状光栅化并采用既有覆盖阈值，矩形左上向下／右下向上取整，边界限制到图内 |
| ASK crop | `[100*x, 100*y, 100*w, 100*h]`；现有工具已经四边外扩 25%，调用方不要再次外扩 |
| ASK focusRect | 草稿本身接受 0～1 `{x,y,w,h}`；现有写入器转像素并规整到 8px |
| EDIT focusRect | 服务使用像素 `{x,y,width,height}`；复用 `snapFocusRect`、`inpaintFocusPlan` |

“归一化”解决的是存储尺度问题，对齐还取决于实际显示几何。图片载入、窗口变动、缩放、平移、移动端可视视口变化都应同步变换；不能每次缩放改写原始坐标。

## 5. 三条工作流的修订方案

### 5.1 CHAT：先准备完整改图输入

建议入口叫 **「去 CHAT 改图」**：准备底图、指示图和输入文字，用户在现有 CHAT 检查模型／来源并发送。这样沿用现有交接和费用行为，批注界面不再复制一套选模、报价与提交按钮。

双图路径：

1. 冻结原图绑定、批注及补充总说明，保留未加标记的原图。
2. 生成同方向、同画幅的指示图，只叠加轮廓、弱填充和编号；不把浮动输入框或大段评论画进图片。
3. 保证最终输入第一张是干净原图，第二张是指示图，其他参考图在后。指示图占用一张实际输入名额。
4. 将明确的图序与逐区域说明写入待发送文字。提示模型基于原图输出，不保留编号／线框，但不把它当成模型必然遵守的保证。
5. 最终发送前校验来源的图片上限和参数；缺少任一配对图片时停止，不允许 CHAT 的常规截断规则静默丢掉指示图后继续提交。

```text
<用户补充的总说明>

输入图 1 是待修改原图，输入图 2 是编号定位图。
请基于图 1 修改；图 2 的线框和数字仅作定位，不应出现在结果中。
尽量保持未指定的内容、构图和分格不变。
1. 矩形区域，X 33%–66%、Y 33%–66%：眼神改温柔，眉毛放平。
2. 椭圆区域，中心 X 50%、Y 82%：嘴巴改成吐舌头。
```

需要补充的内部语义是“该轮指示图”，不能直接作为普通长期参考图放入 `keepIds`。成功、取消、重试、分支和刷新都应恢复该轮实际图片与文字；用户跟随新结果进行下一轮时，不应自动继续携带旧位置标记。用户删除配对附件或切换底图后，应同步取消该批注包，避免孤立的编号说明继续发送。

从 IMAGE／EDIT 进入时，优先使用新建／复用空白会话的现有模式；从 CHAT 当前结果进入时保留当前分支，将该结果明确设为待改底图，并保留用户原输入。现有单图票据需要扩充载荷或新增窄范围的应用级交接方法，不能只转一个 URL。

**按来源支持的图片数量处理：**

| 来源能力 | 可用路径 |
| --- | --- |
| 支持至少两张参考图 | 双图＋逐区域说明 |
| 只收单图 | 明示改用“原图＋方位文字”，或让用户换来源；不静默降级 |

不向 OpenAI 或 Gemini 上传独立 Mask。一次生成失败后，不自动重发另一种策略。生成结果先保留直出，再进入下面的人工审核与本地应用流程。

### 5.2 GPT／Gemini：人工审核后应用本地蒙版

此流程适用于 CHAT 批注改图，以及 EDIT 中使用 GPT／Gemini 双图改图的结果。NAI 沿用现有重绘与回贴流程。

处理顺序固定为：

1. 发送时冻结干净底图、批注、输入变换与外扩／羽化设置，原图与指示图顺序明确。
2. 收到结果后完整保存模型直出，完成解码和任务处理，释放生成槽；等待人工审核不能一直占据 `runTask`。
3. 程序检查方向和宽高比（Aspect Ratio），**不要求像素宽高相同**。模型直出与冻结底图方向一致，且宽高比的相对误差不超过 1.5% 时，允许预览及点击「应用蒙版」；合成以冻结底图的原始像素宽高为画布，将直出等比对齐采样回贴到选区，常规取整误差采用居中对齐处理，不作非等比拉伸。方向或宽高比明显不一致时禁用「应用蒙版」。这只是几何前提，不代表图内主体的比例和位置没有变化，仍须人工审阅。
4. 用户对比干净原图与模型直出，检查人物位置、整体结构、九宫格分格以及局部修改是否合适。通过基础尺寸检查不等于已经通过这一步。
5. 可展示临时合成预览及外扩／羽化的实际影响范围；仅预览不写入正式结果或替换底图。用户点击 **「应用蒙版」** 后，才生成并保存正式本地合成结果。
6. 保留模型直出与合成结果的关联，可切换查看。用户发现整体变化或位移时，可保留直出、不应用蒙版；不自动重新调用上游。

合成规则：

- 将矩形／椭圆／多边形的真实覆盖合并，在原图坐标内外扩，再生成有限范围的柔边 Alpha。不是用各形状的 bbox 代替形状。
- 扩展与羽化范围应有明确外边界；边界之外 Alpha 严格为零，直接保留冻结底图像素。保证的是**最终影响范围之外**的像素，不将外扩带描述成未修改区。九宫格可将外扩设为零，防止侵入邻格。
- 编辑选择仍使用现有二值覆盖表示；柔边 Alpha 在本地合成时派生，不经过 `decodeMask` 阈值化后再使用，也不上传给 GPT／Gemini。
- 合成以冻结的干净原图为底，结果保存 PNG；不把上传压缩副本当保真底图，不对保留区域再作 JPEG 重编码。像素保证以同一方向／色彩归一化后的解码结果为基准，不保证文件字节和原元数据相同。
- 羽化用于缓和接缝，不能补偿模型造成的位移或结构变化；这些由用户在正式应用前审阅。
- 人工应用是本地处理，不请求报价、扣费或生成。处理失败保留已保存的直出与批注，可重新尝试本地合成，无须重新生图。

每轮需要保存批注快照、边缘设置及直出／合成图关联，使用现有图片资产和必要元数据即可；**不新增独立 Mask 资产，也不扩展 `ModelLink` 的 Mask 能力字段**。查看直出不隐式更换底图；用户正式应用后可沿用现有“跟随最新”规则选择合成结果，下一轮以实际选定的完整图为基底，保留之前已经完成的修改。

### 5.3 EDIT：复用现有转换，区分图像模型执行入口

批注转蒙版／聚焦框是向现有 EDIT 能力提供几何输入。NAI 的请求、二值蒙版、普通／聚焦处理和已有局部回贴保持现状，不为新增 GPT／Gemini 防劣化流程改造 NAI。

**转为蒙版：**按真实形状合并覆盖，经过既有 MaskBitmap／蒙版历史路径写入，形成一次可撤销操作，不直接修改 Canvas 后绕过服务状态。

- `importMask` 当前按底图尺寸校验，且要求查看版本就是底图。若用户正在批注另一查看版本，须先明确将这张图作为新底图或独立编辑板；不得直接把选区套到旧底图。
- 原有蒙版非空时，提供简短的“加入现有／替换”选择；两者都按一次操作记录。取消或失败不留下半套几何。
- 评论先作为修改说明保留。直接填入 EDIT 正向词时复用现有提示词输入，并让用户审阅；保留原正向／负向和角色配置，不自动把“右眼画错了”等诊断句覆盖成 NAI 提示词。
- 对不同区域有不同修改要求时，合并 Mask 只合并覆盖，不代表建立了逐区域语义路由。

**转为聚焦框：**取所选区域 bbox 的合并外接矩形作为初值，换算像素并向外规整到 8px，供用户调整上下文范围。

- 框内仍需要非空蒙版；首轮可将同一批注形状转成蒙版，并设置包含它的框。
- 若追加到已有蒙版，聚焦框必须包含最终全部蒙版；不满足时提示扩大或重新选区，不能遗漏旧覆盖。
- 稀疏且相距很远的区域，其合并 bbox 可能接近整图，聚焦收益有限；不自动分裂成多次生成。
- 沿用 NAI 底图 64px 对齐／3MP、框 8px 规整、处理尺寸和型号约束。任意 GPT／Gemini 输出不一定符合 NAI 输入尺寸，不能静默缩图来套用。
- 这些都是用户触发的编辑操作，ASK 不获得修改蒙版、换底图或自动执行的权限。

**GPT／Gemini 在 EDIT 的接入：**增加适用于这两类模型的双图请求分支，复用其现有图像参数和来源选择，不经过 NAI 的提示词、采样器及 64px／3MP 约束。EDIT 的选区在此路径中用于生成指示图和本地回贴，结果同样遵守第 5.2 节的人工审阅与「应用蒙版」，不冒充供应商提供的原生 Inpaint。

### 5.4 ASK：预览、坐标与既有工具

「问 ASK」只打开现有浮窗、准备附件和问题，保留用户已有输入，由用户发送。

**建议首轮保留原稿的单张指示预览＋干净原图引用：**预览作为普通附件进入现有托盘，结构化坐标绑定冻结的工作区原图。模型若尚未看过该原图，先调用 `view_image` 的 glance／look，再 crop。看过指示图不能冒充看过干净原图。

若后续希望首次提问即可直接 crop，可将干净原图也作为第二张附件发送，复用已有“完整附件授予原图实体已看资格”的规则；这会占用两个附件名额。不能仅修改 `viewed` 集合而不发送对应原图。

```xml
<image_annotations image="#c2.1" coordinate_system="normalized_xywh">
  <region id="1" shape="rect" bbox="0.33,0.33,0.33,0.33">这格右眼眉毛歪了</region>
  <region id="2" shape="ellipse" bbox="0.44,0.76,0.12,0.12">蝴蝶结颜色串了</region>
</image_annotations>
```

这里只是文本序列化示例。真实图片编号由现有图片库生成并冻结，还需记录指示附件与原图绑定；不按字符串 `#c2.1` 在下一轮重新猜图。多边形需同时带顶点，bbox 只供粗定位和裁切。评论中的 XML 特殊字符必须转义，作为用户资料发送，不混入 System／工具定义。

实际工具映射：

| 用户期望 | 复用方式 |
| --- | --- |
| 放大第 1 个区域 | `view_image({id:"<原图引用>",spec:"crop",region:[33,33,33,33]})`；前置原图已看，工具自行外扩 |
| 建议当前 EDIT 聚焦框 | `propose_draft` 内 `params_patch.params` 设置 `editMode:"inpaint"`、`inpaintKind:"focused"`、`focusRect:{x,y,w,h}` |
| 修改编辑提示词 | 同一草稿中的 `prompt_patch`，目标为 `edit.prompt` 等合法字段 |
| 从其他工作区准备 EDIT | `edit_handoff`，使用 `focus_rect` 等既有字段；确认后准备画板，用户再进入和执行 |

无需新增 `crop` 或 `edit_action` 工具，也无需重新建立草稿体系。ASK 的 bbox 建议仍要通过最新蒙版包含关系、底图、目标画板和能力校验；它不会因批注存在而自动生成蒙版。

需要处理的现有限制：

- ASK 每轮最多 4 张图片；每张原件最多 20MiB／4000 万像素，发送编码最长边 1568px、最多 1MiB。派生指示图也占名额，不能绕过托盘限制。
- 工具看图共有 4 次／1.5MP／400KB 的每轮预算。多处区域不保证都能分别 crop，应按问题重要性选择；用户附件不占该工具预算。
- 仅元数据轮次或图片开关关闭时，不能偷发指示图；可发送文字坐标，但明确模型尚未看到像素。
- 附件添加目前逐个处理，可部分成功；批注交接应预检容量和尺寸，保证说明、绑定、预览一起进入或一起回滚。
- 必须在成功消息／失败重试中冻结批注快照，防止用户移动区域后改变上一轮语义。收藏 ASK 时，指示附件、说明和绑定随现有收藏保存；历史图片 `#h/#e` 若已消失，不能把新页面同号图当原图。
- 若托盘准备后、发送前来源已失效，应保留批注并提示重新选择或补入干净原图；不只发送预览却继续承诺原图可裁切。

## 6. UI 与手势收敛

维持用户给出的轻量工具条方向，复用项目现有按钮、分段选择、图标、popover 和主题变量。首轮不新增常驻右栏、逐区域大卡片或多层参数面板。

- 工具条只在批注模式出现：形状分段、数量小胶囊、一个主操作和更多菜单、关闭。EDIT 的“转为蒙版／聚焦框”放在同一个动作菜单，避免同时排满四个大按钮。
- 画布常显轮廓和编号，仅选中／悬停时显示短摘要；评论全文只在当前活动气泡中编辑，避免多处批注都盖住图片。
- 描边约 2 CSS px、填充约 12% 可作为起点；表面、输入框和按钮沿用暗／亮主题。蓝紫标记统一取语义强调色，必要时加细反衬保证图片上可见，不另起一套弹窗配色。
- Enter 确认、Shift+Enter 换行，IME 组字回车不提交；Delete 仅在选区拥有焦点且不在文本输入时删除。
- Esc 依次处理：取消未完成绘制／拖拽、关闭评论、退出批注模式；不得同时关掉外层图片检视。聚焦返回原触发按钮。
- 多边形双击结束要去掉重复终点；至少三个有效顶点才能闭合。触屏提供“完成”入口，不依赖双击。
- 空格／中键继续用于平移，双指继续缩放；一旦切到这些手势，暂停批注绘制。EDIT 的蒙版、聚焦框、角色坐标和批注工具互斥。
- 点击别处关闭评论时先保存文本，本次点击不要同时生成一个新圆。移动端气泡避让软键盘和安全区，窄屏通过既有菜单承载次要动作。
- GPT／Gemini 结果审阅复用现有图片检视和对比操作，明确区分模型直出、临时合成预览和已应用结果；「应用蒙版」是正式写入动作，生成完成或切换查看都不能代替用户点击。

共享组件只呈现和发事件，不直接调用收费接口、数据库或其他工作区服务。高频指针与预览由 `native/` 驱动，提交时更新几何；暂停／销毁清理 Pointer Capture、Observer、rAF 和 Object URL。

## 7. 生命周期与持久化边界

首轮建议**未发送的批注为本页状态**，按具体图片绑定保留；退出批注模式只是隐藏，切回同图可继续编辑，刷新清空。UI 应在需要时明确这一边界，不声称批注已保存到原图。

- 原图 Blob 不变，下载原图、收藏原图和 Photopea 分层不带入标记；指示图只作为独立派生素材使用。
- 开启批注或正在交接时保留必要源 Blob 引用；关闭画板、清除批注或释放最后一个引用后清理。
- CHAT 成功交接后，由现有素材存储承担干净图、指示图、模型直出和已应用合成图；批注与边缘设置作为轻量快照保存，不持久化独立 Mask。实际发送快照、待审阅状态和结果关联应可重试、可恢复；新增元数据同步维护普通备份校验和资产引用收集。
- ASK 收藏沿现有 `koma-ask` 保存附件与本轮说明，不进入普通备份。只有引用而无原图附件的来源，失效后须明确提示，不能仅凭指示图恢复干净原图。
- “在收藏图库里长期保存可重新编辑的批注”属于后续范围，需另定存储与备份契约；首轮不增加新数据库、不做旧数据迁移。

## 8. 建议代码落点与实施顺序

原稿的 `src/utils/` 和 `src/components/` 不是当前项目的主要归属。建议顺着现有分层放置：

| 拟新增／修改 | 职责 |
| --- | --- |
| `src/domain/region-annotation.ts` | 形状、稳定 key、校验、bbox／合并、序号、坐标转换、提示文本与安全序列化 |
| `src/native/annotation-canvas.ts` | 指示图、形状覆盖、有限外扩与柔边 Alpha；共用路径绘制，资源释放 |
| `src/native/inpaint-result.ts` | 新增通用本地柔边合成函数供 GPT／Gemini 使用；已有 NAI `composeInpaint` 行为保持 |
| `src/native/region-annotator.ts` | 指针／命中／拖动／调整、键盘、暂停／恢复，与视口变换衔接 |
| `src/shared/annotations/RegionAnnotator.vue` | SVG 宿主、形状分段、评论气泡和动作；复用现有共享控件与样式 |
| `src/services/annotations.ts` | 本页图片绑定、批注快照和交接协调；大图留普通内存 |
| 三个工作区的既有组件 | 增加入口，传入具体图片绑定、视口和业务回调，不复制三套交互逻辑 |
| `services/editor.ts` 与既有 mask／focus 模块 | 批注覆盖和聚焦配置的转换／撤销；增加 GPT／Gemini 双图执行和人工审核后本地应用，复用 NAI 现有路径 |
| `services/chat.ts`、`domain/conversation.ts`、`domain/media.ts` | 双图角色与顺序、待发送说明、当轮指示图、重试快照、人工应用与直出／合成关联 |
| 既有 catalog／选源／native-protocols | 复用图片数量、参数检查和双图发送；不新增 Mask 能力字段或上传协议 |
| `ask/service.ts`、attachments／消息保存 | 预填、派生预览关联与轮次冻结；沿用既有工具和草稿 |

实施范围为前三步及共用的人工审核后本地回贴：

1. **共享批注＋ASK**：三种形状、默认圆、评论／删除／移动／调整、稳定绑定、指示图和坐标交接。保持原图不变，先验证标记与语义对应。
2. **EDIT 转换**：形状覆盖导入、添加／替换、撤销及聚焦 bbox 初值；NAI 复用现有功能。GPT／Gemini 增加双图执行入口，结果由用户审阅后应用本地蒙版。
3. **CHAT 双图**：底图／指示图角色、图片顺序、来源数量限制、分支／重试／持久恢复；模型直出先保存，人工审核后才正式应用本地外扩／羽化回贴，保留直出切换查看。

外扩／羽化与合成作为第 2、3 步共用的本地处理，不另建上游协议步骤。原第 4 步 OpenAI Mask 适配已取消。

本轮不纳入：OpenAI Mask 上传、`ModelLink` Mask 能力扩展、CHAT 独立 Mask 资产、NAI 生成／回贴重构、GPT Image 2.5 专用 markup、Responses、Gemini Interactions／图像多轮签名迁移、逐区域自动多次生成、长期图库批注管理、外部 Bridge 批注写入。

| CHAT | 模拟请求中原图第一、指示图第二；超限不丢关键图；仅单图来源不偷发双图；失败不改策略重试；新一轮不自动续用旧指示图 |
| 人工审核 | 同方向、宽高比相对误差 ≤1.5% 可等比采样至冻结底图原始尺寸；明显不匹配禁止应用；尺寸一致也不自动应用；人工核对主体比例、构图与位置；切换查看和关闭预览不改底图；只有用户点击「应用蒙版」才保存正式合成 |
| 连续改图 | 九宫格逐格修改，以用户选定的上轮完整结果为底图；本轮影响范围外不被直出的全图变化覆盖；直出始终可访问 |
| ASK | 实际出站含指示预览和对应坐标；原图未看先拒绝 crop；0～1 正确转百分比且不重复扩边；真实工具名与草稿字段正确 |
| 保存／异步 | 交接失败不留下半包；切图片／切会话时不串写；CHAT 重试和恢复使用冻结输入；ASK 收藏后说明与附件关联保留 |
| UI | 暗／亮主题、移动端键盘、Esc 层级、IME、画笔／平移冲突；目视检查组件一致性，不用测试锁死字号和间距 |

复用现有 `tests/ask-vision.browser.mjs`、`ask-attachments.browser.mjs`、`ask-edit.browser.mjs`、`editor-return.browser.mjs`、`native-protocols.test.mjs` 的场景／夹具；涉及既有聚焦输入转换时按需参考 `inpaint-focus.test.mjs`。实施时增加几何、人工审核、像素合成、请求及状态用例，使用合成图片和模拟响应。具体已实现行为与本地验证边界见现行专题。

真实供应商仍需另行核验：双图是否正确对应编号、线框是否残留、多个区域指令是否串位、区域外漂移、返回尺寸和拼接接缝、实际费用及渠道对文件字段的支持。自动化只能证明请求和本地处理正确，不能代替真实改图质量结论。
