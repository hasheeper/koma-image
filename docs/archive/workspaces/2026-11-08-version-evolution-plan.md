# 版本演进：需求与实施规划

日期：2026-11-08。状态：**E1 → E5 已完成本地实施与模拟验收，尚未提交、推送或发布。**

本文记录本轮确认的目标行为、代码基底、实施顺序和验收要求。已实现能力仍由[演进专题](../../workspaces/recipe-retrospect.md)维护，整体进度见[当前状态](../../status.md)。第 2 节保留实施前的代码基线，第 14 节记录本地实施结果；本记录不代表真实模型质量或线上发布验收。

## 1. 定位与本轮边界变化

版本演进用于单张图反复修改、抽卡和回退时的持续打磨。完整过程是：

**日常创作无须预先开启 → 遇到瓶颈后 ASK 整理已有历史 → 激活画板演进 → 后续生成自动归组、顺延或回退分叉 → 用户定稿或解除跟踪。**

ASK 首次结合对话、现存图片和配方，判断哪些记录属于同一主题、历史版本如何关联。激活后，程序依据明确的生成配方、恢复操作和草稿基底记录后续关系；ASK 可继续整理同一棵树的阶段名称、归组和拓扑。

这调整了[前一版概念记录](2026-11-07-recipe-retrospect.md)中“整理后保持静态、不接生成／草稿／撤销”的边界。后续实施允许接入这些链路中的必要事件和写入提交点；仍不在激活前维护全局游标，不记录所有日常操作，也不靠字段相似度猜测主题。

本轮保持以下范围：

- 以 IMAGE 的单图打磨为主，不扩展为全局无限画布、Artist Mix 实验矩阵、Slate 多图企划或 EDIT／CHAT 版本系统。
- ASK 不自动生图、重试、报价、扣费或发送 CHAT 消息；创作修改仍须用户确认，经原写入路径完成。
- 保留原始手写配方 Diff、现有连续分组界面、折叠相册节点和唯一 ASK 浮窗；不借此重做整套 UI。
- 活动跟踪、游标及批注仍限定本页。暂不新增演进数据库、跨刷新自动续跟踪、普通备份字段或废稿图片存储。

## 4. 三种归组对象与真实配方

### 4.1 原始快照、有效指纹与语义阶段分开

| 对象 | 定义与用途 |
| --- | --- |
| 原始配方快照 | 保存具体图片的手写 `prompt / negative / characters / params`，供精确恢复和来源核验 |
| 有效配方指纹 | 对已知有效内容做确定性比较，用于连续抽卡候选折叠及激活后的自动归组 |
| 版本节点 `vN` | ASK 归纳的语义阶段，允许多种微调配方；不能用节点代表配方覆盖所有样本 |

有效投影统一过滤 `on=false` 的角色，以及正负词都经 `trim()` 后为空的角色；代码现用字段为 `on`，与需求中的 `enabled` 含义对应。仅负向有内容的已启用角色仍保留。

指纹忽略 Seed、批次数／序号、临时角色 `cN` 与参考行 ID、界面状态，以及已明确不发送的旧 `cfg`。有效角色仍比较内容、顺序和定位；非空文本保留准确原文，不额外归一化大小写、重复词、权重或顺序。缺失字段为未知，不借当前默认值补齐。模型、核心尺寸和已知有效生成配置继续参与比较。

这些过滤同时用于候选指纹、相邻摘要、节点间 Diff 和自动归组。**不得把过滤后的投影写回原记录，也不得用它替代恢复时对原始快照的完整一致性核验。** 原始空角色槽可以保留并恢复，只是不再制造比较噪音。

候选仍折叠同画板时间序列中的连续同配方段，`A、A、B、A` 保留三个候选组。排除 `isComparison` 合成图；同记录的历史／收藏别名不重复计数。

### 4.2 宽松归组与代表图

ASK 可将同一微调阶段的 1～N 张图放进同一 `vN`，即使其词句、权重或参数不同。不增加相似度阈值，也不因跨候选组或角色槽变化拒绝整理。真实身份、样本不重复、父子无环等结构校验仍保留。

节点载荷新增可选 `primary_id`，必须是该节点的成员，且能解析到本轮真实记录。省略时沿用组内最新收藏优先、否则最新样本的确定性规则，兼容现有快照。

节点默认展示代表图；用户选中具体样本后，图片、A/B Diff、恢复和 ASK 引用始终使用该样本。失效样本不能悄悄换成同节点另一张图。自动追加样本不强制打断用户正在查看的 A/B 对照。

### 4.3 自动归组采用当前具体基底

激活后的自动判断比较“本次实际生成配方”与“当前游标所指具体样本的有效配方”。不会在整棵树中寻找任意相同配方后跳回旧节点，也不会仅与节点默认封面比较。

例如 v5 包含两张略有差异的图，用户恢复 `#h7` 后，仅换 Seed 应继续归入 v5；相对 `#h7` 改动有效配方后才从 v5 创建新分支。后续 ASK 可把这些确定记录的细分节点重新归纳成较大的阶段。

## 5. 活动画板与演进游标

活动跟踪至少需要关联：**演进身份、画板身份、`cursorNodeId`、具体基底图片绑定**。图片绑定使用现有记录身份与作用域；`#h7` 是展示短码，不能充当长期主键。

首次 ASK 整理成功后，以树内最近相关生成样本所在节点作为默认游标和具体基底。存在多个根或分支时依据真实记录时间选择，不简单按 `vN` 字符串排序。激活只建立跟踪，不擅自恢复配方或生成图片。

同一画板至多有一份正在跟踪的演进。新建另一份时，旧树保留并停止自动跟踪；ASK 对同一问题的后续梳理优先更新原树，而非反复新建。

| 操作 | 树与游标行为 |
| --- | --- |
| 点击节点、翻图、选择 A/B、多选、框选 | 只影响查看／选择，不移动创作游标 |
| 普通手改或普通 ASK 草稿应用 | 保留当前基底；暂不创建节点 |
| 成功生成，有效配方与具体基底一致 | 样本追加至当前节点，游标仍在该节点，具体基底更新为这张成功图片 |
| 成功生成，有效配方已改变 | 创建当前游标的子节点；默认名称来自精确改动摘要，游标推进到新节点 |
| 恢复旧节点内的具体图片成功 | 将游标与具体基底移到该节点／图片；此时不创建空分支 |
| 应用带回退基底的草稿成功 | 配方写入与游标回拨共同生效；生成后再归组或创建分支 |
| 生成失败、未产图即取消 | 不创建节点，不移动游标 |
| 批量部分成功后取消 | 只记录实际成功样本，合成对比图不计入 |
| 关闭演进面板、收起 ASK、切换工作区 | 保留跟踪；视图的关闭不等于结束 |
| 切换至另一张 IMAGE 画板 | 解除原画板的自动跟踪，树留在总览／历史；切回不自动续跟踪 |
| 明确清空画板 | 解除当前跟踪；新主题先正常创作，需要时再由 ASK 整理 |
| 手动解除跟踪／ASK 按用户要求结束 | 撤下画板与输入框当前挂件，停止后续自动追加，保留历史 |
| 设为定稿 | 记录最终节点及具体图片，停止自动追加，高亮根到定稿节点的路径 |

绘图服务的 `clear()` 实际清理图片历史；本轮在用户确认该操作后解除当前跟踪，但不将其描述为清空配方。普通 `prompt_patch.mode=rewrite` 也可能只是改写当前主题，不能一概结束跟踪。程序不以词条重合率自动断代；无明确换题信号时继续当前跟踪，用户可解除或让 ASK 修正。

“正在跟踪”“已解除”“已定稿”需要可区分。历史面板的打开不改变状态；恢复跟踪需要显式操作并校验原画板与基底。普通收藏不中断跟踪；显式定稿按第 13 节执行。

## 6. 树结构、身份与保存范围

### 6.1 父子关系只保留一个权威来源

目标语义是每个节点有 `parentNodeId: string | null`，根为 `null`，同一父节点可有多个子节点。现有 `edges` 已能完整表达这层关系并携带修改意图；实施可保留 `edges` 为权威来源、推导父节点，也可统一为节点父引用后派生连线。不得维护两份可独立修改的父子真值。

每份活动演进拥有本页稳定 ID；节点身份与显示标题分开，修改阶段名不换节点身份。新增节点使用不重复编号，历史 `vN` 不因删除或整理而随意重排。

### 6.2 活动树与 ASK 回复快照分开

建议由应用级演进服务持有活动树与画板绑定，ASK 回复保存当次整理快照和演进入口，不再以“某轮消息是否存在”决定活动树是否存在。删除来源回复或会话不应误删仍在使用的活动树；删除画板则解除跟踪，剩余演进在本页历史中只读可查。

本页活动面板展示最新树；历史回复的图片条与文字保持当时快照，打开已有活动树时明确沿用同一演进身份，不能静默用旧快照覆盖新树。ASK 重新整理必须明确目标演进。

本轮不扩大持久化：关闭重开保留本页状态；刷新后不自动续跟踪。收藏 ASK 仍保存该回复已有的结构化快照，不承诺后续每次生长都自动回写成持久活动树。普通历史原图仍可能被淘汰，不能靠收藏 ASK 补回。

演进可以保留轻量配方快照与失效标记，图片、缩略图、Object URL 沿用既有资源所有权。没有原记录或必要参考资源时仍可读文字 Diff，但不可伪造可恢复、可看图的状态。

## 7. ASK 回退草稿与确认写入

### 7.1 显式回退基底

内置 IMAGE 草稿增加可选 `base_image_id`，外部 Bridge 不扩展。协议示意：

```json
{
  "base_hash": "当前目标画板的冲突校验值",
  "draft_title": "回到冷光基底，调整机位",
  "base_image_id": "#h7",
  "steps": [
    { "kind": "prompt_patch", "target": "image.prompt", "mode": "append", "text": ", low angle" }
  ]
}
```

`base_hash` 仍保护用户当前画板；`base_image_id` 指定实际回退配方和演进来源，两者不能混为一个基底。

回退草稿的目标语义是：先取该具体图片可完整恢复的原始基础／角色／参数配方，再在其上执行本次修改。默认延续现有恢复规则，不随意带回 Seed、批次数和优化偏好。不能只把游标指向 `#h7`，实际仍在当前配方上追加修改。

草稿不增加独立的换题边界字段。换题由用户解除跟踪、切换／新建画板或清空画板触发；普通 `rewrite` 或没有 `base_image_id` 都不表示新主题。提议新画板时沿用现有新板行为，不把原树自动复制为正在跟踪的新树。

### 7.2 校验与草稿呈现

- 来源须绑定本轮真实记录，能恢复必要原始字段和参考资源；分支回退须能定位到目标活动树的节点。失效、跨树或歧义来源不能猜测挂载，应明确提示先重新整理或改选基底。
- 保留当前画板冲突检查、目标画板身份、模型能力与资源校验；提出草稿或打开卡片均不移动游标。
- 草稿清楚显示“从 v5／#h7 回退”和恢复＋修改后的实际差异。角色恢复可能重新分配 `cN`，后续角色修改须有明确映射，不能误改当前同名 ID 的另一个角色。
- `restore_partial` 仍可借用多个版本的局部字段；不能从任意一步的 `source` 自动推断整份草稿的分支基底。融合两版时也必须有且只有一个明确演进来源。
- `base_image_id` 所需恢复属于这份草稿的基底，不可通过取消某个展示项留下“只回拨游标、没恢复基底”的半套结果。

### 7.3 应用、失败与撤销

配方与游标在成功写入后共同提交。应用失败或冲突不得残留游标变化；演进在等待期间被解除／定稿或结构已被重整时，要检查绑定仍有效，不能暗中恢复跟踪。

回退草稿沿用原 50 条撤销栈，记录必要的跟踪状态前后值；撤销／恢复草稿时，在现有冲突和顺序规则下同步恢复对应基底。不得另建全局操作日志或第二套撤销栈。

草稿应用与生成分开：撤销已应用草稿不会删除随后真正生成的图片或分支；这些已发生的尝试仍保留，下一次生成按有效恢复后的基底继续。过期撤销不得重新激活已经解除的跟踪。

面板直接「恢复到画板」仍是显式恢复，沿用现有写入、冲突与失败回滚；同步回拨游标，但本轮不顺带为它新增 ASK 消息检查点。恢复失败时配方和游标都保持原状。

## 8. 生成归属、批次与迟到结果

本轮增加 `onGeneration` 提交订阅，普通成功图片经本次闭包回调，避免合成图混入；只在返回后读取当前画板或游标会挂错分支。提交时冻结：来源画板、活动演进身份、父节点／具体基底和本次配方；配方沿用这次实际请求记录，不读取返回时已被修改的表单。

同一批次配方不变时，第一张成功图决定归入原节点或创建一个子节点，其余成功图进入同一节点；不产生一张图一个节点。失败不预占节点，合成对比图不入树，重复通知不能重复登记同一记录。

| 在途期间的变化 | 处理要求 |
| --- | --- |
| 用户只是看别的节点或修改未生成的词文 | 结果仍属于提交时的来源，不按当前查看对象挂载 |
| 用户已明确恢复到另一节点 | 原请求可记录到其提交时分支，但不得把用户新选的创作游标抢回去 |
| 用户解除、定稿、切 IMAGE 画板或开启新主题 | 结果仍正常进入原生成历史，不重新激活旧树，也不挂到新树；之后可由 ASK 补入整理 |
| ASK 重整导致原父节点被合并 | 仅在明确成员／节点映射仍有效时归入对应来源；无法确定时保留普通历史，提示演进未同步 |
| 演进元数据同步失败 | 不把已完成的生图改成可自动重试的生成失败，不重复收费请求；保留成功图片并给出可重新整理的反馈 |

一旦本次跟踪绑定因解除／切板／换题失效，之后显式重新跟踪也不让旧请求借用新绑定挂载。以上约束只负责正确归属，不改变全应用 N=1、任务锁、串行批次、取消、报价或付费确认行为。

## 9. ASK 读取与更新同一棵树

`get_recipe_clusters` 继续一次返回所选历史范围内的完整相邻证据：每图 ID、有效参数、Prompt／Negative／有效角色 Diff；不因为轻微差异又要求逐对 `diff_meta`。时间相邻仍只作证据，不等于父子关系。

活动演进的轻量状态应包含演进 ID、画板、跟踪状态、当前节点与具体基底、定稿信息；需要整理时，一次读取当前拓扑、节点成员／代表图、批注及新增历史。普通 ASK 对话不自动塞入所有原始配方或调用视觉工具。

已扩展现有结构化呈现通道，使 ASK 可区分“首次建立”和“更新已有演进”。更新携带目标演进身份与读取版本，成功轮次结束后提交；失败／取消保留原树。如果生成、批注或用户状态变化已使结果过期，不用旧快照覆盖增量，应提示重新读取整理。

更新时必须核对：

- 样本仍使用真实记录绑定，不重复计入，不接受模型自拟参数。
- 未合并的节点保留身份；合并节点后，游标、具体样本、代表图和定稿指向有明确映射。
- 保留仍有效的节点／连线批注；合并批注时保留不同原文，连线含义变化不能把旧意见静默转移给另一条关系。
- ASK 修改阶段名称和意图不改原始配方事实；重整本身不写画板、不生成、不擅自解除／激活跟踪。

活动树中已验证的样本，即使原图后来被历史淘汰，仍可凭既有稳定绑定与配方快照保留为拓扑成员；不要求重整时所有旧图仍在新一轮候选库中。失效只限制需原记录或像素的动作，不能把整棵树因此拒收，也不能接受模型新增无法核验的历史样本。

## 10. 界面要求

继续复用已确认的连续分组 Diff、折叠相册节点、EDIT 胶囊工具栏和现有按钮，不增加大段说明或新的多层卡片。

- 画板和 ASK 输入框保留现有亮色圆点「演进」挂件，标题和版数随同一活动树更新。
- 节点的“当前查看／A/B 对照”和“画板正在从此版继续”可辨认，但只在需要处用小标记表达；点击查看不等于恢复。
- 恢复或回退草稿应用后，简洁提示“从 v5 继续”；新图成功后更新节点、计数和分支，不强制切走当前对照。
- 增加显式定稿与解除跟踪动作；定稿标记绑定具体样本，根到定稿的路径可辨认。非定稿分支保留。
- 结束后撤下画板和输入框当前挂件，任务总览与 ASK 历史仍可进入。面板关闭不结束跟踪。
- 右侧只显示所选图片的原始配方，不添加 `sent_prompt` 开关；浮动 ASK 继续使用唯一服务与窗口。

## 13. 已拍板的实施细节

1. **普通收藏与显式定稿分开**：普通星标收藏保持原行为，不中断跟踪。演进面板提供「设为定稿」，未收藏的具体样本先成功收藏，再记录定稿节点与样本、高亮根至该节点路径并结束跟踪。
2. **只新增内置回退基底**：不增加草稿新主题字段；`base_image_id` 仅供内置 ASK 的 IMAGE 草稿。外部 Bridge／手动 JSON 不开放此字段，不扩展 `PROTOCOL.md`。换题由解除跟踪、切换／新建画板或清空画板触发。
3. **节点容量为 80**：同一棵树最多 80 节点。达到上限且需要新阶段时保留原树与生成图片，提示请 ASK 合并归纳阶段；不静默丢弃旧分支。

本轮实施与本地验证不构成提交、推送或发布授权。
