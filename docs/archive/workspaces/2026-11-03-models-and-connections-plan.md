# 模型与供应商连接调整规划

日期：2026-11-03。状态：**已按确认范围实施，并于 2026-11-04 随 v0.4.0 发布。** 交付核验见[发布记录](../releases/2026-11-04-v0.4.0-release.md)。

本轮只处理三项：GPT／Gemini 模型条目管理与任意上游 ID、一条连接共用地址和 Key 开启 Chat／Images、NAI 来源混列与 401 提示。沿用现有设置页布局和协议适配，不扩展成通用模型管理平台。

现行行为见[设置与连接](../../workspaces/settings-and-tags.md)、[图像协议](../../integrations/image-protocols.md)、[业务契约](../../business-contracts.md)；规划入口见[当前状态](../../status.md)。

## 1. GPT／Gemini 条目可新增、编辑、删除

### 页面与操作

- 保留现有 GPT／Gemini／NAI 分组列表。GPT 初始 6 个、Gemini 初始 7 个是参考预设，数量随增删更新。
- GPT／Gemini 分组提供“新增模型”；条目提供“编辑”和“删除”。新增时可采用本组现有预设的参数作为起点。
- 编辑内容包括显示名称、现有适配器支持的常用默认参数，以及各来源的实际模型 ID。常用参数按现有协议提供质量、尺寸／比例、输出格式等适用字段。
- 参数必须贯通保存、工作区选择和实际请求；不静默丢弃修改值或改回源码默认值。本轮不增加通用参数 schema 或任意 JSON 扩展编辑器。
- 新增、编辑、删除后立即保存，刷新和跨标签同步保持一致；删除的内置预设不自动补回。
- 未配置来源的条目显示“待配置”，没有连接时也能管理模型条目。
- 删除条目保留既有图片和历史记录。当前工作区若选中了该条目，提示重新选择；在途任务遵守现有配置失效和取消规则。
- **NAI 五个型号及专用适配保持固定。** 现有生成界面的步数、Seed、Guidance、参考图等设置照常使用。

### 手动指定任意上游 ID

- 每个来源都可直接输入上游 ID，已自动匹配的来源也可编辑；目录下拉仅作输入辅助。
- 不要求 ID 符合官方命名，不按 GPT／Gemini 前缀限制，不因目录未列出就阻止保存或执行。
- 手动 ID 不在目录中时显示“手动指定”，不标为“已下架”。
- 仅做非空、合理长度、控制字符及协议请求编码等必要校验；模型是否存在和可用由实际请求反馈。
- 同一条目在不同供应商下可使用不同 ID，修改一个来源不覆盖其他来源。
- 模型内部身份与上游 ID 分开，编辑 ID 不破坏历史与工作区引用。
- 既有 Images／Gemini 原生适配继续按用户选择的来源工作；展示分组不强制改写实际 ID。

## 2. 一条供应商连接共用地址和 Key 开启 Chat／Images

供应商配置中，对 OpenAI 兼容连接提供两个可独立开启的选项：

| 选项 | 在 Koma 中的用途 | 使用的现有接口 |
| --- | --- | --- |
| Chat | ASK 推理 | `/chat/completions` |
| Images | 图像生成与现有参考图编辑 | `/images/generations`、`/images/edits` |

- 一条连接只维护一份名称、基础地址和 Key；可只开 Chat、只开 Images，或同时开启。
- 开启 Chat 后供 ASK 选择；开启 Images 后供图像工作区选择。模型选择沿用各工作区现有方式，目录条目不会因此全部自动成为可用生图模型。
- 两项共用连接资料，底层继续使用各自现有的请求与响应适配，不新增通用协议配置层。
- Chat／Images 的开关影响各自入口；关闭其中一项，不清除另一项的模型配置或 Key。
- 按用户配置决定是否启用，不通过域名或模型名称猜测，不自动尝试其他协议。
- 既有仅 Chat 或仅 Images 的连接保持原有行为；已有两条独立连接不自动合并。
- Key 继续遵守浏览器保存／仅本次会话的现有选择，普通备份只保存非秘密配置。
- Gemini 原生、NovelAI 官方、标准网关和 Anthropic Messages 保留现有适配范围。

这里的 Chat 指 ASK 使用的 OpenAI Chat 接口；本轮不增加“通过 Chat 接口生图”、Responses 生图或 Gemini 原生 ASK 接入。

## 3. 修复 NAI 混列与 401 提示

### 来源列表

- GPT／Gemini 条目下不再列出 NovelAI 官方连接。
- NAI 条目继续展示适用的官方或标准网关来源，保留现有型号与操作限制。
- 标准网关按具体模型关联展示，不能仅因供应商名称就把整个连接限制为某个系列。

### 读取失败提示

| 情况 | 页面反馈 |
| --- | --- |
| 目录请求返回 HTTP 401 | 显示“鉴权失败（401），请检查 API Key”，不回显可能含凭据的响应正文 |
| 目录读取失败 | 显示对应来源的实际错误及重试入口，不冒充“模型未找到” |
| 目录读取成功，但没有匹配项 | 提供手动指定 ID 的入口 |
| 手动 ID 未被目录列出 | 保留配置和可用操作，显示“手动指定” |

一个来源失败不覆盖其他来源的正常状态。401 提示不得泄露 Key；403、网络错误等继续区分，不一律改成“Key 错误”。

## 4. 实施与验收

按“模型配置及持久化 → 模型管理界面与实际 ID 传递 → Chat／Images 共用连接 → 来源与错误提示 → 定向验收”的顺序实施。

| 验收场景 | 完成标准 |
| --- | --- |
| 新增 GPT／Gemini 条目 | 分组计数更新；刷新后保留；配置来源后可在相应工作区选择 |
| 编辑名称、默认参数和上游 ID | 保存值进入界面与模拟请求，不被内置预设覆盖 |
| 删除 GPT／Gemini 条目 | 刷新不补回，既有图片与历史保留；当前选择妥善处理 |
| 目录没有该 ID，或目录暂时不可用 | 能手动保存和使用 ID，不以目录缺项判定下架；请求错误正常反馈 |
| 同一条目绑定两个渠道别名 | 各来源 ID 独立，模拟请求使用实际选中来源的 ID |
| 一条连接同时开启 Chat／Images | URL 与 Key 只维护一份，ASK 与图像请求分别走现有正确路由 |
| 关闭 Chat 或 Images 其中一项 | 对应入口停用，另一项配置与凭据保持有效 |
| GPT／Gemini 展开来源 | 不出现 NovelAI 官方；NAI 五型号继续按原规则使用 |
| 一个目录返回 401，另一个成功 | 前者显示鉴权失败，后者正常展示，不混为“未找到” |
| 刷新、跨标签同步、配置与备份往返 | 保留条目增删改、实际 ID 和接口开关，Key 继续隔离 |

实现需覆盖配置校验、保存、工作区选模和请求转换，不能只改设置表单。已有当前 Koma 配置按原行为读取，不建立旧应用迁移链路。

保留标准网关报价、`max_cost`、既有余额分流、默认并发、取消和失败规则；提交后不换协议或自动重试，不改变付费确认行为。

验证使用合成数据与模拟服务，运行 `npm run check` 和相关定向浏览器用例，界面目视确认。真实收费生成、推送及部署不属于本次规划审阅。

实施补充：手动 ID 缺项可用；Images／Gemini 原生允许目录不可用时手动执行，标准网关仍要求报价保护目录有效。同一模型当前会话已保存的参数保留，选择其他模型采用其默认值。默认参数、手动 ID、共用连接及备份隔离已由单元测试覆盖；增删改、跨标签同步、刷新、实际模拟请求、删除后历史与选模、接口开关及局部 401 已由定向浏览器测试覆盖，相关页面完成桌面／移动布局目视检查。只使用合成图片和模拟服务，真实生成与上游兼容不由这些结果证明。
