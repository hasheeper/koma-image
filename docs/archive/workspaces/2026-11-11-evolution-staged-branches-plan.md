# 版本演进：并行预设分支需求与实施规划

日期：2026-11-11。状态：**PB1–PB6 已实现并完成本地模拟验收；容量为每轮 4／每树 16／总节点 80；尚未发布。**

本文明确 IMAGE「逐次单分支挂载 → 配方对比 → 用户载入 → 手动生成 → 原地转实」的实现范围。现行行为以[版本演进](../../workspaces/recipe-retrospect.md)及 [ASK 契约](../../ask/README.md)为准；第 2 节记录实施前勘探结果，第 3 节口径已经用户审阅通过，实际实现与验证见第 14 节。进度入口见[当前状态](../../status.md)。

## 1. 需求理解与范围

用户要的是**在同一棵活动演进树中，提前保存多套可执行的未来配方**。ASK 每次工具调用完整准备一个方向，通常连续准备 2～3 个；用户先比较配方，再决定试跑哪些方向。

```text
                          ┌── [待生成] 办公桌交接
v1 ── v2（具体基底 #h5）───┼── [待生成] 整备理项圈
                          └── [待生成] 雨夜共黑伞

载入「整备理项圈」→ 用户可再微调 → 手动生成 #h6
                         ↓
同一节点原地显示 #h6；其他预设、既有分支和手动位置保留
```

本期确认范围：

- 仅 IMAGE；沿用同一画板和活动树，不在顶栏新建方案画板。
- 新工具暂定 `stage_evolution_branch`，每次只提交一个分支，不提供 `branches[]`。
- 每个成功分支立即可见、独立保留；某个分支失败只退回该次调用。
- 分支保存完整目标配方，生成前已有相对具体基底的红绿 Diff。
- 「载入画板」才写表单，同时绑定待生成节点；纳入已有 50 步撤销栈。
- 用户手动生成；载入后即使微调，首张成功图仍填入该预设节点，实际结果取代计划作为当前配方事实。
- 支持独立拖动、删除未采用预设、兄弟分支对照、继续演进和显式定稿。
- 不扩展 EDIT／CHAT 的预设分支或外部 Bridge，不改变生成、报价、并发、失败与取消规则。

### 对原稿的一点事实修正

现行演进已经是会自动归组、顺延和回退分叉的活体树，并非静态历史树。本次新增的是**尚未生成、但已准备好配方的节点**；既有的生成跟踪、历史树和回退能力应复用。

| 工具预算 | [session.ts](../../../src/ask/session.ts) 实际为 24 次普通调用、一次保留草稿机会、最多 26 次模型请求；[service.ts](../../../src/ask/service.ts) 每次输出上限 4096 tokens | 原稿中的「10～12 次」需更正；先沿用现有预算，不因本功能放宽全部请求 |
| 提交边界 | `show_retrospect` 返回树对象；[service.ts](../../../src/ask/service.ts) 等整轮成功才登记／更新；读取器使用本轮冻结的树列表 | 新增逐分支提交边界，并打通同轮先建树再挂分支，不能依赖下一轮初始化 |
| 恢复与撤销 | 面板恢复经 [restore.ts](../../../src/ask/retrospect/restore.ts) 直接写画板，并不进入草稿撤销栈；回退草稿才使用 [apply.ts](../../../src/ask/draft/apply.ts)／[stack.ts](../../../src/ask/draft/stack.ts) | 「载入预设」必须接入共享撤销栈，不能只改按钮文案复用直接恢复 |
| 生成归属 | drawing 的 `onGeneration` 在生成开始时捕获接收器；`begin/land` 按有效签名归组，首张决定批次节点 | 增加预设定向落图路径，优先填入预设，不能先按签名归入父节点 |
| 读取与重整 | `get_recipe_clusters` 返回现有节点、配方、相邻 Diff；`update` 按真实样本映射游标和批注 | 返回未生成分支，重整保留其具体基底；无图节点不能走现有按图片成员匹配的逻辑 |

因此这不是只加一个工具或一张卡片：**节点分型、逐次提交、可撤销载入、定向落图**必须一起完成。

## 3. 已确认的实施口径

以下口径已审阅通过；容量按最终决定调整为每树 16 个未生成预设。

| 问题 | 确认口径 |
| --- | --- |
| 「最多 4 个」如何计数 | 每树同时最多 16 个未生成预设；每轮最多新建 4 个成功预设。失败修正仍消耗普通工具预算，但不占成功名额；生成转实或删除后释放树的预设名额 |
| 与 80 节点上限关系 | 实际版本与预设合计最多 80；预设创建时预占位置，点亮时不增加节点数，不会到落图时才因容量被拒 |
| 版本编号 | 预设创建时用 `nextVersion` 预留稳定 `vN`；待生成态突出短标题与状态，生成后显示正式版本身份。删除不回收编号，按生成先后不重排编号 |
| 后续回复失败／停止 | 已经成功挂载的分支保留，未完成的那次不提交；失败提示可说明已保留数量。不能以整轮失败回滚已成功分支 |
| 重整／定稿的废案处理 | 默认保留，用户可显式删除／清理未生成分支；定稿不静默丢弃方案。本期不为模型另加批量删除工具 |
| Seed、批次数、优化偏好 | 沿用既有配方恢复口径：未显式修改则在载入时保留当前画板值；`steps` 明确修改了允许写入的运行选项则冻结并回显这些覆盖值。它们不进入有效配方归组签名 |
| 保存范围 | 沿用本页活动树，不新增数据库或跨刷新续跟踪。成功回复可保存当次含预设的只读快照；收藏会话不等于持续保存活动树增量 |

上述 Seed 口径需在详情中说明，避免把「完整创作配方」误读成重新执行历史批次数。需要完全复现历史 Seed 时，模型可通过现有参数步骤显式指定。

## 4. 数据模型与所有权

### 4.1 同一棵树中的两类节点

建议将节点改为可判别联合类型：

| 字段／对象 | 已生成节点 | 预设节点 |
| --- | --- | --- |
| `kind` | `generated`；现有历史快照缺省按该类读取 | `staged` |
| `id / label / description` | 稳定版本身份及阶段说明 | 同样稳定，原地转实后不改 ID |
| `image_ids / cover / recipes` | 真实图片与逐图配方 | 无真实图片；实现保留 `image_ids: [] / cover: ""` 供共享渲染，不填父图或虚构 ID |
| 展示 `recipe` | 当前所选具体样本的真实配方 | 从完整目标快照派生的比较配方 |
| 分叉基底 | 已有 `sampleBases` 记录实际来源 | 冻结具体基底的稳定记录绑定、原始配方、来源角色 ID；父节点仍由 `edges` 推导 |
| 执行快照 | 真实生成记录 | 完整目标创作字段、明确运行选项覆盖、步骤检查结果与必要来源信息 |

只保留一份权威目标快照，不分别维护能独立修改的「卡片配方」「载入配方」。比较投影可派生；原始角色槽、停用槽和空槽不能因 Diff 过滤而从快照删除。

预设是实际演进节点，但不是实际图片。它不进入历史图索引、`#h` 编号、视觉工具、缩略相册或图片计数。树摘要区分「已生成版本数／待生成分支数」，避免挂三份计划就增加三张图。

### 4.2 游标与生成绑定

现有 `EvolutionCursor = { nodeId, imageId }` 必须扩展：已生成游标指向真实样本，预设游标只指向待生成节点及其计划身份，不虚构 `imageId`。

`EvolutionChange`、撤销预检、`GenerationBinding`、结束／继续、定稿、挂件和资源保护一起适配。仅增加可空图片字段而不区分状态，会使 `sample()`、`begin()` 和续跟踪检查继续拒绝预设。

生成提交时冻结树 ID、画板、跟踪代次、游标令牌、目标预设 ID、计划身份、具体父样本。生成回调使用这份绑定，不读取落图时用户正在看的节点。

### 4.3 布局、批注与来源

所有预设使用 `nodeLayout[nodeId]` 独立存位置、层级；连线沿用单父无环的 `edges`。不引入第二套可独立修改的 `parentNodeId`。

转换保留节点 ID、父边、标题、说明、批注、位置与选中态；结果尺寸可以变化，继续以图片左边缘与垂直中心锚点布局，不重排整棵树。待生成节点的宽高比从目标配方取值，不机械沿用父图比例。

## 5. 单分支工具与完整候选求值

### 5.1 输入与返回

```json
{
  "retrospect_id": "r1",
  "base_image_id": "#h5",
  "label": "整备理项圈",
  "description": "用近距离整理衣领替代僵硬站姿，建立手部接触点",
  "edge_summary": "调整距离与手部互动",
  "steps": [
    { "kind": "prompt_patch", "target": "image.prompt", "mode": "rewrite", "text": "此处为完整的该方向提示词" },
    { "kind": "character_edit", "op": "set_position", "id": "c2", "x": 0.35, "y": 0.5 },
    { "kind": "params_patch", "params": { "scale": 5 } }
  ]
}
```

示例中的角色 ID 与位置格式必须以真实来源槽位、当前型号能力为准。省略 `retrospect_id` 时只解析当前 IMAGE 活动树，或本轮刚由 `show_retrospect` 准备的树。

- Schema 为一个对象、`additionalProperties: false`，无 `branches`；`steps` 为 1～12 个，与现有步骤上限一致。
- `base_image_id` 必填，必须解析到目标树中真实、仍有效且原始 IMAGE 配方完整的具体样本；本期不以未生成预设作为另一个预设的基底。
- `label` 为 2～10 字短名，`description` 可选且 40 字内；连线概括省略时使用短名或确定性改动摘要，沿用现有连线长度上限。
- 仅开放 IMAGE 的 `prompt_patch`、`params_patch`、`character_edit`、`restore_partial`；共用原步骤定义，排除 CHAT／EDIT 靶点、文件／任务写入、交接、新画板字段。
- `restore_partial` 继续解析本轮已读取的真实来源，采用其指定字段；不因局部取词改变当前分支父节点。

成功回执仅包含树／节点 ID、基底、短名、已保存状态、剩余预设名额、精简 Token 预算与警告；不回传刚生成的整套长提示词。失败返回具体步骤编号、靶点与已有锚点诊断，不创建半节点。

### 5.2 求值流程

1. 校验工作区、目标树、基底记录、容量和读取证据。
2. 从真实样本建立隔离的完整执行基底，含基础正负词、原始角色槽、模型及参数、参考配置；不混入当前画板的创作词文。
3. 按现有规则解析步骤并顺序执行。角色 ID 映射和新增角色分配只在候选内发生，不推进真实画板的角色计数器。
4. 检查所有启用步骤的结构／参数／锚点错误，得到完整目标；随后复用 `checkNaiInput`。非 NAI 返回 `null` 不能被当作跳过其他步骤校验的理由。
5. NAI 硬错误拒绝该次调用；普通 Token 超量、分词器不可用按现行规则提示，不静默截短正文。无来源配置仍可准备文字，不进行选源、报价或编码。
6. 异步检查后重新核对目标和修订，原子提交一个节点与一条边；发出更新后再返回成功。

应抽取／复用现有纯求值能力，而非直接调用 `propose_draft.run()`：后者承担「一轮唯一草稿＋终结工具阶段」，与本功能职责不同。已有回退草稿中的基底恢复、角色映射和检查可下沉复用，但不能为了计算候选临时拨动画板游标。

### 5.3 补足读取证据

现有候选配方适于对比，但其角色 ID 已被移除。工具读取需补齐每个可用基底的原始槽位与 ID 对应，包含停用／空槽的执行身份；模型不得以过滤后的「角色 1」猜测 `c1`。

`get_recipe_clusters` 继续一次返回历史与相邻演进证据，并增加已有预设的节点 ID、具体基底、短名、说明、待生成状态和目标配方。完整原文在同一结果中只保留必要的一份，分组与身份可引用它；不在工作区初始摘要或每次成功回执重复灌入所有方案正文。

## 6. 逐次提交与同轮先建树

### 6.1 已有活动树

每次通过检查后直接提交该分支。A 成功、B 锚点失败、B 修正成功、C 成功时，A 的内容、位置和身份不变。取消、网络失败或最终说明失败，也不撤销之前已经成功保存的分支。

这是对现有「整轮成功才提交演进」的局部扩展：对话上下文本身仍沿用原成功／回滚规则；新工具已经完成的树操作不随模型消息回滚。失败轮次 UI 应显示「已保留 N 个预设分支」，下轮状态与读取工具能再次找到它们，避免模型误以为全部失败而重复创建。

工具执行不得依赖消息动画／pacer 的延迟提交；UI 动画只呈现已完成的业务状态。

### 6.2 同轮 `get_recipe_clusters → show_retrospect → stage…`

实施前 `show_retrospect` 仅把结果放进流式消息，尚未注册到 store；读取器也固定在开轮的树快照。因此不能直接写一个「只查当前 activeForBoard」的新工具。

建议采用本轮准备树的衔接方式：

1. `show_retrospect` 校验后，将待登记／待重整树放入本轮演进上下文，后续工具可以解析它，普通调用仍保留原成功轮次提交规则。
2. 首个分支校验成功时，将准备树与该分支**一起提交**；已有树重整先检查读取修订，不能覆盖在此期间新增的真实图、批注或用户操作。
3. 返回真实树 ID 与当前修订，更新本轮演进读取视图；后续调用继续操作这棵树。
4. 整轮收尾识别已经提交的演进，不再用之前的 `show_retrospect` 快照登记第二棵树或覆盖新增分支。
5. 首个分支尚未成功就失败／取消，不提前激活准备树；首个分支已成功后，本轮即使失败也保留树和成功分支。

这样无需全局改为「所有 `show_retrospect` 立即落地」，但必须补这条明确的提交路径及回归测试。

### 6.3 修订、重试与并发

- 分支追加推进树修订，不改变当前画板配方或创作游标；同轮自己的成功提交更新本轮可操作修订，不让第二个分支必然报过期。
- 外部生成、重整、删除、解除、换板等变化仍检查。可重新读取最新树元数据后继续，图片配方证据仍使用已冻结、身份已核对的样本。
- 后续 `show_retrospect` 必须基于当前修订并保留预设；不能在收尾用旧树清空它们。
- 工具提交以本页调用身份防重复。显式重试旧失败轮次时，可对仍存在且未转实的同基底、同完整计划识别重复并返回已有节点；用户已删除的方案不复活，不把仅有相同标题的不同方案合并。
- 预设挂载不移动游标，所以不会把正在生成的普通图片误接到新方案上。长输出截断或 JSON 不完整时不得部分提交。

## 7. 画布与配方对照

复用现有点阵背景、悬浮配方窗、底部胶囊、缩放适应、单／多／框选、节点和连线批注；本期不重设计整套演进界面。

- 预设为虚线边框、短标题、小字说明；前端经 Opus 咨询后采用轻底色与文档图标，普通空白后继框继续使用紫色加号。选中沿用紫色边缘，不增加重填充背景。
- 图形尺寸由预设目标尺寸决定。不同横竖比例、拖动和放大使用现有布局规则。
- 初次追加采用现有避让算法，所有旧节点与旧预设位置保持；关闭重开保留位置和视野。新增时不强制把镜头拉回全图。
- 选中预设只浏览；「载入画板」才改变游标。已载入节点提示「已载入」，主操作切换为「前往画板」，不把普通选中状态当成载入。
- A 默认取**创建分支时绑定的具体父样本**，B 取该分支完整计划。父节点代表图或当前浏览样本后来变化，不悄悄换掉 A。
- 沿用 `recipeDiff → groupsOf → RecipeReview` 以及完整配方／仅变化切换，保留红绿词级上下文、角色位置与参数类型差异；空／停用角色只在有效比较层过滤。
- 可选择其他预设或已生成版本作为配方比较对象；无图身份显示待生成状态，不渲染破图，不提供下载／收藏／定稿或虚假的大图。真实兄弟节点点亮后正常支持大图 A/B。
- 普通无配方的续画空框继续保留。游标指向预设时，该预设本身就是落图位置，不再额外生成一个游离空框；指向已生成样本时，原空框继续负责普通续作。
- 新预设沿用首访 NEW 提示；转实保留节点身份和批注，不因替换 DOM 重置整张画布。

## 8. 载入画板与撤销闭环

「载入画板」是一项面板发起的完整写入，直接复用草稿 writer／stack 的冲突、租约和补偿流程。新增明确的操作来源信息，以便撤销入口显示「载入分支：短名」；不伪造一条 ASK 回复，也不覆盖已有待确认草稿。

载入流程：

1. 重新确认当前为所属 IMAGE 画板、树仍活动、节点仍为预设，快照与参考资源有效；检查模型／采样器／角色数量和参数，沿用现有忙状态约束。
2. 以点击时画板状态作为撤销前态，使用已冻结的目标快照构造完整写入。角色在真实画板上分配合法新 ID，不沿用候选求值时占用的临时编号。
3. 在一次操作中写入配方、提交预设游标，成功后才入 50 步栈；任一步失败补偿前态，不留下半套表单或提前移动的游标。
4. 成功后用户自行核对、修改或生成；不自动发起图像请求，不新建画板。

撤销与恢复：

- 撤销载入恢复载入前的表单与游标，仍按全局栈顶和外部修改冲突规则执行；不删除方案或已经生成的图片。
- A → B 连续载入，先撤销 B 回到 A，再撤销 A 回到原节点；普通 ASK 草稿与面板载入共用同一顺序。
- 载入后已生成，节点保持实心；撤销不能把它还原成空壳。再次恢复这条载入记录时，使用其保存的目标配方，并把游标解析到同一实节点的真实样本，不能复活旧的预设状态。
- 已解除、定稿、换板、被删除或无法映射的目标，过期撤销／恢复不能重新开启跟踪。
- 原有「已生成节点恢复」是否统一进入栈不在本期顺便扩大；本期明确保证的是预设载入可撤销。

## 9. 生成后原地转实

在现有 `begin/land` 中增加优先级更高的预设落图路径：

| 情况 | 目标行为 |
| --- | --- |
| 未修改直接生成 | 第一张成功图填入指定预设，不与父节点合并 |
| 仅换 Seed，甚至有效配方与父节点相同 | 仍优先填入该预设，尊重用户选定的试跑目标 |
| 用户载入后微调提示词／参数／角色 | 首张仍填入该预设，以真实结果记录为准；不做相似度判定 |
| 首张请求失败或取消，没有结果 | 保留待生成节点及位置，不创建正式图，不自动重试 |
| 一批多张图 | 首张将节点转实，其余本批样本进入同一节点；部分失败保留已成功样本 |
| 节点转实后的下一批 | 重新以该节点所选真实样本为基底，同有效配方归组、修改后新建后继 |
| A 在途时用户后来切换创作基底到 B | A 的结果仍按提交绑定填 A；不抢回 B 的游标 |
| 生成途中解除／定稿／切板 | 延续既有跟踪代次规则：成功图片仍保存历史，不向已停止树追加、不重新开启跟踪 |
| 对比拼图或重复通知 | 不作为分支结果；重复结果不重复记数 |

转实一次性更新 `kind`、真实 `cover/image_ids/recipes`、稳定图片绑定、`sampleBases`、资源保护与显示计数；`sampleBases` 指向创建该分支的具体父样本。计划目标可以作为来源说明留存，但不能继续被当作实际结果的 Diff 或恢复来源。

保留节点和连线的原名称、说明、位置、批注；实际生成与原计划不同无需判错，后续归组以实际配方为准。转实不再占未生成名额，也不再额外消耗 80 节点容量。

## 10. 重整、删除、收口与保存

### 10.1 同树重整

`show_retrospect` 仍负责真实样本阶段，不要求模型在 `image_ids` 中伪造无图项。已有预设由程序合并保留；根据冻结基底的稳定记录身份找到重整后的父节点，沿用预设 ID、目标配方、位置和批注。

重整不能复用已被预设占用的 `vN`；也不能默认丢弃预设。若拟移除预设依赖的基底样本，返回明确冲突，要求保留来源或先显式清理该预设。不要把具体基底悄悄替换为新父节点的代表图。

### 10.2 删除与定稿

- 删除仅作用于未生成预设，同时清理该节点的边、批注和布局；不影响兄弟分支、已生成版本或普通历史。
- 删除当前载入的预设时，建议把游标回拨到其原父样本，画板表单保持用户当前内容并明确反馈；后续生成按普通续作处理。
- 正在接收在途生成结果的预设暂不能删除，待任务结束后再处理，避免结果归属悬空；需要由生成生命周期释放在途标记，失败或取消也必须释放。
- 定稿仅允许真实样本，仍先收藏再结束跟踪。其余预设默认保留为未采用方案，历史视图可看配方；清理须显式操作。

### 10.3 资源与快照

IMAGE 仅保留缩略图但完整配方仍在的真实记录，可以作为预设基底；该能力不需要像素。主动删除导致记录无效时按现有身份规则拦截载入，不拿同字节收藏偷换配方。引用的参考资产／编码仍须在载入时检查，缺失不静默移除。

活动预设仍只保留本页；关闭重开保留，刷新不自动恢复活动跟踪。收藏成功回复时保存当次预设文本快照与可信来源，无原图复制；刷新恢复只供查看，不自动恢复写入权限。后续预设转换与删除不持续回写旧回复。

树上的成功预设不归某条回复 DOM 所有；删除来源回复不自动删方案。整轮失败前已保存的分支同样留在本页树，但不承诺随失败会话刷新后恢复。

## 11. ASK 提示词与工具说明

沿用用户定稿的简洁引导，只补三点：

1. 单图卡在瓶颈，或用户要求准备几个不同方案试跑时，可在版本演进里准备通常 2～3 个待生成分支。
2. 每次 `stage_evolution_branch` 完整推敲并提交一个方向，逐次读取回执再提交下一个；成功后只总结差异和试跑建议。单一明确修改仍用 `propose_draft`。
3. 新分支仅保存计划；用户载入画板后自行生成。需要新建演进时，先读取并 `show_retrospect`，再在同轮挂分支。

不要将修订号推进、内部游标联合类型、撤销补偿和事件时序写进创作系统提示词。工具字段描述提供基底与角色 ID 规则，具体错误由运行时回执说明。
