## Opus 原稿（原文）

### 二、通用图像模型（GPT Image / Gemini Image / Seedream）

这一类模型按使用方式归类：以自然语言和参考图驱动生成与修改。不同型号的内部架构不一定相同。后续新增的同类模型也按本节理解。

1. **共性与提示词组织**
   - 常见用途：文生图、参考图编辑、人物或物件一致性、风格转换、多图元素整合、画中文字与版式。先确认用户要完成的任务，再选用当前来源支持的操作。
   - **从零生图**：用自然语言写清主体及其关系、构图与机位、场景、光影色彩、风格材质。画中文字要写出准确原文、位置和层级。中英文跟随用户的表达，不为套模板而翻译。
   - **有底图**：写增量修改，即改哪个对象、改在哪里、改成什么。同时写明需要保留的人脸、服装、机位、线条和光影。
   - **多张参考图**：逐张说明用途，如身份、构图、服装或风格。用途冲突时写明取舍。
   - **从标签式写法迁移**：NAI 的 `W::`、`{}` 等权重语法在这里不起作用。把标签内容改写成连贯描述，突出关键关系和保留项。没有独立负向字段时，在正文写明不要的元素及期望的替代。

2. **能力以当前来源为准**
   - **CHAT**：读取 `chat_model` 的 `family`、`max_images`、`writable` 与 `read_only`。草稿只写入 `writable` 中的参数，`read_only` 项仅供参考。
   - **EDIT**：读取 `capabilities`、`source` 与 `effective`（实际生效值）。可做通用改图和本地蒙版合成。
   - 参考图数量、尺寸、质量、复杂度、透明背景、原生标注等能力，均以当前状态为准。不从型号名或版本号推断，不把某一型号的经验或参数套用到其他型号。
   - 新模型、用户自定义名称和渠道别名，沿用本类的基本写法，再结合其当前能力和用户提供的实测经验调整。
   - 下列型号介绍不是参数白名单。来源声明优先于参考模板；来源仅标为参考模板时，其能力尚未经实际来源验证。

3. **型号简介**
   - **GPT Image 2 / 2.5 / 2.6**：适合复杂的自然语言要求、图中文字与版式、参考图编辑和细节调整。Sunburst、Flare 等版本按已选来源使用。
   - **Gemini Image（Nano Banana 系列）**：适合参考图驱动的连续修改、角色在不同场景中的延展，以及多图信息整合。Flash、Pro、Lite 各型号的参考图容量与分辨率不同。多轮修改只依据本轮实际发送的文字和图片，未重新发送的旧图不算在内。
   - **Seedream（字节跳动）**：可用自然语言完成文生图、参考图修改，以及人物、服装、场景、风格的多图整合。5.0 Lite、Pro、Flash 均按本类写法使用。5.5 目前只有参考模板，实际 API 能力尚未验证。

4. **画风保护与迭代**
   - 底图为二次元插画或特定手绘风格时，写明保持线条粗细、笔触、上色方式和五官比例，只改目标部分。这类要求能引导结果，但不能保证未选区域或人物特征完全不变。
   - 大幅改姿态、翻转机位、复杂遮挡和精细接缝，生成后需看图核验。
   - 多轮修改后脸型、构图或画风出现漂移时，回到效果最好的版本，精简修改目标后重新开分支。需要把改动严格限制在局部时，使用局部蒙版合成。

### 三、跨模型语法互转（替换原章节第一条）

- **NAI → 通用图像模型**：把权重强调、画师串和离散标签所表达的内容与风格，改写为自然语言描述，保留用户指定的外貌、构图和画风意图。有参考图时写明每张图的作用。
- **通用图像模型 → NAI**：用标签表达主体、机位、姿势等要素，用短句补充空间和光影关系，再按 NAI 的角色栏和当前预算拆分。
