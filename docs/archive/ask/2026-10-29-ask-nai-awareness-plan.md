# ASK 的 NAI 基础感知实施规划（EA0）

归档说明：这是本轮获准实施前的规划原文；现行行为见 [NAI 基础感知](../../ask/nai-awareness.md)与 [ASK × EDIT](../../ask/edit.md)，验证证据另存。原文的“未实施”描述只对应规划时点。

日期：2026-10-29。状态：**规划已补充，代码尚未实施**。本稿定义 [ASK 接入 EDIT](2026-10-29-ask-edit-plan.md) 的前置基础，在 IMAGE 中先完成并验证，再由 EDIT 复用。本次更新只涉及文档，不表示代码已接通，不构成推送或部署授权。

现行参数、分词、费用与生成边界以 [NAI 官方接入](../../integrations/novelai.md)、[业务契约](../../business-contracts.md)和 [ASK 维护入口](../../ask/README.md)为准。这里的“模型能力”指生成目标的 NAI 型号、来源协议与操作能力，不是 ASK 推理模型的名称或权限。

## 1. 现状与目标

| 对象 | 已有实现 | EA0 要补齐 |
| --- | --- | --- |
| 参数与型号 | Guidance／Rescale、Variety+、噪声调度、Anime／Furry、Effort、预设、角色、参考配置已有生成链路 | ASK 可读的能力与限制、保存值／生效值，以及可写字段 |
| 初始状态 | 活动画板完整基础／角色词文与部分参数；按 board_id 可读完整原始表单 | 初始摘要漏掉的 Variety+、调度、透明底；型号规范 ID 与当前来源能力 |
| 输入预算 | 本地 T5／Qwen3.5 Worker；IMAGE／EDIT 显示用量和上限；执行检查 | 把同一计算结果交给 ASK，并支持提议前检查候选修改 |
| 费用 | 官方本地 Anlas 估算、参考／编码费用、标准网关报价 | 脱敏、绑定输入与来源的只读费用摘要，区分未知、旧价和估算 |
| 图片参数 | get_meta／diff_meta 按具体记录读取 | Variety+、Director 配置与来源配方等漏项；缺失字段保持未知 |
| 提示词 | 静态模型知识包含部分型号限制 | 动态事实优先；修正与 Koma 实现不符的产品说明 |

目标是让 ASK 在提议前知道：当前能用什么、哪些值实际生效、词文占多少预算、预计消耗属于哪一种口径。现有参数控件与生成协议不重做，不扩展参考写入权限。

## 2. 共用数据来源与冻结

### 2.1 唯一计算路径

复用现有实现，建立不依赖组件是否显示的服务层只读快照：

- `domain/nai.ts`、`nai-parameters.ts` 与目录／Profile：型号、参数、预设和来源限制。
- `domain/characters.ts`、`nai-references.ts`：启用角色、定位、参考的模式和操作限制。
- `domain/nai-input.ts`、`native/nai-tokenizer.ts`：有效词段、token 与 Text 字符计数。
- `domain/nai-cost.ts`、`services/quote-preview.ts` 及既有账户／参考缓存：本地估算和已取得的报价。
- `domain/nai-enhance.ts`、`inpaint-focus.ts`、`director-tools.ts`：EDIT 阶段的操作特例。

参数 UI、ASK 摘要、候选检查、草稿校验与出站校验共用规则；不得在提示词或 ASK 模块里再维护一套数值表。计数沿用现有有界缓存和 Worker 清理机制，不从 DOM、tooltip 或当前挂载的计数组件抓取数字。

### 2.2 快照位置

共享摘要的规划名称为 `NaiCapabilitiesDigest`、`NaiEffectiveDigest`、`NaiInputBudgetDigest`、`NaiCostDigest`，分别对应下列四类对象；本稿规定其数据口径，实际 TS 类型在代码实施时从共用实现导出，不另建手写配对声明。

- IMAGE 的 `image.form` 保留可编辑原文与保存值；新增同级 `image.capabilities`、`image.effective`、`image.input_budget`、`image.cost`。
- EDIT 接入后在 `edit` 下采用相同的四类对象，再添加编辑模式、底图、蒙版和聚焦框信息。HOME／CHAT 等页面仍能读取活动 IMAGE 的摘要；EDIT 非活动板按需读取。
- 能力摘要传规范型号 ID、显示名、来源 Profile 类型、当前操作及可用型号目录；不输出连接地址、Key、原始账户响应、私有上游 ID 或参考编码。
- 发起一轮时，表单、源身份、目录能力和可用的费用／计数结果一起冻结。`get_state` 默认读取 initial，latest 只追加读取，不替换草稿初始基底。
- 计数尚未完成时可以发送 `pending`，不得把旧输入的结果当成本轮用量；随后按需工具只计算冻结输入。另一画板或旧修订的异步结果不能覆盖当前快照。
- `input_hash` 表示实际计算输入，连同来源／目录修订用于匹配结果；账户变化或计数完成不进入草稿 `base_hash`。确认草稿时仍重检当前目标能力，不能用过时能力放行。

## 3. 能力、保存值与生效值

### 3.1 能力摘要

至少包含以下结构化信息：

| 类别 | 内容 |
| --- | --- |
| 就绪状态 | ready／unavailable 及原因；当前型号、Effort、来源类型、操作 |
| 可写字段 | 字段类型、枚举／范围、是否固定、禁用原因；区分 UI 滑杆上限与实际校验上限 |
| 参数 | Guidance、Rescale、步数、采样器、噪声调度、Variety+、Complexity、预设、透明底 |
| 尺寸 | 当前操作的对齐、面积及产品文件限制；不把绘图的 2048 单边限制套给官方 EDIT |
| 角色 | 最大启用数、位置模式、当前启用数；超限报错，不截掉多余角色 |
| 参考 | supported_kinds、active_kind、active_count、mutually_exclusive、不可用原因；支持两种不代表能同时启用 |
| 编辑预留 | Img2Img／Inpaint、聚焦、Enhance 倍率、放大及 Director 能力；EA0 不因此开放 EDIT 写入 |

能力必须同时满足型号、当前来源与操作条件，不能只按“NAI”或模型显示名推断。例如：

- Variety+ 只在官方 V4.5 支持，按实际请求尺寸计算 sigma；V5／未声明此能力的网关不启用。保存值仍可保留，摘要明确实际不生效。
- V4.5 可调噪声调度，V5 固定 Karras。Medium 实际为 14 步、Euler Ancestral、固定 Heavy 负向，不使用用户负向或可调 Rescale。
- Effort 从规范模型 ID 派生，High／Medium 是不同型号来源，不作为可独立漂移的布尔参数。
- V4.5 官方文生图／Img2Img 可用 Vibe 或 Precise；Inpaint 只支持 Precise，V5 两种参考仍不开放。
- V5 Curated 不提供独立 Inpaint；聚焦、Enhance、Director 和放大的限制按各操作判定。无可用来源时不猜测可执行。

### 3.2 生效值

`form` 用于原文审阅和恢复；`effective` 用于解释实际请求，必须明确固定值与未采用字段。例如 Medium 保存了 25 步和自定义负向，仍应显示“生效 14 步／固定负向；保存值未参与”。

生效摘要至少覆盖实际型号／Effort、步数、采样器、Guidance／Rescale、调度、Variety+、预设和参考状态。完整生效词文可按需返回；初始状态保留原文和差异／追加项摘要，避免重复整段提示词。

草稿校验基于整份候选修改后的型号和操作，不按步骤先后误判。新建议不能把不支持的字段写入后再静默丢弃；切型号时已有的休眠配置可以保留，并明确说明其不生效。遗留 `cfg` 仅作旧数据兼容，不重新开放为参数或映射成 Rescale。

## 4. Token 与 Text 字符计入契约

### 4.1 角色按方向合计，不独享配额

当前分词入口先形成有效基础词段与启用角色词段，**每个词段独立计数，再按方向求和**。设 T 为对应型号的计数器：

```text
正向 used = T(有效基础正向) + Σ T(每个启用角色的有效正向)
负向 used = T(有效基础负向) + Σ T(每个启用角色的有效负向)
remaining = max(0, limit - used)
overflow  = max(0, used - limit)
```

- 正向与负向分别对照该型号上限，不能相加后对照同一个上限，也不能互借剩余额度。
- 单角色显示的小计是总预算的一部分；新增角色不会获得额外的 512／703／1471 tokens。
- 停用角色不计入。启用数超过型号限制是结构错误，不取前 N 个后假装可用。
- 计入有效质量／负向预设、模式／Complexity／透明底追加词，以及普通 Enhance 追加词；同一个追加过程只执行一次。
- Medium 使用实际固定负向；用户保存的基础／角色负向不参与。角色的正向仍照常累加。
- 各段保留现有分词器的归一化与特殊 token 规则，不把文本拼成一个大字符串重算。T5 含 EOS，空词段也不能凭直觉强记为 0；是否存在该词段由实际输入构建器决定。
- 角色 ID、UI 标签、坐标和文件名不作为提示词加入计数。参考图片也不折算成这里的文本 tokens。

示例（数字代表已完成分词的小计，含生效追加词）：

| V4.5 输入 | 基础 | 角色 c1 | 角色 c2 | 合计／上限 | 结果 |
| --- | ---: | ---: | ---: | --- | --- |
| 正向 | 300 | 120 | 100 | 520／512 | 超出 8 |
| 负向 | 60 | 25 | 15 | 100／512 | 剩余 412 |
| 停用 c2 后正向 | 300 | 120 | 不参与 | 420／512 | 剩余 92 |

### 4.2 型号上限与诊断

下表对应当前 `naiInputLimits`，ASK 实现必须读取该函数，不另写常量：

| 型号 | 分词器 | 每个方向的 token 上限 | 正向 Text 字符合计上限 |
| --- | --- | ---: | ---: |
| V4.5 Full／Curated | T5 | 512 | 118 |
| V5 Curated | Qwen3.5 | 703 | 374 |
| V5 Full High／Medium | Qwen3.5 | 1471 | 750 |

`input_budget` 需给出：

- `status`：ready／pending／unavailable／error／not_applicable；`model_id`、`encoder`、`input_hash`。
- `positive`、`negative`：used、limit、remaining、overflow、基础小计和按稳定角色 ID 的小计。
- 角色启用与是否实际参与状态，区分“停用／Medium 不采用／内容为空”。
- `text`：字符 used／limit／overflow，以及基础／角色来源；超限给出可定位的诊断。

未算出时省略 used／remaining，不能填 0 或旧值。非 NAI 操作和 Upscale／Director 不套用这套生成提示词预算；Director 有独立的输入规则。

`Text:` 沿用当前识别与 Unicode 字符计数：对每个启用正向词段分别提取标记后的正文，再将基础与角色的字符数相加，空白和换行按现有规则计入。它不是每个角色一份字符额度，也不替代 token 计算；同一输入可能同时触发两种限制。Koma 没有实现自动双引号提取，不得告知用户只加双引号就会由 Koma 转成 Text 块。

Token 超限保持警告，提示可能被上游截断，不自动删词或新增硬拦截；Text 超限给出执行阻断诊断，沿用付费编码／生成前的既有拦截。计数失效时保留未知，不声称输入已通过检查。以上与 ASK 推理上下文的默认 64,000 tokens 压缩阈值完全独立。

## 5. 费用感知契约

### 5.1 只读来源

ASK 仅可读取工作区已取得的费用快照，或使用已缓存且适用的账户／参考信息调用纯本地估算。不得因构建摘要、get_state、候选检查、提议、应用或撤销草稿调用 `selectSource`、刷新额度、请求报价、付费编码或生成。

| 信息 | 规则 |
| --- | --- |
| 状态 | ready／loading／stale／unknown／unsupported／error；loading 携带的旧价不得视为当前报价 |
| 来源 | provider_quote 或 local_estimate，注明 unit；标准网关积分与官方 Anlas 不混用 |
| 绑定 | 操作、计算尺寸、输入指纹、来源修订和取得时间；原图尺寸不一定等于 Enhance／聚焦的请求尺寸 |
| 分项 | 已知时给每张费用、每张参考附加费、一次性编码费和 batch_total；不得用本次总价直接乘张数重复计编码费 |
| 缺失 | 不知道的分项或总价省略，给 reason；已知最低附加费只能标 lower_bound，不能充当整次报价 |

修改影响计价的字段后，旧费用失效。候选表单可用纯本地函数重新计算官方估算；标准网关没有对应有效报价时返回 unknown，不能用官方公式冒充该网关的积分价。账户信息不足、已知过期、参考编码缓存未就绪或来源失效时保留未知，不因缺数据猜测零费。

### 5.2 批量、权益与展示

- 官方批量按“每张基础／参考费 × 张数 + 唯一待编码费”计算；仅基于当前缓存假设，不执行编码，费用最终由实际请求决定。
- 免费资格只保留在原有内部计算中，不恢复“Opus 免费”或零费宣传标签。Anlas 为零不等于 V5 用量不消耗。
- V5 用量百分比只有基准近似，不当作精确账单或额度拦截依据，不默认传冗长小数并诱导模型复述。用户询问时才作适度舍入的说明，明确近似口径。
- 账户原始对象、连接秘密和路由细节不进入模型上下文；只提取判断所需的非秘密结果。
- 阅读或比较费用不改变现行执行前重报、max_cost、涨价提示、选源、取消、不重试和无新增付费确认弹窗的行为。

## 6. 候选修改检查与元数据

### 6.1 本地只读检查

规划新增 `check_nai_input` 工具：以本轮冻结的目标与 `base_hash` 为基底，接受待检查的候选 `steps`；步骤复用现有 prompt_patch、params_patch、character_edit、restore_partial 解析与候选状态计算，EA2 后再接受 EDIT 对应步骤。不接受任意请求参数，不含网络或写入端口。

- 返回候选的能力诊断、生效差异、input_budget、可用的费用摘要，以及与该候选对应的指纹；steps 为空时检查冻结的当前输入。
- 修改角色、预设、型号或模式后重新构建全部有效词段，不能只计新加的字符串。新增角色 ID 在试算中使用临时绑定，不消耗真实画板计数器。
- 工具不结束本轮，模型可以据结果精简后再检查；`propose_draft` 仍是一轮一份并结束工具调用。
- 检查不是应用许可，不能跳过确认时的冲突／能力校验。候选检查不替换初始基底、不创建草稿卡、不触发生成。
- 诊断区分警告和执行阻断；保留 §4 的 token／Text 行为。没有完成有效计数时不得回答“未超限”。

### 6.2 图片参数

补齐 get_meta／diff_meta 的安全白名单：Variety+ 与实际调度、Enhance／聚焦、Director 工具／变体／defry／emotion、适用的 source_recipe。参数按具体图片记录读取，不用当前表单或同实体另一条记录补造；历史缺失字段仍是未知。图片与蒙版位图、参考编码、地址和凭据不输出。

## 7. 提示词与 UI

- `prompts/workspaces.ts` 说明能力、有效值、预算和本地检查工具；明确先读当前动态事实，再提议参数。
- `prompts/models.ts` 保留用户创作经验，修正产品接口事实：角色共享预算、Medium 的实际参数、Variety+ 的适用条件、Koma 未提供双引号自动提取、费用不是保证。
- `prompts/manuals.ts` 只维护长篇创作方法，不重复维护参数上限。仅在代码接通时更新对应提示词版本；本次文档修改不提前改版本串。
- 不新增大面板、常驻费用说明或长篇契约文案。共用现有 token 小计与 tooltip；草稿沿用紧凑 Diff 和现有警告样式，细节按需读取。

## 8. 实施顺序与验收

EA0 在 EA1 之前收口，内部按依赖完成以下工作：

1. 抽取共用的型号／来源能力与有效输入快照，先补 IMAGE 摘要、get_state 和元数据漏项。
2. 接入 token／Text 计数、冻结／过期处理及候选检查，复用 Worker 和缓存。
3. 接入只读费用摘要，更新工具说明／提示词事实，完成 IMAGE 验收；EDIT 阶段仅扩展目标适配。

| 必验项 | 预期 |
| --- | --- |
| Variety+ | 官方 V4.5 开关／支持性在摘要、元数据、Diff 一致；切 V5 或网关后保留本地值但明确不生效 |
| Medium | 保存值与 14 步／固定采样器／固定负向明确分离；用户负向不计入实际预算 |
| 多角色合计 | 基础与两个启用角色分段计数后相加，正负分别校验；停用一角后小计退出合计 |
| 空值与超限 | T5 EOS 与现有计数一致；没有额外角色配额；角色超上限不静默截断 |
| 有效追加词 | 质量／负向预设、Furry、Complexity、透明底与普通 Enhance 只计一次；Max 不误加普通 Enhance 词 |
| Text | 基础与角色共享上限，Unicode／空格／换行一致；token 警告与 Text 执行阻断分开 |
| 异步结果 | 快速改词／切板／切型号时旧结果不覆盖；pending／error 不伪装 0；初始快照不漂移 |
| 候选检查 | 改词、角色和型号后重新计数，不创建卡片／持久数据，不耗角色 ID，不请求上游 |
| 费用 | Anlas 与积分分开；一次编码多张复用；旧价标 stale；账户或参考信息缺失保持未知 |
| 权限 | ASK 摘要／工具／草稿应用与回退不触发报价、额度、编码、生成请求；只允许正常推理与同站点词表加载 |
| 元数据 | Variety+、Director 与来源配方可读；旧图缺字段不补造；不包含图片和秘密 |
| 生命周期 | 视图隐藏后仍可读取；取消、切板、卸载不留下订阅或无界缓存 |

代码实施时运行 `npm run check` 及受影响的 ASK／NAI 浏览器测试，使用合成数据与模拟接口。真实供应商效果、分词采用与扣费仍按 [当前待办](../../status.md#仍待真实验证)独立核验。文档阶段只校验链接、契约一致性与改动范围。
