# Photopea PE2：官方 iframe 与双向选区核验

日期：2026-10-27。范围：`codex/ask-chat-handoff` 工作区中的 PE2 增量，基于前轮尚未提交的 NAI EDIT／PE1 实现。未推送或发布，未配置真实供应商 Key，未执行收费生成。真实 Photopea 与本地模拟接口分别记录，不相互替代。

## 已实现

- EDIT 顶栏增加「高级编辑」图标。只在用户打开后加载 `https://www.photopea.com`；既有覆盖层内切换，iframe 填满可用空间，保留紧凑顶栏和一个应用组合按钮。深色、中文与图层／历史面板由官方 Environment API 设置，品牌和广告不做覆盖。
- 当前图片归一化为 PNG 后以 `ArrayBuffer` 传入；Koma 位图／笔画蒙版渲染成透明覆盖，再通过临时图层透明通道恢复为 Photopea 选区。只传当前图片与蒙版；图片不放进 URL，不传 Prompt、Key、历史或供应商配置。iframe 仅发送宿主 origin 作为 Referrer，避免官方的空 Referrer 提示。
- 「图像」「重绘选区」「图像与选区」共用 PE1 一次提交入口。空选区拒绝回传；仅选区仍核对源图像素哈希，同宽高旋转也不能套回旧底图。图像／蒙版先全部校验，随后才创建版本或更改蒙版。
- 图层组中的临时选区图层先移至顶层，避免被隐藏的父组或原图层影响。导出后恢复原活动历史状态和活动图层，原选区与当前图层／可见性保持。该回退不合并 Koma 与 Photopea 的逐步历史，也不承诺清除 Photopea 的重做分支。
- 固定 origin、当前 iframe window、打开标识与命令编号共同限定回传；每次导出还回传 `document.source`，由 Koma 再次比对。其他 Photopea 文档不能被当作当前图的子版本。缺失、错序、重复片段及非法 PNG 使通道失效；超时后不接收迟到数据或自动重试。
- 普通校验失败保留 Photopea，可修正后再次应用；通道异常需用户显式重新载入。关闭、切换会话和取消废弃该次结果；退出确认尚未决定时，不抢先写入已返回的图片。进入实际校验／提交阶段后暂时禁用返回，避免写入与放弃确认交叉。
- 高级编辑期间暂停 Koma 原生画布、指针与快捷键，停止该编辑会话的报价并阻止生成；返回后恢复画布和入口焦点。监听器与 iframe 随关闭释放。回传不占用生图任务槽、不调用 NAI。
- IMAGE 来源的手动版本继续直接进入主历史，可收藏或给 Slate 绑图；CHAT 仍由用户显式回传。来源配方和手动编辑标识延续 PE1，没有伪造生成 Seed、费用或耗时。

## 真实 Photopea 验证

命令：`KOMA_PHOTOPEA_LIVE=1 node --test tests/photopea-live.browser.mjs`。使用 Chromium 和 384×256 合成图，走主程序正式入口、官方跨域 iframe 与公开消息／脚本 API；没有通过读取第三方 DOM、下载再上传或私有接口完成回传。

两个真实用例均通过，页面无脚本异常：

1. Koma 带孔洞的蒙版 → Photopea 选区 → Koma 蒙版，逐位比较覆盖一致。仅选区不创建图片历史。180° 同尺寸旋转后的选区单独回传被拒绝，图层／原选区保持；改选组合回传后成功。清空选区会阻止回传；再切为仅图像并旋转 90°，得到真实新尺寸的手动版本并直接进入历史。
2. 在图层组内部编辑，导出后当前图层、可见性、选区和根图层数量恢复。通过二进制另外打开一张 64×64 文档，核实其来源为 `file`，应用被拒绝；切回原文档后组合回传成功。

真实探测中修正的兼容点：

- `autosave: 0` 实际产生重复保存，不能用它表示关闭。现行环境完全省略自动保存配置。
- 全局打开脚本会产生额外 `done`，影响紧接着的初始化命令；现行导入只等待官方二进制完成回执，再显式发脚本。
- Photopea 解释器会跳过 `finally`。现行临时状态清理采用显式路径，预期错误通过回执和 `return` 退出。
- 选区边界为 UnitValue，使用其 `.value`；空选区 getter 的异常单独转换为可恢复错误，不继续访问未定义边界。
- 文档来源不能只靠嵌入脚本中的条件／异常守卫。Koma 主环境独立验证来源，错文档即使返回合法图片也不会应用。

合成截图与研究过程放在被 Git 忽略的 `.local/pe2/`，不进入发布包。
