## 实施范围

- 提取共享草稿 Schema，增加内外共用 `params_patch`，保留既有 Diff、勾选、最终模型／画幅约束、冲突和原数据写入链路。
- `src/bridge/` 提供目录挂载／权限恢复、同源单写入者、手动 JSON、协议生成、实时状态与预览、轻量历史／收藏索引、收件去重及单份回执。
- 外部记录进入原 ASK 会话，忙时排队；收藏保存待审草稿与等待队列，沿用来源板／新板、检查点及页面撤销栈。
- 状态与预览分开缓存；文本更新不重编码。新预览先于 JSON 写完，旧预览根据本机归属清理，外部 JSON 不能赋予文件删除权。
- 新增 `koma-bridge/state`，保存目录句柄、回执去重和预览归属；所有本机写入走数据租约，不加入普通备份。

## B1 浏览器场景

1. **手动入口**：没有 ASK 文本 Key、没有目录选择 API 时导入合法 JSON；参数 Diff、Seed 0、重复 ID、同 ID 改正文、按所属会话排队、应用／撤销／新板、状态下载及四宽度菜单。收件、应用、撤销和导出没有新增上游请求。
2. **目录与失败恢复**：无效根 JSON、重复 ID 冲突、结构无效回执后仍接收下一份合法草稿；外部伪造预览引用不删除用户文件；模拟读权限丢失时释放锁，拒绝授权保持暂停、显式授权恢复；数据维护后恢复同步。
3. **状态与幂等**：合成图片预览、文本修改不重新编码、半写 JSON 后正常收件、旧草稿完成不覆盖新回执、终态刷新不重放、未收藏 pending 刷新变为 invalid、第二标签页显示占用且不能绕过锁手动导入、卸载释放。
4. **ASK 事务**：模拟文本请求运行期间只排队；收藏待审草稿和队列刷新后恢复；注入写入失败保留 pending 且画板回滚，解除失败后可继续应用。

目录用例采用浏览器真实 OPFS 目录句柄、文件写入、IndexedDB structured clone 与 Web Locks；`showDirectoryPicker`、`queryPermission` 和 `requestPermission` 的结果由测试控制。没有将此结果称为真实用户目录兼容成功。
