# Photopea 界面精简验收

日期：2026-10-27。范围：用户确认[精简勘探](2026-10-27-photopea-ui-research.md)后的主程序实现。基于 `codex/ask-chat-handoff` 中既有 PE1–PE3 工作；未推送、未发布。测试使用合成图片和隔离浏览器，未调用收费生成。

## 载图后的视口重排

用户排查其浏览器中的 AdGuard 扩展后，要求避免 iframe 重建及固定扩宽裁剪，并在载图完成后触发一次内部尺寸重算。本轮按此实现；用户扩展的注入时序属于用户提供的诊断，没有将隔离浏览器的结果当作 AdGuard 实测。

- 容器与 iframe 使用标准宽高 100%，保留左上角定位和 `overflow: clip`，无负边距或永久宽度偏移。
- 首次按需创建，退出后 `v-show` 隐藏，重入复用 iframe、URL 与通信通道；关闭旧文档后载入新图，既有来源校验和取消排空保留。
- 图片及选区初始化的 `done` 全部确认后等待 150ms，将 iframe 缩窄 1px，保留 50ms 后移除临时宽度并恢复 100%。短暂宽度变化给跨进程子页面足够时间接收 `resize`；仅连续 rAF 的尝试在隔离 Chromium 中可能将两次事件合并到恢复后的宽度，未采用。
- 退出、重新载图、连接故障与卸载取消定时器并移除临时宽度。不检测扩展、不操作第三方 DOM、不修改 Environment URL，也不把这次重排当作独立去广告能力。

最终验证日志为 `.local/pe3/reflow-final-{check,browser,live,compat}.log`。真实 Photopea 验证首次载图和保活重入的子页面宽度变化，以及原有图像／选区往返；生产静态包使用 Chromium 151.0.7922.34 与 Edge 156.0.4314.50 验证四宽、图层／历史入口、键盘、鼠标／触摸和回传。断言等待第三方异步布局完成后检查最终边界，不将短暂的 1px 重排当作永久裁剪。

本轮最终结果：`npm run check` 通过（含 316 项单测及生产构建）；宿主／编辑回归 11 项、真实 Photopea 往返 2 项、Chromium／Edge 静态包用例 2 项均通过，`git diff --check` 通过。构建仍有既有大 chunk 提示。未推送或发布。

- Koma 顶栏右端新增折叠箭头。默认展开为 46px，折叠为 34px；返回、应用图标、完整回传方式及展开入口始终可达。窄屏展开态使用「应用」短文案，可访问名称与提示仍为「应用并返回」。

- 品牌、账户、官方链接与广告仍由 Photopea 提供，未使用遮挡、跨域样式覆盖或第三方 DOM 改造。

配置归 `src/native/photopea-scripts.ts`，顶栏结构与样式归 `src/overlays/PhotopeaPanel.vue`。通信、编辑提交和生成接口未增加新路径。

## 实例保活与左缘固定

同日按用户指定，首次打开后保留 iframe DOM，退出以 `v-show` 隐藏；重入复用通信实例，经固定脚本关闭旧文档并以新来源标识载图。命令编号跨重入递增，取消后先排空旧命令，隐藏时忽略保存；显式保存携带活动文档来源。宿主的菜单定位与离页监听退出即解除，组件卸载才释放通信资源。

容器使用相对定位、`overflow: hidden` 和 `display: block`；iframe 设置绝对定位、`top: 0; left: 0; margin: 0; max-width: none`，仅向右扩展。桌面扩展 320px，1280px 以下为 180px。四宽展开／折叠均断言 iframe 左上角与裁剪容器重合。

- `node --test tests/photopea.browser.mjs`：4 项通过，覆盖四宽对齐、实例只请求一次、隐藏保存无效、监听器不累加、取消导出后载不同尺寸图片及新来源保存回传。
- 真实 Photopea 双向选区及图层恢复 2 项通过；生产静态包 Chromium／Edge 四宽、真实指针编辑与回传 2 项通过。左缘绝对定位调整后补验 Chromium 的生产静态包，实际图片与选区回传仍通过。

## 内部聚焦触发的左侧裁切修复

随后在用户实际 Edge 页面确认左侧工具栏仍消失。宿主容器虽然已绝对对齐，但 `overflow: hidden` 创建的滚动容器发生了自动横向滚动；现场读取到 `scrollLeft: 180`。先前验证仅覆盖初始位置和顶栏切换，未覆盖内部控件聚焦，不能作为本问题已解决的依据。

改用 `overflow: clip`，阻止裁剪容器成为焦点滚动目标，继续保留 iframe 左上角绝对定位与 320／180px 扩宽。用户现有页面临时应用相同样式后，`scrollLeft` 与 iframe 左缘均回到 0，实际截图确认左侧工具栏完整；未刷新页面或重新传图。

新增跨 iframe 聚焦测试：旧代码会被滚动到 `scrollLeft: 320`、iframe 左缘 `-320`，修复后四宽均保持 0。宿主 5 项回归与 `npm run check` 通过；记录位于 `.local/pe3/focus-repro.log`、`focus-browser.log` 和 `focus-check.log`。生产静态包的真实 Photopea 用例增加强制滚动后的左缘检查，继续验证键盘、鼠标／触摸与图片／选区回传。修复不解决右侧固定裁剪与第三方动态布局之间的既有局限。

## 最终界面收口

随后根据用户发现右侧工具丢失的反馈，撤掉 320／180px 固定扩宽，iframe 恢复宽高 100%，保留左上角绝对定位与 `overflow: clip`。右侧图层／历史记录入口完整保留，广告由官方免费嵌入控制。保活、来源校验、取消排空和回传路径继续保留。

用户进一步明确不需要顶栏展开／折叠功能，现已删除对应状态、按钮、详情 DOM 和动效样式。顶栏固定为原紧凑样式：桌面 30px／24px 按钮，触屏 34px／28px 按钮；仅保留返回、Photopea 标识、应用图标和完整回传方式。此调整不改变 Photopea 自身图层面板的展开能力。
