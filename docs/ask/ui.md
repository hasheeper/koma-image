# ASK UI 与交互规范

更新：2026-10-29。本文维护用户批准的 B v5 窗口及后续已落地微调；原型、W1–W6 过程与旧动画参考见[历史归档](../archive/2026-10-25/README.md)。现行行为优先级以[ASK 维护入口](README.md)为准，产品颜色与字体沿用[设计语言](../product/design-language.md)。

## 1. 悬浮容器与全局布局


`AskDrawer.vue` 属于唯一 App Shell，在 HOME／IMAGE／CHAT／EDIT／TAGS 切换时保活。IMAGE／CHAT／TAGS 的布局不预留侧栏；HOME 停靠例外见 §1.1。点击图标或 ⌘J／Ctrl+J 展开／收起，桌面图标与标题栏空白处可拖动；各工作区的位置仅保留在本页内存。Alt 加方向键移动、Alt 加 Home 归位。EDIT 使用同一浮窗与顶栏图标，Photopea 打开时收起并让出键盘。

桌面 IMAGE 与 EDIT 的默认入口及浮窗位于画布右上角，距画布右缘 8px、顶缘 12px，避开历史／版本栏。EDIT 按实际画布边界定位，随版本栏开关和栏宽变化更新；手动移动后保留该工作区的位置，归位时重新对齐当前画布。860px 及以下打开后直接全屏，沿用 HOME 全屏的 canvas 实色背景与阅读列，不保留浮窗边距；隐藏放大／还原和拖动入口，背景工作区暂时不可交互。窗口跟随可视视口的高度与偏移，适应软键盘和浏览器栏，保留安全区；收起恢复原页面、入口和输入。EDIT 的收藏、下载等图片操作在宽度足够时位于底部工具栏右端，以细线分组；放不下时拆为工具栏上方、左对齐的独立胶囊，主工具栏保持单行并可横向滚动。

- 同一容器的五种形态：静默圆形 40×40、运行胶囊 304×40、结果卡宽 372px／内容高度、已写入胶囊 236×40、普通窗口 420×660。放大窗口宽 760px，高为可用视口减 32px；浮动形态限制在视口内，至少留 8px 边距；移动端展开使用全屏，收起仍为原圆形／胶囊／结果卡。
- 统一材质：`rgba(22,22,25,.88)`、20px 磨砂、1.4 饱和度；消息、草稿和输入叠加透明底色。容器圆角 20px，展开窗口 18px。菜单使用共享 raised 实色表面，预览使用近实色磨砂，保证叠字可读。
- 顶栏高 48px，内边距 `0 10px 0 14px`：标识、标题下拉、拖动空白、放大／还原、更多、收起。移动端全屏不显示放大／还原，顶栏与输入区避让安全区。标题显示当前会话名称，初始取提问首行，可手动或 AI 命名，附件单独提问时回退到文件名。
- 消息区弹性占满，内边距 `2px 16px 16px`，内部滚动。底部依次是草稿、会话待办和输入框，内边距 `0 16px 14px`；保留消息区和输入操作的可达空间。
- 标题下拉宽 300px（受窗口约束），统一紧凑行高 32px；选中勾距菜单右缘 13px。桌面悬停／聚焦时同一位置显示删除；触屏保留独立删除入口与选中勾，第二次点击确认。最多 20 个对话；标题菜单提供收藏／取消收藏，收藏项置前并显示星标，刷新后保留，其他对话刷新清空。运行／写入／保存收藏时不可新建、切换或删除。更多菜单仅保留「压缩上下文」「调用调试」。图片与偏好在已有设置 → ASK 页面管理。菜单锚定按钮、间距 4px，常规项最小宽 156px、行高 32px；目录菜单向上展开，会话菜单保留 300px 宽度，均限制在视口内。

### 1.1 HOME 上的呈现

HOME 与车间共享唯一 ASK。头部发送后打开停靠窗口，收起后在输入条下方显示运行、结果、草稿待确认或已写入状态；不显示闲置圆形和浮动胶囊。规则由 [HOME](../workspaces/home.md) §7.1 维护；会话、草稿、撤销、收藏与压缩沿用同一服务。

- 入口是 HOME 头部的单行输入条，复用标识、模型选择与发送／停止部件，与窗口输入框共用输入；HOME 上不显示静默圆形和收起胶囊。
- 窗口停靠而不浮动：默认半屏贴视口右侧，可放大为全屏；视口窄于 1280px 时直接全屏。不能拖动，也不记位置；停靠时不用玻璃，改用页面实色表面。
- 收起后由输入条承接运行、结果、草稿待确认与已写入状态，与浮窗胶囊共用同一份状态和收起判定。
- 输入条与窗口之间用浏览器原生 View Transitions 衔接，时长与曲线沿用本窗口的 520ms 几何过渡；减少动态时直接切换。

## 2. 色彩与排版

- 使用站内资源圆体 `--sans`，ID／代码与等宽统计使用 `--mono`，Koma 字标使用 Fredoka `--brand`；不新增字体。颜色与常规控件沿用 `--fg`、`--fg-2`、`--fg-3`、`--line`、`--a`、`--ok`、`--err` 等站内 tokens。
- B v5 的几何与字号沿用批准值及后续微调：消息正文 `13px/1.72`，提问 `13px/1.6`，输入 `13px/1.6`，文本预览 `12.5px/1.65`。不把原型小数字号四舍五入到相邻 token。
- 正文用 regular，标题用 medium，强调用 semibold；选中／引用为品牌紫，草稿新增为绿、删除为红。数字使用表格数字，静默／运行胶囊的图标与文字分别使用固定格子和共同基线。

## 3. 品牌标识与待机动画

浮动入口和顶栏使用 20px 整数 SVG 网格：核心 8px、边块 4px、角块 3px，间隔 1px，三层基础不透明度为 1／.5／.24。宿主和 SVG 均为块级固定格子，消除行内基线空隙；胶囊图标中心距左侧 20px。空对话页的品牌组合使用 34px 展示标识。

待机采用用户批准的方案 B：核心、光晕和描边按 5 秒呼吸；边块／角块按 9 秒周期依次亮起，分别延迟 1.2／1.42 秒。图标本体不平移或缩放。悬停时角块外散、光晕亮起、核心按 1.6 秒轻呼吸；按下整个静默入口缩至 .94，拖动时取消按压变形。处理中保留由内向外的三层呼吸。

主画布出现生成波浪时，待机周期放慢至 1.8 倍，光晕与心跳幅度降至 35%；页面隐藏时暂停。减少动态模式只保留静态微光，关闭呼吸、变形和闪光。

## 4. 消息流与操作

- AI 回复无气泡；用户提问右对齐，最大宽度 84%，气泡圆角 14px。轮次之间 30px，同轮常规间距 12px，连续段落 6px。
- 回复使用 CommonMark／GFM 解析（`marked`），由 `AskMarkdown.vue` 创建 Vue 节点：支持六级标题、嵌套有序／无序列表、引用、分隔线、粗体／斜体／删除线、行内及围栏／缩进代码、链接、表格、任务列表、转义与字符实体。标题中的数字保留为标题正文；单换行可见。正文仍为 13px，h1／h2／h3 分别为 17／15／14px，h4–h6 为 13px；表格与代码块在自身容器横向滚动。
- 加粗补充兼容：中文紧邻的 `**“引号内容”**`、英文双引号及「」／『』仍可加粗，允许标记内侧带空格或 Tab。先用标准规则，仅在不匹配时识别成对的带引号加粗；复用解析器对代码、转义和链接目标的遮罩，不预先改写全文，复制仍保留原文。
- 中日韩相邻边界（2026-10-24）：CommonMark 要求紧贴标点的 `**`／`*` 外侧是空格或标点，中文无空格，`**晶石（crystals）**点缀`、`使用**（注意）**为准` 因此不加粗，一行两处时还会错配。ASK 词法器按 markdown-cjk-friendly 规则把外侧的汉字／假名／谚文视同边界；只替换 ASK 每条消息新建词法器的两条分界规则，不改 Marked 全局。不含中日韩字符的文本解析与 CommonMark 一致。
- `#h`／`#f`／`#c`／`#a` 在正文、强调和独立行内代码中均保留图片引用；整段代码不创建引用按钮，链接标签内也不嵌套按钮。无属性的行内 `<br>`／`<br/>`／`<br />`（大小写均可）渲染为换行，支持表格单元格；其他原始 HTML 按文字显示，不加载资源或执行属性。代码与转义文本保留原样。Markdown 图片显示为可点击链接；链接仅接受 HTTP／HTTPS／mailto，点击后新页打开。复制回答保留原始 Markdown，收起摘要使用同一解析树提取文字；文本附件预览保持原文。
- 提问下方右侧显示复制／编辑，回答下方左侧显示复制／分支。按钮 28px；桌面悬停或键盘聚焦显示，最后一轮回答操作常显。触屏可点按显露操作。附件单独提问没有空白提问气泡或复制提问按钮。
- 每组工具默认以摘要行折叠，出错或含部分失败原因的组默认展开；运行中摘要保持可见。展开后动作、对象与统计在同一行，动作不换行、对象可省略；失败原因独占下方并逐项换行，部分失败的图标用警示色、全失败用错误色。摘要行高 26px、字号 13px，展开明细行高至少 22px、字号 12px。
- `#h`／`#f`／`#c`／`#e` 引用按逐轮冻结绑定预览并定位工作区图片；`#a` 预览对应 ASK 附件。旧页面或缺失原记录时不给同名新图补位。工具返回的候选消歧按钮由 `ToolOutcome.picks` 驱动，最多 4 项；点击只绑定锚点并在空输入时预填，不自动发送。
- 输入 `#` 在输入框旁显示紧凑图片候选，方向键切换、Enter／Tab 插入、Esc 关闭；Shift+Enter 保留换行，中文组字不抢键。插入不发送，补全关闭后沿用原发送与草稿确认键。
- 手动修改外部提示词仍显示 `.note`；应用／回退以检查点行表达，不重复插入操作说明。
- 新对话和普通打开／Ctrl/⌘J 唤起不绑定当前图，也不显示默认图片胶囊；已有显式引用可在同一打开窗口内继续使用或手动取消。活动画板完整基础／角色词文直接发送；无锚点历史原文和其他画板按需读取。工具完成不能以空正文成功结束；缺少正文时仅补一次简短说明，失败或停止仍显示对应状态。
- 原位编辑铺满消息区可用宽度，保留原轮附件；Enter 重答，Shift+Enter 换行，IME 组合不提交，Esc 取消。成功重答前先整体预检并回退后续已应用草稿，再截断；失败保留可见轮次，底部未发文字与托盘保持。分支复制至所选成功轮次，清除新分支中的检查点／未决草稿／托盘，新分支用量从零开始。
- 空对话显示品牌组合与三个起手问题；点击只预填并聚焦，不自动发送。

## 5. 动画节奏与滚动跟随（Pacing & Motion）

统一三档时长，落地使用站内 `--t1 (120ms)`、`--t2 (220ms)`、`--t3 (380ms)` 与缓动 `--e`／`--e-out`。原型中的 `--d1–--d3` 与 `--k` 慢放倍率只用于演示，不实现：

* **入场与切换**：
  * 新消息/新工具入场（`.enter`）：`380ms`，**透明度先行**（`--soft: cubic-bezier(.25,.1,.25,1)`），**`4px` 向上位移跟随**（`--out: cubic-bezier(.2,.7,.2,1)`）。
  * 工具完成态切换（`.swap`）：整行从“正在查看…”交叉淡化为“已查看…”，时长 `220ms`。
  * 初始思考占位退场（`.leave`）：`120ms` 淡出后再移除 DOM。
* **运行态微光（`.run .txt`）**：采用低对比度慢速扫光（暗底 `--fg-3`，柔和光带峰值 `--fg`，两侧经 22%／72% 过渡），背景宽 `200%`，周期 `2.4s linear` 匀速，温和不刺眼。每轮恰好移动一个背景宽度（`130%` → `-70%`），循环点光带正从左侧进入，约 0.9s 在文字外的暗底中匀速走完，没有减速停顿，循环无接缝。窗口工具汇总行与收起的岛都按当前运行工具重建，换工具时从左侧重新起扫，不因文字长短变化半路跳位（2026-10-24 用户批准，替代原 `250%` 缓动宽光带）。
* **诚实节拍器（最小驻留补足，只补足不累加）**：
  * `toolMin: 600ms`：本地瞬时完成的工具（如元数据对比、草稿生成）至少在运行态停留 `600ms`，防止界面闪烁。
  * `betweenTools: 160ms`：连续工具之间的出现间隔。
  * `afterText: 320ms`：文字段落输出后的阅读停顿。
  * `beforeDraft: 300ms`：正文与工具流完全静止 `300ms` 后，底部才弹出草稿卡。
* **阻尼滚动跟随**：流式输出期间通过 `requestAnimationFrame` 以阻尼系数缓动滑向底部；**一旦检测到用户向上滚动滚轮（`e.deltaY < 0`），立即解除自动跟随**，直至用户滚回底部（距离 `< 4px`）才恢复。
* **减少动态（`prefers-reduced-motion: reduce`）**：所有位移与微光扫光全部关闭，入场简化为 `120ms` 纯透明度渐变，运行态文字末尾静态追加 `…`。

## 6. 草稿卡与检查点

草稿卡仍是唯一写入出口，使用 B v5 的字段分组 diff，替代早期时间轴、三列参数切片和 `.keep` 下划线展示。`draft/view.ts` 只计算展示；工具 Schema、校验和写入端口不由 UI 改动。

### 6.1 头部与展开

圆角 14px，头部最低 44px。左侧为展开箭头、标题及启用步骤的 `+N −M` 统计，右侧为无底色「忽略」及紫色应用按钮；未指定新板的普通 IMAGE 草稿使用「勾选图标＋应用＋箭头」分体按钮。严格沿用用户截图：箭头展开时浅紫高亮，菜单宽 184px、圆角 9px、底色 #26262d，第一组为带勾的「应用到来源画板」和带复制图标的「应用到新画板」，点击直接执行；第二组可附加画板配方、创作备忘录及活动任务交接资料，追加文件草稿后仍须统一确认。不追加画板名、默认标记或说明。菜单使用原生 popover，跟随按钮定位并限制在视口内，Esc／Tab 先关闭菜单并返回按钮；关闭菜单不会忽略或应用草稿。CHAT 保留单个应用按钮。

模型通过 `new_board_name` 提议具名新板时，标题下增加不可点的“新画板 · 名称”，只显示“新建并应用”单按钮，隐藏箭头和整个应用方式菜单；跨工作区显示“切回绘图并新建”，完整目标仍可见。长名称省略显示并保留 title，长操作文案允许换行。该草稿不能改选来源板。未指定新板的普通草稿才提供分体按钮，沿用“应用”与“切回〈画板名〉并应用”。不再额外挂一行新板链接。compact 保留命名目标和明确的主按钮文案，普通草稿的箭头菜单只在完整窗口提供；Tab 快捷键遵循同一目标规则。

CHAT 交接草稿（`chat_handoff`）标题下同样显示不可点的“新对话 · 模型名”，正文不再单列新开会话一行。只有单按钮，图标与 CHAT 的「新对话」相同：在 CHAT 中为“新开对话并应用”，其他工作区为“切到对话并新开”；无方式菜单，提示“新开对话写入参考图、画幅和输入框，不会发送 · Tab”。compact 同样只有忽略／应用。

默认折叠，展开状态跨草稿保留；收起形态的「核对草稿」会展开完整窗口和正文。应用按钮提示写入后不会生成／发送。全部无效或撤回时禁用应用及方式菜单。

正文内部滚动，最高 `min(44dvh, 340px)`；底部仍有更多内容时渐隐。≤360px 的普通草稿头部允许操作另起一行；含文件时省略长标题、隐藏词文 ± 总数并保持头部单行，保证应用操作可见。

### 6.2 字段分组与预览

- 按 Prompt、Negative、参数、CHAT 分支等分组，图标／正负号在左侧 12px 栏，正文从 34px 起对齐。
- 文本以逗号词组 diff 展示，删除／新增行相接成一个色块；改写提供「改动／全文」，全文用删除线与新增底色显示差异。模型只给原始文本，不生成 HTML 或保留词标记。
- 参数按行显示名称、旧值、箭头和新值；分支准备以动作说明展示，锁定步骤不可撤回。
- 交接分组「新对话」：每张参考图一行，沿用参数行网格，值为 26px 缩略图、可悬停预览与定位的图片 ID 和尺寸；图片已移除时缩略图为虚线空框、ID 划线并列出原因。尺寸项用画幅图标，原值取来源会话。输入框按原文逐字显示（保留中文标点与换行），不提供「改动／全文」。
- 多步草稿的可选步骤提供撤回／恢复，关闭后淡化；冲突步骤列出原因且不会写入，提供「基于当前内容重新提议」。统计只计启用且有效的步骤。

### 6.3 撤销栈与检查点

执行规则见[检查点、编辑与分支](runtime.md#检查点编辑与分支)：

- 应用后卡片收起，在所属轮次的回复正文下方、复制／分支图标上方显示「✓ 已写入 标题 +N −M」；正文与横幅间距 8px、横幅与图标行间距 4px。保留读屏播报和 3 秒已写入胶囊。
- 任务、文件及外部来源的完成记录复用 `AskToolGroup.vue` 的一行工具完成态，无独立边框或重复草稿标题／已应用脚标；外部记录同行显示小号「来自外部」，具体来源放在 title 与展开详情。多项更改合为计数摘要，撤销／恢复按钮仍在同行。普通内部词文草稿保持原检查点。
- 页面共享最近 50 条完整撤销记录，超过时释放最早的完整快照，保留轻量检查点。仅当前对话拥有的全局栈顶显示「回退」。
- 回退后该行变为「已回退」，统计划线，上一条成为栈顶；仅最近一次回退显示「恢复」，新应用成功清空恢复点。回退不重新弹出旧草稿卡。
- 字段、CHAT 会话或分支不符时显示具体失败原因；保存失败不出栈。⌘Z／Ctrl+Z 和窗口内检查点的回退操作同一栈顶，保留原生输入撤销护栏；收起的小岛不提供撤销。
- 删除 ASK 对话只移除它的撤销记录，不改动已写入内容；刷新清空未收藏 ASK 对话和撤销记录，不撤回表单；收藏会话恢复消息、附件和待确认草稿，已应用检查点只供查看。

## 7. 输入框与附件

- 圆角 14px、透明层底色与 `--line-2` 描边，内边距 `14px 6px 10px 12px`。输入区默认最低 26px、多行自动增高至 30dvh，与底部工具栏间隔 14px；占位符保持「问这张图，或用 #h 引用历史…」。
- 工具栏左侧 ＋、目录标签、锚点胶囊，右侧模型和发送。模型按钮向上展开已选模型（站内菜单样式，项前为厂商图标，多连接时按连接名分组，末项「管理模型」），运行中不可切换；未选用任何模型时直接打开设置。添加／发送桌面 28px，≤860px 为 36px；运行时发送原位换停止。只有偏好暂停／仅元数据等异常状态显示提示，可点击恢复。
- 模型与发送之间增加 14px 环形上下文指示，24px 宽热区与模型／发送垂直居中。中心留空、暗色底环、圆头亮色进度从顶部顺时针增长；进度按下一次输入的本地估算除以用户设置的压缩阈值（默认 64,000 tokens），上限为整环；无可用估算时仅显示底环。悬停或键盘聚焦时即时显示 176px 紧凑浮层，内边距 8px 10px 7px：「上下文 · 估算」与 13px 等宽百分比同排，下接 2px 进度条，底行为 11px 等宽用量／阈值及「压缩阈值」弱标签；浮层距热区 8px、右缘外扩 4px，Esc 可关闭，减少动效时取消淡入。读屏保留完整 token 单位，不依赖浏览器原生 title，也不冒充模型最大上下文。估算包含静态提示词、工具、压缩后的历史、当前状态和待发输入／附件，并遵循历史图片脱水设置；不改变以有效 usage 为依据的自动压缩触发规则。浮层设计咨询原稿见忽略提交的 `.local/ask/compaction-design/context-tooltip-opus-v1.txt`（Opus 5.5 v1），尺寸按用户反馈收紧。
- ＋ 文件选择、窗口内粘贴、拖入共用同一附件管道；超过 2000 字的纯文本粘贴转为文本附件。ASK 内事件不落入 CHAT 或绘图导入；拖出、收起或切换后投放层清除。
- 托盘在文字上方横向滚动，间隔 8px；图片 52×52，圆角 12px，移除按钮外置。已发送图片 64×64；文本附件点击打开窗口内预览，长文在预览内部滚动，正文不溢出浮层。
- 图片准备完成前禁用发送；仅附件也可发送。图片各最多 20MiB／4000 万像素，每轮最多 4 张；文本默认单个 5 万字符、每轮合计 10 万字符，在「设置 → ASK → 上下文与附件」的两个数字输入中调整，与压缩阈值共用「恢复默认」，每轮仍最多 4 个。新上限用于后续添加，不截断现有附件或历史正文。页面原文件合计最多 200MiB，图片实际外发每张最多 1MiB。具体压缩、格式和生命周期见 [附件与视觉契约](runtime.md#附件与视觉)。
- 「发送图片给模型」开启时，本轮用户图片作为提问的一部分发送；关闭时托盘图片灰显，只发元数据，并移除历史像素。文本附件仍以数据块发送。未收藏对话与附件仅留本页；收藏内容保存在本机 koma-ask，恢复时重新创建预览 Object URL。URL 最后一个引用释放时回收。
- 仅元数据轮次在提问下方显示小号「仅元数据」，与全局图片开关分开表达。失败保留普通「重试」；拒绝／空白回复另提供「仅发元数据重试」。仅元数据轮次失败时，普通重试继续保持隐私限制，全局图片开启时另外提供「发送图片并重试」，由显式点击恢复，不静默增加图片发送。
- Esc 先关闭后打开的菜单／预览或取消编辑，再按未决草稿、运行、窗口顺序处理；Tab 应用保留焦点与输入法护栏。

目录标签与输入工具栏处于同一行，高 22px、左右内边距 6px、图文间距 4px，文字与图标均为 11px：未挂载显示「挂载目录」，已挂载仅显示目录名，长名省略。异常状态点击恢复，已连接时菜单只有切换／卸载目录；菜单贴着按钮上方。目录 API 不可用时提供现有 ASK 设置的入口。

不提供协同资料勾选弹窗或独立的保存预览弹窗。「＋」直接唤起原生文件选择器；挂载目录资料由状态清单与 `read_ref` 按需读取。已完成回答的「保存为备忘录」创建真实文件草稿。手动导入草稿、导出状态与导出协议全部位于现有「设置 → ASK → 外部协同」分组，不是另一套设置弹窗。

文件在 DraftCard 的「文件」分组中一行展示名称与去向，点击箭头展开路径、来源及可读摘要，不显示原始代码或格式下拉。配方固定 JSON、备忘录固定 Markdown、任务交接资料固定 JSON；内容与目录在提议时冻结，目录失联或改变时保留整稿并禁用应用，不静默换为下载。应用／Tab 与其他步骤统一确认，完成后显示同一工具完成行。

## 8. 自由创作设置

「设置 → ASK → 创作」提供默认关闭的「自由创作」开关，下方无附加说明。开启后可配置词表混淆和文本替换，两类列表均默认空。文本替换用「原文 A → 替换为 B」输入与规则行，不另放行为解释小字；支持添加、编辑、取消与删除，编辑时聚焦原文输入。发送时替换，回复和草稿在展示／校验前还原。开关关闭时隐藏编辑区域并暂停转换，保留已存规则。行为和存储以[现行设置契约](README.md#设置自由创作与附件)为准。

## 9. 上下文压缩

现行压缩记忆行采用轻量分隔样式，几何如下；设计过程保存在归档。

- 完成态无卡片底色：图标、压缩轮数、细线、记忆大小、箭头。主文字 14px，tokens 12px，统一 20px 行高；图标 16px、箭头 14px，行高至少 32px。正式消息流上下 margin 为 20px，对应原型 14px 消息 gap 加 6px 组件 margin。全部沿用站内颜色和字体。
- 完成记录出现在压缩发生处，即原「正在压缩上下文」运行行的位置（压缩时最后一个成功轮次之后），不跳到归档分界处；手动压缩与发送前自动压缩都保持跟随底部，接续的提问和回复排在它之后。原聊天内容仍保留。
- 展开先显示记忆，默认正文最高 88px，全文最高 240px 并内部滚动。纯文字页签切换「记忆／轮次／附件」，无附件时不显示空页签。窄屏 token 信息移至页签栏，必要时换行，标题不挤压。
- 轮次一行显示编号、标题及草稿状态；画板与回复摘要在 title 提示中保留。附件一行显示文件名与字数／尺寸，编号在 title 中保留。原文与文本附件在同一组件内预览，返回／Esc 还原焦点；轮次保留「引用到输入框」。普通附件浮层不变。
- 页签支持方向键、Home／End；Esc 先退出内部预览，再收起压缩行。Tab 保留正常导航，不触发草稿应用快捷键。组件卸载时清理 Esc 层和所属预览。
- 运行态同款分隔行，文字和细线轻微扫光，减少动效时关闭动画。失败行保留短标题、显式重试与可展开原因；不显示虚构百分比或节省量。

数据与触发规则见[压缩规范 §14](compaction.md#14-界面与设置)，呈现层不改变归档、缓存、用量、停止或持久化行为。

## 10. 会话待办与轻量总览

绘图 API Key 旁任务图标打开 280px 轻量任务总览，各清单仅图标、标题、进度与进入箭头，不扩成大任务板。总览更多菜单承载新建、在新会话中打开、导入，以及按条件出现的目录映射／冲突操作。

会话内任务位于输入框上方，收起一行显示待办、进度、当前事项；展开各行只有状态、标题和一个成果图标。没有单项详情展开、添加任务、常驻关联行或 Bonus 标签。点击标题准备提问，状态勾选走原提交路径；需交图时先打开必要的成果选择界面，标注来源显式选择。长清单内部滚动并折叠已完成，输入框始终可见。展开采用 0fr → 1fr 高度过渡，收起反向裁切，减少动态偏好时直接切换。

共享 `slate_edit` 的「任务」「配方」与 Prompt 同级，图标使用同一槽位，正文统一缩进。任务只列变更行，默认最多三行，详情按需展开，仅含改变字段；界面 `mutation` 为「更改记录」。配方默认一行，长配方再按需展开并内部限高。与 Prompt／参数／文件组合时整体确认，原 Diff、Tab 与撤销保持。任务和文件完成后使用工具完成态，外部记录同行保留「来自外部」。目录冲突由用户审阅或明确保留本机版本，界面不印协议说明段落。

## EDIT 的草稿呈现

EDIT 沿用同一 DraftCard 与紧凑参数 Diff，不增加大面板。目标行显示「编辑画板 · 名称 · 底图完整编号」，模式、强度、聚焦像素框与 Director 预设各一行；编辑配置整体确认。应用只填好表单／面板，确认后的检查点提供「去编辑」图标；交接新建或复用画板不自动导航。

Photopea 打开时收起 ASK，流式输出保留；未处理回传、生成准备、蒙版笔画或目标冲突时保留卡片并显示短原因，不抢走 Photopea 的 Tab／撤销按键。语义与写入边界见 [ASK × EDIT](edit.md)。
