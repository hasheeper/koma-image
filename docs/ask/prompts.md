## 按需手册索引

通过 `get_model_manual({ id })` 读取本地正文，不联网、不写入；正文不常驻 System。`modelManualIds` 从 `manuals` 的键自动生成，同时供类型与工具 Schema 使用；新增手册还需同步 L2 的查阅入口、工具描述与本索引。手册返回版本沿用 `models.version`。

| ID | 何时读取 | 专项范围 |
| --- | --- | --- |
| `nai5-prompting` | 写 NAI 词、调整多人互动或排查表达冲突 | 字段混排、权重、文字、预设、施受方向与词义陷阱 |
| `nai5-comics` | 将分镜写成单页多格提示词 | 逐框可见内容、状态连续性、文字载体、色彩转换与预设冲突 |
| `oc-costume-design` | OC 换装、服装结构设计或衣物片段转换 | 轮廓层级、材质、穿着关系与术语核验，不内置完整服装词库 |
| `nai5-reverse` | 照图反推提示词，或仅提取构图、光影、服装等局部 | 区分原文、用户事实与视觉推测；盲推、可见依据与身份边界 |

方法对照 [Miint-Sunny/nai5-prompting v1.2.6](https://github.com/Miint-Sunny/nai5-prompting/tree/7b130f8) 的写法规范、普通插画、漫画、服装与反推资料，按 Koma 实际能力适配，不是上游全部技能的镜像。官网引号自动转 `Text:`、默认开启的预设及逐字段代码块交付不能直接当作 Koma 行为；Koma 仍读取生效状态、使用显式文字段并经草稿确认写入。原文标明的个人工作流、V4.5 经验与 V5 待验证技巧保留证据边界。

L0 统一维护创作范围与原串保护，L1 维护工作台／工具事实，L2 保留日常摘要与手册路由；具体案例只在手册维护。漫画与反推按需引用通用写法，不再复制整套语法；文档只留用途与接口，不复制创作正文。

## 状态、工具与创作正文

当前工作区活动画板原文随 `<workspace_state>` 发送；EDIT 无有效 IMAGE 历史／收藏锚点时，image 仅为目录摘要，跨区原文通过 `get_state({board_id})` 读取，指定其他编辑板使用 `edit_board_id`。无锚点历史按需读取。角色靶点使用完整稳定 ID，add／set_position 不隐式开启手动定位。新板草稿可带 `new_board_name`，提议时不建板，确认才写入；不会为了草稿名称另调命名模型。

连续追问沿用本会话仍有效的图片锚点，具体绑定和取消规则见[检索与状态](retrieval.md#1-状态与展示边界)。L1 明确：同一记录所需字段已完整提供时直接使用，缺失时才补读 `get_meta`；历史图片参数不替代当前活动表单。`retained_verbatim` 与归档召回规则由 L0 维护。

L0 保留当前画面、显式 ID 优先及不传空 ID 的原则；具体字段仅由 L1 维护：EDIT 使用 `edit.viewing_version.id`，IMAGE 使用 `image.current.id` 或 `image.history.latest_id`。EDIT 的表单与查看图边界见[编辑状态](edit.md#编辑状态)。

L1「图片批注」按收到的数据说明原图／定位图分工、区域与点、坐标和编号：`<image_annotations>` 的 `image` 指向原图，可选 `guide` 指向编号定位图；`image_edit.annotations` 只含底图 ID、尺寸与批注数据，不代表已收到图片。`view_image(annotation)` 按编号裁切，完整原图查看资格由 L0 和工具说明统一维护。界面与组装契约见[批注专题](../workspaces/annotations.md#ask原图指示图与坐标)。最终答复须说明结论或修改，篇幅遵循 L0 原则，不另在工具描述强制简短。

`params_patch` 支持内置 ASK 提议能力范围内的表单参数。L1 说明企划分组索引与按需读取、档案 ID 与角色槽区别、一套服装的 TAG 组合、可信企划图片交接，以及任务摘要／归属与 `save_ref` 用途。目录续页、12 个工具文本及具体字段留在工具说明与 Schema，不加入 UI 点击步骤或独立系统层。

所有静态核心和 tools 顺序保持稳定，动态状态在队尾。专项手册和召回结果通过工具追加，不回改 System；详见[协议与运行契约](runtime.md)。前端不依据文体、画师名字、词义或自然语言推断权限，只校验草稿结构并交给用户确认。

## 自由创作

开关保存于 `koma.ask.adult.v1`，默认关闭，不进备份。关闭不加载附加语境、不转换词表或替换；开启后在中立核心追加一次附加块，规则默认空。个人偏好与编码方式的静态说明保持在实际最后一个 System 块。

出站在 provider 网络边界确定性转换，入站文本与草稿先还原再展示／校验；本地表单始终原文。只检查格式、长度、重复与逆向冲突，不建立语义排除表。规则切换在下一轮生效，同轮请求冻结 System 和 codec；关闭不改写历史。

不发送 `<codebook>` 或明文映射表。词表与 A → B 原词／替换关系只留在客户端，代号编号保持稳定；启用非空代号词表时只附带一句不含原词的固定说明，让模型根据上下文理解并保留代号。Unicode 模式只附带通用转义说明；仅启用 A → B 时不附加映射说明。正文、历史、工具参数值与工具结果统一转换，入站流式回复和草稿再还原。替换按最长匹配单次完成，目标中含原文或其他规则的原文也不递归处理；协议字段、模型与工具 ID、Schema、图片数据和 Gemini 原生签名历史保持原样，不对最终请求整包扫描原词并拦截。转换效果与实际模型行为需单独验证。

## AI 命名

ASK 标题和画板胶囊保留星光按钮，CHAT 会话菜单新增「AI 命名」；再次操作当前命名目标可停止。设置 → ASK → AI 命名统一配置命名模型，默认沿用 ASK，也可独立指定连接与完整 ID；显式不可用时报配置问题，不静默回退。`koma.ask.v1` 的可选 `naming` 与 `autoNaming` 布尔开关 均进入普通备份。

ASK 与 CHAT 共用一个「自动命名」开关、默认关闭，每个新会话只有一次自动命名机会：ASK 在首次成功回复后，CHAT 在首条需求获准提交后、等待图片生成前触发。输入文字、预填草稿和打开窗口不触发；后续回复、生成重试、已有会话恢复与分支复制不重新命名。手动保存过名称的会话跳过自动命名。未开启时经过首次触发点的会话，不因之后开启开关而补命名。

命名要求单行中文短名，优先 4–12 字。ASK 只取成功轮次的提问／回复正文；CHAT 取用户需求与所选成功版本的文本回复，自动首发只需当前需求。对话均限首轮及最近四轮，约 12,000 字符上限；画板只取基础正向词与启用角色正向词。不发送其他会话、其他板、Negative、图片、附件原件、工具轨迹或完整状态，不加载主提示词与工具。

每次触发只发一次文本请求，60 秒未完成停止并保留原名，不自动重试。自动任务与手动命名共用串行队列，独立于 ASK 回复和生成锁；排队时冻结目标及文本，关闭自动命名会清除待发任务并中止在途任务。写回前检查目标仍存在且未被手动改名，迟到结果不会覆盖用户名称。画板／CHAT 保存失败还原名称；CHAT 名称随会话持久化，ASK 名称随收藏持久化。命名沿用自由创作规则，调试轨迹为「AI 命名 · ASK／CHAT／画板」，用量计入本页。

## 压缩与验证

压缩使用当前 ASK 模型，指令只覆盖归档边界之前的成功历史，不读取待发提问或托盘附件，不新写提示词或调用工具。全文和输出校验由 `prompts/compaction.ts`、`compact/validate.ts` 维护；触发与事务见[压缩专题](compaction.md)。

模拟只能证明请求、还原、名称写回和备忘录结构的程序契约。真实命名、提示词质量、诊断和压缩备忘录质量仍待验证。

HOME 状态由 `home/ask-context.ts` 生成创作线与收藏摘要；L1 说明 `home.lines[].face` 非空时可按 ID 读取，以及在 HOME 可提议的草稿。EDIT 明确底图、当前查看版本与当前配置的区别，合成预览与正式结果通过引用和状态区分。交接后的页面导航由应用负责，不进入 L1。

## 图片身份事实

L1 说明五类图片编号及具体记录的配方读取；实体共享、作用域和稳定绑定的实现由[图片身份](../engineering/image-identity.md)维护，不再展开为工作区提示词。视觉重看与裁切资格由 L0 和工具说明负责。

工具说明与 Schema 同时列出 `#e`：可参与图片检索、CHAT 参考图交接及 Slate 绑图，仍通过既有草稿确认链路处理。

## NAI／EDIT 的事实维护

L1 说明动态 capabilities／form／effective／input_budget、候选校验、EDIT 目标与模式、聚焦区域、Director 参数及 Photopea 的精修用途。费用、图像处理、导航和应用时校验由对应状态、工具及程序负责。

L2 明确基础与启用角色共用正负方向预算、Medium 的固定负向、显式 Text: 与四份手册入口；多人字段分工与手册一致，写作经验不当作引擎硬限制。Variety+ 等来源限制与费用估算由动态状态提供。动态数值留在状态／工具结果，静态说明只解释稳定规则。表情网格属于创作建议，不能当作接口保证。详细契约见 [NAI 基础感知](nai-awareness.md)与 [ASK × EDIT](edit.md)。

通用 EDIT 状态与草稿事实由 L1 维护：来源字段及有效默认值、image_options 动态写入、批注坐标、三图比较与人工蒙版应用边界。通用模型写作方法由 L2 共用，具体参数不硬编码到提示词。
