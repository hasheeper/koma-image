## 多角色与画板

- 初始 `<workspace_state>` 直接提供活动画板的基础 Prompt/Negative、角色稳定 ID、启停、词文与位置，无需先调 get_state。其他画板只给目录；`get_state({ board_id })` 默认读取本轮冻结原文，读取不改变草稿目标。
- 单幅 NAI 基础描述承载画风、总人数、镜头、场景、动作与表情；角色以 girl/boy/other 开头，仅放外貌、服饰、具名角色及可选施受前缀。整页多格漫画例外沿用专项手册。
- 草稿以本轮源板为基底，使用稳定角色靶点、character_edit 与整组恢复。模型可通过 new_board_name 提议具名新板，或由用户在菜单选择新板；确认后的角色分组、检查点及撤销覆盖完整结构。
- 定位动作的工具说明明确：add/set_position 指定坐标不自动打开手动定位；需要让坐标生效时，同草稿 set_placement 为 manual。set_position 与界面重新选点一样替换为单中心。

## AI 命名

ASK 标题右侧与画板胶囊内的星光图标按需生成名称；生成中显示停止图标，再次点击取消。名称可以继续手动修改，ASK 标题菜单新增「重命名」。原有对话列表、画板切换与复制入口保留。

「设置 → ASK → 推理模型」中的「命名模型」行默认沿用当前 ASK 连接与模型，也可独立选择推理连接及一个模型，支持手填完整 ID；独立选择不加入或改变 ASK 主模型列表。配置沿用 `koma.ask.v1` 的可选 `naming` 字段并纳入新版备份。显式选择不可用时提示配置问题，不静默切回主模型。

命名提示词版本独立为 `naming-1`，要求优先 4–12 字的单行中文名称，不加解释。对话只取已完成轮次的用户提问和回复正文（首轮与最近四轮，最多约 12,000 字符）；画板只取该板正向描述和启用角色的正向描述（最多约 12,000 字符）。不发送其他会话、其他画板、Negative、历史图片、附件原件、工具轨迹或完整工作台摘要；不加载 L0–L2、个人偏好或工具 Schema。沿用自由创作开关对用户词表和替换规则的门控与双向编解码。

一次点击只发一次文本推理请求，不走工具循环、不占生图锁、不报价或生成图片。60 秒未完成则停止并保留原名，不自动重试。结果校验为非空单行名称后写回发起时的目标；目标已删除或被手动改名则丢弃迟到结果。切换对话／画板不会改写新目标。画板名称通过原保存路径与数据租约持久化，保存失败还原原名；ASK 名称随会话管理，收藏后持久化，未收藏仍只留本页。每次实际请求进入现有调用上下文记录，标记「AI 命名 · ASK／画板」，可查看、复制、导出与核对缓存计数。

实现入口为 `src/ask/naming.ts` 与 `service.ts`；UI 共用 `src/shared/AiNameButton.vue`。模拟验证与截图记录在 `.local/ask/naming/`，不代表真实供应商命名质量已验证。

本轮验收：`npm run check` 通过，含 195 项单元检查、样式、严格类型与构建；新增命名 6 项浏览器验收覆盖两种协议、独立设置、完整模型 ID、实际请求与调试入口、取消／超时／保存失败、目标切换／删除／手动改名，以及 320／390／768／1440px。ASK 全套首轮为 75/77，两项失败仅因主模型列表标题多了一个分隔点；恢复原标题后，与命名一起定向复验 8/8 通过。画板相关浏览器回归 3/3 通过。仅使用合成文本和模拟接口，没有执行真实收费请求或发布。

## 自由创作

- 关闭时不注入 `constitution.adult` 的「创作语境与题材包容」整段；开启后在中立核心后追加一次。
- 开关保存在 `koma.ask.adult.v1`，默认关闭且不进备份；切换从下一轮生效，同轮各次调用使用锁定系统块。
- 关闭后恢复中立系统字节，不重写历史用户消息与工具记录。词条混淆与 A → B 替换均由此开关控制，词条和规则默认空，只做结构及映射冲突校验；代码排除表已移除。

## 工具与缓存

状态摘要已删除 `image.prompt_sections`；活动画板原文及根层 base_hash 保留，hash 覆盖源板与完整生成表单。历史检索覆盖角色 Prompt/Negative，变化比较按来源画板对齐；词典使用 queries 数组批量核验，复用共享在线服务，不要求先打开词典。具体接口由 tools.ts 的 Schema 及 [检索规范](ask-retrieval-state.md)约束。

`get_model_manual({ id })` 只读取三份内置手册，不接收任意路径或 URL，不联网。手册正文只作为 `<data>` 工具结果追加，不预装进静态 System；计入原六次工具调用预算。

切换工作区/生图模型不替换静态核心。版本或 Schema 变化可能影响缓存；实际命中仍以上游 usage 为准。
