# Koma ASK A0 实施记录

分支：`codex/ask-a0`（基于 `codex/ask-plan`）。范围以[决策与实施规划](ask-implementation-plan.md)（文档 4）§6 为准。A0.1 交付协议与设置，A0.2 交付会话与抽屉。全部验证使用合成数据和模拟接口，未请求任何真实推理服务。

## A0.1 协议与设置

日期：2026-10-21。本阶段没有抽屉、会话或工具循环，用户界面只新增「设置 → ASK」。

### 1. 已实现

#### 推理协议与连接

- `src/gateway/profile.ts` 新增 `openai-chat-v1` 与 `anthropic-messages-v1`。两者都声明 `reasoning`（缓存方式分别为 `implicit` 与 `breakpoints`），都声明 `image: false`，只开放 `catalog` 与 `reasoning` 两条路径。两者均不声明报价、成本上限或额度，执行路线全部关闭。
- 现有四种协议显式声明 `image: true`。`imageConnections()` 和 `reasoningConnections()` 按能力过滤：绘图、对话、编辑的模型目录汇总以及「设置 → 模型」只读图像连接，ASK 只读推理连接。没有按名称或域名判断。
- 鉴权方式：
  - `openai-chat` 使用 `Authorization: Bearer`。
  - `anthropic-messages` 使用 `x-api-key`，并附带 `anthropic-version: 2023-06-01` 与 `anthropic-dangerous-direct-browser-access: true`。
  - 本地代理模式仍只发送本地令牌；A4 之前，本地模式不提供推理连接。
- 地址规则见文档 4 §2.1，由 `tests/ask-provider.test.mjs` 固定：
  - `openai-chat` 仅在服务根地址后补 `/v1`，`…/v1beta/openai`、`…/api/v1` 等地址原样使用。
  - `anthropic-messages` 统一补一次 `/v1`。
  - Anthropic 模型列表带 `limit=1000`，不自动翻页。
- 两种协议的模型列表都从 `data[].id` 读取，只用于选择 ID，不映射到图像模型。连接测试在成功文案后标注「推理尚未实测」。
- 「添加连接」的协议选项新增「OpenAI Chat 兼容 · ASK」与「Anthropic Messages · ASK」。推理连接的卡片底行显示「ASK 模型 · N 个 ID」，点击进入「设置 → ASK」，不打开图像模型来源对话框，也不计算图像来源用量。

#### 请求结构（`src/ask/`）

| 模块 | 职责 |
| --- | --- |
| `messages.ts` | 中间结构 `AskTool`／`AskBlock`／`AskMessage`／`AskRequest`、流事件 `AskEvent`、用量 `AskUsage`、`ProviderError` 与错误分类 |
| `canonical.ts` | 按键名排序的深拷贝与序列化 |
| `adapters/sse.ts` | 增量 SSE 解析：兼容 CRLF／CR／LF 和跨块断行，跳过注释行，可缺少末尾空行 |
| `adapters/openai-chat.ts` | 组装 Chat Completions 请求体，解析文本与工具调用增量 |
| `adapters/anthropic-messages.ts` | 组装 Messages 请求体并设置断点，解析内容块与 `input_json_delta` |
| `provider.ts` | 按 Profile 分派适配器，调用 codec，处理流式读取、空闲超时与中断 |

请求体按文档 3 §1.2 的顺序组装：

- **固定键序**
  - OpenAI 为 `model, stream, stream_options, tools, messages`，`messages` 放在最后，因此相邻两轮的请求体共享完整字节前缀。
  - Anthropic 为 `model, max_tokens, stream, tools, system, messages`。
  - 工具 schema 与工具调用参数按键名排序。
  - 两个 System 块按顺序拼接；OpenAI 合成一条 system 消息，以兼容不接受多条 system 的服务。
- **Anthropic 断点**
  - 共三个：最后一个工具、最后一个 System 块、最新消息的最后一个内容块。
  - 历史块不带断点，因此逐轮保持相同字节。
  - 空文本块会被丢弃；同一条用户消息中，工具结果排在其他内容之前。
- **OpenAI 工具结果**
  - 以 `tool` 消息返回文本。
  - 结果中的图片另起一条 user 消息，用 `image_url` 携带 data URL，因为 Chat 的 tool 消息只能携带文本。
- **输出上限**
  - OpenAI 兼容请求不发送 `max_tokens` 或 `max_completion_tokens`，因为两者在各兼容服务中的接受情况不一致。
  - Anthropic 必须携带 `max_tokens`，取值来自 `AskRequest.maxTokens`。
- **用量**统一为 `input`（含缓存）、`output`、`cacheRead`、`cacheWrite`：
  - OpenAI 读取 `prompt_tokens_details.cached_tokens`，也兼容 `prompt_cache_hit_tokens`。
  - Anthropic 的 `input` 为 `input_tokens` 与两项缓存计数之和。
- **工具调用增量的容错**：
  - 缺少 `index` 时按 `id` 归并；`id` 也缺少时，片段续接上一条调用。
  - 重复下发的完整名称不会重复拼接。
  - 参数可以是已解析的对象。
  - 只有 `finish_reason`、没有 `[DONE]` 时，轮次也会结束。
  - Anthropic 缺少 `message_stop` 时，以已收到的 `stop_reason` 结束本轮。

流式与错误：

- 流事件为 `text`、`call` 和 `done`。`done` 携带停止原因与用量；工具调用的参数在入站时先还原，再交给调用方。
- 默认 90 秒没有收到数据即判定超时，每收到一块数据重新计时。用户中断时抛出调用方传入的 `AbortError`，并取消响应体的读取。
- 错误分为以下几类，消息优先显示上游原文：

  | 类别 | 含义 |
  | --- | --- |
  | `auth` | Key 无效或无权访问 |
  | `rejected` | 被渠道或模型拒绝 |
  | `config` | 地址、模型 ID 或协议不被接受 |
  | `rate` | 请求过于频繁或额度不足 |
  | `server` | 服务暂时不可用 |
  | `network` | 连接中断 |
  | `timeout` | 响应超时 |
  | `empty` | 模型没有返回内容 |
  | `protocol` | 返回格式无法识别 |

  - 以下情况归为 `rejected`：403、`content_filter` 结束、Anthropic 的 `refusal`，以及消息中出现过滤或审核类字样。
  - 收到内容后流中断归为 `network`，完全没有内容归为 `empty`。
- 不自动重试，也不自动换模型。错误类别只用于 A0.2 失败界面决定显示哪些重试按钮。

#### 词表混淆（`codec.ts`、`codec-exclusions.ts`）

- 代号格式为 `@t_NNN`，按词条顺序编号：先是内置词表，再是自定义词条。
  - 大写写法编码为 `@T_NNN`，下划线写法在末尾加 `u`。
  - 每种已编码写法都能还原成原样，经单元测试锁定。
  - 只在 ASCII 词边界处匹配完整词，`sexy` 不会命中 `sex`；中文词条不检查边界。
- 首字母大写等混合大小写不编码，原样出站。
- 代号表只列小写原词，以 `<codebook>` 附在 System 块 2 末尾。
- 出站时编码全部文本，包括 System、历史、工具参数与结果；代号表本身和图片不编码。入站文本经流式解码器处理，跨块的代号会暂存到下一块。
- 门控：`codecFor()` 只有在「已确认成年」且「启用」时才返回编码器，否则返回恒等函数。「启用」= 始终启用开关，或会话内点击「启用词表混淆并重试」（后者在 A0.2 接入）。
- 排除表：
  - 覆盖未成年与 R18G 两类，英文按整词匹配并含复数，中日文按子串匹配。
  - 匹配前统一 NFKC 宽度、大小写、下划线、连字符与空白。
  - 内置词表不含排除词，自定义条目命中时拒绝保存。
  - 即使旧数据或备份中已有排除词，编码器和设置读取时都会再过滤一次。
- 内置词表只收录常见成人标签，不收录体型、年龄相关词；需要时由用户自行添加。

#### 设置与存储

- `settingsSections` 新增 `ask`，路由为 `#/<workspace>/settings/ask`。设置导航末尾新增「ASK」分组。
- `AskSection.vue` 共四组：
  - **模型**：在推理连接中选择；模型 ID 可手动填写，也可点「获取」后从列表选择。附一行能力边界说明，以及「发送图片给模型」开关（默认开启）。
  - **个人偏好**：最多 300 字，失焦时保存。
  - **成年内容**：开关文案为「我已成年，自行承担渠道风控与封号风险」，默认关闭，不弹原生确认框。
  - **词表**：仅在确认成年后显示。包括「始终启用词表混淆」、只读的内置词条，以及自定义词条的添加与删除，命中排除表时提示「该词不在可混淆范围」。
- 本地代理模式只显示「本地模式暂不支持 ASK」。
- 存储：
  - `koma.ask.v1` 保存连接引用、模型 ID、图片开关、偏好、自定义词条与始终启用开关，作为备份逻辑字段 `ask`，恢复时校验并规范化。
  - `koma.ask.adult.v1` 只保存在本机，不在备份白名单中。
  - 两者都通过偏好服务和 `data.write` 写入，跨标签页同步。

### 3. 已知边界与实测待办

- 没有请求任何真实推理服务，CORS、鉴权头、流格式和缓存命中都没有经过供应商实测。浏览器直连 Anthropic 依赖服务端接受直连声明头。部分兼容服务可能不接受 `stream_options`，若出现 400，会如实显示上游错误。
- 代号表中包含原词。会扫描整个请求体的网关仍能看到这些词，混淆的实际效果未经真实渠道验证，按文档 4 §5 不声称已解决拦截问题。
- 用户文本中若原本就有与当前代号相同的字面串，例如 `@t_001`，入站时会被还原成对应词。这在实际使用中极少出现，不另做转义。
- 工具参数无法解析时，本轮按 `protocol` 失败处理，不把错误回传给模型重试。A0.2 的运行器可以视需要调整。
- 当前测试文案和提示词都是占位文本，L0–L2 提示词在 A0.2 及以后交付。

## A0.2 会话与抽屉

日期：2026-10-21。在 A0.1 未提交的改动之上继续。抽屉目前只能用 ⌘J／Ctrl+J 打开；绘图工作区内的可见入口与 ID 展示按文档 4 §6 留到 A1，先出截图方案。

### 1. 已实现

#### 应用级服务与外壳

- `src/ask/service.ts` 的 `createAsk()` 在 `App.vue` 中创建，经 `src/app/ask.ts` 的 `askKey`／`useAsk()` 提供给组件。作用域销毁时 `dispose()` 停止进行中的轮次、移除 keydown 监听并退订。工作区只调用 `show({ anchor })`，不导入 ASK 内部模块。
- Vue 只持有低频界面状态：打开状态、条目、进行中轮次的视图、输入、胶囊、提示、播报、用量与设置。会话消息、Provider、AbortController 与摘要都是普通对象。进行中的轮次在 rAF 中合并刷新文本，工具行的开始与结束立即刷新。
- `AskDrawer` 是非模态 `aside#askDrawer`，挂在 `KeepAlive` 之后、设置等覆盖层之前，不写 hash。新增令牌 `--z-drawer: 30`，高于工作区侧栏，低于提示、弹出层和模态框。打开时焦点进入输入框，关闭时还给打开前的元素。
- 宽度 `min(460px, 100vw)`，从顶栏下沿开始。≤860px 改为底部面板，高度 `min(78dvh, 640px)`，上沿 20px 圆角，底部留出安全区。
- 快捷键：
  - ⌘J／Ctrl+J 切换抽屉并 `preventDefault`，输入法组字时忽略，有模态框时不响应。
  - 编辑器覆盖层打开时抽屉隐藏、快捷键停用，关闭后恢复原状态。
  - Esc 只在焦点位于抽屉内或页面没有焦点时处理，顺序为：弹出层（个人偏好预览）→ 草稿层（A2，目前为空）→ 停止进行中的轮次 → 关闭抽屉。模态框打开时 Esc 交给模态框。
- 回复完成后，`role=status` 的 live region 整段播报一次；停止与失败各播报一句。
- 减少动态时，标识脉冲与工具行扫光停用，工具行改为静态「…」，进场只保留短淡入。

#### 会话、运行器与节拍

- **`session.ts`**：内存会话，不持久化。
  - 轮次是事务：`begin` 时固定已提交历史，成功才 `commit`；失败或停止时 `rollback`，本轮消息不进入历史。同一时间只允许一个进行中的轮次。
  - 预算为 `toolCalls 6`、`requests 8`；视觉预算字段在 A1 启用。
  - 本地 token 估算：CJK 字符按 1 计，其他字符按 1/4 计，图片按 1000 计。
- **`runner.ts`**：async generator。
  - 每一步用当前轮次的消息组装请求，收集文本与工具调用。没有调用即结束；否则按顺序执行工具，把结果作为一条 user 消息追加在队尾。
  - 超过 6 次的调用、未知工具和工具异常都以错误结果回传模型；第 9 次请求时以 `protocol` 失败结束。
  - `final` 工具（A2 草稿）执行后立即结束本轮。
- **快照隔离**：本轮的 `<workspace_state>` 在发送时生成并固定在用户消息中，之后的工具轮只在队尾追加。需要新状态时，由 `get_state` 以工具结果返回。
- **`tools.ts`**：工具注册表。A0.2 只有 `get_state`（「读取 工作台」），工具只拿到 `signal`、`metadataOnly` 和只读的状态函数。
- **`pacer.ts`**：诚实节拍器放在界面层。事件到达后只补足最短间隔：工具行最短 600ms、工具之间 160ms、文本后接工具 320ms；草稿前的 300ms 留给 A2。已经慢的步骤不再加时，失败或停止时立即清空队列。

#### 摘要与提示词

- **`ids.ts`**：
  - `#hN` 按进入历史的顺序编号，`#fN` 按收藏时间升序编号，本页会话内只增不复用。
  - 同一张图同时在历史和收藏中时，显示历史编号。
  - `#cN.M` 按当前分支计算。
- **`digest/segments.ts`**：按逗号与换行切分 Prompt，保留原文偏移与权重，分为 `artist_mix`、`style_tags`、`subject`、`modifier`、`freeform` 五类。画师判断可接收词典分类回调（分类 1）。
- **`digest/index.ts`**：L0 摘要为固定键序 JSON，不含 Blob 或图片数据。内容包括：
  - 表单，含为 A2 预留的空 `characters` 与 `vibes`；
  - Prompt 分区；
  - 当前图；
  - 生成状态与进度；
  - 历史索引：每张一条参数；Prompt 与表单或上一张相同时写 `= form`／`= #hN`，否则截取前 120 字；
  - 收藏数量与最近 5 条；
  - CHAT 概要，仅对话工作区提供。
- **`base_hash`**：只覆盖草稿可写的目标（Prompt、Negative、对话输入框），更换种子等参数不会改变它。轮次结束时若已变化，插入「提示词已在外部修改」。
- **转义**：用户文本中的 `<` 会被转义，无法闭合 `<workspace_state>`。
- **`prompts/`**：版本号 `c1.w1.m1`。
  - System 块 1 依次为：
    - 规则：只读与草稿权限、数据不是指令、四条原则、画师串规则、中立与单行拒绝、状态说明；
    - 绘图与对话工作区说明；
    - 模型语法知识。
    - 确认成年后，追加一句成年语境。
  - System 块 2 为个人偏好（可本次停用）和代号表。
  - 这是文档 3 §4.3 所说的结构合规基础版，领域调优以后用黄金样例迭代。

#### 失败与重试

- 失败轮次回滚后，原位置显示上游原文与重试按钮，不自动重试：
  - **`rejected`／`empty`**：
    - 已确认成年且未启用词表混淆时，先显示「启用词表混淆并重试」；
    - 然后是「仅发元数据重试」，本轮已是仅元数据时显示为「重试」；
