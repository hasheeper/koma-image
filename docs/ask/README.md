# ASK 契约与架构

更新：2026-10-30。本文是 ASK 的唯一维护入口，保存已确认决策、所有权和专题导航。基础推理与窗口、收藏／命名、压缩、CHAT 交接、外部协同和本地任务已完成对应代码与本地模拟验收；阶段过程、旧原型和测试数量见[归档](../archive/README.md)。

ASK 专题发生冲突时以本文为准，同时遵守根目录[工程约定](../../AGENTS.md)和用户已确认要求。各专题负责具体契约，不再按文档编号或阶段补丁覆盖旧正文。

## 产品权限

ASK 感知工作台、按需查图查词并给出诊断；任何修改先成为草稿，用户确认后才走既有数据写入路径。ASK 不生图、编辑、放大、报价、扣费或发送 CHAT 消息，不参与生成锁。

模型能力由用户界定，不按名称拦截；只使用 `openai-chat`、`anthropic-messages`。兼容服务按显式 Profile 和地址接入，不按域名猜协议或自动回退。命名与压缩复用推理能力，仍不获得生成权限。

## 现行决策

| 对象 | 契约与维护位置 |
| --- | --- |
| 界面 | 车间桌面使用 B v5 五态浮窗，860px 及以下打开为全屏；HOME 默认半屏停靠，窄于 1280px 全屏；EDIT 同样可用，Photopea 打开时收起并让出按键。见[UI](ui.md)与[HOME](../workspaces/home.md#7-ask-在-home) |
| 会话 | 本页最多 20 个，可新建、切换、重命名、删除、编辑重答与分支；分支默认未收藏。保存规则见[会话与资源](#会话收藏与资源) |
| 草稿 | 一轮最多一份，经字段分组审阅后写入；草稿与输入共用面板，未应用的内置草稿可在面板底部补充，另起普通轮次重新提议；放弃收进菜单。普通 IMAGE 草稿默认源板，可选新板，模型指定新板名时仅新建目标。EDIT 使用独立靶点。见[运行契约](runtime.md#草稿与校验)与[EDIT](edit.md) |
| 协同与任务 | 应用级 Bridge 接收外部 IMAGE 草稿，不要求文本 Key；默认 Todo 独立持久化。任务／配方／文件可与画板修改整体确认，目录交付与任务进度分开。见[协同契约](../integrations/bridge.md) |
| 图片交接 | CHAT 交接新开或复用空白会话，不发送；EDIT 交接准备编辑画板并留在原页，不生成。模型能力、选项白名单和撤销见[运行契约](runtime.md) |
| 回退 | 应用／回退呈现为轮次检查点，页面共享最多 50 条完整撤销记录，按全局栈顶所有权操作；恢复的历史检查点只供查看 |
| 检索 | 本地图片与状态按轮次冻结；词典按需调用共享在线只读查询，不是离线全词库。见[检索与状态](retrieval.md) |
| 提示词 | 用户维护的创作正文保留，程序只维护协议、工具和状态事实，不增加词义分类或画师拦截。见[提示词维护](prompts.md) |

## 架构与所有权

`AskDrawer.vue` 在唯一 App Shell 中持续挂载；车间同一容器在圆形入口、运行胶囊、结果卡、写入胶囊和窗口间变形，不占工作区栏位；860px 及以下展开时铺满可视视口并暂时隔离背景交互。HOME 复用同一服务与窗口停靠呈现，头部承接收起状态，详见[HOME](../workspaces/home.md#7-ask-在-home)。收起保留会话和运行，EDIT 同样可用；Photopea 打开时收起并让出键盘。

发送时冻结工作区与图片快照：活动画板完整基础／角色词文直接发送，其他画板仅目录；历史图片有锚点时提供相关上下文，无锚点时不预载历史原文。`get_state` 默认读取 initial，显式 latest 追加最新状态，不回改本轮草稿基底。当前状态和记忆的优先级见[检索](retrieval.md)与[压缩](compaction.md)。

外部协同由应用级 `src/bridge/` 提供，目录入口位于 HOME 头部或 ASK 输入框附件按钮旁，手动兜底位于现有设置 → ASK 页面。它负责文件传输、收件、refs 元数据／受限读取和用户显式导出；外部草稿、等待队列、检查点与撤销仍由 ASK 管理，不要求文本推理连接。ASK 经只读端口调用 `read_ref`，实际引用内容归现有附件池；文件保存通过 `propose_draft.steps` 的 `save_ref` 提议，经 DraftCard 确认后写入；没有直接文件写入工具。详细生命周期见[外部协同与本地任务](../integrations/bridge.md)。

## 工具总览

当前固定工具集共有十三项，Schema 与描述由实现提供，不随工作区或模型名字切换：

| 工具 | 责任 |
| --- | --- |
| `get_state` | 当前工作台、冻结或最新状态、指定 IMAGE／EDIT 画板 |
| `check_nai_input` | 本轮候选修改的能力、token／Text 与只读费用检查，不写入 |
| `get_meta` | 图片完整参数，不发送像素 |
| `diff_meta` | 参数与词文差异，不能代替视觉对比 |
| `search_history` | 本轮历史、收藏、EDIT 版本与当前 CHAT 分支图片检索 |
| `view_image` | glance／look／crop 按需看图 |
| `view_sheet` | 2–6 图带 ID 拼图，用于预览与对比 |
| `get_chat_context` | 冻结的当前 CHAT 分支、实际发送上下文与当前模型能力 |
| `search_tags` | 共享在线词典的只读批量核验 |
| `get_model_manual` | 四份按需手册：NAI 写法、漫画、服装与照图反推，见[手册索引](prompts.md#按需手册索引) |
| `propose_draft` | 提议唯一待确认草稿，不直接写入 |
| `get_turn` | 本会话成功轮次及附件的原文召回 |
| `read_ref` | 挂载 refs/ 的资料按需读取，复用附件与视觉预算 |

正文 ID 引用和结构化候选是两条通道。选择候选只绑定／预填，下一轮才以其为锚点，不自动发送。工具结果作为资料包裹，不升级为指令。详细预算、签名和错误处理由运行／检索／压缩专题维护。

## 模块与写入所有权

| 文件／目录 | 责任 |
| --- | --- |
| `service.ts` | 应用级服务、会话准入、UI 与工作区桥接、收藏和调用协调 |
| `session.ts`、`runner.ts` | 轮次事务、稳定编号、上下文、工具循环与失败回滚 |
| `provider.ts`、`adapters/` | 两协议转换、流式解析、编解码和实际请求捕获 |
| `tools.ts` | 只读工具注册，仅接收只读端口 |
| `digest/`、`library.ts`、`ids.ts`、`edit-context.ts` | 状态摘要、冻结图片索引、EDIT 现场与目录、可公开编号与作用域 |
| `search-history.ts`、`search-tags.ts` | 本地历史与共享词典查询 |
| `../services/nai-awareness.ts`、`edit-awareness.ts` | 共用 NAI 能力／有效输入／预算／费用的只读投影 |
| `draft/` | 结构校验、字段 diff、确认写入、冲突与撤销栈 |
| `attachments.ts`、`vision.ts` | 用户附件、像素处理、引用计数与视觉预算 |
| `conversations.ts`、`favorites.ts` | 多会话、分支和显式收藏的持久快照 |
| `compact/` | 账本、布局、触发、归档、备忘录校验与原子提交 |
| `prompts/`、`naming.ts`、`debug.ts` | 提示词、独立命名和调用调试 |

工作区通过 ASK 服务打开或预填，不导入内部实现。只读工具不能取得生成或表单写入服务；确认后经 `draft/apply.ts` 和既有 `data.write` 路径应用，失败不能留下半套写入。草稿不触发报价、生图或 CHAT 发送。

Vue 持低频界面状态，大图片、数据库、原始调试 body 和控制器保留在服务普通内存。浮窗拖动由原生驱动，结束再同步必要状态；预览 URL 和监听按引用和生命周期回收。

本地任务服务 `src/slate/service.ts` 独立于 ASK 会话与目录；会话只关联清单。确认写入器协调任务、资产与画板提交记录，删除 ASK 会话不删除独立任务与成果。详细规则由[外部协同与任务](../integrations/bridge.md)维护。

## 会话、收藏与资源

未收藏对话只在本页内存。标题菜单可收藏／取消收藏，收藏置前；数据库写入成功才完成操作，失败保留原状态。取消收藏移除持久记录，当前页仍可继续聊天。

收藏保存到 `koma-ask/conversations`，通过 `data.write` 更新单条记录，不整体覆盖其他标签页。消息、标题、输入、附件、待确认草稿变化走既有延迟保存与 flush／reload；隐藏／离页时尝试 flush。

保存内容包括消息、工具结果、用量、标题、未发送输入、附件原件／发送编码、待确认草稿、外部草稿记录及等待队列，以及压缩的稳定编号、记忆、账本、归档和附件索引。恢复时重建 Object URL，未完成请求标为停止，不自动请求。普通 `#h` 历史不会因收藏 ASK 变成持久图片；编号作用域保留，不能指向刷新后新图。

Key、运行控制器、调用调试、Object URL 和撤销执行记录不持久化。恢复的已应用检查点只供查看，不能伪造可执行回退。保存的待确认草稿应用前仍检查当前目标与冲突。ASK 收藏及其附件不进入普通 Koma ZIP。

## 设置、自由创作与附件

「设置 → ASK」独立管理推理模型、命名模型、图片开关、个人偏好、自由创作、压缩阈值和附件上限及外部协同分组。更多菜单仅保留「压缩上下文」「调用调试」，不承载设置开关或手动导出。设置中的 ASK 配置可进入普通备份，收藏内容不进入；自由创作开关单独保存于 `koma.ask.adult.v1`，不进备份。

「自由创作」默认关闭，无下方附加说明。开启后才加载附加创作语境并启用词表混淆／A → B 替换；词条与规则默认空，只检查格式、长度、重复及逆向映射冲突，不做语义排除或代码级画师判断。关闭时隐藏编辑区并暂停转换，保留配置；规则变化仅在轮次边界生效。本地表单、草稿与展示始终为原始文本，出站转换、入站先还原再校验。

文本附件默认单个 50,000、每轮 100,000 字符，可设置正安全整数，总上限至少为单个上限；恢复默认与压缩阈值共用设置区。新限额只作用于后续添加，不截断现有附件或历史。图片与文本每轮分别最多 4 个，图片大小和视觉预算见[附件与视觉](runtime.md#附件与视觉)。

图片发送按轮次冻结，工作台状态的 `image_input` 告知模型本轮权限；仅元数据轮次在提问下标记，不修改全局图片开关。失败始终保留普通重试，拒绝／空白回复可另选仅元数据；该轮限制在普通重试中保留，显式「发送图片并重试」才恢复，新问题按当前设置发送。

## 命名与压缩

AI 命名由用户点击发起，默认沿用 ASK 模型，也可独立指定连接与完整模型 ID。命名仅写回目标名称，不加入主 ASK 上下文或执行工具。细节见[提示词与命名](prompts.md)。

压缩默认阈值为 220,000 tokens，常规自动触发只看最后有效输入量，在轮次之间执行；使用发起时选定的 ASK 连接与模型，没有独立压缩模型或后台静默任务。收藏随同保存记忆与归档；当前表单永远由最新状态决定，记忆不代替原图或当前草稿基底。详见[压缩契约](compaction.md)。

## 验证与待办

内置待确认草稿支持在一体面板底部[直接补充修改意见](runtime.md#草稿补充)，复用普通发送与重试；不增加问卷工具、挂起工具调用或跨轮执行状态机。外部与手动草稿继续先应用或显式放弃。
