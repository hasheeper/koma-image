# ASK 协议与运行契约

更新：2026-10-26。现行决策以[ASK 维护入口](ask-implementation-plan.md)为准。本文负责消息、工具、视觉、草稿和并发；生命周期、UI、检索与压缩分别由对应专题维护。

## 推理协议

| 协议 | 路径 | 缓存 |
| --- | --- | --- |
| `openai-chat` | `/chat/completions`，根地址补 `/v1`，已带版本路径则保留 | 上游隐式前缀缓存，不增加显式缓存参数 |
| `anthropic-messages` | `/v1/messages`，保留服务前缀、不重复版本 | 显式 `cache_control: { type: "ephemeral" }` |

只通过能力匹配的显式连接访问，不使用 OpenAI Responses 或 Gemini 原生多轮工具协议。实际模型能力由用户界定。浏览器直连依赖 CORS；本地代理使用两组独立可选环境变量，固定目录／推理路径，支持流式与停止，不转发任意 URL。

## 消息、前缀与状态

请求顺序为固定 tools、System（宪章／工作区／模型核心和可选自由创作语境）、用户偏好与映射、可选冻结 `<session_memory>`、完整历史轮次、当前 user（状态／图片与文本附件／实际提问）、本轮工具调用及结果。

- 动态 `<workspace_state>` 和本轮数据追加在队尾，不塞入 System 或回改旧历史。
- 静态核心一次包含主力模型知识，不因切换生图模型重排；较长专项手册按工具读取。
- 同轮初始快照与 codec 规则冻结，latest 读取只追加工具结果。活动板原文直接提供，其他板和无锚点历史原文按需读取。
- System／tools 不加入时间戳、随机数或无谓键序变化。用户偏好、自由创作与规则变化在轮次边界生效。
- 外部词文、元数据、附件与工具结果通过 canonical／`<data>` 等资料边界表示，不赋予指令权限。

Anthropic 断点位于 tools 末尾、实际最后一个 System 块、最新消息末尾；有真实记忆消息时增加第四个，全请求最多四个，不创建空 System。OpenAI 合并 System，不发送缓存控制参数。冻结记忆只在成功压缩时替换。缓存标记只是申请，真实命中以上游 usage 为准；详细布局见[压缩](compaction.md#8-消息布局与缓存断点)。

## 工具循环与失败

一轮最多 6 次工具调用，一轮最多一份草稿；`propose_draft` 成功后停止执行工具。整轮没有回复正文时仅补一次说明请求，使用 `tool_choice=none`；再次空白、拒绝、网络错误或停止均失败，不重复工具或自动重试失败请求。

轮次成功才提交上下文。失败／取消移除本轮状态、提问和半截工具轨迹，保留 UI 失败展示与已报告消耗；下一轮不携带失败的半轮请求。可由用户显式重试，拒绝／空白回复同样保留普通「重试」，不强迫改用仅元数据。仅元数据重试移除附件及历史像素，作用于本轮，不修改全局图片开关；普通重试和编辑重答继续保留该轮限制，失败轮次可在全局图片开关开启时显式选择「发送图片并重试」。新提问按当前图片设置开始。词表重试遵循当前自由创作开关，不另设旧的成年确认门控。

工具和视觉预算不能因重试悄悄放宽。上游错误、缺失数据和未命中分别表达，不伪造已核验结果；失败／部分失败工具组在 UI 可查看逐项原因。

## 附件与视觉

- 用户图片每轮最多 4 张，各原文件不超过 20MiB／4000 万像素；实际外发每张不超过 1MiB。PNG／JPEG／WebP 长边不超过 1568px 且满足大小限制时可原样发送，其余解码为受限 WebP，GIF 仅首帧。
- 文本每轮最多 4 个，默认单个 50,000、合计 100,000 字符，可在设置调整；超过 2000 字的纯文本粘贴转附件。页面原文件合计上限 200MiB。
- 显式用户图片属于提问，不占工具视觉预算。图片开关关闭时只发送元数据，并剥离历史像素；文本仍作为资料发送。实际仅元数据的轮次在提问下标注「仅元数据」；初始／后续读取的工作台状态附带冻结的 `image_input`，明确本轮是否允许视觉工具，工具定义保持静态。
- 工具视觉最多 4 次，总量 1.5MP／400KB；`view_image`、`view_sheet` 与 `read_ref` 图片读取共享预算，超限返回错误，不静默降质。
- glance 长边 384px、look／crop 最大 768px；sheet 合成 2–6 个不同 ID 的图，默认 768px，glance 为 384px。
- crop 要求本轮或历史看过同 ID 的 glance／look，或收到该 ID 的用户完整附件；sheet 不计单图全图前置。区域为 0–100 百分比 `[x, y, width, height]`，四边自动外扩 25% 并限于边界。
- 仅保留最近 3 轮像素，较早轮次请求转文字占位；UI 记录仍可见。再次看图须原图仍存在，不能凭记忆声称看过。

预览 Object URL 属本页临时资源，最后一个引用释放即回收；用户显式收藏的附件原件与发送编码另存本机，恢复时重建 URL。

`read_ref` 只能按冻结清单访问挂载 `refs/` 内的受限路径；本地附件与工具读取共用每轮附件数量、字符和页面容量上限。文本每次最多 8000 字符，同轮重复／分页使用首次成功读取的冻结版本；图片走 look 视觉通道，图片能力关闭时拒绝。实际内容、来源路径与 SHA-256 随所属轮次保存，收藏后不依赖目录仍可恢复。重试／编辑重答不把工具读图改为用户图片绕过视觉预算；正文始终作为资料。路径、清单截断和导出规则见[共享资料](bridge.md#共享资料与按需读取)。

## 草稿与校验

对外 `draft_title` 与可选 `new_board_name` 保持稳定，不增加语义判定字段。步骤包括：

| 步骤 | 责任 |
| --- | --- |
| `prompt_patch` | 基础 Prompt／Negative、稳定角色词文或 `chat.composer`（仅在 CHAT 提问时）；replace／before／after／append／rewrite |
| `params_patch` | 白名单内直接提议绘图参数，按最终勾选结果校验模型、画幅与关联能力，复用参数 Diff |
| `restore_partial` | 从本轮冻结图片元数据恢复选择字段，数值由程序读取而非模型提供 |
| `character_edit` | 稳定角色 ID 的增删、重排、启停、定位与自动／手动模式 |
| `chat_distill_branch` | 冻结当前分支的起点、文字排除与提纯描述，不发送 CHAT；仅在 CHAT 提问时 |
| `slate_edit` | 默认本地任务清单、状态／成果与配方；版本和图片冲突联合检查 |
| `save_ref` | 冻结配方／备忘录／任务资料与目标，统一确认后保存；目录改变或失联阻断整稿 |
| `chat_handoff` | 独立成稿：新开 CHAT 会话（复用空白会话），按序写入参考图、尺寸类选项与输入框，不发送、不报价 |

在 IMAGE 或 TAGS 提问时，写入 CHAT 一律走 `chat_handoff`，`chat.composer` 补丁和分支草稿被拒绝。交接图片取冻结库中的 `#h`、`#f`、`#e` 或 `#cN.M[a-z]`（兼容旧数字尾段），附件 `#a` 不可；按记录 ID 或素材 ID 去重，不超过当前模型 `max_images`。`#h`／`#f`／`#e` 经参考图压缩后加入 CHAT 素材，`#c` 直接引用既有素材。选项只接受 `size`、`aspect_ratio`、`image_size` 中当前模型声明的键与可选值；`quality` 只读，由回复提醒用户手动调整。草稿选项只写新会话，不改全局 CHAT 设置。写入后直到用户下一次操作 CHAT 前不报价、不刷新额度。

CHAT 图片 ID 为当前分支的 `#c轮次.版本`；一个版本有多张图时逐张为 `#c轮次.版本.图序`，省略图序指第一张。旧 `#cN.M` 仍可解析。

校验源画板／会话身份、完整基底、目标存在、文本锚点与参数能力。文本先精确匹配；失败后统一空白及中英文逗号作唯一宽容匹配，再映射原字符串位置；仍不唯一或找不到即失效。不根据名字、次序、权重或自然语言推断画师授权，不对词义分类。

`params_patch.params` 仅开放表单安全字段，完整白名单、范围与示例见[外部协同](bridge.md#直接修改参数)。内部工具与外部 JSON 共用 `draft/schema.ts`、解析器和参数校验。勾选后的非法组合或冲突不能部分写入；连接、Key、路由、并发和参考资产导入不在允许字段中。

文件草稿固定配方 JSON、备忘录 Markdown、任务资料 JSON；提议时冻结内容与去向，保存与撤销检查文件所有权，浏览器已下载文件不能收回。详细预览与补偿规则见[文件保存](bridge.md#文件保存草稿)。

外部 IMAGE 草稿通过[Bridge](bridge.md)进入当前 ASK 会话，不伪造模型轮次或用量；忙时进入该会话的等待队列。手动与目录收件使用同一解析管线，应用仍由用户确认。

展示由 `draft/view.ts` 计算字段分组与逗号词组 diff，支持「改动／全文」。角色新增／删除、参数与分支按实际结构合并审阅；不恢复已删除的 `.keep` 解析。

应用前重新检查外部改动和勾选范围，经既有写入路径完成；保存失败原样回滚，不留下新板副本。普通草稿默认源板，可显式选择新板；给出 `new_board_name` 时锁定新建目标。提议不创建画板。

交接在用户确认后才建会话；CHAT 模型变化时整卡作废，单张图片已移除时该行失效。回执为新会话的完整状态键：撤销要求新会话仍存在且未被继续编辑，新建的会话直接删除，复用的空白会话恢复原状，并切回来源会话；保存失败原样还原，可用同一回执重试。

## 检查点、编辑与分支

应用和回退由所属轮次检查点呈现，页面最多保留 50 条完整撤销记录。回退或恢复必须满足全局栈顶所有权和外部状态校验；输入框内保留系统撤销语义。撤销不生成、不报价或发送。

原位编辑先整体预检需要撤回的应用，失败不截断会话；成功后再删除重答点及之后上下文。分支继承选中成功前缀，默认不收藏。删除会话只移除其撤销记录，不撤回已写入工作区；刷新清空执行栈，收藏恢复的历史检查点仅供查看。压缩后的编辑／分支另遵守[归档恢复](compaction.md#13-多次压缩编辑重答与分支)。

## 并发、焦点与中立处理

发送时冻结根基底、历史最大游标与当前 CHAT 分支；后台新图或用户改表单不打断轮内工具，也不回改初始锚点。结束后检查外部变化，提示并重新校验待确认草稿。压缩／收藏／写入中的会话准入由 ASK 服务控制，不借用生图锁。

IME 组合不提交，Tab／Esc／⌘Z 遵循当前焦点与浮层层级；UI 细节见[UI 规范](ask-ui-spec.md)。工具日志、查看和预览不触发写入。

自由创作附加语境、词表与 A → B 规则仅在网络边界启用；本地始终保存原文，入站先还原再展示／校验。规则默认空，只校验结构和逆向冲突。具体配置和轮次边界见[提示词维护](ask-prompts.md#自由创作)。

图片引用采用[统一身份](../image-identity.md)：`#h/#e` 属页面作用域，`#f` 属持久收藏库，CHAT／附件保留会话绑定。整轮库、回复、草稿与记忆链路冻结具体记录；视觉可以共享同实体资格，参数不按实体替换。EDIT 只读感知不开放编辑草稿或生图执行。
