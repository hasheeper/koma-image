## 1. 协议选型与前缀缓存（KV Cache）策略

在单轮最多 6 步的工具循环中，前缀缓存直接决定首字延迟与用户账单。

### 1.1 只实现两个推理协议适配器

在 `src/ask/provider.ts` 中将内部消息与工具格式统一为一套中间结构，仅向外适配两种协议：

| 协议适配器 | 接口路径 | 缓存机制 | 覆盖范围 |
| --- | --- | --- | --- |
| `openai-chat` | `/v1/chat/completions` | 隐式前缀匹配（前缀字节一致即自动命中） | OpenAI 官方、Google Gemini 的 OpenAI 兼容层、通用中转站 |
| `anthropic-messages` | `/v1/messages` | 显式断点 `cache_control: { type: "ephemeral" }` | Claude 系列、支持 Anthropic 协议的国产模型（DeepSeek、Qwen 等）及中转网关 |

* **不做** OpenAI `/v1/responses`（依赖服务端状态，与纯前端内存架构冲突）。
* **不单独做** Gemini Native 的多轮函数调用与 `cachedContents` 生命周期管理；Gemini 统一走其官方或中转的 OpenAI 兼容接口。
* 复用现有的「设置 → 连接」Gateway Profile；仅用于生图的专用连接（如 NovelAI 官方）在 ASK 模型选择器中过滤隐藏。

### 1.2 「静态前缀冻结 + 队尾状态追加」结构

严禁将每轮变化的 L0 工作台摘要塞入 System Prompt，否则每次表单变动都会打碎整场会话的缓存。请求载荷必须按以下顺序组装：

```text
1. [Tools Schema]                                  <-- 静态冻结（Anthropic 断点 #1）
2. [System Block 1: L0 宪章 + L1 工作区 + L2 全模型知识包] <-- 静态冻结
3. [System Block 2: <user_preferences> 个人偏好]    <-- 静态冻结（Anthropic 断点 #2）
4. [History Turns: 历史对话与已脱水的工具记录]
5. [Current Turn User Message:
     <workspace_state> 当轮 L0 快照 JSON </workspace_state>
     用户的实际提问文本]                            <-- 动态内容永远追加在队尾
6. [Current Turn Tool Calls & Results]             <-- 循环中每步在队尾追加（动态打断点 #3）
```

### 1.3 防破功（Anti-Cache-Busting）三条戒律

1. **一次性装载 L2 核心**：System Block 1 中直接包含 NAI 4.5/V5、OpenAI Images、Gemini 等全部主力模型的精简知识，**不因用户切换生图模型而动态抽换 System Prompt**。2026-10-22 分层调整后，较长的专项手册通过只读 get_model_manual 读取，作为工具结果追加到队尾，不塞入静态核心；详见 [提示词分层记录](ask-prompts.md)。
2. **禁止动态噪声**：System Prompt、Tools 定义及历史消息中严禁包含当前时间戳、随机数或每次重排的對象键名（JSON 序列化键序必须固定）。
3. **工具循环内快照锁死**：在同一轮的第 1 步至第 6 步之间，第 5 项中的 `<workspace_state>` 保持不变；若模型调用 `get_state()`，新快照作为最新的 `tool_result` 追加在队尾，不回改前面的消息。

## 2. 内容防拦截、防说教与死档自愈

二次元与插画创作高频涉及萌系审美（Petite）、16+ 软色情（Ecchi）及成人向（NSFW）标签。在坚决不触碰违法绝对红区的前提下，必须解决「模型默认保守暗改」与「渠道网关 WAF 关键词死档」两大问题。范围不涉及未成年与 R18G，由代码中的排除表强制执行；成年内容由用户在「设置 → ASK」中自行确认，并自行承担渠道风控与封号风险（文档 4 §5）。

### 2.1 L0 宪章：成年人虚拟艺术语境与防暗改声明

2026-10-22 用户调整：下列「创作语境与题材包容」内容现已整体移入成人模式附加块；中立核心仅保留通用的文体/画风保护与只改相关内容等原则。以下早期定稿中「下面三条始终生效」由此更新替代，注入行为以文档 4 与 [提示词分层记录](ask-prompts.md) 为准。

在 System Block 1 中植入以下客观、去情绪化的工具规范（避免使用对抗性越狱措辞）：

* **语境声明（R18 门控）**：用户已在设置中自行确认成年（18+）后才加载，措辞为：当前环境为用户已自行确认成年的本地私有 2D 虚拟插画参数调试工具（Taxonomy & Parameter Inspector）。不写「已验证」。未确认时不加载本条，下面三条始终生效。
* **技术中立与零说教**：仅从构图、光影、色彩与标签权重冲突的技术角度诊断问题。严禁对用户的画面审美、服装暴露度或成人向标签发表道德评判、安全警告或说教。
* **严禁擅自净化（No Silent Sanitization）**：调用 `propose_draft` 时，**严禁出于保守倾向擅自删除、弱化或替换用户原有的 NSFW、身体特征或萌系画风标签**。只允许修改与用户当前提问直接相关的技术词汇。
* **极简拒绝边界**：若请求确实触发模型底层绝对红线而无法处理，只允许输出单行 `当前请求超出模型处理边界，无法生成建议。` 并立即结束本轮，不输出多余训诫。

### 2.2 网关敏感词双向编解码中间件（`src/ask/codec.ts`）

针对部分 API 渠道网关对特定 Danbooru 标签（如体型词、评级词、部位词）的死板正则拦截，在网络收发层增加轻量纯函数转换：

* **本地绝对干净**：Koma 的 Store、提示词框以及展示给用户的草稿卡片中，永远保持 100% 原始标签。
* **出站混淆（Outbound）**：发送 HTTP 请求前，按静态映射表（内置常见误杀词 + 允许用户在设置中自定义补充）将高危词替换为无害代号（如 `@t_01`），并在静态 System 末尾附上简短代号表供模型意会。纯函数替换具有确定性，不破坏前缀缓存。
* **入站还原（Inbound）**：收到模型流式文本与 `propose_draft` 参数后，先逆向还原回原始标签，再交由前端校验器与 UI 渲染。
* **门控**：仅在 R18 确认后可用；未确认时编码器为恒等函数，「词表」设置隐藏。启用或停用只在轮次边界改变静态前缀。
* **排除表（`src/ask/codec-exclusions.ts`）**：未成年与 R18G 两类词永远原样出站。内置词表不收录；用户自定义条目命中时拒绝保存。匹配前统一大小写、下划线与空格、全角与半角，并由单元测试锁定。
* **实效边界**：模拟测试只证明编解码往返一致。能否通过具体渠道的过滤，需真实渠道实测后再下结论。

### 2.3 失败轮次事务回滚（防止单次拦截搞死整个会话）

* **不污染历史栈**：当某轮请求收到 `400 / 403 / Content Filter` 或空流中断时，当前轮次注入的 `<workspace_state>`、用户提问及半截工具调用**一律不提交进 `session.messages`**，确保下一轮发言不会因为携带上一轮的被拦截词而连续报错死档。
* **就地降级重试 UI**：被渠道拦截时，流中显示单行提示并提供两个快捷重试按钮：
  * `[ 启用词表混淆并重试 ]`
  * `[ 仅发元数据（不发图）重试 ]`（绕过渠道网关的低级图像分类器）。
* **按门控显示**：「仅发元数据重试」始终可用。「启用词表混淆并重试」只在 R18 确认后显示，点击后本页会话内保持启用；未确认时改为一行提示与设置入口。两者都由用户点击触发，不自动重试。

## 3. 领域结构与多模态容错算法

### 3.1 NovelAI 完整表单结构感知（多角色分区与 Vibe）

不能将绘图页表单简化为单一的正负提示词框：

* **L0 摘要扩展**：`form` 快照必须完整包含 NAI V4.5/V5 的**多角色独立描述区**（`characters: [{ id, prompt, negative, position }]`）以及已挂载的 **Vibe Transfer / 参考图摘要**（数量、强度与信息提取权重）。
* **草稿靶点扩展**：`propose_draft` 的 `target` 字段除 `image.prompt`、`image.negative`、`chat.composer` 外，支持定位到具体角色分区（如 `image.char.0.prompt`、`image.char.0.negative`）。
* **当前预留**：现有绘图表单尚无多角色分区与 Vibe 输入（`src/gateway/routes.ts` 的 `char_captions` 恒为空，只有图片元数据解析会识别）。L0 结构与靶点类型照此定义；表单缺少对应对象时，校验器返回「目标不存在」，该步作废并标注。ASK 不顺便修改绘图业务。

### 3.2 视觉裁切（`crop`）的坐标系归一化与安全扩边

不同多模态模型对原图像素坐标的估算极易偏航。`view_image(id, "crop", region)` 必须遵守以下约束：

1. **先全图后局部**：模型必须在本轮或历史中先调用过该图的 `glance (384px)` 或 `look (768px)`，才允许对该图调用 `crop`；否则工具直接返回错误提示模型先看全图。
2. **百分比输入 + 25% 自动扩边**：`region` 参数统一规定为 `0–100` 的归一化百分比 `[x_pct, y_pct, w_pct, h_pct]`。前端 `vision.ts` 在换算为原图像素坐标时，**自动向四周外扩 25% 的安全边距（Padding，限制在画布边界内）**，再缩放到 `768px` 以内，确保即便模型指偏也能完整框住目标部位（如眼睛、手部）。

### 3.3 宽容锚点匹配（Fuzzy Anchor Matcher）与 `.keep` 本地计算

为防止模型输出细微的标点或空格差异导致草稿报废，减轻模型计算负担：

* **两级锚点匹配（`src/ask/draft/validate.ts`）**：
  1. **Level 1（精确匹配）**：直接在目标文本中查找 `anchor` 子串。
  2. **Level 2（归一化宽容匹配）**：若精确匹配失败，将目标文本与 `anchor` 均忽略首尾空白、统一中英文逗号与连续空格后再做唯一匹配，并映射回原字符串的真实起止区间。仍不唯一或找不到时，才将该步标记为失效。
* **整段改写中的 `.keep` 下划线由前端本地生成**：
  * 模型在 `rewrite` 草稿中只需输出干净的新文本字符串，**不需要自己标注哪些是保留词**。
  * 前端在渲染 `.slice` 预览时，自动将原区段拆分为有效 Tag/词组，在新文本中进行大小写不敏感匹配，命中的原词自动包裹 `<span class="keep">`。

### 3.4 多轮会话的历史图片脱水（Image Dehydration）

为防止长会话在缓存过期或切换模型时因历史堆积大量 Base64 图片而撑爆 Token：

* 在 `session.ts` 构造请求消息队列时，**仅保留最近 3 轮（Hot Turns）内工具返回的真实 Base64 图像块**。
* 第 4 轮及更早轮次的视觉 `tool_result`，在序列化发送前自动替换为纯文本占位符：`[Image #h12 (look, 42KB) was viewed in an earlier turn; call view_image again if re-inspection is needed]`。前端 UI 流中的历史轨迹显示不受影响。

## 4. 并发竞态、焦点护栏与工程红线

### 4.1 「人在改、图在生、ASK 在想」的快照隔离

生图等待期间是用户使用 ASK 的高频时段，必须处理好并发碰撞：

* **回合内快照隔离**：用户点击发送提问的瞬间，锁定当轮的 `base_hash` 与历史最大 ID 游标。工具循环运行期间，即便后台新图 `#h25` 生成完毕入库，或用户正在左侧修改提示词，也不打断当前正在进行的工具循环。
* **回合结束后的状态同步**：当轮流式输出与草稿渲染完成后，对比当前最新 Store 状态：
  * 若提示词已变动：在消息流中插入 `.note` 分隔行 `提示词已在外部修改`，并对当前挂起的草稿执行冲突对齐检查（见文档 1 §10）。
  * 若有新图生成：平滑更新输入框左下角的默认上下文胶囊（或提示新图已就绪）。

### 4.2 快捷键焦点护栏与跨工作区应用

* **`Tab` / `Esc` 焦点边界**：
  * 仅当焦点位于 `AskDrawer` 内部（且不在输入框内正在输入文字或选词），或焦点在全局 `body` 上时，按 `Tab` 才触发「应用草稿」。绝不劫持用户在左侧 Prompt 框或 CHAT 输入框中的正常键盘操作。
  * `Esc` 严格遵循外壳层级：若存在打开的下拉菜单或预览浮层先关浮层；否则若有未决草稿则忽略草稿；若正在运行工具循环则中断请求；最后才是关闭 `AskDrawer`。
* **跨工作区草稿保护**：
  * `AskDrawer` 在外壳切换工作区时保活。若当前挂起的草稿靶向 `IMAGE`（如 `image.prompt`），而用户切去了 `#/chat`，草稿卡不丢失，但主按钮文案自动变为 **`[切回绘图并应用]`**，点击后先切回目标工作区再执行写入并高亮预览，防止在后台盲写导致用户感知不到变化。

### 4.3 提示词内容与仓库治理移交约定

1. **System Prompt 分步交付**：AI IDE 在实现阶段先搭建好 `src/ask/prompts/` 的分层加载器、版本号与 `<data>` 注入包裹机制，内置结构合规的基础版提示词跑通全量单元与模拟浏览器测试；领域深度的模型调优词可在管道验收后独立迭代。
2. **遵守仓库既有工程红线**：实现前必须先读取 `AGENTS.md`、`docs/architecture.md`、`docs/style-ownership.md` 与 `docs/style-checks.md`。文档 2 原型中的 CSS 必须按项目现有的「公共变量/基础层 vs Vue 组件私有样式」拆分，严禁引入外部运行时依赖，确保 `npm run check`（含字体、Stylelint、严格 TS 检查与构建）一次通过。
3. **字体与颜色统一**：ASK 正文使用站内圆体 `--sans`，ID 与代码使用 `--mono`，字标使用 `--brand`；颜色、按钮与动效时长映射到站内 tokens，见文档 4 §2.2。
