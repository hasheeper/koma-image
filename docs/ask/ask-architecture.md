# Koma ASK：子产品理念、开发需求与基本框架

日期：2026-10-21。状态：设计定稿，未实现；实施细节与后续决策见《决策与实施规划》（文档 4，`ask-implementation-plan.md`）。

适用基线：Koma Image（Vue 3 + TypeScript + Vite 单页外壳，M1–M7 已发布）。本文汇总此前的讨论结论，替代之前的「Koma Copilot」草案。产品原则冲突时以《产品特点参考》的六条设计原则为准；工程与交互细节的优先级为文档 4 > 文档 3 > 文档 2 > 本文。

## 第一部分：子产品理念

### 1. 一句话

**能看、能查、能提议，不能动手。**

ASK 能感知当前工作台的状态，按需读取图片和参数，用经过调校的专业知识给出诊断和建议。它唯一的写入方式是提交一份**草稿**，由用户确认后才生效。生成、扣费、发送消息，永远由用户亲手完成。

### 2. 为什么叫 ASK

- 与 `IMAGE`、`CHAT`、`EDIT`、`DICT` 一样，都是不需要意会的大白话。
- 名字本身就说明了权限：用户来问，它来答，不替用户执行。
- 同一个词既是模块名，也是按钮动作：「Ask #h4」「Ask Diff」「Ask Why」。
- 不叫 Agent，以免让用户以为它会自动执行任务；不叫 Copilot，以免与微软产品混淆。

### 3. 定位：外接的视觉前额叶，不是代工的画师

| | 全能 Harness | Koma ASK |
| --- | --- | --- |
| 目标 | 替用户完成任务 | 让用户少卡壳 |
| 生图与扣费 | 自己调用 | 没有权限，也没有间接途径 |
| 人的状态 | 下发任务后离开 | 始终在场 |
| 上限对标 | Claude Code、Codex | 不与它们比，只比「零准备成本」和「懂当前画面」 |
| 失败代价 | 烧积分、审美跑偏、心流中断 | 一条草稿没用，按 Esc 忽略 |

两个基本判断：

1. **审美无法代理。** 写代码有测试可以判定对错，画画只有用户自己能判断好坏，所以判断环节不能自动化。
2. **长任务不在站内做。** 需要深度调研、批量脚本、大量阅读资料的工作，交给外部通用工具。站内做的残缺版 Harness 唯一的优势是省去准备工作，上限却被锁死。

### 4. 子产品原则

在全站六条原则之下，ASK 增加五条：

1. **先取证，再下结论。** 涉及画面的判断，必须先看过图，不能只凭参数推测。
2. **草稿是唯一的出口。** 任何修改都以草稿形式出现，用户确认前界面状态不变。
3. **按需取图，有预算。** 默认不发图；取图时只发缩小或裁切后的版本，从不发原图。
4. **尊重用户的文体。** 用户写 Tag，就用 Tag 回应；用户写句子，就用句子回应。只改与问题相关的区段，不顺手「优化」其他部分。
5. **对没有把握的领域保持沉默。** 画师串在专门的能力建成之前不做任何主张（见 §10）。

## 第二部分：开发需求

### 5. 核心场景

| # | 场景 | 用户说 | ASK 做什么 |
| --- | --- | --- | --- |
| S1 | 诊断 | 「为什么还是红眼睛？」 | 读 Prompt 并看图，指出冲突来源，提交草稿 |
| S2 | 对比考古 | 「#h12 比现在好，我改坏了什么？」 | 比较参数，并用拼图对比画面，提议只恢复相关的几项 |
| S3 | 改写与转换 | 「这段改成哥特装」「这堆 Tag 织成一句话」 | 局部替换，或在 Tag 与自然语言之间转换，以 diff 展示 |
| S4 | 找词与灵感 | 「想要电影感，但说不出词」 | 查本地词典，给出有依据的候选，或 2–3 个文字方案 |
| S5 | 画风修饰与偏置抗衡 | 「这个画风太扁平」「blue eyes 不生效」 | 只增删通用画风、光影、主体 Tag 及其权重，不碰画师串 |
| S6 | 对话上下文顾问 | 「为什么越改越糊？」 | 读取上下文面板状态，建议排除某些轮次，或提纯后新开分支 |
| S7 | 跨工作区摆渡（v2） | 「把这张对话图转成 NAI 的写法」 | 看图反推出混排 Prompt，作为草稿交给绘图页 |

### 6. 功能需求

**F1 入口**

- `⌘J` 打开或关闭 ASK 抽屉。在绘图、对话、词典中都可以使用，抽屉属于外壳层级，切换工作区时不关闭。
- 抽屉从右侧滑出，覆盖图片栏，不挤压画布。
- 画框元数据栏增加「Ask」按钮，点击后自动带上 `#id`。历史栏选中两张图时出现「Ask Diff」。报错卡片上可以出现「Ask Why」。
- 生成等待期间可以正常使用，这正是适合提问的时间。
- v1 中，编辑器全屏覆盖层打开时不能使用 ASK（见 D9）。

**F2 感知**

- 每轮对话自动附带工作台摘要（§8），不包含图片。
- 用户输入 `#h12`、`#f3`、`#c4.2` 等标准 ID，或从画框点击进入，即视为指定了锚点。

**F3 只读工具**

由模型按需调用，见 §9。每次调用在抽屉中显示为一行状态，例如「查看 #h4 · 768px」，可以展开查看详情。

**F4 草稿**

- 草稿以 diff 或动作清单的形式展示，并在提示词框内高亮预览。
- 按 `Tab` 应用，按 `Esc` 忽略。可以逐处勾选，只应用其中一部分。`Tab` 的焦点护栏与 `Esc` 的层级顺序见文档 3 §4.2。
- 应用时走与手动编辑相同的写入路径，留下一个撤销点，`⌘Z` 可以一次撤回。
- 应用后不自动生成。生成按钮照常重新报价。

**F5 ID 锚点**

回复中的 ID 渲染为小方块标记。悬停显示缩略图，点击后在画布上定位到对应的图。

**F6 成本可见**

- 发送前显示本轮预计的 token 用量。
- ASK 的费用与媒体积分分开计量、分开显示。
- 不自动重试；失败时显示原因和「重试」按钮。

**F7 隐私**

- 只有模型调用视觉工具时才外发图片，并且只发缩小或裁切后的版本。
- 「设置 → ASK」中提供「发送图片给模型」开关，同时用于隐私选择和由用户声明模型是否支持图片。关闭后只提供元数据，抽屉中会标明当前处于受限模式。

**F8 个人偏好**

- 一个最多 300 字的文本框，默认为空。
- 非空时，输入框上方显示「个人偏好已生效」，可以预览内容，也可以临时停用。
- 偏好不能凌驾于宪章之上，包括画师串禁区。

### 7. 非目标

- 不调用任何生图、编辑、放大、报价扣费接口，也不能间接触发（例如替用户点按钮）。
- 不替用户发送 CHAT 消息。
- 不做后台任务、长期任务、定时任务，不联网搜索。
- 不持久化 ASK 对话。对话只保存在内存中，刷新即清空，与绘图历史一致。
- 不对画师串提出主张（§10）。
- 不支持纯文本 LLM 或能力较弱的 VLM，也不做「视觉模型 + 文本模型」两段拼接。
- 不做头像、悬浮球或语音。

## 第三部分：基本框架

### 8. 上下文引擎：双模式历史索引

摘要分三层，**默认只发送 L0**：

- **L0 工作台摘要**（每轮附带）：当前工作区、表单（含 Prompt 的分区结构和 hash）、当前选中的图、生成状态、历史索引。
- **L1 元数据**（按需读取）：单张图的完整参数，或两张图之间的结构化差异。不消耗视觉 token。
- **L2 视觉**（按需读取）：缩小、裁切或拼图后的图片。

历史索引根据用户是否给出锚点，分为两种模式。

**模式 A：有锚点，以相似度划分同心圆**

以锚点图的 Prompt 为基准，计算其他图的词级相似度：

| 层级 | 条件 | 提供的内容 | 典型用途 |
| --- | --- | --- | --- |
| 锚点 | 用户指定 | 全量参数 | — |
| T1 | Prompt 完全相同，只有参数不同 | 每张图列出变化的参数 | 直接用 `view_sheet` 做控制变量对比 |
| T2 | Prompt 相似度 ≥ 90% | 每张图列出词级 diff | 拼图对比 |
| T3 | 其余 | 区间摘要 | 需要时再查 |

**模式 B：无锚点，按时间动态衰减**

| 区域 | 范围（默认值，可调） | 提供的内容 |
| --- | --- | --- |
| 热区 | 最近 3 张 | 全量参数 + 词级 diff |
| 温区 | 第 4–15 张 | 只列相对上一张的变化字段 |
| 冷区 | 更早 | 按变化字段聚类，例如「#h01–#h09：Prompt 相同，只改了 seed 和 scale ∈ [4.5, 7]」 |

**兜底顺序**

模糊提问在摘要中找不到对应的图时，按以下顺序处理：

1. 调用 `search_history` 做本地检索。
2. 以命中的图为锚点，切换到模式 A。
3. 如果仍然有歧义，给出 2–3 个候选缩略图，请用户确认。

**Prompt 分区**

复用权重高亮的分词结果，把 Prompt 标记为以下几类区段，供摘要和草稿使用：

- `artist_mix`：画师串
- `style_tags`：画风、媒介、质感
- `subject`：主体与动作
- `modifier`：光影、构图等修饰
- `freeform`：自然语言句子

### 9. 工具集

```text
get_state()                                   L0 最新快照
search_history({ query?, changed_field?,
                 similar_to?, min_sim? })      穿透冷区，本地检索
get_meta(id)                                  L1 完整参数
diff_meta(a, b)                               字段变化 + Prompt 词级 diff
view_image(id, spec, region?)                 L2，spec ∈ glance | look | crop
view_sheet(ids[], spec?)                      L2 带 #id 标注的拼图，最多 6 张
search_tags(query, lang?, limit ≤ 20)         本地词典
get_chat_context(conv?)                       CHAT 各轮勾选、底图、配额、实际发送的文字
propose_draft(draft)                          提交草稿，本轮结束
```

视觉规格：

| 规格 | 处理 | 约 | 用途 |
| --- | --- | --- | --- |
| `glance` | 长边 384px，WebP | 15KB | 构图、色调、整体风格 |
| `look` | 长边 768px | 50KB | 光影、脸部、画风细节 |
| `crop` | 按原图坐标裁切，结果缩放到 768px 以内 | — | 手、眼睛、局部瑕疵 |
| `sheet` | 多图拼成网格，复用批量对比图的模块 | — | 多图对比 |

**循环规则**

- 单轮最多 6 次工具调用。达到上限后，模型必须基于已有信息作答。
- 单轮最多 4 次视觉调用，外发总量不超过 1.5MP 和 400KB。超出预算时工具返回错误，由模型自行改用 sheet 或 crop，前端不悄悄降低画质。
- 调用 `propose_draft` 后本轮立即结束，一轮最多一份草稿。
- 视觉处理归原生驱动层负责（`createImageBitmap` + `OffscreenCanvas`），结果按 `id + 规格 + 区域` 缓存在内存中。

### 10. 草稿协议与画师串禁区

**草稿类型**

| `kind` | 内容 | 版本 |
| --- | --- | --- |
| `prompt_patch` | 用锚点子串定位，对 Prompt 或 Negative 做替换、插入、删除；也可以按区段整体替换 | v1 |
| `restore_partial` | 从历史图中勾选部分参数或词写回表单，复用「从图片导入」的核对表 | v1 |
| `chat_distill_branch` | 从指定轮次新开分支，重设上下文勾选，填入提纯后的描述 | v1（M3） |
| `cross_workspace_stage` | 写入绘图页的交接槽，并在切换器上提示 | v2 |

**规则**

- 用锚点子串定位，不用字符偏移。匹配不到或匹配到多处时，该处修改作废并标注出来。
- 每份草稿带 `base_hash`。用户在 ASK 思考期间改过内容时：锚点仍能唯一匹配，就照常预览并标注「已按当前内容对齐」；锚点失效，就把失效部分灰显，并提供「基于当前内容重新提议」。不做静默合并。
- 复合草稿（例如提纯后新开分支）中的每一步都是普通的界面操作，不包含任何付费请求。用户按一次 `Tab` 全部就位，光标停在输入框末尾，最后是否发送由用户决定。

**画师串禁区**

画师串是多画师权重非线性融合的结果，通常是用户反复测试、妥协得出的。通用模型没有这些画师在 NAI 潜空间中的真实先验，任何主张都可能是幻觉。

- **代码拦截。** 草稿中凡是修改 `artist_mix` 区段的操作，校验器一律丢弃，除非用户在本轮消息中明确点名要改哪个画师。
- **宪章约束。** 不评价画师风格，不建议增删画师或调整权重；把画师串视为既定前提。
- **允许做的事。** 调整主画师之外的画风 Tag、光影、构图和主体权重，用来与画师串的偏置抗衡。
- **弱归因。** 排除了所有普通原因之后，才可以在回复末尾用推测的口吻提一句「画师串中可能有特征偏置」，不作为主要结论，也不附带修改。
- **解禁条件。** 只有当站内具备离线整理好的画师实测知识库（通过词典扩展提供查询）时，才重新评估这一限制。

### 11. 系统提示词分层

```text
L0 宪章        身份、权限边界、子产品原则、画师串禁区、输出格式
L1 工作区包    IMAGE / CHAT 各一份：可用工具、常见问题、什么时候该看图
L2 模型知识包  NAI 4.5 / NAI V5 / OpenAI Images / Gemini 等：语法、混排写法、怪癖、上下文上限
L3 运行态      工作台摘要 + 个人偏好（<user_preferences>）
```

- 每一层单独存放，带版本号，在黄金样例上做回归测试。
- L2 一次性装载全部主力模型的知识包，不随生图模型切换而更换；载荷顺序与前缀缓存规则见文档 3 §1.2–1.3。
- 回复结论先行，默认不超过 5 句，并附带 ID。能直接给草稿的就给草稿，不说「你可以试试」。
- 工具返回的外部文本（图片元数据、导入的 Prompt）一律包在 `<data>` 中，宪章明确规定其中的文字不是指令。即使注入成功，最坏结果也只是一份用户可以拒绝的草稿，权限设计本身就是兜底。

### 12. 运行时与目录

**ASK 在浏览器中运行，不新增后端。**

历史、收藏、原图、Store 全部在客户端，Agent 循环放在浏览器里，是数据离得最近的位置。放到服务端反而要先把状态上传一遍。

```text
src/ask/
  AskDrawer.vue       外壳级抽屉：流式渲染、ID 锚点、Esc 层级、live region
  session.ts          会话（内存）、轮次、预算计数
  runner.ts           工具循环：async generator，最多 6 步，遇到草稿即停
  digest/
    index.ts          L0 组装
    anchor-rings.ts   模式 A
    decay.ts          模式 B + 冷区聚类
    segments.ts       Prompt 分区（复用高亮分词）
  tools.ts            工具注册；只接收 Store 的只读视图
  vision.ts           调用原生驱动做缩放、裁切、拼图与缓存
  draft/
    validate.ts       锚点定位、hash 校验、画师串拦截
    apply.ts          唯一的写入入口，走现有编辑路径
  provider.ts         对话推理调用（流式 + 工具 + 视觉），复用 Gateway Profile
  prompts/            L0–L2，带版本号
```

文档 4 §4 在此基础上补充了 `codec.ts`、`ids.ts`、两个协议适配器、设置分组与界面组件拆分。

**结构约束**

- `tools.ts` 拿到的只有只读 getter，从类型和结构上都接触不到写入接口。
- `draft/apply.ts` 是唯一能写入的模块，并且只在用户确认后由界面事件调用。
- ASK 不参与生成锁和串行调度。

**不嫁接 pi agent**

ASK 不需要文件、终端、长线规划等能力，嫁接通用框架后要剥离 Node 依赖、补齐严格类型、防止影响打包与脱敏，成本高于自己写。自研循环约 300–400 行，完全纳入现有的 `npm run check`，并可以用模拟网关测试。

### 13. Provider 与部署形态

**连接**

- 在 Gateway Profile 登记表中新增 `openai-chat` 与 `anthropic-messages` 两种协议，并声明对话推理能力（流式 + 工具调用 + 视觉输入）。用户在「设置 → 连接」中添加，Gemini 走其 OpenAI 兼容接口（文档 3 §1.1）。
- 在「设置 → ASK」（单独分组）中选择连接和模型，与生图用的模型分开配置。Key 沿用现有的加密存储方案。

**模型能力**

- 不维护模型名单，不按名称拦截。是否为纯文本或小参数量模型由用户自行界定。
- 设置中说明能力边界（需要流式、工具调用与图片输入），并建议使用原生多模态、工具调用稳定的模型，例如 Gemini、Claude、GPT 系列的视觉模型，以及 Qwen、DeepSeek 的视觉版。
- 模型能力不足时如实显示上游错误，不自动换模型或降级。
- 不做「视觉模型 + 文本模型」的两段管线。

**部署形态：两种方式同构，不阉割静态版**

| 形态 | ASK | 说明 |
| --- | --- | --- |
| 静态站（Cloudflare Pages） | 可用 | 浏览器直连，需要上游允许 CORS |
| 本地 `npm start` | 可用 | 循环仍在浏览器中运行；`server.mjs` 只负责无状态转发和环境变量 Key 注入 |

- 本地代理目前只支持标准网关。为 ASK 增加推理接口转发属于新增工作，排在 A4，并沿用 Host、Origin 校验和回环监听；在此之前本地模式显示「本地模式暂不支持 ASK」。
- 上游不支持 CORS 时，静态版显示明确提示，并引导用户改用本地模式，不做静默回退。

## 第四部分：关键决策

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 写入只限于草稿；v1 的目标是提示词、表单参数核对、CHAT 输入与分支准备 | 生成权限永不开放 |
| D2 | 一轮一份草稿，提交后暂停 | 防止 ASK 把多步修改串成用户看不清的链条，每一步都经过人 |
| D3 | 默认不发图，有硬预算 | 控制成本、延迟，保护隐私 |
| D4 | 历史索引采用锚点同心圆 + 时间衰减 + 冷区聚类 + 检索兜底 | 一次会话常有 40 张以上的图，固定窗口会让 ASK 失忆 |
| D5 | 画师串代码拦截并保持沉默 | 通用模型在这方面没有可靠先验，画师串又非常脆弱 |
| D6 | 抽屉覆盖图片栏 | 一个操作只有一个位置；三栏布局已经饱和 |
| D7 | 浏览器内运行，不新增后端，不嫁接外部框架 | 数据都在客户端；自研成本最低，可测试 |
| D8 | 静态版和本地版功能同构 | 沿用现有的双模连接策略 |
| D9 | v1 编辑器覆盖层内不提供 ASK | 编辑器是顶层全屏 dialog，与抽屉的层级和焦点管理有冲突，延后处理 |
| D10 | 不持久化 ASK 对话 | 建议依赖当时的画面，过期后没有价值；被采纳的修改已经写进 Prompt |
| D11 | 不自动生成灵感变体图 | 自动生成就是变相的 Harness，而且会花钱 |

## 第五部分：质量与里程碑

### 14. 验收标准

1. 用户确认前，提示词框和表单内容不发生变化（浏览器测试断言）。
2. 任意对话路径下，生图类请求数为零（模拟网关记录请求并断言）。
3. 单轮外发图片不超过预算（单元测试）。
4. 涉及 `artist_mix` 区段的草稿操作被拦截（单元测试）。
5. 内容变化后的旧草稿不会被直接应用（浏览器测试）。
6. 不出现原生弹窗；Esc 按层级关闭；回复完成后整段播报，不逐字播报。
7. 在四个基础视口下可用；窄屏时抽屉改为底部面板。

### 15. 测试

- **单元测试**：分区、相似度同心圆、衰减与聚类、锚点定位、hash 冲突、预算、注入文本的包裹、画师串拦截。
- **浏览器测试**：使用模拟 LLM，按脚本返回工具调用，确定性地验证完整流程。
- **黄金样例**：每个场景 5–10 个真实案例，附图和期望结论。每次修改提示词层都要回归，记录命中率。黄金样例的优先级等同代码。
