# Koma 产品总览

更新：2026-10-28。本文介绍当前产品定位、功能和整体框架；实现细节由[架构](architecture.md)、[设计语言](design-language.md)和各专题维护，完成范围与真实待验项见[当前状态](implementation-plan.md)。

## 产品定位与理念

**暗房里的创作台。** Koma 是以图片为中心的 AI 创作工作台，把提示词、生成、对比、局部编辑、创作讨论与多图交付放在同一个持续保留状态的环境里。

产品围绕五个原则组织：

1. **作品优先**：深色外壳压低存在感，主要空间留给图片与正在编辑的内容。
2. **连续创作**：工作区切换保留现场，独立画板保存不同方案，历史、收藏与实际生成参数便于比较和追溯。
3. **可审阅的 AI 协作**：ASK 和外部 Agent 的修改先成为草稿；用户核对差异后确认，生成和发送仍由用户发起。
4. **本地保存，按需共享**：创作数据保存在当前浏览器；协同目录是用户选择的共享出口。模型调用会向所选供应商发送该次请求所需的文字和图片。
5. **信息克制、状态诚实**：常驻界面只展示当前决定所需的信息；估算与实测分开、未知费用与免费分开、任务完成与目录交付分开。

HOME 已作为默认创作桌面，以现有画板、会话和收藏组织「继续／进行中／定稿」；支持标准行对齐、标准列对齐与拼图，直接返回车间和交付成果。头部与同一 ASK 共用输入和模型选择，默认右侧停靠、窄屏全屏；收起后用一行承接运行、结果与待确认草稿；不另建作品数据体系，详见 [HOME 工作区](koma-home.md)。

## 当前功能

| 区域 | 用户可以完成的工作 |
| --- | --- |
| HOME 首页 | 继续上次车间／本页 EDIT，查看有图的创作线与定稿；三种排列、收藏封面、大图送去绘图／对话／编辑与 Slate 交付；首次空白只展示创作入口 |
| IMAGE 绘图 | 编辑正负 Prompt、分辨率、采样和 Seed；串行批量生成；管理独立画板、多角色及定位；比较历史、收藏原图、导入图片参数 |
| CHAT 对话生图 | 通过文字和参考图生成或修改图片；选择实际发送的上下文；管理会话、分支和同轮多个版本；逐张收藏结果，源会话删除后收藏仍保留 |
| EDIT 编辑 | 独立工作区中的图生图、蒙版重绘、放大与六项 Director Tools；每张来源图有独立编辑画板与板内衍生版本；继承词文、预设、角色与参考。高级编辑按需打开 Photopea，支持图像／蒙版自动回传、同尺寸沿用蒙版与保活分层修图；纯修图可直接进入历史、收藏与任务交付，来源配方独立记录。生成操作取决于连接与模型能力 |
| TAGS 词典 | 搜索和组合标签；在支持的输入框中补全，Anime／Furry 使用对应词库 |
| Koma ASK | 感知画板和上下文，按需看图、对比参数、查询历史与标签，提议词文／角色／安全参数草稿；支持附件、多会话、收藏续聊、压缩与归档召回、向新 CHAT 会话准备交接内容 |
| Todo／Slate | 在 ASK 会话内查看紧凑待办，从顶栏图标打开轻量总览；由 ASK 通过草稿拆解和推进任务、保存共用配方、记录更改、绑定持久成果；也可手动交付与勾选 |
| 外部协同 Bridge | 挂载目录，向外部 Agent 提供 IMAGE 状态、轻量索引和预览；接收修改草稿，排队审阅、确认和回执；共享 `refs/` 资料及多图任务与成果 |
| 设置与数据 | 管理图像／文本连接、模型来源与图像供应商优先级；即时保存偏好，支持新版 Koma ZIP 备份及各专题独立导出 |

### 模型与供应商

图像接入包括 Koma 标准网关、OpenAI Images、Gemini 原生和 NovelAI 官方；ASK 使用 OpenAI Chat 兼容或 Anthropic Messages 推理协议。用户显式配置协议、地址、Key 和模型能力，不按服务名称猜测协议。

NAI 已接入 V4.5／V5 型号、多角色、Anime／Furry、适用型号的 Effort／Complexity／预设／透明底及独立 Guidance Rescale。V4.5 官方来源另有 Vibe 与 Precise Reference，和参数共用底部抽屉；V5 的两种参考当前不开放。官方五型号已接入图生图与普通 Enhance（复用图生图入口的倍率／强度预设，V5 另有 Max 倍率），V4.5 与 V5 Full High／Medium 已接普通与聚焦蒙版重绘，并提供独立 4× 放大，以及去背景、线稿、草图、上色、表情、去杂物六项 Director Tools；V5 Curated 无独立重绘接口，用户可明确选择其他型号。重绘中的图片参考仅开放 V4.5 Precise，聚焦重绘由用户手动画蒙版并框选周边范围，处理后回到原尺寸整图。各型号的限制、编辑工具缺口和真实消费待验项以 [NAI 专题](novelai-official.md)为准。

连接按图像和文本分区，综合供应商可在两区出现。图像来源按用户排序，在模型与操作匹配、没有明确额度不足时优先使用；余额未知仍按顺序选择，提交失败后不换源重试。文本保持用户手动选模。

## 产品框架

| 层次 | 组成与关系 |
| --- | --- |
| 创作工作区 | HOME／IMAGE／CHAT／EDIT／TAGS 共用唯一外壳，设置有统一入口，切换保留创作现场 |
| 创作助手 | 车间使用 ASK 浮窗，HOME 使用同一 ASK 停靠，EDIT 中隐藏；待办贴近当前对话，轻量总览负责查找与进入清单 |
| 共享审阅 | 内部推理与外部草稿复用 DraftCard；提示词、参数、任务、配方与文件可组合审阅，确认后按原数据路径写入 |
| 本地数据与协同 | Slate 独立保存任务和成果；Bridge 负责用户授权目录的状态、收件、资料与成果同步，目录同步是可选能力 |
| 模型接入 | Gateway Profile 声明协议和能力；应用服务统一管理连接、选源、任务、数据租约与资源生命周期 |

实现采用 Vue 3、严格 TypeScript、Vite 和浏览器原生能力；详细技术选型与源码责任见[核心技术与架构](architecture.md#核心技术)。

## 一次创作如何形成闭环

1. 在画板准备提示词、角色、模型和参数，显式生成并比较结果。
2. 向 ASK 提问，或由能访问协同目录的外部 Agent 读取状态与预览，提交可审阅的修改。
3. 在同一张草稿卡中核对词文、参数、Todo 和文件；点击应用或按 Tab 确认，随后由用户决定是否生成。
4. 多图项目将结果绑定到 Todo，保留原图和该图实际生成参数；需要共享时同步选定成果，并将配方或备忘录保存到 `refs/`。

需交图的 Todo 必须绑定图片才能完成。绑定后的成果独立持久保存，不依赖刷新后会失效的历史编号。未挂载目录时仍可推进任务、保存本地成果并下载；挂载后的本地任务进度和外部文件交付状态分别记录。

## 界面组织

整体保持冷调近黑灰阶、单一紫色强调、圆体与线性图标。层次通过表面明暗、字重和留白表达，主要动作与图片保持清晰；完整原则见[设计语言](design-language.md)。

新增协作能力沿用原有界面结构：Todo 位于输入框上方，每项只留状态、标题与成果图标；目录标签靠近附件入口，菜单紧贴触发器；任务／配方／文件在草稿中默认显示摘要，详情按需展开。更多菜单只保留压缩与调用调试，手动 JSON 兜底归现有「设置 → ASK → 外部协同」。

资料由模型根据 `refs/` 清单按需读取，手动附件走系统文件选择器或拖拽粘贴。配方、备忘录与任务资料通过草稿保存，界面不再提供独立的资料勾选、原始代码预览或导出格式弹窗。任务和文件的完成记录复用工具调用完成态，外部来源保留「来自外部」。

## 数据与运行边界

| 数据 | 保存与恢复 |
| --- | --- |
| 画板、图片收藏、CHAT 与偏好 | 当前站点的浏览器本地存储；普通 Koma ZIP 按备份范围导入导出 |
| 普通绘图历史、未收藏 ASK、撤销执行栈 | 仅当前页面；刷新后不保留 |
| EDIT 画板、版本、蒙版与 Photopea 分层 | 仅当前页面；跨工作区和画板切换保留，刷新清空；收藏／Slate 保存原图，长期分层由用户另存 PSD |
| 已收藏 ASK | 消息、附件、待确认草稿与压缩归档持久保存在独立 `koma-ask` 库，不进入普通 ZIP |
| HOME 展示副本与偏好 | 每画板一张缩小 WebP、封面指针、返回位置及行／列／拼图偏好；仅供展示，不进普通 ZIP、不恢复历史原图 |
| Slate 与已绑成果 | 独立 `koma-slate` 库，刷新、删除 ASK 会话或卸载目录不移除成果；不进入普通 ZIP，有独立资料与成果导出 |
| Bridge | 授权目录句柄、映射与回执独立保存；仅前台近实时同步，目录中的文件不会因卸载而删除 |

「本地」指当前站点在浏览器中的数据，Cloudflare Pages 等 HTTPS 静态站同样支持 Todo，不要求启动本地服务。不同域名和浏览器的数据相互独立；没有云账号同步。目录挂载取决于浏览器 File System Access API 支持，不支持时保留 JSON 导入／下载。

外部 Agent 可直接在线读取[公开 SKILL.md](https://koma-image.pages.dev/skills/koma-bridge/SKILL.md)，具体字段以挂载目录内 `PROTOCOL.md` 为准。公开说明不提供本机目录访问权限，也不暴露用户状态或密钥。

静态站可直接部署 `dist/`，另有可选的本地 Node 固定路径代理。Key 不进入普通备份，未配置连接时不请求上游。代码与模拟验收、真实供应商效果与扣费、线上部署是分别核验的状态；目前仍需逐项验证的能力见[当前待办](implementation-plan.md#仍待真实验证)。
