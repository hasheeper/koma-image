# 多角色与画板：基础接入实施计划

日期：2026-10-23。状态：C1–C5 基础代码已完成本地收口；C2 标准网关映射已依据实际接口探测补齐并通过本轮回归。真实生成与效果验证独立待办。画板入口采用用户确认的分段胶囊样式；活动画板全文、NAI 角色分工与按角色合并草稿预览三项开工修订均已落地。阶段状态与证据见 §8–9。

能力依据见[多角色勘探](novelai-multi-character.md)。本文是该专题的实施细化；ASK 实施规划 §2.7 采纳本文后，以这里的稳定角色 ID、画板归属、活动画板全文与其他画板按需读取规则替代早期下标靶点预留。其他工程边界继续遵守 `AGENTS.md` 与 [ASK 实施规划](ask/ask-implementation-plan.md)。

## 1. 交付范围

交付一条能实际使用的链路：**迁入已确认 UI → 编辑并保存独立画板和角色 → 报价／生成携带角色 → 参数导入与复用 → ASK 读取、提议、确认应用和回退。**

| 本期做 | 本期不做 |
| --- | --- |
| 角色方案 A：基础描述下的独立角色区；Prompt／Negative、启停、增删、排序、自动／手动定位 | 不同时维护角色方案 B，不把演示页方案切换器搬进正式产品 |
| 画板方案 A：顶部胶囊下拉；新建、复制、切换、改名、删除 | 不做标签条方案 B、画板文件夹、云同步、版本树或独立工作区路由 |
| NAI V4.5／V5 的结构化角色、既有生成路线与参数往返 | 不扩展 Vibe、角色参考图、动作关系编辑器、官方重绘／放大 |
| ASK 使用现有工具扩展字段，草稿支持角色动作与应用到新画板 | 不增加生图工具、自动生成、自动语义拆分或通用 Agent 框架 |
| 沿用本地偏好与新版备份、原全应用并发 1 | 不新建数据库、迁移系统、任务队列或新后端接口 |

“画板”是一份独立生成表单，不是绘图结果区的像素画布，也不是 IMAGE／CHAT／DICT 工作区。正式 IMAGE 当前只提供 NAI 模型；本期不顺便把 GPT／Gemini 的生成界面搬入 IMAGE。

## 2. 前端迁入基线

### 2.1 原型与样式来源

- 本地预览：`http://127.0.0.1:8792/#view=desk&zoom=form&plan=a&count=2&model=v5&pos=auto&stage=off&board=a`。
- 本机源文件：`.local/multi-char/preview/variants.js`、`variants.css` 及 `desk.html`／`tablet.html`／`phone.html`。其中 `plan=a` 选择角色布局，`board=a` 选择画板导航，两者不是同一个开关。
- 画板胶囊已实际咨询 Opus 5.5，并完成原型调整。原始建议在 `.local/multi-char/consult/board-capsule-opus-v1.md`；封版参照图为 `.local/multi-char/review/board-capsule-closed.jpg`、`board-capsule-open.jpg`、`board-capsule-phone.jpg` 和 `board-capsule-320.jpg`。
- 正式迁入使用 Vue 模板和现有控件；不引入冻结 HTML、演示数据、内联图片、插入 DOM 的脚本或演示页路由参数。参照文件继续留在忽略目录，不加入发布包。

### 2.2 画板胶囊

放在左侧表单顶部、基础 Prompt 上方，始终显示，即使只有一个画板。采用已确认的整行分段胶囊：`● 名称   1/3 ▾ │ ＋`。

- 胶囊占满可用栏宽。略亮于侧栏的 `--raised` 底、细边、顶部内高光与轻投影构成层次，不另加空白标题栏或说明卡。
- 左段包含色点、名称、数量与箭头，整段可展开菜单；右段 `＋` **新建空白画板**。2026-10-23 用户批准菜单精简后，由原先“复制当前画板”改为与加号一致的新建语义；复制保留在菜单底部。
- 默认高 40px，窄屏／触屏 44px；名称可截断，计数、箭头和加号保持固定宽度。字体、间距、光环和菜单尺寸沿用调整后的原型及站内 tokens。
- 菜单左边与胶囊对齐、相距 6px，宽度随最长一行，最窄 216px（底部两个按钮所需），最宽不超过胶囊；名称超出时才截断（2026-10-24 用户批准，原为与胶囊同宽，短名称时右侧空白过多）。展开时浅紫描边、切换段轻染色、箭头翻转，当前项有选中标记。列表可滚动；320px 优先显示名称，收起次要模型信息。
- 菜单列画板名称、模型、角色数；模型与角色数用小圆角文字标签紧跟名称，不加厂商图标，NAI 显示 V5／V4.5，其他模型显示目录名称。整行悬停；勾号与「⋯」共用行尾位置，悬停或聚焦时「⋯」替换勾号，触屏常显「⋯」，当前行改用浅底。底部一行等宽并列“新建空白”“复制当前”，都采用小图标在前、文字在后，内容居中。每个画板行末的「⋯」打开重命名／删除，不必先切换画板；只剩一个画板时禁用删除，删除仍先确认。改名在对应行内输入，不增加四行常驻管理动作。列表单独滚动，底部操作保持可见；子菜单使用嵌套原生 popover，Esc 先关闭子菜单，再关闭画板列表。
- 再次点击、点击外部、Esc 可关闭；焦点返回入口，键盘可选择菜单项。使用原生 popover 与已有菜单行为，不自建弹层系统。

不增加画板数量套餐或复杂限制；列表滚动足以容纳日常数量，保存仍受现有偏好与备份大小限制。

### 2.3 角色区与定位

角色方案 A 位于基础 Prompt／Negative 框之后、画幅和参数之前。零角色时仅显示简洁区头和添加入口，不占据一块空白编辑区。

- 列表折叠行显示编号、Prompt 摘要和停用／超出状态；一次展开一个角色。展开后使用原型的 Prompt／Negative 页签、字数、启停、上移／下移与删除。编号是当前显示顺序，内部身份不随排序变化。
- 输入复用 `HighlightInput.vue`、Tag 补全与现有偏好，保留原生输入、IME 和焦点语义。基础描述与角色文本互不覆盖。
- 区头保留“自动／手动”；手动时展示与当前表单宽高比一致的小定位板。V4.5 显示 5×5，V5 显示自由坐标。角色点编号与列表对应，停用角色不参与定位和请求。
- 保留原型“在画面上调整／完成”的放大定位入口，使用同一套位置数据和定位组件。覆盖层按**下一次生成的表单比例**显示；旧图比例不同时按实际适配框对齐，不拿整张历史图边界冒充新图边界。移动点只改位置，不改图片或蒙版。
- 拖动过程由原生指针驱动更新位置样式，结束后一次提交并保存；方向键移动，V4.5 一次一格，V5 使用固定小步长。隐藏工作区、关闭定位层、切换画板时结束交互并清理监听。
- 用户主动删除角色即时生效；不增加一套手工角色撤销栈。ASK 应用仍进入现有检查点与撤销栈。

正式界面不搬入原型的 V3 测试型号、固定历史角点、模拟 ASK 标记或“按 `|` 拆分”演示动作。文本拆角色由 ASK 提议草稿，前端不猜语义。

## 3. 数据与本地服务

### 3.1 最小领域结构

以下为目标结构，字段最终由 TS 实现直接导出，不另写配对声明：

```ts
type Character = {
  id: string;                 // c1、c2…；在所属画板内稳定且不复用
  on: boolean;
  prompt: string;
  negative: string;
  centers: { x: number; y: number }[];
};
type BoardForm = {
  // 当前 DrawingForm 中的生成字段：Prompt／Negative、模型、画幅、
  // sampler、steps、scale、cfg、seed、batchCount、optimize、
  // serverCache、transparentBg
  characters: Character[];
  placement: "auto" | "manual";
};
type DrawingBoard = {
  id: string;                 // 本地生成的稳定 ID；不使用列表下标
  name: string;
  color: string;              // 固定站内色板，供胶囊与来源圆点显示
  nextCharacterId: number;
  form: BoardForm;
};
type Boards = { activeId: string; items: DrawingBoard[] };
```

上面的 `BoardForm` 省略的是已有字段声明，不是另造一份不完整表单。所有生成参数归画板；`localCache`、`historyLimit`、`tagSuggest` 与分栏／输入框尺寸等仍为应用通用偏好，不随画板切换。

- 角色数组顺序就是请求顺序。`c2` 移到第一行后，显示“角色 1”，其靶点仍是 `image.char.c2.prompt`。
- 角色编号由本地分配，删除后不复用；计数随画板保存。复制画板保留内部角色 ID，但新画板有独立 board ID，二者共同确定目标。检查点回退可以恢复原角色身份。
- 坐标在本地保存原精度；导入的完整中心数组继续保留并在参数预览可见，本期定位板显示第一个中心。用户主动重新选点或应用 ASK 的 set_position 时，将该角色替换为所选单中心；不建设多中心专用编辑器。
- `placement=auto` 时忽略位置参与定位，保留已有中心便于切回手动；首次手动时为尚无中心的角色提供默认点。自动定位不等同于把所有角色设为画面中心。

### 3.2 复用绘图服务

`services/drawing.ts` 继续持有画板、活动表单、历史、收藏与任务。`snapshot().form` 暂保留现有活动表单视图，避免为画板重写全部消费者；新增画板列表、activeId 与角色能力快照。

只增加业务需要的本地方法：切换、新建／复制、改名、删除，以及按 ID 修改角色；方法名由实现定稿。`patch` 按字段归属写活动画板或通用偏好，`writeDraft` 显式接收目标 board ID 和预期内容。角色与画板不单独建立 Store、事件总线或 CRUD 后端。

- 新建空白：Prompt／Negative 为空、角色为空、随机 Seed，其余生成参数使用现有默认值。复制：深复制整份表单，包括固定 Seed，名称追加“副本”，切到副本。
- 保留至少一个画板；最后一个不提供删除。删除其他画板使用现有确认面板；删当前后切到相邻项。历史与收藏不随画板删除。
- 切换只变活动表单、清理编辑焦点并刷新对应报价；不切工作区、不清历史、不新开 ASK 对话。菜单关闭后不把旧输入的迟到回调写到新画板，角色编辑回调同时带 board ID／character ID。

### 3.3 保存与新版备份

沿用 `koma.prefs.v1`，增加 `boards: { activeId, items }`；通用／布局偏好保持原键。`snapshot().form` 是活动画板的视图，新保存不再双写一份独立活动生成表单。

当前 Koma 偏好缺少 `boards` 时，普通读取将现有单份生成字段视为“画板 1”，缺少角色时读作 `[]`、自动定位；下一次正常保存写入新结构。不扫描旧应用、不建迁移标记、转换器或迁移 UI。

所有保存继续经 `preferences.set`／`data.write`。有延迟保存才补既有 `flush`／`reload`；备份导入、跨标签偏好更新后重读整份画板数据，避免旧缓存覆盖。保存失败保留当前编辑并反馈；ASK 确认写入失败沿用原回退与不入栈语义。

新版 Koma v2 备份继续使用现有逻辑字段 `preferences.drawing`，其 JSON 中包含画板列表，无需另加同内容的顶层 `boards` 或升级整个 ZIP 格式。补齐结构、ID 唯一性和坐标有效性的必要校验；ASK 会话、普通历史与 Key 的备份边界不变。

## 4. 生成、能力与参数往返

### 4.1 模型能力与切换

在现有规范模型／目录结构补一份轻量角色能力描述：`maxCharacters` 与 `positioning: "grid5" | "free" | "none"`，由规范模型及已核对的协议映射得出。官方 V4.5 Full／Curated 为 6 与 grid5，V5 Full／Curated 为 22 与 free；不据渠道名称、域名或 ASK 推理模型 ID 猜测。

- 标准网关不能仅靠官方产品说明宣布全部能力，接线前按 §4.2 核对其角色字段、限制与路线。未知能力如实保留未验证状态，不伪造一次成功探测。
- 超过当前支持型号的启用数量时保留全部角色，显示原型的超出提示并禁止提交，不静默只发前 N 个。用户可停用、删除或换回模型；新增入口按当前上限限制。
- 不支持结构化角色的型号保留角色区并显示“当前模型不支持角色，生成时不发送”；实际只使用基础描述，不自动拼接角色文本。原型的这一状态保留，但不为演示而添加新型号。
- V5 → V4.5 仅把有效提交坐标投影到格中心，不覆盖本地原始坐标；用户主动在网格移动时才更改该角色位置。A–E 从左到右、1–5 从上到下，格中心为 `(列序号 + 0.5) / 5`、`(行序号 + 0.5) / 5`。切回 V5 可恢复未编辑坐标。

### 4.2 补接口的实际范围

不新增 HTTP 路径。扩展现有领域请求、适配器和本地服务端口：

| 接点 | 要补的内容 | 保持的边界 |
| --- | --- | --- |
| `domain/drawing.ts` 的 `collect`／`DrawingParams`／`drawingPayload` | 深复制角色与定位；分离本地完整角色组和本次实际启用角色；角色变更使报价失效 | 零角色时维持当前请求行为；不重写用户 Prompt |
| `gateway/routes.ts` 的 `toNativePayload` | 构造 `v4_prompt.caption.char_captions` 与 `v4_negative_prompt.caption.char_captions`，同步位置、`use_coords`、`use_order` | V5 仍用 `v4_` 字段；正负数组相同角色顺序，空 Negative 仍有对应项 |
| `gateway/client.ts` 与标准网关映射 | 报价／重报／Studio／工具转为 `characters: [{ prompt, uc, center }]` 与顶层 `use_coords`；免费原生继续从同一领域快照构造正负数组 | 本地 ID／启停／placement 不发上游；V4.5 先投影，V5 保留坐标；映射依据为真实元数据解析与报价探测，生成效果仍待实测 |
| `gateway/native-protocols.ts` | 官方基础生图复用上述 NAI 转换；已开放 img2img 接收显式来源角色 | 官方继续无 `max_cost`、无虚拟报价；不新增重绘／放大能力 |
| `server.mjs` | 原固定路径正常透传新增 JSON 字段，按现有模式补模拟验证即可 | 不新增上游、路径、凭据注入或任意代理能力 |

标准网关接线的最小前置结果是一份脱敏字段示例及路线映射，记录到勘探文档；无需建设能力探测平台。只有某一路线无法表达角色时，保留该路线边界并给出具体错误，不自动换路线或悄悄丢字段。未确认的高级角色请求不可用自写 mock 宣布真实接入成功。

已观察的标准格式只有单个 `center`。导入的多中心原文仍保存在本地，官方 NAI 保留数组；标准网关手动定位遇到多个中心时明确提示重新定位，用户在现有定位板选点后改为单中心。自动模式关闭 use_coords，不使用这些中心。没有新增高级定位界面。

### 4.3 提交快照与画板归属

当前代码在额度预检结束后才捕获最终提交参数。保留这一时序，但点击生成时先锁定**来源 board ID**：预检后读取该画板的最新值，不能因切换到画板 B 就改为提交 B。源画板预检期间被删除则取消本次提交。

最终快照捕获后，报价重报、整批、返回记录均使用同一份角色、定位、模型和参数；后续编辑与切板不改变在途请求。任务快照另记 `boardId`、当时名称和颜色，这些本地归属字段不发上游。

- 全应用并发仍为 1；切换画板可以继续编辑，生成／停止按钮反映真实共享任务。不新增每板任务锁或独立队列。
- 当前预报价属于当前活动画板，切换时作废旧预览，迟到响应不得写入新画板；生成中的费用信息属于原任务。ASK 写入继续暂停网络报价，用户后续操作才按既有规则报价／生成。
- 普通历史仍共用，`#hN` 全页递增；缩略图的来源点来自记录，不能像原型一样按 ID 硬编码。删除／改名画板不改既有图片当时的归属信息。
- 保留“浏览旧图不被新结果抢走”的行为。切板不自动选图；若切板时正在跟随在途结果，转为浏览状态，结果仍入历史并保留来源，不把用户拉回原画板。

### 4.4 导入、收藏、复用与编辑

| 路径 | 基础规则 |
| --- | --- |
| 图片元数据解析 | `native/image-meta.ts` 从只读 extras 补为结构化角色，保留原顺序、正负对应、定位方式和原始中心。格式不明的部分继续只读显示，不猜字段 |
| 导入核对表 | 增加“角色”整组选择，展示 Prompt／Negative、顺序与位置。来源明确有空角色组时可清空；字段缺失表示未知，不能当作清空 |
| 复用参数／ASK `restore_partial` | 复用同一角色恢复函数；选中角色时恢复整组及定位方式。外来角色在目标画板分配新本地 ID，不复用删除过的编号；其他未选字段不变 |
| 历史／收藏／批量对比 | 参数记录保留本次生成的有效角色；本地完整快照可另保留停用项供表单恢复，明确区分“已发送”与“仅本地”。对比合成图沿用源参数记录，不造一份混合角色表单 |
| 收藏备份 | 保存角色 JSON 与归属，原图字节和现有合并／去重规则不变；角色不能只存在于预览组件中 |
| 编辑交接 | IMAGE 来源的既有 img2img 接收显式来源快照，不偷读后来切换的画板。支持的 NAI 路线透传角色；不支持的操作明确显示边界。原生图片含可解析角色时同样读取 |
| CHAT 与其他模型 | 不新增结构化角色编辑协议，不把角色数组暗中写入 CHAT；用户需要自然语言合并时由 ASK 出文本草稿 |

历史图片不强行保存整份画板列表；下载仍保留原字节，不为保存本地 board ID 而重编码图片。

## 5. ASK 的读取与状态感知

### 5.1 活动画板直接提供完整词文

每轮初始 `<workspace_state>` 必须直接提供当前活动画板的基础 Prompt／Negative、每角色 id／on／Prompt／Negative／position，以及参数和能力。其他画板只给目录，历史图片没有显式锚点时不预载词文：

```json
{
  "active_board_id": "<本地稳定ID>",
  "boards": [{ "id": "<本地稳定ID>", "name": "雨中二人", "model": "nai-diffusion-5-full", "characters_count": 2 }],
  "character_capability": { "max": 22, "positioning": "free" },
  "prompt": "2girls, …",
  "negative": "lowres",
  "placement": "auto",
  "characters": [{ "id": "c1", "on": true, "prompt": "girl, white hair", "negative": "", "position": "auto" }]
}
```

此例只示新增字段语义，实际放在现有 `image` 摘要下，不另建一份状态文档。手动定位时提供格子标签或坐标；有效模型能力与协议未核验项分别表达，不把“未实测”写成“不支持”。

活动画板全文不受图片锚点影响，模型第一轮即可改词、出草稿，不必先调 get_state。仅非活动画板词文和无显式锚点的历史图片词文／Diff 省略；后者仍只留 count／latest_id。新建画板不自动绑旧图。

### 5.2 扩展现有工具

| 工具 | 接入行为 |
| --- | --- |
| `get_state({ scope?, board_id? })` | 默认 initial 为本轮活动画板完整表单；显式 board_id 可读本轮其他画板用于对比，含每角色 id／on／Prompt／Negative／中心／定位。latest 才读最新状态，追加在队尾，不改变草稿基底 |
| `get_meta(id)` | 输出结构化角色、有效定位及真实图片参数；本地停用项如存在另列，不能冒充模型输入；无元数据时标缺失 |
| `diff_meta(a,b)` | 分开列基础词、角色增删／顺序／词文／位置差异。相同来源画板且保留稳定 ID 时按 ID 对齐；外来元数据只按列表顺序对照，并说明不能确认是同一角色 |
| `search_history` | 关键词覆盖角色 Prompt／Negative；`changed_field` 增加 characters，返回紧凑命中字段与片段；共享历史的前序变化按同来源画板比较，避免轮流切板产生假变化。没有画板归属的旧记录沿用原规则 |
| `view_image`／`view_sheet` | 能力不变，仍用于多图预览、筛选与对比；位置数据不能代替看图，也不新增“画板截图”工具 |
| `get_model_manual` | 功能落地后补对应说明与排错表，不加新联网来源 |

图片相似检索和锚点同心圆也使用基础正向词＋有效角色正向词构成的确定性文本，防止角色完全不同但基础场景相同被判定为“Prompt 相同”。这只用于比较，不拼接成新提示词，也不预载更多原文。

一轮冻结的画板与角色是普通 JSON 深快照；latest 可看到新板，原轮草稿仍只针对发送时的活动画板。读取其他板不授予写入其他板的权限。不新增 `list_boards`／`switch_board` 工具。

## 6. ASK 草稿、冲突与回退

### 6.1 三类既有／扩展步骤

仍使用一个 `propose_draft`，一轮一份草稿；保持 `draft_title`、`base_hash` 和最多 12 步等现有边界。

**文本修改**：`prompt_patch` 新靶点为 `image.char.c2.prompt`、`image.char.c2.negative`，原局部替换与 rewrite 规则不变。数值下标靶点不再解释为列表位置；目标删除或 ID 不在源画板中则该步失效。

**角色动作**：新增 `character_edit` 步骤，只提供以下实际表单动作：

| op | 输入与效果 |
| --- | --- |
| add | 携带完整 Prompt／Negative、启停和可选位置；新 ID 由本地分配，模型不用预留编号或先新增再 patch |
| remove | 按现有角色 ID 删除 |
| reorder | 提供现有角色 ID 的完整排列，不增删角色 |
| set_enabled | 按 ID 设 on，保留词文与位置 |
| set_position | 按 ID 提供 V4.5 的 cell（A1–E5）或 V5 的 x/y（0–1），替换为单中心；不自动切换定位模式，要启用位置须同时 set_placement 为 manual |
| set_placement | 设为 auto／manual，对应角色区已有定位开关 |

add 自带完整内容，不提供同份草稿中引用尚未创建角色的临时别名。需要新增很多角色时保持 12 步预算，超过就分轮提议，不扩大工具循环。

**历史恢复**：`restore_partial.fields` 加 `characters`，从本轮图片快照取角色整组和定位，不接收模型捏造的恢复值。来源没有此字段时该步骤不可用。

角色动作可与基础 Prompt rewrite 组成同一份草稿，例如“把多人提示词拆成角色”：改基础描述＋添加若干完整角色。前端不提供另一套竖线拆分算法；显式结构化角色与原竖线文本的整理由草稿完整展示后确认。

### 6.2 原子写入与可见预览

- IMAGE 草稿在本地绑定源 board ID，不让模型通过任意 board ID 改写其他画板。用户切板后按钮显示“切回〈画板名〉并应用”；来源删除则作废，不回退成当前板。
- 所有角色步骤按顺序在临时副本上计算；统一检查目标、数量、坐标和互相依赖，再一次写入结果。不逐步保存半份角色组，也不引入事务框架。
- 草稿卡按角色紧凑分组：同一角色的 Prompt／Negative、启停和位置共用一个角色标题，在组内合并展示词文 diff 和状态变化，不拆成多个碎步骤块；新增、删除和全组排序独立表达。编号旁可查看稳定 ID。新增词、删词与参数沿用 B v5 预览。存在依赖的部分按现有锁定步骤处理，不能撤回父步骤却保留无目标的子步骤。
- 角色数组／定位按一个结构化字段组保存前后值，`Change` 类型补足数组值的表达即可；不建设通用 JSON Patch 引擎。
- `base_hash` 扩为源 board ID＋完整生成表单＋CHAT composer 的固定序列化，覆盖角色、定位和模型参数，不含名称／颜色／滚动偏好。hash 变化后，普通文本仍可按现有唯一锚点重新对齐；角色结构动作需要匹配其预期角色组，冲突就失效，不做语义合并。
- `writeDraft`、冲突比较、预检模拟、检查点与 50 条撤销栈全部带 board ID；嵌套值用结构比较，不能沿用浅对象引用相等。手工重排后，针对仍存在 `c2` 的独立文本 patch 可以按原规则对齐，不能改成写当前第二行。
- 回退／恢复核对该画板实际已写内容；外部变化或画板删除时反馈具体原因。ASK 编辑重答的批量回退预检也用同一多画板快照，不能只修单次回退而漏掉 W4。

### 6.3 应用到新画板

普通 IMAGE 草稿使用「应用＋箭头」分体按钮，菜单可明确选择来源画板或新画板；忽略为无底色轻按钮，移除原先孤立的“应用到新画板”链接行。`propose_draft` 新增可选 `new_board_name`（非空，最多 80 字）：模型填写后，目标锁定为此具名新板，卡片标题下显示“新画板 · 名称”，仅提供“新建并应用”单按钮，不显示箭头或来源板选项；执行层也不允许通过旧参数改写成来源板。`draft_title` 继续概括改动，两者分开。省略名称时默认应用到源板，手动选新板仍使用既有的“〈源板〉副本”命名。普通草稿的菜单直接执行所选方式。来源板始终是本轮基底，切板不会把草稿写到无关板。

名称由本次 ASK 回复提供，不额外请求命名模型；提议阶段只保留名称与目标意图，不分配画板 ID、不保存。仅 IMAGE 允许这个字段，目标名称参与确认用 fingerprint。用户点击主按钮、菜单或已有 Tab 快捷键确认后，才执行下面的流程：

1. 先按源画板当前内容完成现有冲突核对，得到用户勾选部分的最终表单。
2. 深复制源画板，分配新 board ID，使用提议名称或既有副本名称，再写入草稿结果并切到新板；源画板不改。角色编号计数同时覆盖本次新增或恢复的 ID。创建与写入用一次现有偏好保存完成，保存失败不留下空副本。
3. 留一个检查点。回退时，仅当新板仍与写入结果一致才删除它并回到源板；新板被用户继续编辑或源板已删除时明确失败，不删除后续成果。恢复时恢复同一份结果、名称和身份。

应用、回退、恢复均不发报价／额度／生成／CHAT 请求，继续使用 ASK 现有暂停报价路径。手动切板的普通报价与 ASK 确认写入引起的导航需区分。

本次本地验收：`npm run check` 通过（196 项单元测试）；28 项相关浏览器回归通过。双推理协议模拟覆盖具名新板的目标锁定、跨工作区／收起状态／Tab 应用、保存失败回滚、检查点撤销与恢复，以及普通草稿菜单在 320／390／768／1440px 的定位与键盘操作；未执行真实上游生成。
