# Koma 设计语言与产品语言

日期：2026-10-24。状态：根据现有实现与已批准的决定整理，作为后续前端微调、统一质感的共同基准。

本文描述现状和判断标准，不新增任何批准。以下内容仍按原约定执行：
- 复刻约束、已批准调整与 ASK 规格分别见 `AGENTS.md`、`docs/architecture.md`、`docs/ask/ask-ui-spec.md`。
- 变量、字体和样式归属以 `public/styles/tokens.css`、`config/fonts.json`、`docs/style-ownership.md` 为准。
- 本文与上述文件冲突时，以上述文件为准，并回头修正本文。

## 1. 一句话

**暗房里的创作台。** 外壳安静、偏冷、低对比，生成的图片是屏幕上唯一明亮的东西，像一张放在深色衬纸上的照片。圆体和圆润的 Fredoka 字标让这套专业工具显得亲和，不冷硬。

关键词：安静、一级之差、单一紫色、图片优先、诚实、克制的触感。

## 2. 参照系：像什么软件

参照只用来对齐质感，不照搬界面。复刻范围内的布局、尺寸和行为以参考工程为准。

| 区域 | 最接近的参照 | 借鉴的部分 | 不借鉴的部分 |
| --- | --- | --- | --- |
| 整体外壳 | Linear、Raycast 的深色主题 | 近黑偏冷的灰阶；表面之间只差一级；单一紫色强调；细线分隔；图标按钮配提示 | 霓虹渐变、大面积品牌色、营销式插画 |
| IMAGE 工作区 | NovelAI 的出图界面；Lightroom 的中性暗背景 | 左侧参数栏、中间舞台、右侧历史缩略图；背景压暗来衬托作品；画框只做轻微浮起 | 多层面板嵌套、对比强烈的分区 |
| CHAT 工作区 | ChatGPT、Claude 的网页版 | 空白时输入框居中；左侧会话列表；用户消息靠右、带气泡，回复不带气泡 | 头像、角色名、彩色身份标识 |
| ASK | iOS 灵动岛、Raycast 浮窗、Cursor 类 AI IDE 面板 | 同一个容器在多种形态间变形；毛玻璃浮层；上下文占用环、检查点、压缩记忆行 | 常驻侧栏、强制占用布局、自动执行写入 |
| 设置 | macOS 系统设置、Linear 设置页 | 左侧导航；居中的分组列表；每行左边是文字，右边是控件；改动即时保存 | 每节都有大标题和说明段落、多余的「保存」按钮 |
| 品牌 | 日式漫画工具的亲和感（Koma ＝ コマ，漫画分格） | Fredoka 字标；8 个方块组成的标识；资源圆体 | 卡通吉祥物、手绘装饰 |

## 3. 产品语言

1. **作品优先。** 外壳为图片让路，任何新元素都不能比图片更抢眼。紫色只用在选中、焦点、主操作、品牌和图片引用上。
2. **工作台，不是网站。** 唯一外壳；三个工作区原地切换并保持状态。编辑以覆盖层打开，设置以弹窗打开。没有页面跳转感，也没有落地页式的内容。
3. **用户掌握决定。**
   - ASK 只读：所有修改先成为草稿，由用户确认后才写入，并且可以回退。
   - 不自动重试、不自动生成，也不替用户发送消息。
   - 浮层可以拖开，但不占用工作区的布局。
4. **诚实。**
   - 没有报价时保留未知费用状态，生成按钮暂不显示费用标签；不当作免费。
   - 失败就是失败，并说明原因。
   - 估算值要标成「估算」。
   - 动效节拍只补足最短停留时间，不靠拖延制造「在思考」的假象。
5. **少即是清楚。** 只保留基本信息和操作反馈。不重复标题，不写大段说明、建议或教程。说明文字只在影响决定时出现，例如 Key 会发送到哪里。
6. **中立。**
   - 连接用中性的 Gateway Profile，不出现私有渠道的品牌。
   - 模型图标只表示合法的模型供应商。
   - ASK 对技术和态度都保持中立。

## 4. 视觉语言

### 4.1 表面与层级

层级靠「一级之差」区分，不靠强对比。相邻表面的感知亮度差约 2.5 ΔL*，比 VS Code 和 Linear 更安静，接近 NovelAI。

| 变量 | 用途 |
| --- | --- |
| `--canvas` #131315 | 舞台与视口，即照片下面的衬纸 |
| `--sunken` / `--well` | 输入框、凹槽、缩略图。凹陷是一种相对关系：在 `--raised` 容器里要重新指向更深一级的值 |
| `--chrome` #18181c | 顶栏、输入区、图片栏 |
| `--raised` #1e1e24 | 卡片、抽屉、浮层、提示 |
| `--hover` #24242c | 悬停反馈 |
| `--line` / `--line-2` | 普通分隔线 / 强调分隔线与焦点凹槽 |

判断标准：
- 一个区域如果需要靠边框、底色和标题同时区分，说明层级做多了，先减一层。
- 灰底上再套灰框是用户明确不喜欢的写法。
- 需要键入的数字和文字放在比所在行低一级的凹槽里，默认就是深色；从列表里选的值与行齐平，悬停才出现表面。独立成块的输入框自己就是一层，外面不再套卡片。

### 4.2 颜色

- **文字分四级**：`--fg` 主文字；`--fg-2` 次要文字；`--fg-3` 标签与提示（在 raised 上满足 AA）；`--fg-4` 只用于装饰或大字。小字不要低于 `--fg-3`。
- **强调色只有一个**：`--a` #b3a1ff。配套的有 `--a-dim`（选中底色）、`--a-line`（选中描边）、`--a-glow`、`--a-ink`（紫底上的深色文字）。
- **语义色**：`--ok` 绿、`--warn` 琥珀、`--err` 红，只表达状态。草稿差异用很淡的红、绿行底色，文字保持中性。
- **背景偏冷**：灰阶整体偏蓝（越亮越偏），让暖色作品更跳出来。新加颜色时先选现有变量，不写新的十六进制值。

### 4.3 字体

| 角色 | 字体 | 用途 |
| --- | --- | --- |
| `--sans` | Koma Rounded（资源圆体，字重 400／500／700） | 全部界面文字，中英文统一 |
| `--mono` | JetBrains Mono | 数字、ID、Seed、尺寸、快捷键、计数，配合表格数字 |
| `--brand` | Fredoka | 只用于「Koma」字标 |

- **字号阶梯**：11／12／13／15／18／22／28px。正文、输入框和按钮是 13px；Prompt 和主操作是 15px；分节标题 18px；弹窗标题 22px。中文笔画重，所以小字号保持 11／12／13 紧凑。
- **层次来源**：靠字号、字重（regular 正文、medium 标签、semibold 强调）和文字亮度。不要用加框或加底色来表示层次。
- **已批准的例外**：ASK B v5 保留小数字号，消息 13px/1.72，输入 13.5px，预览 12.5px。

### 4.4 尺寸、间距与圆角

- **间距**：4px 网格，即 `--sp-1`…`--sp-7` 对应 4／8／12／16／24／32／48。
- **圆角**：`--r1` 5（小件与标签）、`--r2` 7（按钮、输入框、分段控件）、`--r3` 10（主按钮、卡片）、`--r4` 15。另外，浮动玻璃容器 20、展开窗口 18、气泡 14、胶囊 999。同类元素的圆角必须一致。
- **固定尺寸**：顶栏 60px、列头 48px、左侧参数栏 316px、历史栏 132px、Tag 组合栏 300px。
- **按钮尺寸**：图标按钮 32px，小号 28px；结果栏与图片栏底栏 36px。

### 4.5 图标

- 站内 sprite（`public/assets/icons.svg`），24 格线性图标，圆端圆角。主体字形几何尺寸占 24 格的 70%–75%；箭头、关闭、勾选、加减、更多等次级字形最大边 13.5–16 格；超出范围的字形在 sprite 内用 `<g transform>` 缩放并居中，左右箭头不移位。品牌和厂商标识、键帽字形、停止方块按原样。
- 描边是非缩放描边，渲染线宽与图标尺寸无关：统一 `--ico-stroke` 1.3px；实色按钮上的字形（发送）和展示图标（`.ico-lg`／`.ico-xl`）用 `--ico-stroke-strong` 1.6px。
- 尺寸只取四档，组件通过 `--ico` 引用档位变量，不写像素值：`--ico-xs` 11（键帽、角标）、`--ico-sm` 14（菜单、标签、行内提示、消息工具、小按钮）、`--ico-md` 16（默认，含 28／32px 图标按钮、列表行、区头）、`--ico-lg` 18（主工具栏：结果栏、图片栏页签与底栏、Prompt 工具栏、顶栏）。空状态和拖放的展示图标 26／34px 不入档。
- 按钮容器分裸图标（默认）、凹槽（Prompt 工具栏）和强调（下载，见 §9）三种。同一排按钮同尺寸。
- 开关型图标按钮（收藏、对比）选中时只改字形：紫色，有实心形的填实，不加底和框。编辑器的当前工具保留紫底，表示正在使用的工具。
- 图标按钮闲置默认 `--fg-3`，主工具栏 `--fg-2`；悬停 `--fg`；选中 `--a`。同一水平线上的相邻工具栏同档、同色、共用中线，比如结果栏和图片栏底栏。
- 实心图标只用于区头标签和少数状态，比如收藏选中、停止。
- 图标按钮的含义靠悬停提示（`data-tip`）和读屏标签表达，不在旁边加可见文字。
- 模型图标来自 LobeHub，用于模型选择、模型列表与额度标签；官方 Profile 或已识别官方地址的连接也可使用对应 Logo。其他连接以对话／图片图标区分文本与生图，不把兼容协议视为官方身份；地址识别仅影响图标。
- 供应商连接分为图像、文本两区；分组标题不另加面板。图像卡底行沿用设置页的左侧信息、右侧操作布局；模型入口、辅助计数与排序通过字重、明暗和留白区分，不新增控件外框。文本卡不提供排序。综合供应商按已配置能力出现在两区。

### 4.6 阴影与材质

- **阴影**：分 `--sh-1`…`--sh-4` 四档，层级越高扩散越负，边缘越紧。浮起的表面带 `--sh-lip`，即顶部 1px 内高光，表示光从上方来。
- **画框**：图片用 `--print-shadow`，一圈 1px 浅描边加柔和的投影，像照片轻轻离开衬纸。
- **全页唯一的实体按钮**：只有「生成」按钮会花费额度，所以只有它有完整的立体处理，包括竖向渐变、顶部高光、深色描边和紫色光晕，运行时它本身变成进度条。其他按钮都保持扁平。
- **毛玻璃**：只用于浮在工作区上方的 ASK 容器，材质是 `rgba(22,22,25,.88)`，加 20px 磨砂和 1.4 倍饱和度。菜单和预览用接近实色的磨砂，保证文字可读。普通面板不使用玻璃。

### 4.7 动效

- **时长**：三档，`--t1` 120ms 用于反馈和颜色，`--t2` 220ms 用于切换，`--t3` 380ms 用于入场。
- **缓动**：主曲线 `--e`，弹出用 `--e-out`。
- **入场**：透明度先变化，再跟一段 4px 位移。按下反馈：图标按钮缩到 .94，普通按钮缩到 .978，「生成」按钮下沉 1px，光晕收紧。
- **运行态**：短时等待用小号转圈，例如连接提示条、补全请求和「生成」按钮内部（均为参考工程原有）。ASK 的运行态用低对比的慢速微光，或者由内向外的呼吸。占用环、进度条这类图形只表示数量。
- **循环扫光**：无限循环一律匀速 `linear`，每轮恰好移动一个背景宽度，间歇放在文字外的暗底里走完。缓动循环会冲—停顿挫，宽光带留在字上也会让停顿露出来。文字换了就重建元素、从头扫，不让光带因宽度变化半路跳位。
- **减少动态**：所有组件都要处理 `prefers-reduced-motion`，关闭位移、扫光和呼吸，只保留透明度变化。

## 5. 布局语言

- **桌面端**：顶栏下面，IMAGE 分三栏（参数｜舞台｜历史）；CHAT 是两栏（会话｜对话），可展开上下文栏；TAGS 是两栏（搜索｜组合）。设置是左侧导航加居中的分组列表。
- **主断点 860px**：窄屏改成单列，固定动作放在底部，例如 IMAGE 的「生成」和 CHAT 的输入框。设置导航变成顶部横向标签。
- **其他断点**：只有局部组件额外使用 600／480／360px 等细分断点。
- **验收宽度**：320／390／768／1440px，不能出现横向溢出。
- **浮层**：ASK 是全局浮层，不预留侧栏，默认位置要避开关键控件，用户可以拖开。编辑覆盖层打开时隐藏 ASK。

## 6. 交互语言

- **即时生效**：设置改动立即保存，并同步到其他已打开的页面，不需要「保存」按钮。
- **删除前确认**：在原位二次确认，比如 × 变成红色「删除」，或在确认面板里操作。危险按钮永远不是默认焦点。可以撤销的操作用提示条里的「撤销」，不弹确认框。
- **不增加付费确认**：涨价时提示后继续，按原有规则处理。
- **显露与常显**：桌面端操作在悬停或聚焦时显露；触屏和最后一项常显。按钮之间要留出真实间距，不能和正文挤在一起。
- **键盘**：⌘↵ 生成，⌘J／Ctrl+J 打开或收起 ASK，Esc 按层级由内到外逐层关闭。输入法组合输入时不提交。
- **错误提示**：统一用站内提示条，不在页面里插入说明块。

## 7. 文案语言

界面主体是中文，技术词保留原文：Prompt、Negative、Tag、Seed、Guidance、Guidance Rescale、tokens。产品名写作 ASK；结果栏入口按钮写作「Ask」，这是已批准的写法。

| 场景 | 写法 | 示例 |
| --- | --- | --- |
| 成功反馈 | 「已 + 动词」，可以带数量 | 已复制、已收藏、已导入 3 项参数、已撤回 2 份草稿 |
| 阻止操作 | 原因加唯一可做的动作 | 正在生成，请先停止再删除 |
| 不支持 | 只陈述事实，不给建议 | 不支持 PDF、仅支持 PNG 或 JPEG 图片 |
| 空状态 | 一行字，附快捷键 | 写下描述，按 ⌘↵ 生成；生成的图会排在这里 |
| 未知或估算 | 估算明确标出；无报价时暂不显示生成按钮费用标签 | 上下文 · 估算、上下文尚未估算 |
| 数值 | 等宽数字，单位紧跟 | 25 张、64000 tokens、832×1216、1.01 MP |

标点与符号：
- 用全角标点。引用界面上的名称用「」。
- 分隔用「·」，尺寸用「×」，并列项之间用「／」。
- 快捷键用 `kbd` 样式显示。

不要写：
- 建议口吻，如「建议…」「您可以…」。
- 教程式说明、营销用语、感叹号。
- 重复标题、每节一段说明，或孤零零一行的小字。
- 界面统一写「压缩」，不混用 compaction、精简、摘要等译法。

## 8. 微调检查清单

每次调整前后逐条对照：
1. 图片仍然是屏幕上最亮、最抢眼的东西吗？
2. 有没有新增的底色、边框或标题？能不能只用一级表面、文字亮度或间距来表达？
3. 颜色、字号、间距、圆角、图标档位是否都取自变量？同类元素是否一致？
4. 紫色是否只出现在选中、焦点、主操作、品牌和引用上？
5. 文案能不能再短？是否有建议口吻或重复信息？
6. 四种宽度下是否有遮挡关键控件、横向溢出或被裁切的情况？
7. 悬停、聚焦、按下、禁用、触屏和减少动态这几种状态是否都覆盖了？
8. 改动是否越过了复刻约束，或改到了报价、分流、额度、取消、失败的行为？

## 9. 已批准的特例

以下是有意为之的设计，微调时不当作问题处理。如需改动，要先得到用户确认：
- ASK 的统一玻璃材质：窗口下方有图片时会透出浅色，这是材质本身的效果。
- ASK 的上下文占用环：未发送时也会按静态提示词和画板状态的估算显示占用。
- ASK B v5 的小数字号和几何尺寸。
- 「生成」按钮的立体处理，以及结果栏下载按钮的紫色描边（参考工程原有样式）。
- 在 raised 容器内重新指向 `--well`／`--well-focus`，见 `ui.css`、`TagPicker.vue`、`ToastList.vue`。这是记录过的凹陷关系，不是零散硬编码。

NAI 模型、模式与 Effort 收在同一行共用外框，使用短模型名，三段统一高度；Effort 预留 Medium 宽度，切档不推挤相邻文字。参数菜单沿用画板菜单的实色 raised 表面、12px 圆角、轻边及阴影；选中项用字重和紫色勾，指针打开不主动聚焦选项，键盘焦点用中性底色与内描边。提示词内底栏维持原有高度。

绘图参数与 NAI 参考共用底部面板：上圆角、略深一级表面、36px 深色三段凹槽；导航在展开内容上方，参考总开关在当前查看的段名旁，无右侧空槽。参考图 64×80 横排、无文件名；沿用原有参数控件。生成按钮前固定留出 12px 空间，费用只在生成按钮展示。无参考能力时使用同高的单行深色凹槽，左侧「参数」，右侧为实际生效的采样器／步数摘要与箭头，不增加说明行或嵌套卡片。
