# Koma 设计语言与产品语言

更新：2026-10-29。根据现有实现与已批准决定整理，包含 HOME、独立 EDIT、Photopea、NAI 抽屉、会话内 Todo、外部协同与统一草稿审阅。产品定位与功能框架见[产品总览](product-overview.md)。本文作为前端微调的共同基准。

本文描述现状和判断标准，不新增任何批准。以下内容仍按原约定执行：
- 复刻约束、已批准调整与 ASK 规格分别见 `AGENTS.md`、`docs/architecture.md`、`docs/ask/ask-ui-spec.md`。
- 变量、字体和样式归属以 `public/styles/tokens.css`、`config/fonts.json`、`docs/style-ownership.md` 为准。
- 本文与上述文件冲突时，以上述文件为准，并回头修正本文。

## 1. 一句话

**暗房里的创作台。** 外壳安静、偏冷、低对比，生成的图片是屏幕上唯一明亮的东西，像一张放在深色衬纸上的照片。圆体和圆润的 Fredoka 字标让这套专业工具显得亲和，不冷硬。

关键词：安静、一级之差、单一紫色、图片优先、诚实、克制的触感。

## 2. 参照系：像什么软件

参照只用来对齐质感，不照搬界面。复刻范围内的布局、尺寸和行为以参考工程为准。

| 区域 | 最接近的参照 | 借鉴的部分 | 不借鉴的部分 |
| --- | --- | --- | --- |
| 整体外壳 | Linear、Raycast 的深色主题 | 近黑偏冷的灰阶；表面之间只差一级；单一紫色强调；细线分隔；图标按钮配提示 | 霓虹渐变、大面积品牌色、营销式插画 |
| IMAGE 工作区 | NovelAI 的出图界面；Lightroom 的中性暗背景 | 左侧参数栏、中间舞台、右侧历史缩略图；背景压暗来衬托作品；画框只做轻微浮起 | 多层面板嵌套、对比强烈的分区 |
| EDIT 工作区 | IMAGE 的同级编辑车间 | 独立画板胶囊、参数／画布／版本栏；同类菜单、底部抽屉和控件保持一致 | 挂在其他工作区之上的第二层外壳、无内容的大空隙 |
| CHAT 工作区 | ChatGPT、Claude 的网页版 | 空白时输入框居中；左侧会话列表；用户消息靠右、带气泡，回复不带气泡 | 头像、角色名、彩色身份标识 |
| ASK | iOS 灵动岛、Raycast 浮窗、Cursor 类 AI IDE 面板 | 同一个容器在多种形态间变形；毛玻璃浮层；上下文占用环、检查点、压缩记忆行 | 常驻侧栏、强制占用布局、自动执行写入 |
| 待办与协同 | AI IDE 的会话内计划清单、输入框工具栏 | 进度贴近对话；任务单行；成果图标；目录标签与菜单贴近输入区 | 独立大任务板、常驻关联表单、协议说明与原始代码预览 |
| 设置 | macOS 系统设置、Linear 设置页 | 左侧导航；居中的分组列表；每行左边是文字，右边是控件；改动即时保存 | 每节都有大标题和说明段落、多余的「保存」按钮 |
| 品牌 | 日式漫画工具的亲和感（Koma ＝ コマ，漫画分格） | Fredoka 字标；8 个方块组成的标识；资源圆体 | 卡通吉祥物、手绘装饰 |

## 3. 产品语言

1. **作品优先。** 外壳为图片让路，任何新元素都不能比图片更抢眼。紫色只用在选中、焦点、主操作、品牌和图片引用上。
2. **工作台，不是网站。** 唯一外壳；HOME 与 IMAGE／CHAT／EDIT／TAGS 原地切换并保持状态。EDIT 使用独立画板，设置以弹窗打开。没有页面跳转感，也没有落地页式的内容。
3. **用户掌握决定。**
   - ASK 用只读工具理解工作台；词文、参数、任务、配方和文件修改先进入共享草稿，由用户确认后才写入，沿用冲突检查与回退路径。
   - 不自动重试、不自动生成，也不替用户发送消息。
   - 浮层可以拖开，但不占用工作区的布局。
4. **诚实。**
   - 没有报价时保留未知费用状态，生成按钮暂不显示费用标签；不当作免费。
   - 失败就是失败，并说明原因。
   - 估算值要标成「估算」。
   - 动效节拍只补足最短停留时间，不靠拖延制造「在思考」的假象。
5. **少即是清楚。** 只保留基本信息和操作反馈。不重复标题，不写大段说明、建议或教程。说明文字只在影响决定时出现，例如 Key 会发送到哪里。
6. **中立。**
   - 连接用中性的 Gateway Profile，不出现私有渠道的品牌。
   - 模型图标只表示合法的模型供应商。
   - ASK 对技术和态度都保持中立。
7. **进度贴近创作。** Todo 是会话内的轻量进度，不另建一块占据空间的管理页面；总览只帮助定位清单，详细修改进入草稿。
8. **共享按需开启。** Todo 与成果是默认浏览器本地能力，在线静态站同样可用。挂载目录增加外部协作，不成为任务可用的前提；界面只在实际连接异常或交付失败时提示处理。

## 4. 视觉语言

### 4.1 表面与层级

层级靠「一级之差」区分，不靠强对比。相邻表面的感知亮度差约 2.5 ΔL*，比 VS Code 和 Linear 更安静，接近 NovelAI。

| 变量 | 用途 |
| --- | --- |
| `--canvas` #131315 | 舞台与视口，即照片下面的衬纸 |
| `--sunken` / `--well` | 输入框、凹槽、缩略图。凹陷是一种相对关系：在 `--raised` 容器里要重新指向更深一级的值 |
| `--chrome` #18181c | 顶栏、输入区、图片栏 |
| `--raised` #1e1e24 | 卡片、抽屉、浮层、提示 |
| `--hover` #24242c | 悬停反馈 |
| `--line` / `--line-2` | 普通分隔线 / 强调分隔线与焦点凹槽 |

判断标准：
- 一个区域如果需要靠边框、底色和标题同时区分，说明层级做多了，先减一层。
- 灰底上再套灰框是用户明确不喜欢的写法。
- 需要键入的数字和文字放在比所在行低一级的凹槽里，默认就是深色；从列表里选的值与行齐平，悬停才出现表面。独立成块的输入框自己就是一层，外面不再套卡片。

### 4.2 颜色

- **文字分四级**：`--fg` 主文字；`--fg-2` 次要文字；`--fg-3` 标签与提示（在 raised 上满足 AA）；`--fg-4` 只用于装饰或大字。小字不要低于 `--fg-3`。
- **强调色只有一个**：`--a` #b3a1ff。配套的有 `--a-dim`（选中底色）、`--a-line`（选中描边）、`--a-glow`、`--a-ink`（紫底上的深色文字）。
- **语义色**：`--ok` 绿、`--warn` 琥珀、`--err` 红，只表达状态。草稿差异用很淡的红、绿行底色，文字保持中性。
- **背景偏冷**：灰阶整体偏蓝（越亮越偏），让暖色作品更跳出来。新加颜色时先选现有变量，不写新的十六进制值。

### 4.3 字体

| 角色 | 字体 | 用途 |
| --- | --- | --- |
| `--sans` | Koma Rounded（资源圆体，字重 400／500／700） | 全部界面文字，中英文统一 |
| `--mono` | JetBrains Mono | 数字、ID、Seed、尺寸、快捷键、计数，配合表格数字 |
| `--brand` | Fredoka | 只用于「Koma」字标 |

- **字号阶梯**：11／12／13／15／18／22／28px。正文、输入框和按钮是 13px；Prompt 和主操作是 15px；分节标题 18px；弹窗标题 22px。中文笔画重，所以小字号保持 11／12／13 紧凑。
- **层次来源**：靠字号、字重（regular 正文、medium 标签、semibold 强调）和文字亮度。不要用加框或加底色来表示层次。
- **已批准的例外**：ASK B v5 保留小数字号，消息 13px/1.72，输入按后续微调为 13px/1.6，预览 12.5px。

### 4.4 尺寸、间距与圆角

- **间距**：4px 网格，即 `--sp-1`…`--sp-7` 对应 4／8／12／16／24／32／48。
- **圆角**：`--r1` 5（小件与标签）、`--r2` 7（按钮、输入框、分段控件）、`--r3` 10（主按钮、卡片）、`--r4` 15。另外，浮动玻璃容器 20、展开窗口 18、气泡 14、菜单 12（行 8，同心）、胶囊 999。同类元素的圆角必须一致。
- **固定尺寸**：顶栏 60px、列头 48px、左侧参数栏 316px、历史栏 132px、Tag 组合栏 300px。
- **按钮尺寸**：图标按钮 32px，小号 28px；结果栏与图片栏底栏 36px。

### 4.5 图标

- 站内 sprite（`public/assets/icons.svg`），24 格线性图标，圆端圆角。主体字形几何尺寸占 24 格的 70%–75%；箭头、关闭、勾选、加减、更多等次级字形最大边 13.5–16 格；超出范围的字形在 sprite 内用 `<g transform>` 缩放并居中，左右箭头不移位。品牌和厂商标识、键帽字形、停止方块按原样。
- 描边是非缩放描边，渲染线宽与图标尺寸无关：统一 `--ico-stroke` 1.3px；实色按钮上的字形（发送）和展示图标（`.ico-lg`／`.ico-xl`）用 `--ico-stroke-strong` 1.6px。
- 尺寸只取四档，组件通过 `--ico` 引用档位变量，不写像素值：`--ico-xs` 11（键帽、角标）、`--ico-sm` 14（菜单、标签、行内提示、消息工具、小按钮）、`--ico-md` 16（默认，含 28／32px 图标按钮、列表行、区头）、`--ico-lg` 18（主工具栏：结果栏、图片栏页签与底栏、Prompt 工具栏、顶栏）。空状态和拖放的展示图标 26／34px 不入档。
- 按钮容器分裸图标（默认）、凹槽（Prompt 工具栏）和强调（下载，见 §9）三种。同一排按钮同尺寸。
- 开关型图标按钮（收藏、对比）选中时只改字形：紫色，有实心形的填实，不加底和框。编辑器的当前工具保留紫底，表示正在使用的工具。
- 图标按钮闲置默认 `--fg-3`，主工具栏 `--fg-2`；悬停 `--fg`；选中 `--a`。同一水平线上的相邻工具栏同档、同色、共用中线，比如结果栏和图片栏底栏。
- 实心图标只用于区头标签和少数状态，比如收藏选中、停止。
- 图标按钮的含义靠悬停提示（`data-tip`）和读屏标签表达，不在旁边加可见文字。
- 模型图标来自 LobeHub，用于模型选择、模型列表与额度标签；官方 Profile 或已识别官方地址的连接也可使用对应 Logo。其他连接以对话／图片图标区分文本与生图，不把兼容协议视为官方身份；地址识别仅影响图标。
- 供应商连接分为图像、文本两区；分组标题不另加面板。图像卡底行沿用设置页的左侧信息、右侧操作布局；模型入口、辅助计数与排序通过字重、明暗和留白区分，不新增控件外框。文本卡不提供排序。综合供应商按已配置能力出现在两区。

### 4.6 阴影与材质

- **阴影**：分 `--sh-1`…`--sh-4` 四档，层级越高扩散越负，边缘越紧。浮起的表面带 `--sh-lip`，即顶部 1px 内高光，表示光从上方来。
- **画框**：图片用 `--print-shadow`，一圈 1px 浅描边加柔和的投影，像照片轻轻离开衬纸。
- **透明图像**：图片范围使用 `--image-checker` 的低对比灰色棋盘，历史／收藏、HOME 与 EDIT 保持一致；棋盘只是展示背景，不写入原图或交付文件。
- **全页唯一的实体按钮**：只有「生成」按钮会花费额度，所以只有它有完整的立体处理，包括竖向渐变、顶部高光、深色描边和紫色光晕，运行时它本身变成进度条。其他按钮都保持扁平。
- **毛玻璃**：只用于浮在工作区上方的 ASK 容器，材质是 `rgba(22,22,25,.88)`，加 20px 磨砂和 1.4 倍饱和度。菜单用实色 raised 表面，不加磨砂；预览用接近实色的磨砂，保证文字可读。普通面板不使用玻璃。

### 4.7 动效

- **时长**：三档，`--t1` 120ms 用于反馈和颜色，`--t2` 220ms 用于切换，`--t3` 380ms 用于入场。
- **缓动**：主曲线 `--e`，弹出用 `--e-out`。
- **入场**：透明度先变化，再跟一段 4px 位移。按下反馈：图标按钮缩到 .94，普通按钮缩到 .978，「生成」按钮下沉 1px，光晕收紧。
- **抽屉**：参数面板与会话待办通过内容区域的真实高度展开／收起，内容随容器边界裁切；导航保持稳定，不只靠透明度或整体平移模拟展开。减少动态时按组件契约直接切换或取消位移。
- **运行态**：短时等待用小号转圈，例如连接提示条、补全请求和「生成」按钮内部（均为参考工程原有）。ASK 的运行态用低对比的慢速微光，或者由内向外的呼吸。占用环、进度条这类图形只表示数量。
- **循环扫光**：无限循环一律匀速 `linear`，每轮恰好移动一个背景宽度，间歇放在文字外的暗底里走完。缓动循环会冲—停顿挫，宽光带留在字上也会让停顿露出来。文字换了就重建元素、从头扫，不让光带因宽度变化半路跳位。
- **减少动态**：所有组件都要处理 `prefers-reduced-motion`，关闭位移、扫光和呼吸，只保留透明度变化。

### 4.8 菜单

全站下拉、⋯ 菜单与 Tag 补全共用 `controls.css` 的 `.menu`／`.menu-item`；组件只定宽度、定位和特殊部件，不另写表面或行状态。
- **表面**：raised 实色、`--line-2` 轻边、`--sh-3` 加 `--sh-lip`，圆角 12、内距 4；最高 `min(360px, 视口 − 16px)`，超出滚动。
- **行**：单行 32px，触屏与 ≤860px 为 44px；字号 13px（触屏 15px），左右内距 8，行圆角 8，图标 `--ico-sm`、闲置 `--fg-3`。ASK 内的锚定菜单按 B v5 几何在触屏仍为 32px。
- **状态**：悬停与键盘焦点同为 `--hover` 底，焦点加内描边；选中只用字重和右侧紫色勾；危险项红字，悬停 `--err-dim`；禁用 `--fg-4`，无悬停。
- **辅助**：分组标题 11px `--fg-4`；分隔线贯穿菜单全宽；右侧附注（Key 尾号、计数）11px 等宽数字 `--fg-4`。Tag 补全同样单行：Tag 名、译名、分类点与计数，命中部分加粗。
- **定位**：距锚点 4px、距视口 8px，下方放不下时向上翻；选择型菜单与触发器同宽、左对齐，⋯ 菜单右对齐。入场只用透明度加朝向锚点的 4px 位移（`--t1`、`--e-out`），向上展开时位移反向。
- **交互**：触发器带 `aria-expanded`，打开期间保留悬停底；菜单内方向键与 Home／End 移动焦点，Tag 补全由输入框的方向键选择。

## 5. 布局语言

- **桌面端**：顶栏下面，IMAGE 分三栏（参数｜舞台｜历史）；CHAT 是两栏（会话｜对话），可展开上下文栏；TAGS 是两栏（搜索｜组合）。设置是左侧导航加居中的分组列表。
- **主断点 860px**：窄屏改成单列，固定动作放在底部，例如 IMAGE 的「生成」和 CHAT 的输入框。设置导航变成顶部横向标签。
- **其他断点**：只有局部组件额外使用 600／480／360px 等细分断点。
- **验收宽度**：320／390／768／1440px，不能出现横向溢出。
- **浮层**：ASK 是全局浮层，不预留侧栏，默认位置要避开关键控件，用户可以拖开。EDIT 页面中隐藏 ASK。

## 6. 交互语言

- **即时生效**：设置改动立即保存，并同步到其他已打开的页面，不需要「保存」按钮。
- **删除前确认**：在原位二次确认，比如 × 变成红色「删除」，或在确认面板里操作。危险按钮永远不是默认焦点。可以撤销的操作用提示条里的「撤销」，不弹确认框。
- **不增加付费确认**：涨价时提示后继续，按原有规则处理。
- **显露与常显**：桌面端操作在悬停或聚焦时显露；触屏和最后一项常显。按钮之间要留出真实间距，不能和正文挤在一起。
- **键盘**：⌘↵ 生成，⌘J／Ctrl+J 打开或收起 ASK，Esc 按层级由内到外逐层关闭。输入法组合输入时不提交。
- **错误提示**：操作反馈使用站内提示条；工具、草稿或同步的失败原因留在对应操作处，详情按需展开，不增加常驻说明块。

## 7. 文案语言

界面主体是中文，技术词保留原文：Prompt、Negative、Tag、Seed、Guidance、Guidance Rescale、tokens；NAI 型号用官方全称，模式与 Effort 档位写作 Anime／Furry、High／Medium。产品名写作 ASK；结果栏入口按钮写作「Ask」，这是已批准的写法。

| 场景 | 写法 | 示例 |
| --- | --- | --- |
| 成功反馈 | 「已 + 动词」，可以带数量 | 已复制、已收藏、已导入 3 项参数、已撤回 2 份草稿 |
| 阻止操作 | 原因加唯一可做的动作 | 正在生成，请先停止再删除 |
| 不支持 | 只陈述事实，不给建议 | 不支持 PDF、仅支持 PNG 或 JPEG 图片 |
| 空状态 | 一行字，附快捷键 | 写下描述，按 ⌘↵ 生成；生成的图会排在这里 |
| 未知或估算 | 估算明确标出；无报价时暂不显示生成按钮费用标签 | 上下文 · 估算、上下文尚未估算 |
| 数值 | 等宽数字，单位紧跟 | 25 张、64000 tokens、832×1216、1.01 MP |

标点与符号：
- 用全角标点。引用界面上的名称用「」。
- 分隔用「·」，尺寸用「×」，并列项之间用「／」。
- 快捷键用 `kbd` 样式显示。

不要写：
- 建议口吻，如「建议…」「您可以…」。
- 教程式说明、营销用语、感叹号。
- 重复标题、每节一段说明，或孤零零一行的小字。
- 界面统一写「压缩」，不混用 compaction、精简、摘要等译法。

## 8. 微调检查清单

每次调整前后逐条对照：
1. 图片仍然是屏幕上最亮、最抢眼的东西吗？
2. 有没有新增的底色、边框或标题？能不能只用一级表面、文字亮度或间距来表达？
3. 颜色、字号、间距、圆角、图标档位是否都取自变量？同类元素是否一致？
4. 紫色是否只出现在选中、焦点、主操作、品牌和引用上？
5. 文案能不能再短？是否有建议口吻或重复信息？
6. 四种宽度下是否有遮挡关键控件、横向溢出或被裁切的情况？
7. 悬停、聚焦、按下、禁用、触屏和减少动态这几种状态是否都覆盖了？
8. 改动是否越过了复刻约束，或改到了报价、分流、额度、取消、失败的行为？

## 9. 已批准的特例

以下是有意为之的设计，微调时不当作问题处理。如需改动，要先得到用户确认：
- ASK 的统一玻璃材质：窗口下方有图片时会透出浅色，这是材质本身的效果。
- ASK 的上下文占用环：未发送时也会按静态提示词和画板状态的估算显示占用。
- ASK B v5 的小数字号和几何尺寸。
- 「生成」按钮的立体处理，以及结果栏下载按钮的紫色描边（参考工程原有样式）。
- 在 raised 容器内重新指向 `--well`／`--well-focus`，见 `ui.css`、`TagPicker.vue`、`ToastList.vue`。这是记录过的凹陷关系，不是零散硬编码。

模型区位于画板与提示词之间，不设「模型」标题：全宽模型框以紫色模型图标开头、只放官方全称，按钮与菜单同名；下方并排 Anime｜Furry 与 High｜Medium 两组 `.seg` 分段直接点选、等宽，手机宽度也不竖排；无 Effort 的型号由模式分段占满整行，此时 Anime／Furry 前加樱花／爪垫实心图标（选中项紫色）；四段并排时只用文字。参数菜单使用共享菜单（§4.8），指针打开不主动聚焦选项。提示词内底栏维持原有高度。

EDIT 复用同一模型、模式／Effort、提示词预设、角色和底部抽屉，模型位于提示词上方；强度是主表单项，噪声和其他参数进入抽屉。参考缩略图、启用开关、圆角材质与绘图一致，不新增独立参考弹窗。仅展示当前操作可用的型号和入口，不以界面复用扩大官方接口能力。

Enhance 在图生图表单内使用一行标题与共享开关，开启后两列并排倍率／目标尺寸与 Magnitude；V5 的 Max 直接列入同一倍率下拉框并显示实际尺寸，不单独增加开关。强度保持原滑杆，噪声留在参数抽屉，底部原按钮显示 Enhance。关闭时不留额外参数或说明段，不增加独立模式、卡片或弹窗。

EDIT 重绘与放大使用同一个画布工具栏组件：图标为主操作，旁边独立箭头打开类型菜单，二者共用尺寸、对齐与底色；重绘、放大与 Director 魔棒三个图片操作之后只放一条分隔线，图标和箭头之间不画线。重绘主按钮记住类型并切换启停，菜单选择普通／聚焦；放大主按钮打开当前类型的设置，菜单选择原生／外部，对应设置只展示该类模型与参数。不在左侧表单增加开关、说明或尺寸行。聚焦启用时显示现有框选图标；画布使用主题色细框、克制的范围外遮罩，范围与处理尺寸收进角标，涂画时范围层不拦截笔刷。指针移动只更新原生几何，结束一次提交；Esc 优先关闭菜单，否则退出框选，失焦／双指／页面暂停撤销未完成框选，减少动效偏好同样适用。

放大与 Director Tools 使用紧贴工具栏上方 6px 的同材质紧凑面板，水平限制在视口内。Director 底部为单行带名称图标，参数与执行行向上展开，窄屏横向滚动；上色／表情只展示必要参数，不扩张左侧。去背景三种结果归一个版本入口，信息栏切换；切换不重复调用。NovelAI Upscale 使用统一正文字体与 600 字重。

Photopea 从 EDIT 顶栏单个「高级编辑」图标进入。开启后参数栏与版本栏让出空间，iframe 填满 EDIT 工作区，只留固定的紧凑顶栏，没有展开／折叠功能；应用图标与「自动／仅图像／仅蒙版」组成一个控件，每次进入默认自动，返回始终可用。外壳沿用 Koma tokens 和共享菜单；第三方内容通过官方设置默认使用 Dark Blue、中文、折叠的图层／历史面板与精简的菜单／修图工具，保留当前工具参数行。宿主左上角固定，iframe 宽高 100%，完整保留两侧工具；不扩宽裁剪广告或修改跨域内容。不增加边距外框、独立预览弹窗或常驻说明段落。返回使用「暂不应用」，保活分层修改保留；重新载入明确提示工作栈重建，不让用户误以为已保存分层工程。

绘图参数与 NAI 参考共用底部面板：上圆角、略深一级表面、40px 深色三段凹槽，段名 13px 半粗；导航在展开内容上方，参考总开关在当前查看的段名旁，无右侧空槽。参考图 64×80 横排、无文件名；沿用原有参数控件。生成按钮前固定留出 12px 空间，费用只在生成按钮展示。无参考能力时使用同高的单行深色凹槽，左侧「参数」，右侧为实际生效的采样器／步数摘要（12px 中粗）与箭头，不增加说明行或嵌套卡片。

HOME 沿用同一衬纸表面，内容宽 min(84%, 1080px)，窄屏两侧 16px，无车间顶栏。继续／进行中直接摆放完整印样，外层不加卡片框；定稿保留标准行、标准列和有限双图堆叠的拼图三种排列，不裁图、不留拼图内部空洞。当前批准的特例：

- 状态与计数使用 raised 填充胶囊；外层不再叠加卡片框。
- 横向陈列右缘保留 40px 渐隐；「继续」按钮高 40px，横向布局按内容宽度左对齐，仅上下堆叠时铺满文字栏。
- HOME 头部宽屏居中（字标、输入条与车间入口），设置胶囊在右上角；页面只有一条进行中的线且没有定稿时，「进行中」整区随头部居中；HOME 字标独立承担品牌；使用现有 `brand-title` 的 Fredoka 650 字重与品牌渐变，副标沿用 `brand-subtitle`。不得以普通正文字重替代确认示例。

## 10. ASK、待办与协同的界面取舍

- **清单贴近会话**：Todo 在输入框上方，收起只留进度与当前事项，展开每项只有状态、标题和单个成果图标。没有任务时不留关联占位；单项没有详情展开、添加表单或额外标签。顶栏 API Key 旁的任务图标打开轻量总览，低频清单操作留在其更多菜单。
- **草稿突出实际改动**：Prompt／Negative 与参数保留原有 Diff；任务、配方和文件与它们同级，以统一图标槽和缩进对齐。任务只显示真实变化，长配方先显示一行摘要，路径与详情按需展开；界面 `mutation` 写作「更改记录」。不把大段配方、原始 JSON／Markdown 或格式下拉常驻在卡片中。
- **保存复用确认**：配方、备忘录与任务资料统一成为 DraftCard 的文件行，与其他步骤一并确认。资料由清单与 `read_ref` 按需读取，手动附件使用系统选择器、拖拽或粘贴；不提供应用内资料勾选或独立导出预览弹窗。
- **入口贴近动作**：目录标签与「＋」在输入框同一工具栏，字号与体量低于正文，长名省略；菜单紧贴按钮并随视口翻转。右上角更多菜单只有「压缩上下文」「调用调试」。图片开关与手动 JSON 兜底归现有「设置 → ASK」，不另设一套设置弹窗。
- **完成态使用同一语言**：任务、文件及外部草稿应用后复用工具调用的完成行，只展示动作结果、必要计数和可执行撤销；同行保留「来自外部」，具体来源放在详情。不再套独立卡片、重复标题或已应用脚标。
- **内容和控件留出距离**：消息、草稿、待办、输入区各有明确间距；展开内容内部限高滚动，不能将输入框和发送操作挤出可见区域。层级靠间距、明暗和字重加强，控制区沿用所在容器表面，不靠叠加边框制造分区。
- **状态与排版可信**：本轮仅元数据与全局图片开关分开呈现，重试保持该轮限制，新问题遵循当前设置。回复支持表格单元格的行内 `<br>` 换行，代码仍按原文显示，表格与长代码只在自身区域滚动。

具体尺寸、动画、焦点和响应式规则由 [ASK UI 规范](ask/ask-ui-spec.md)维护，文件、任务与目录生命周期由[协同契约](ask/bridge.md)维护。

图片角标按所在区域显示 `#h/#f/#e`，EDIT 复制使用完整码；ASK 的 `#` 候选贴近输入框、紧凑呈现，不增加常驻身份说明或 UUID。旧页面引用仍可显示准确收藏原图时标明旧页编号。见[图片身份](image-identity.md#界面与维护)。
