## 使用方式

1. 在 ComfyUI 原生界面调通单张文生图，安装该工作流需要的模型、LoRA 和节点，导出 **API Format** JSON。
2. 在 Koma「设置 → 连接 → 配置供应商」中选择 **ComfyUI · Custom Workflow**。一个供应商共用地址与 Key，在工作流页管理独立的模型管线。
3. 在「连接信息」页填写名称、ComfyUI 根地址和可选 Key，例如 `http://127.0.0.1:8188`，或允许浏览器跨域的 HTTPS 代理地址。新连接 Key 留空表示无鉴权；填写则使用 Bearer。编辑已有 Bearer 连接时，空输入保留 Key；勾选「无鉴权」才停止发送原 Key。
4. 点击「下一步」进入「工作流」页，为工作流命名；通过工作流下拉切换，或点击「添加工作流」。每份工作流默认从本机选择 API `.json` 文件，也可切换「粘贴 JSON」。两种方式共用同一份 JSON 和绑定；文件只在浏览器本机读取，导入不请求 ComfyUI。确认 Prompt、Seed 和输出绑定：正向 Prompt 与 Seed 支持多选；Negative 最多绑定一处，也可由工作流固定；图片输出只选一个 SaveImage／PreviewImage。
5. 如需从 Koma 调参，展开「基础参数 · 可选绑定」，分别指定宽度、高度、步数、CFG、采样器与调度器的输入；宽高、步数与 CFG 可同步绑定多处（默认值必须一致），采样器／调度器各一处；默认不绑定。
6. 如需换用已接好位置的 LoRA，展开「LoRA · 绑定已有节点」，点击「绑定 LoRA 位置」，选择加载节点及文件名、模型强度、可选文本编码器强度。标准节点会预选字段，自定义节点须手动确认全部强度已绑定且归零能停用。
7. 在「允许使用的主模型」中绑定 checkpoint／UNET 的字面量文件名输入，添加允许切换的完整文件名和可选显示名。不绑定时使用工作流原模型。该名单由用户确认兼容性，不依据名称猜测，也不代表模型已经下载。
8. 保存后在 IMAGE 选择对应模型，填写 Prompt、Seed 和串行批次数；已绑定的尺寸复用原有画幅控件（档位、方向、比例、宽高输入和互换），步数／CFG、采样器／调度器显示在参数抽屉。Prompt、Negative 旁的 **LoRA** 页签用于选文件、启停和调强度。添加更多 LoRA 节点或更改采样流程，仍需在 ComfyUI 修改后重新导出，再上传或粘贴并保存。

每份工作流独立保存 JSON、字段绑定和模型名单；切换工作流保留未保存草稿，最终一次保存整个供应商。删除工作流不删除 GPU 权重或图片。新工作流和模型各自拥有稳定身份，改名不改变身份。

两个配置页可通过顶部页签和上一页／下一步切换，未保存的名称、地址、Key、JSON 与绑定保留；最后一次保存才提交完整连接。连接卡片的「工作流」直接打开第二页，更多菜单的编辑打开连接信息。文件读取中显示加载状态并禁用保存；取消关闭后，迟到的读取结果不影响重新打开的配置。

普通画布 JSON（含 `nodes` 数组）会被拒绝，不自动转换。扫描包含空字符串、安全整数与有限数值；Seed 只使用安全整数，CFG 可选小数。跳过数组连线、对象和布尔值。候选只代表可绑定的字段，不判断主提示词语义：改良节点只要暴露字面量字符串即可手动选择；输入来自拼接、翻译等节点时，选择实际需要替换的上游字段。

Seed／noise_seed 字段会预选，仍须核对；唯一 SaveImage 优先预选。更新 JSON 时，仅保留节点 ID、类型和输入类型仍匹配的绑定，失效项需要重新选择。保存与执行均重新校验，所有绑定目标不得重复，基础参数也不能与 Seed 共用同一输入。

## 工作区行为

一个连接保存多份工作流，按不同模型管线分组；每份可配置多个能共用该管线的主模型。IMAGE 仍只选模型，由模型身份定位工作流和允许的文件名。内部条目 ID 由连接、工作流和模型身份组成，改名不会改变身份；不映射成 NAI 或 GPT 型号，不要求 ComfyUI 返回模型目录。已有单工作流配置继续读取；保存为多工作流时，未新增主模型名单的原条目身份保留。工作流条目在本地建立；选中具有采样／LoRA 绑定的条目时，只读获取所绑节点的选项。「测试连接」显式读取 `/system_stats`，成功只证明服务可达，不代表工作流已经运行。

画板列表使用简短的「ComfyUI」角标，悬停显示配置的工作流名称；内部连接 ID 不作为界面名称。连接失效或缺少名称时使用工作流提示，不回退成 UUID。

模型选择框与下拉列表统一左侧名称、右侧来源胶囊：NAI 使用「NovelAI」，自定义工作流使用「ComfyUI」。已配置名单的模型优先显示自定义显示名，否则显示文件名；固定工作流的 ComfyUI 名称从所选输出的上游模型加载节点读取，支持标准 Checkpoint／UNET 及 GGUF UNET 加载器，只取 MODEL 输出的字面量文件名；不把 LoRA、VAE、仅作文本编码器的 checkpoint 或未连接节点当成生成模型。显示时去掉目录和权重扩展名，不推断模型系列；多模型显示并列名称，未识别则沿用工作流名称。悬停可查看工作流名和完整文件名；同模型的不同工作流会附上工作流名以便区分。此过程纯本地，不请求 GPU，也不改变工作流。

IMAGE 可编辑 Prompt、Seed、串行批次数，以及已绑定的 Negative。宽高、步数和 CFG 仅在绑定后开放编辑；未绑定项由工作流固定。NAI 模式、角色、预设、参考等控件隐藏，原画板值保留。ComfyUI 不读取这些旧值，也不追加 NAI 质量词或角色词。Prompt 原文注入；全空时沿用 `best quality` 兜底，结果记录实际发送文本。未绑定 Negative 不覆盖工作流内固定值，也不把画板旧负向记录为本次采用值。

等待出图沿用 IMAGE 的方块波纹动画。工作流输出尺寸未知时，动画按可用舞台展示；收到原图后按实际尺寸揭示结果，不将占位尺寸记为图片尺寸，也不显示虚构的完成百分比。「测试连接」显示转动图标与测试中状态。

空 Seed 随机、0 合法；显式 Seed 每次提交递增并按 uint32 回绕，同一次 Seed 写入所有绑定位置。串行批次数等于提交次数，每次只收指定输出的第一张图片，建议工作流 batch 固定为 1。本协议不额外生成本机批次对比图。

LoRA 的数量、顺序和连线由原工作流加载节点决定。Koma 只调整已绑定位置的文件与强度，不解析 `<lora:…>`，不下载或上传权重，不生成通用动态节点表单或修改连线。触发词继续写在 Prompt。没有 AI 字段识别、自动安装的模型／工作流库、图生图、视频、WebSocket 预览或跨刷新任务恢复。

ASK 使用现有草稿类型：允许 Prompt、已绑定 Negative、Seed、批次数、现有条目选择和已绑定的基础参数。`params_patch` 继续使用 `width`／`height`／`steps`；仅在 ComfyUI 下，`scale` 表示绑定的 CFG，审阅界面显示 CFG。历史遗留的顶层 `cfg` 不复用，模型专用 Guidance 不在本轮范围。状态提供可写字段与配置版本；确认时按最终目标检查固定参数、失效版本与原有冲突。部分恢复同样受限，实际画板写入器再次检查可写字段、数值和连接版本；应用与撤销均检查工作流身份及版本。ASK 不获得连接／工作流／LoRA 写入权限，也不提交生成。

## 基础参数的可选绑定

| 参数 | 可绑定输入与本地校验 | 示例 |
| --- | --- | --- |
| 宽度／高度 | 正安全整数的字面量输入；不绑定连线 | 主阶段潜空间节点的 `width`／`height`，或上游整数节点的数值输入 |
| 步数 | 正安全整数字面量 | 主采样器 `steps` |
| CFG | 有限数值，允许小数 | 主采样器 `cfg`；不能将模型专用 Guidance 当成 CFG |

只按类型列候选，由用户确认语义，不通过字段名强制推断或自动激活。每项可绑定多个需同步的输入，配置时要求默认值一致，提交时写入同一个值；宽高均绑定时开放原有尺寸预设和互换，预设只在用户点击时写入；只绑定一边时另一边显示工作流固定，不显示其假定数值。未绑定的二阶段采样、放大、裁切及其余参数保持 JSON 原样。Koma 不套用 NAI 的 64 像素对齐、2048 边长或 50 步限制，也不自行猜测模型上限；具体范围、尺寸倍数和显存可行性由工作流节点与运行环境校验，错误沿用原节点报错展示。

首次使用读取所绑输入的工作流默认值。数值按画板与模型条目身份保存，切换回普通模型恢复原尺寸／步数／Guidance；刷新和画板复制保留该记录。绑定目标、节点类型或任一基础默认值改变时，已绑定基础参数整组重新读取默认值；仅改名、Key 或无关 LoRA 值不会重置它们。参数抽屉「恢复默认」恢复当前工作流的已绑定默认值，并重置 Seed／批次。未绑定项不从 NAI 默认值注入。

输入尺寸只代表所绑节点的数值；工作流仍可放大或裁切，结果栏分别显示实际图片尺寸与已注入的输入宽高。批次中途修改数值或重新上传工作流，只作用于下一次生成。

## 采样器、调度器与 LoRA

采样器和调度器分别绑定一个字面量字符串输入：可以是 `KSampler` 的 `sampler_name`／`scheduler`，也可以是拆开的 `KSamplerSelect`、`BasicScheduler` 等节点。不将连线当成名称输入；某个专用调度节点若没有可选名称，保持固定。候选值读取该节点实际声明的输入，不硬编码 NAI 采样器，也不按模型名称推测。

选中工作流时，以 `GET /object_info/{class_type}` 读取所绑节点的字段定义，重复类型只请求一次；只读连接当前可用的枚举和强度范围。缓存仅在本页内，按连接、工作流控件签名、配置和凭据版本隔离，改地址／Key／工作流后重新读取。参数抽屉和 LoRA 页签共用读取状态、加载反馈与「刷新服务选项」按钮；新增 GPU LoRA 文件后可手动刷新。如果节点声明自由字符串，则提供文本输入。

读取失败保留当前设置，枚举控件暂不可选并显示错误，可手动重试；不自动改成别的文件或采样器。选项已加载但当前值不在列表时保留该值并标明缺失，提交前要求重新选择；停用 LoRA 也保留有效文件名，因为 ComfyUI 可能先校验枚举再执行节点。可读取的强度范围在提交前检查；没有选项信息时仍允许原工作流执行，最终以 ComfyUI 的节点校验为准。单次选项读取限时 10 秒，不自动生成或重试生成。

| LoRA 节点 | 绑定要求与启停 |
| --- | --- |
| `LoraLoader` | 必须绑定 `lora_name`、`strength_model` 和 `strength_clip`；停用时两种强度同时归零 |
| `LoraLoaderModelOnly` | 绑定 `lora_name` 和 `strength_model`；停用只归零模型强度 |
| 结构相似的自定义节点 | 手动选择同一节点的文件名和强度字面量，明确确认全部相关强度已绑定且归零等于停用；不凭字段名保证语义兼容 |

每个位置只能绑定一次。LoRA 页签逐位置显示文件选择、启用开关和已绑定的强度；可使用负强度，具体范围由服务节点声明。关闭时保存原强度，提交副本中归零；重新启用恢复记住的强度。原值本来全为零时不会擅自设为 1。取消位置绑定仅恢复模板原值，不等于删除或停用节点。

不支持任意数量的堆栈／数组 LoRA、自动增删节点、自定义旁路开关，或从文件名判断底模兼容性。模型和 LoRA 权重的实际兼容、显存及效果需在目标管线验证。标准节点语义依据 [ComfyUI v0.3.59 nodes.py](https://github.com/comfyanonymous/ComfyUI/blob/v0.3.59/nodes.py)；拆分采样节点依据 [nodes_custom_sampler.py](https://github.com/comfyanonymous/ComfyUI/blob/v0.3.59/comfy_extras/nodes_custom_sampler.py)。

这组设置按画板和模型条目独立保存。绑定目标、节点类型或本组默认值变化后整组重新读取模板值；只改标题或凭据不重置。参数抽屉的「恢复默认」同时恢复当前工作流的基础参数、采样与 LoRA，并重置 Seed／批次。ASK 可读取采样与 LoRA 的当前设置及图片配方，本轮不新增这些字段的草稿写入权限；仍由用户在 IMAGE 调整。

## 三组管线配置示例

[三组工作流配置包](../../examples/comfyui/three-workflows.json)来自用户提供的 API 图，不含地址、Key 或权重。工作流页点击「导入配置包」追加配置；导入后仍需保存供应商。普通 API JSON 继续使用单份工作流内的上传／粘贴入口。配置包格式为 `format: koma-comfy-workflows`、`version: 1`、`workflows: [...]`，导入身份冲突时分配新工作流身份，不覆盖已有草稿。

| 工作流 | 允许的主模型 | 保留的管线差异 |
| --- | --- | --- |
| FLUX | FLUX.2 Klein 4B | 独立 UNET、Qwen 3 4B 文本编码器、FLUX.2 VAE；拆分采样与 Flux2Scheduler；宽高同步绑定潜空间和调度器；无可写 Negative |
| SDXL | Illustrious XL v2、NoobAI XL v1.1 | 共用 checkpoint 加载、双文本编码和 KSampler；选模型只替换 `1.inputs.ckpt_name` |
| Anima | Anima Turbo v1.1 | 独立 UNET、Qwen 3 0.6B 文本编码器与 Qwen Image VAE；无可写 Negative |

这些是不同模型架构的文生图管线，不是高清或二阶段模式。三组原图没有 LoRA 加载节点，因此不会自动插入 LoRA。名单与本地模拟只验证路由和字段替换；模型文件是否完整、底模／LoRA 是否兼容及实际生成效果，仍需在 GPU 环境验收。

## GPU 与内存状态

IMAGE 选中 ComfyUI 模型时，顶栏以运行状态替换费用／额度栏：常显首个 GPU 的显存已用占比与服务器内存已用占比，点击查看设备名称、已用／总量、可用显存、服务版本、更新时间，并可手动刷新。其他供应商继续使用原额度栏。

只读 `GET /system_stats`，使用该连接的地址与鉴权。内存来自 `system.ram_total/ram_free`，设备显存来自 `devices[].vram_total/vram_free`；以总量减可用量计算已用量，以 GiB 显示容量。多设备分别列出，CPU 或共享内存设备不冒充独立 CUDA 显存。零可用量是合法的 100% 占用；字段缺失、不合理数值或未报告 GPU 时显示未提供，不按 0 处理。`torch_vram_*` 是 PyTorch 分配器数据，不作为整卡显存占用。

原生接口没有 CPU／GPU 计算利用率，因此这两项明确显示「原生接口未提供」；显存占比不代表 GPU 计算利用率。本轮不安装监控插件、不建立额外服务器指标接口。内存数据属于远端整机，可能包括其他进程，并非 Koma 单个任务的消耗。

当前 IMAGE 可见且无设置覆盖层／全屏 ASK 时，每次读取结束后间隔 5 秒刷新，读取限时 5 秒，无重叠请求。隐藏浏览器页面、切换工作区或普通模型、打开覆盖层时停止轮询并取消读取；返回后重新读取。切换连接或改变地址／Key 立即清空原来源读数并丢弃迟到结果。同一供应商内切换模型共用该设备读数。读取失败保留上次值并标为更新失败，不伪装成实时成功，也不阻止生成。监控不进入任务锁、不持久化、不发送工作流或 Prompt。

实现分别位于 `domain/comfy-system.ts`、`gateway/comfy-system.ts`、`services/comfy-monitor.ts` 和 `shared/ComfySystemStatus.vue`；顶栏复用既有 wallet、菜单和颜色样式。

## 执行与取消

全批次通过现有 `runTask` 占用全应用 N=1。启动时冻结来源画板、所选模型及允许的文件名、文本、基础参数、采样与 LoRA 设置、工作流、绑定和来源版本，批次中的配置编辑不会替换该快照。地址、鉴权方式或 Key 改变后停止后续请求；不向新地址续跑。

| 阶段 | 行为 |
| --- | --- |
| 提交 | 深拷贝 API 图，只替换绑定的输入；一次 `POST /prompt`，不自动重试或换源。未取得有效任务 ID 时明确提示提交结果未知，上游可能仍在执行 |
| 等待 | 以任务 ID 读取 `/history/{id}`；上次请求结束后间隔 1 秒，不重叠轮询 |
| 读取容错 | 网络错误、单次超时、502／503／504：连续第 3 次失败停止，成功读取清零。鉴权、结构和明确执行错误立即失败 |
| 收图 | 只读所选输出的 `images[0]`；经 URL 参数编码请求 `/view`，读取最多 3 次。接收 PNG／JPEG／WebP 原始字节并解码实际宽高；无图、错误页和解码失败不能记为成功 |
| 时限 | 单次读取 10 秒；单次生成、等待、下载及解码沿用 240 秒执行期限，重试不重置。缩略图、历史处理与展示仍在同一任务槽完成 |
| 取消 | 中止本地等待／下载；取得 ID 后以独立短超时最多尝试一次 `/queue` 删除自己的排队项。绝不调用全局 `/interrupt`；已运行的 GPU 任务可能继续 |

失败和取消停止剩余批次，保留已完成结果。ComfyUI 不调用报价、额度或扣费接口，界面显示运行状态；协议层不伪造零价格。其他供应商保留各自的报价、额度和付费规则。

## 原图与配方

下载并解码成功后，图片进入本页 `#h` 历史，刷新即清空。点击星标且写入成功后进入持久 `#f` 收藏，可跨刷新读取；数据属于当前浏览器和站点来源。GPU 在原图尚未下载前断开，不能保证继续收图。

记录包括实际注入文本、Seed、实际宽高与格式、任务 ID，以及冻结的模板 API JSON、绑定、连接身份、工作流身份／名称、所选模型身份／显示名／文件名和版本。已绑定参数的实际注入值独立记录在 `comfyParameters: { width?, height?, steps?, cfg? }`；顶层 `width`／`height` 仍是原图实际尺寸。工作流更新不覆盖旧图配方。导入、历史回填与 ASK 部分恢复采用输入参数，不把放大后的输出尺寸重新注入潜空间；没有此元数据的旧图不会猜测可恢复尺寸或步数。收藏、EDIT 来源配方、Slate／Bridge 元数据和新版 Koma 备份保留经过校验的快照；ASK 按需元数据可读取该快照。连接 Key 和鉴权头不进入图片配方，工作流自身应使用不含凭据的推理图。

采样与 LoRA 独立保存在 `comfyControls`：包括 sampler、scheduler，以及每个位置的文件名、启用状态和记住的模型／文本强度。`enabled: false` 表示该次提交的有效强度为零，不把记住的数值误当成本次生效值。历史导入提供「采样／调度／LoRA」审阅项；仅当目标工作流身份和本组绑定／默认值仍匹配时回填，配置已变时不会把旧节点数值写入新节点。收藏、备份和 EDIT 来源配方保留该结构。

送入 EDIT 保留来源配方；送入 CHAT 沿用原图交接与尺寸／体积规则，作为参考图使用，不把后续 CHAT 结果当作此工作流配方。CHAT 需另有可用模型连接才能领取交接图片；ComfyUI 连接本身不提供 EDIT／CHAT 的生成能力。图片配方不会自动创建连接或覆盖当前 JSON；普通配置恢复仍走已有备份校验。

## 部署与维护

保持静态网页浏览器直连。服务或其 HTTPS 代理须允许 Koma 来源的 CORS；Bearer 模式同时允许 Authorization 和 JSON POST 的预检。访问回环或私网可能需要浏览器的本地网络许可。WeTTY 登录地址是终端入口，不能填成 ComfyUI API 地址；需要可用的 ComfyUI HTTP 通道。

`127.0.0.1` 指运行浏览器的电脑。使用本机转发连接云 GPU 时，转发进程必须持续运行；保存连接和「测试连接」都不会自动启动它。GPU 服务仍在运行，也不代表本机端口仍可连接。电脑重启、休眠或终端断线后应先恢复通道。

CORS 必须匹配浏览器当前的页面来源，包括协议、主机和端口。例如开发页 `http://127.0.0.1:3216` 与预览页 `http://127.0.0.1:3217` 是不同来源，允许线上 Pages 域名不会自动允许这两个本机地址。可在用户自行管理的本机转发器配置明确来源白名单，无需为此重启 GPU 或修改工作流；不要使用任意来源反射。

「测试连接」只读 `/system_stats`。本机连接失败会提示检查服务／转发和浏览器本地网络许可；服务可访问但响应无法读取时提示检查当前页面来源的 CORS；终端 HTML 或无 API 的地址会提示填写 API 根地址。浏览器的网络异常不能单独证明域名错误。

首期不新增 `server.mjs` 代理。启用服务端托管连接的本地运行模式继续保持只读；自定义工作流连接使用允许用户配置供应商的静态／开发模式。

API 图规则在 `src/domain/comfy-workflow.ts`，基础参数在 `comfy-parameters.ts`，采样与 LoRA 绑定／值在 `comfy-controls.ts`；HTTP 执行与节点信息读取在 `src/gateway/comfyui.ts`，选项缓存归 `src/services/comfy-options.ts`。工作流列表和配置包导入归 `src/overlays/settings/ComfyWorkflows.vue`，路由与模型名单校验归 `domain/comfy-workflows.ts`；单份绑定表单位于 `ComfyWorkflowFields.vue`／`ComfyLoraBindings.vue`，由既有供应商弹窗承载；IMAGE 复用原有页签、参数抽屉和表单控件。Profile、连接、IMAGE、ASK 与图片元数据保留各自所有权。初始实现范围来自[已确认方案](../archive/comfyui/2026-11-01-custom-workflow-plan.md)，后续已批准扩展及现行行为以本文为维护位置。
