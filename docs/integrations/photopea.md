# Photopea 接入与工作栈规范

更新：2026-10-28。当前实现规范。三层初始化、自动回传、同尺寸蒙版沿用和保活分层文档已接线；代码检查、宿主模拟与真实 Photopea 的证据及未验范围见[工作栈核验](../archive/photopea/2026-10-27-photopea-workstack-verification.md)。本地验证不代表已经发布。

本文统一维护宿主、通信、图层、蒙版与回传边界；编辑画板、生成参数与来源回流由[EDIT 工作区](../workspaces/edit.md)维护。

## 1. 目标与范围

默认操作为「打开高级编辑 → 修图或标记重绘区域 → 应用」。用户不需要新建专用蒙版层、将涂色转为选区，或在回传前手动隐藏蒙版。

- Photopea 负责本次分层编辑、画笔／橡皮和选区操作；Koma 负责来源、版本、蒙版、参数、结果与后续生成。
- 由固定脚本分离最终图像与重绘区域，读取、校验成功后一次提交；失败不留下半份图像或蒙版。
- 回传不触发生成，不切换模型或供应商，不改变报价、余额检查、生成锁、取消、失败及付费行为。用户回到 EDIT 后决定是否执行生成。
- 纯修图保留为 EDIT 版本，可直接收藏和交付 Slate；不要求再调用 NAI，不自动进入 IMAGE 历史。
- 本规范不增加 PSD 持久化、软蒙版推理、Focused Inpainting 或第三方 AI 工具接入。

### 1.1 宿主入口与界面

EDIT 顶栏单个 Photopea 图标按需打开官方免费 iframe，覆盖 EDIT 全部可用空间；原生画布暂停，参数和版本栏让出空间。宿主只保留固定紧凑顶栏：桌面高 30px、按钮 24px，触屏高 34px、按钮 28px；没有展开／折叠按钮。返回、应用图标和回传方式始终可达，状态供屏幕阅读器读取。

默认 Dark Blue、中文，图层／历史面板折叠成图标；菜单保留文件、编辑、图像、图层、选择、滤镜、视图，文件菜单保留置入、保存回传、另存 PSD 和导出。工具聚焦选区与栅格修图，移除文字、钢笔、矢量形状、画板和切片，保留当前工具参数行、官方品牌、广告和两侧面板。只使用官方 Environment API，不改跨域 DOM，不扩宽裁剪广告或工具区。

就绪时聚焦 iframe，返回后恢复 EDIT 入口焦点。回传菜单聚焦当前项，支持方向键、Home／End、Enter 与 Esc；返回提示「暂不应用」，保留本页分层修改。就绪期间注册刷新／离页提醒，退出后清理；不保证浏览器每次都显示提醒。长期分层由用户在 Photopea 另存 PSD。

### 1.2 通信与写入边界

宿主只接收当前 iframe、官方 origin、本次打开标识和串行命令编号匹配的消息；未标记的手动导出不写入 Koma。二进制顺序、大小、超时和来源由固定消息通道校验；取消后排空旧操作，异常隔离通道，由用户显式重载，不自动重试。

图片按 EXIF 方向归一化后以二进制传入，不传 Prompt、Key 或其他工作台资料。没有自动保存；Photopea 的显式保存动作与「应用并返回」共用本规范回传入口。命令、载图与隐藏期间的资源责任见第 9 节。

## 2. 输入来源与初始化

### 2.1 本次来源

输入是进入高级编辑时**当前查看的图片版本**，不擅自换成另一张主底图。蒙版属于当前 EDIT 画板的会话画布，各板完全隔离：像素宽高相同的版本共用当前区域，不按版本恢复旧快照。只有主动清空或切到不同宽高的图片才重置；切回旧版本也不会复活已经清空的区域。

打开时冻结编辑会话、当前查看版本、原主底图、本次打开标识、蒙版修订号、尺寸与来源配方。载入图片按现有方向归一化；图片与蒙版使用同一画布坐标。进入高级编辑本身不改写 Koma 的主底图、蒙版或历史。

### 2.2 初始三层结构

以下为文档根级从下到上的初始结构，三层默认可见，另有一层已确认的隐藏选区辅助层：

| 图层 | 用途与初始内容 | 初始属性 |
| --- | --- | --- |
| Koma 选区辅助 | 全画布不透明覆盖，仅供脚本复制活跃选区 | 最底层、隐藏且锁定；不进入底图或重绘蒙版 |
| 原图 | 当前查看图的完整像素，可液化、调色或直接修改 | 普通可编辑栅格层，100% 不透明度，不保留妨碍编辑的背景锁定 |
| 涂鸦与修补 | 引导色块、画笔修补、拼贴；初始为空白透明 | 普通栅格层、正常混合、100% 不透明度 |
| Koma 蒙版 | 专用重绘标记；有原有蒙版时还原覆盖区域，否则为空白透明 | 普通栅格层、正常混合、图层不透明度 55%，填充不透明度 100% |

- 从重绘模式进入，默认激活「Koma 蒙版」；从普通图像编辑或放大上下文进入，默认激活「涂鸦与修补」。入口模式只决定初始活动层，不决定回传方式。
- 初始化的蒙版像素用白色、55% 图层不透明度表示，实际覆盖不依赖颜色。用户可以使用自己的画笔颜色。
- 原有蒙版还原到专用层后**取消初始化产生的选区**。不同时保留一份旧选区，以免擦除后被并集规则重新加回。
- 三层、原有蒙版和本次角色标识全部初始化成功后，才解除加载状态；失败时保留 Koma 原状态并给出重载反馈。
- 初始化建立本次编辑起点，不让正常第一次撤销依次拆掉三层结构。后续用户编辑的撤销／重做按 Photopea 行为保留。

三层是默认工作起点，不要求用户始终只保留三个图层。普通图像层可以自由新增、删除、分组或排序；其最终可见效果参与图像合成。

## 3. 蒙版的像素语义

### 3.1 专用层表示覆盖

「Koma 蒙版」中的像素透明度表示重绘覆盖；透明部分表示保留。涂黑、涂白或涂其他颜色均可标记，橡皮擦移除覆盖。它不同于导入黑白蒙版文件时「白色重绘、黑色保留」的灰度语义。

- 图层 55% 不透明度只用于透视底图。提取时读取像素自身的透明度，不把图层不透明度、填充不透明度或混合模式再乘入覆盖。
- 画笔自身的不透明度、橡皮擦和直接修改像素产生的透明度属于真实像素覆盖，按现有阈值处理。
- 图层眼睛开关只控制预览。隐藏专用层不代表停用蒙版；「仅图像」用于明确忽略本轮蒙版编辑。
- 普通图像层、原图透明区域及图片颜色不自动转换为蒙版。不按红色、紫色或黑白外观猜测图层用途。
- 专用层和辅助层不支持附加光栅／矢量蒙版或图层效果。应用时检查内存 PSD 的图层元数据，存在这些结构时阻止回传，提示移除；普通图像层的蒙版和效果正常参与合成。

### 3.2 与活跃选区取并集

最终区域由「专用层像素覆盖」与「当前活跃选区覆盖」取并集。选区不存在时只有专用层生效；专用层为空时仍可单独使用选区。两者都有效时，重叠区域不重复累计强度。

合并在当前文档完整画布坐标进行，先取两份覆盖的最大值，再按现有规则将覆盖值 **大于 32** 的像素设为重绘。输出给 Koma 的覆盖为二值，后续 NAI 蒙版仍是全尺寸、白色重绘、黑色保留；不承诺灰度强度或羽化完整往返。

用户需要理解的选择行为：

- 取消选区只移除选区这一份贡献，不清除专用层已画区域。
- 橡皮擦只改变图层像素，不会减去仍然活跃的选区；要减去选区贡献，使用 Photopea 的选区减选或取消选区。
- 活跃选区仍会按 Photopea 原生规则限制画笔。需要在全图自由绘制时先取消选区，宿主不擅自取消用户主动建立的选区。
- 魔棒取样原图时，可选中原图层或使用 Photopea 的全部图层取样，随后直接应用，无需把选区写入专用层。

## 4. 图层身份与结构边界

### 4.1 专用角色识别

显示名称固定初始化为「Koma 蒙版」，内部必须记录本次文档的专用图层身份。识别不依赖「最上面一层」、数组下标、当前活动层或仅仅一个同名字符串。

- 同一文档内改名及根级重排后，仍须识别原专用层并从图像导出中排除。
- 原图和修补层的名称用于引导操作；其改名或普通合并不改变图像用途。只要专用蒙版角色仍完整，用户可以自由组织图像层。
- 外部新开文档、跨文档粘贴或加载 PSD 不自动获得本次来源身份。回传必须针对本次受控文档。
- 不把相同显示名称当作身份恢复依据。遇到新建同名层、可识别的专用层副本或多个冲突角色，停止回传并提示整理图层，不悄悄任选一层或全部当作图像导出。默认名称及常见副本名称可识别；用户复制后彻底改名的普通像素层不能可靠反推为蒙版副本，程序不按颜色猜测删除。

同一受控文档用公开 `layer.id` 关联角色，已核验改名、根级重排、撤销／重做及临时导出后的稳定性。内存 PSD 保留对应图层 ID，元数据检查不依赖名称；临时副本的导出位置只使用本次冻结快照的根级索引。跨文档输入预留独立 ID，返回状态拒绝重复 ID。

### 4.2 结构破坏与首版边界

| 操作／状态 | 约定 |
| --- | --- |
| 隐藏或调整专用层不透明度 | 保留身份，覆盖仍按第 3 节提取 |
| 在文档根级移动、缩放、旋转专用像素层 | 按最终画布位置提取覆盖，不使用旧图层边界作为蒙版尺寸 |
| 删除专用层、与图像层合并或拼合整个文档 | 身份结构不完整，阻止所有回传方式；不能将其视为「空蒙版」 |
| 撤销结构破坏 | 重新验证身份后允许回传；不能只因名称恢复就认为结构恢复 |
| 专用层移入分组、成为剪贴层，或附加图层蒙版／矢量蒙版 | 阻止回传，提示恢复独立根级像素层；附加蒙版与效果由 PSD 元数据检查 |
| 专用层转为智能对象、调整层或其他非像素类型 | 阻止回传，不能把读取失败解释成没有覆盖 |
| 普通图像层的分组、图层蒙版、混合及透明度 | 按 Photopea 的可见合成结果进入底图，不能连同普通图像层蒙版一起剔除 |

结构无效时提示用户撤销相关操作；需要重新进入时先由用户自行保存仍需保留的 PSD。不得在后台新建一张空蒙版来掩盖专用层丢失，更不能通过「仅图像」绕过结构检查。

防污染保证针对可验证工作栈中的专用蒙版角色。用户主动把标记画到普通图像层，或将其像素作为普通图像素材另行复制，属于图像编辑；系统不按颜色猜测并删除这些图像内容。

## 5. 图像导出与现场恢复

**任何回传方式都必须得到排除专用蒙版层后的干净图像。** 即使用户没有手动隐藏，专用层也不能参与底图 PNG 的合成。

一次应用按以下流程执行：

1. 冻结本次来源、回传意图和文档输入，检查受控文档及图层结构；检查通过前不写 Koma 数据。
2. 在同一文档状态下读取专用像素覆盖和活跃选区，计算最终蒙版与是否为空。
3. 隔离专用蒙版角色及其显示效果，导出其他可见图像层的完整画布 PNG；普通图像层的可见性和效果保持原意。
4. 导出只修改临时文档并在完成后关闭，原分层文档的可见性、活动层、选区、内容和已有重做分支保持；复制选区时临时选中辅助层，随后恢复活动层。
5. Koma 校验图像、蒙版、来源与返回项，计算像素变化，按第 6–8 节一次提交。

仅传蒙版也需要干净图像作为底图一致性的校验证据，但该图片不会因此自动进入 Koma 历史。不能用仍包含专用层颜色的合成图作一致性校验。

导出使用 `saveToOE("psd:true")` 生成临时内存快照，校验后在 Photopea 打开临时副本，再导出干净图像、选区、专用层覆盖与辅助层覆盖四份 PNG。PSD 只在内存中传输，上限 128MiB，不下载、不写数据库。原文档不隐藏图层、不合并、不改 `activeHistoryState`，因而保留已存在的重做分支。

活跃选区通过隐藏的不透明辅助层复制到 Photopea 内部剪贴板，再粘贴到临时文档并恢复源坐标。此操作会替换 Photopea 内部复制内容；不承诺系统剪贴板行为。辅助层的原始 Alpha 必须在选区外接矩形内完全不透明；用户破坏辅助层或扩展画布后选到未覆盖区域会被拒绝，不能静默缩小选区。无选区时不需要复制。

公开脚本解释器的异常和 `finally` 不能作为唯一保护。已知结构错误直接发送带编号的错误回执并停止脚本；异常／超时仍由宿主隔离通道，Koma 不接受不完整输出。

若无法恢复现场，本次结果不得提交到 Koma；给出错误并解除宿主忙态。通信错序、超时或关联失败继续废弃该通道，不把迟到输出当作下一次结果。能保留的编辑现场由用户另存 PSD，宿主不自动重载覆盖。

## 6. 回传入口与自动决策

### 6.1 单按钮与三种意图

保留紧凑的「应用并返回」主按钮及同一个下拉，选项为：

| 界面选项 | 行为 |
| --- | --- |
| 自动 | 每次进入默认选择；同时检查干净图像与最终蒙版，按变化决定提交 |
| 仅图像 | 忽略本轮蒙版编辑，仍自动排除专用层；只提交实际变化的图像 |
| 仅蒙版 | 只更新或清空蒙版；要求干净图像仍对应进入时的源图 |

「自动」已经覆盖图像与蒙版一起回传，不额外保留第四个「图像与选区」入口。模式显示始终可见，Photopea 的显式保存与宿主主按钮使用同一选择和提交管线。

不轮询打印图层数、蒙版面积、技术状态或常驻说明；点击应用时进行必要检查。失败留在现有错误反馈区域，不增加独立导出预览弹窗。短文案使用「仅蒙版」，选区是生成该蒙版的一种输入。

### 6.2 变化的定义

- 图像变化：当前干净合成图与进入时归一化源图比较尺寸和解码后像素；PNG 编码、文件名、活动层或专用蒙版层的预览显隐不算变化。普通图像层的显隐若改变最终像素，仍算图像变化。
- 蒙版变化：最终二值覆盖与进入时当前会话的完整二值覆盖比较；改画笔颜色、仅改变预览不透明度或把同一区域从选区转画到图层，若最终覆盖相同则不算变化。
- 不能仅凭历史条目数、文档脏标识或「有选区」判断是否需要新建图片版本。
- 读取失败、结构无效及来源失效属于错误，不进入「无变化」或「空蒙版」分支。

### 6.3 自动模式决策表

下表以结构、来源及输出均校验成功为前提：

| 干净图像 | 最终蒙版 | 自动结果 |
| --- | --- | --- |
| 未变 | 与原蒙版相同 | 直接返回，不新增图片、蒙版撤销项或历史记录 |
| 未变 | 非空且与原蒙版不同 | 仅替换当前会话蒙版，作为一次可撤销操作 |
| 未变 | 有效为空，原来非空 | 明确清空当前会话蒙版，作为一次可撤销操作 |
| 已变 | 非空 | 创建一个手动图片子版本，同时绑定最终蒙版 |
| 已变 | 有效为空 | 创建一个无蒙版的手动图片子版本，不沿用旧版本区域 |

「只有蒙版变化」不制造手动图片版本，也不自动收藏或绑图。新增图像时，图像和蒙版必须共同通过校验才创建版本；重试保存不重复创建版本。

### 6.4 显式模式

- **仅图像**：结构有效且图像未变时直接返回，当前会话蒙版保持不变；图像变化时创建手动子版本，忽略 Photopea 本轮蒙版编辑；输出与当前画布同尺寸时沿用当前 Koma 蒙版，不同尺寸时重置。
- **仅蒙版**：干净图像与源图尺寸和像素一致时，按最终覆盖替换、清空或无操作。若用户同时修图、裁剪、旋转等导致干净图像变化，拒绝本次回传并提示改用「自动」；不暗中升级用户的显式选择。
- 两种显式模式与自动模式共用来源校验、专用层排除、事务提交和错误处理，不能成为绕过保护的捷径。

## 7. 空蒙版、清空与失败的区别

接收管线需要明确表达以下语义；这是内部受控回传语义，不是新的外部 Bridge 协议：

| 语义 | 来源与处理 |
| --- | --- |
| 保留 | 显式仅图像且不改当前源图，或最终蒙版无变化；不写蒙版历史 |
| 替换 | 已完整读取并校验的非空覆盖；替换该版本完整区域，而非再与旧 Koma 蒙版取并集 |
| 清空 | 专用层身份有效、像素提取成功，最终覆盖和选区贡献均为空；写入显式清空，不制造全选 |
| 失败 | 专用层缺失、读取失败、身份冲突、输出缺项或来源失效；不修改任何 Koma 状态 |

用户把原有蒙版用橡皮擦到全透明，取消残留选区，再按「自动」或「仅蒙版」应用，就是清空意图，不要求再去其他面板点清空。若选区仍存在，最终覆盖仍可能非空。

空蒙版不能靠缺少文件、缺少二进制返回或捕获异常来表达。消息明确区分「合法为空」与「本应收到却没有收到」；有覆盖时校验实际数据一致，没有覆盖时也校验声明完整。

本规范只对受控高级编辑回传增加合法空值语义；现有独立蒙版文件导入的空图拒绝行为不随之放开。空蒙版回到 EDIT 后，重绘生成仍按现行规则拦截，不能自动解释为整图重绘。

## 8. 版本、坐标与模型边界

### 8.1 当前查看图与主底图不同

高级编辑始终编辑被冻结的查看版本。应用前主底图不变；应用时按以下规则处理：

- 自动或仅蒙版确实修改了该版本蒙版时，若它不是当前主底图，**在同一次应用中将该已有版本设为底图并写入对应蒙版**，不创造一张内容相同的新图片。
- 这次底图切换和蒙版修改共同构成一次可撤销操作，撤销恢复先前主底图及相关蒙版状态。必要反馈可简短说明「已设为底图」，不增加确认弹窗。
- 自动无变化、仅图像无变化时，不切换主底图。
- 有图像变化时，新建子版本并将其设为查看图及底图，沿用手动编辑版本规则。

底图和蒙版共同由统一编辑服务提交／撤销；UI 不先切底图再异步补蒙版。仅蒙版校验的图像锚点是本次进入的当前源图（如 A2），不再固定为最初的 A1。

### 8.2 画布与变换

- 导出图片和蒙版使用应用瞬间的同一画布尺寸、方向与源像素坐标。视口缩放、平移及设备像素比不影响输出尺寸。
- 裁剪、画布旋转或改变画幅后，按最终画布导出两者；不把旧蒙版静默缩放或贴到新坐标。
- 用户只移动原图层时，专用层不会被程序擅自跟随。用户需要按画面调整蒙版，程序按最终文档的位置回传。
- 单独查看版本或切换本次受控文档，不得绕过来源冻结。源版本、主底图、蒙版修订或编辑会话在外部发生变化后，旧回传失效。
- 输入、输出继续使用现有每张图片 8MiB／3200 万像素限制，并要求蒙版与最终图片尺寸严格一致；超限在解码和分配前后按现有校验拒绝，不自动缩图。
- NAI 的 64 对齐、边长、面积和型号支持限制是后续生成的独立检查。可保留的手动图像不因不满足生成尺寸被偷偷重采样。

### 8.3 编辑模式与生成

有蒙版不代表自动切模型、自动选支持 Inpaint 的另一型号或开始生图。原 EDIT 模式继续保留；从普通编辑进入后带回蒙版，用户可通过已有「重绘」入口使用。模型不支持重绘时沿用现行能力限制和明确反馈。

仅图像和图像加蒙版的手动结果均记录真实修改来源及来源配方，不伪造新的生成 Seed、模型消耗或生成耗时。结果保留在 EDIT，可直接收藏或交付 Slate，不自动进入 IMAGE 历史；CHAT 仍显式回传参考图，不自动发送消息。

## 9. 分层复用、生命周期与资源

- 首次按需创建 iframe，之后 `v-show` 隐藏保活，正常重入不改 URL、不重建实例。Photopea 自己持有真实分层文档，Koma 只记录会话／源版本、像素尺寸、图层身份、当前蒙版摘要和已烘焙图层标识，不把大对象放入深层 reactive。
- **未切换底图**：唤醒原分层文档，不重新打开回传的 PNG。原图、修补、自定义图层、专用蒙版及 Photopea 历史均保留。只有在 Koma 外层真正改过蒙版，才替换专用层像素并取消旧选区。
- **同尺寸换底**：在当前文档插入新的「原图」，隐藏旧原图；保留专用蒙版与自定义层。不重新初始化文档。原图层已被删除或合并、无法明确换底时，提示保存需要的 PSD 后重载，不擅自拍扁。
- **已烘焙衍生图**：返回过的手动合成结果作为后续版本祖先时，原先参与合成的可见修补／自定义根级图层已包含在新图中，将其隐藏保留，并建立新的空白修补层，避免二次叠加。普通同尺寸独立底图沿用原图层显隐。判断基于当前会话中可追踪的版本关系；不做像素内容猜测。
- **同画板不同像素尺寸、显式重新载入、通信故障后的重建或页面刷新**是工作栈重建边界。不同编辑画板由同一 iframe 保留各自文档，A→B→A 激活原文档；关闭画板只释放其文档。同板不同尺寸初始化新三层及辅助层，蒙版按尺寸规则重置。不提供 PSD 数据库或跨刷新恢复；需要长期保存分层时用户自行另存 PSD。
- 「暂不应用」返回只取消本次 Koma 写入，当前保活文档保留用户修改。重新载入前提示分层文档会被重建；不把返回文案写成「已丢弃编辑」。
- 应用期间 iframe 禁止输入；旧命令排空后才开始新进入。隐藏不接受保存回调，活动监听和待执行重排取消；卸载释放通道。迟到、错序及失效来源不能写入其他会话。
- 保留标准 100% 视口、`overflow: clip`、固定紧凑顶栏。整个载入流程完成后延迟 150ms，将 iframe 缩窄 1px、50ms 后恢复，触发子页面重排；不裁切两侧面板。
- 临时导出文档与图像资源在成功、失败和取消路径清理；通信不可恢复时停止写回并保留可供用户另存的现场。蒙版继续使用二值位图与笔画历史及其内存预算，持久保存沿用数据租约和 `data.write`，不增加普通备份内容。

## 10. 用户操作约定

| 目标 | 操作 |
| --- | --- |
| 普通修图 | 普通编辑进入，在默认修补层涂画；需液化等操作时选原图；按默认「自动」应用 |
| 画区域重绘 | 重绘模式进入，默认就在蒙版层；画笔增加、橡皮减少；直接应用 |
| 用魔棒／套索 | 取样图像并建立选区，直接应用；不需要手工转换图层或隐藏专用层 |
| 画引导色块再重绘 | 修补层画引导，蒙版层画区域，自动应用一次带回图像与蒙版 |
| 只看底图 | 隐藏蒙版层预览；再次显示可继续画，应用仍携带有效区域 |
| 清空原有区域 | 擦空专用层并取消选区，自动或仅蒙版应用 |
| 本轮只想收修图 | 选择「仅图像」；专用层仍由程序排除 |

这些是文档中的使用说明，不作为常驻长文案印在工具栏或弹窗中。
