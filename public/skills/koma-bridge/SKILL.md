# Koma 外部协同

## 任务选路

先读取用户指定企划根目录下的 `PROTOCOL.md`。文件读写边界、接口字段、示例和 Schema 均以该协议为准；本指南只说明整理方法和协作流程。

- **整理企划**：阅读原始设定和现有资料，按用户目标拆解、编排，并写入企划目录。
- **调整画板或任务**：读取最新的 `state.live.json`，结合相关资料和图片准备草稿。
- **检查成果**：按协议读取成果图、配方、标注和任务记录，对照用户目标进行核对。

## 企划拆解与角色五要素

主动理解任意格式的原稿，包括大型混合 TXT、Markdown、YAML 和 XML 标签块。按语义识别角色、世界观和公共设定：公共内容整理到 `lore/`，角色内容整理到 `characters/<char_id>/`。结构化拆解由你完成，Koma 按约定字段读取整理结果。

为每个角色建立以下五项资料：

1. **完整人设 `profile.md`**：收录该角色在原稿中的全部设定、细节和台词。可以划分章节、归置内容，但不得用摘要代替原文，也不得删改原始设定和台词。
2. **识别摘要 `brief`**：不超过 160 字，包含身份、性格核心和标志性外观。
3. **绘图 TAG `char.json.tags`**：按需编写或整理。
   - 固定外貌（发色、发型、瞳色、体型、种族特征等）写入顶层 `prompt`。
   - 主服装、私服和替换装分别写入 `outfits`，每套只描述该套服装本身。这样换装时外貌保持不变，每次只穿一套。
   - 已有 TAG 中有效的词条和权重予以沿用。
4. **标准立绘 `portrait`**：归置该角色的主立绘并填写引用，标明哪一张是当前形象基准。
5. **参考资料**：角色细节图、换装图和场景图归入该角色的 `refs/` 或 `extra/`；公共参考图归入 `references/`，并在 `references/references.json` 中填写名称、分类和用途。

整理完成后，检查角色对应关系、资料来源、路径和 TAG 组合，名称保持简短。修改现有企划时，先核对字段引用和取值优先级，再修改实际生效的资料。

## 画板改词原则

结合当前配方、历史图和企划资料理解用户目标。

- **日常改词**：保留已有的画师串、画风段和常驻负面词，集中调整本次的主体、动作、场景和参数。
- **更换风格或与旧词冲突**：按用户目标修改相应部分。
- **另起主题**：移除与新主题无关的旧主体和旧场景。

使用角色时，选出本次所需的一套服装，与固定外貌组合后写入目标槽位。完整人设作为创作依据，TAG 按当前画面需要取用。

多图任务可以拆分为待办，把本次改动、交图和下一张的准备工作合并到一份连贯的草稿中。

## 草稿主流程

1. 读取最新状态，以及本次需要的原文、图片和任务信息。
2. 按用户目标起草修改，按 `PROTOCOL.md` 规定的格式投递到 `draft.inbox.json`；如果无法访问企划目录，则提供 JSON 供用户手动导入。
3. 等待用户审阅后读取对应回执。如需修正，先重新读取当前状态，再重新提出修改。
4. 说明本次已应用的修改或尚待处理的问题，然后按用户目标推进下一步。

图片编号与作用域、回执状态、任务版本和资料保存方式，均以 `PROTOCOL.md` 为准。
